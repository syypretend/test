算法编程 ⭐⭐ 第 1 题

数组中第K个最大元素

给定一个未排序的整数数组 nums 和一个整数 k，请返回数组中第 **k** 个最大的元素。

注意：你需要找的是数组排序后从大到小数的第 k 个元素，而不是第 k 个不同的元素。

要求：平均时间复杂度优于 $O(n^2)$。
输入
两个参数：整数数组 nums 和整数 k
输出
返回第 k 个最大的元素（整数）
示例 1
输入：nums = [3,2,1,5,6,4], k = 2
输出：5
排序后为 [6,5,4,3,2,1]，第 2 大的元素是 5
示例 2
输入：nums = [3,2,3,1,2,4,5,5,6], k = 4
输出：4
排序后为 [6,5,5,4,3,3,2,2,1]，第 4 大的元素是 4
约束
1 <= len(nums) <= 10^5 -10^4 <= nums[i] <= 10^4 1 <= k <= len(nums)
🧑‍💻 在线代码编辑器
def findKthLargest(nums, k): # 返回数组中第 k 个最大的元素 pass
--- 以下为答案与解析 ---

💡 解题思路

使用 **快速选择算法（QuickSelect）**：

1. 转化问题：第 k 大 = 排序后第 (n - k) 小的元素（0-indexed）
2. 随机选一个 pivot，用 Lomuto 分区将小于 pivot 的放左边、大于的放右边
3. 若 pivot 恰好落在目标位置 k_idx，直接返回该值
4. 若 pivot 位置 < k_idx，只在右半递归；否则只在左半递归
5. 随机化 pivot 保证期望时间复杂度 $O(n)$

**备选方案**：维护大小为 k 的小顶堆，遍历一遍后堆顶即为第 k 大，时间 $O(n \log k)$，空间 $O(k)$。当 k 较小时堆方法更优。

📝 参考代码（python）

import random

def findKthLargest(nums, k):
    def quickselect(left, right, k_idx):
        if left == right:
            return nums[left]
        # 随机选 pivot，避免最坏情况
        pivot_idx = random.randint(left, right)
        nums[pivot_idx], nums[right] = nums[right], nums[pivot_idx]
        pivot = nums[right]
        # Lomuto 分区：小于 pivot 的放左边
        store = left
        for i in range(left, right):
            if nums[i] < pivot:
                nums[store], nums[i] = nums[i], nums[store]
                store += 1
        nums[store], nums[right] = nums[right], nums[store]
        # 判断 pivot 最终位置
        if store == k_idx:
            return nums[store]
        elif store < k_idx:
            return quickselect(store + 1, right, k_idx)
        else:
            return quickselect(left, store - 1, k_idx)
    # 第 k 大 = 第 (n - k) 小（0-indexed）
    return quickselect(0, len(nums) - 1, len(nums) - k)

⚡ 复杂度分析

时间 O(n) 期望 空间 O(log n) 递归栈

🎯 考点

QuickSelect 分区思想、随机化 pivot 避免最坏情况、第 k 大与第 (n-k) 小的索引转换、Lomuto 分区写法
算法概念 ⭐⭐ 第 2 题

KMP 算法 prefix table（LPS 数组）性质判断

KMP 算法通过预处理模式串构建 prefix table（又称 LPS 数组 / 失败函数），实现 $O(n + m)$ 的字符串匹配。关于 LPS 数组，以下说法 **错误** 的是？
--- 以下为答案与解析 ---
✅ 正确答案：D

💡 解题思路

LPS（Longest Proper Prefix which is also Suffix）数组的核心性质是：对每个位置 i，LPS[i] 记录 P[0..i] 的最长公共前后缀长度，用于失配时确定模式串滑动的距离。选项 D 将 LPS 混淆为「字符匹配跳转表」（类似 Boyer-Moore 的坏字符表），这是两种不同的概念。

🎯 考点

LPS 数组的定义（最长公共前后缀）、预处理 $O(m)$ 递推、失配跳转 LPS[j-1]、文本指针不回退、LPS 与坏字符表的区别

🔍 逐项分析

  • A 正确：这正是 LPS 的定义。例如 P="ABABCABAB"，P[0..7]="ABABCABA"，真前缀 {A,AB,ABA,ABAB,ABABC,...}、真后缀 {A,BA,ABA,CABA,...}，最长公共为 "ABA"（长度 3），故 LPS[7]=3。
  • B 正确：LPS 完全由模式串结构决定，与文本串无关。预处理时通过递推（利用 LPS[i-1] 跳跃）在 $O(m)$ 内完成，这是 KMP 优于暴力匹配的关键。
  • C 正确：失配在位置 j 时（j>0），已匹配部分 P[0..j-1] 的最长公共前后缀长度为 LPS[j-1]。将模式串滑动使 P[LPS[j-1]] 对准当前文本位置，相当于「利用之前匹配的前缀信息」避免了文本指针回退。j=0 时模式串整体右移一位。
  • D 错误：LPS[i] 刻画的是 P[0..i] 子串的「最长真前缀=真后缀」长度，与「第 i 个字符在前面的出现位置」无关。D 描述的更接近 Boyer-Moore 坏字符规则中的跳转逻辑，与 KMP 的 LPS 是完全不同的概念。例如 P="ABAB"，LPS[3]=2（"AB" 既是前缀又是后缀），而非「上一个 A 的位置」。
AI公式推导 ⭐⭐ 第 3 题

CNN 卷积层输出尺寸公式与感受野递推公式推导

设卷积层输入特征图宽度为 $W_{in}$，卷积核大小 $K$，填充 $P$，步长 $S$。

**任务 A**：推导单层卷积输出特征图宽度 $O$ 的计算公式。

**任务 B**：在多层堆叠的 CNN 中，定义第 $l$ 层的感受野 $RF_l$ 为该层一个输出像素对应原始输入图像上的像素跨度。已知第 1 层 $RF_1 = K_1$，推导第 $l$ 层感受野的递推公式。
--- 以下为答案与解析 ---

🎯 考点

输出尺寸 $O = \lfloor (W_{in} + 2P - K) / S \rfloor + 1$、感受野递推 $RF_l = RF_{l-1} + (K_l - 1) \prod S_i$、jump 的定义与传递、多层小卷积等效大卷积的参数量优势

📐 推导过程

**符号定义**：$W_{in}$ 输入宽、$K$ 卷积核大小、$P$ 零填充、$S$ 步长、$O$ 输出宽。

**Part A：输出尺寸公式推导**

**Step 1 — 确定有效输入范围**

两侧各填充 $P$ 个零后，有效输入宽度变为 $W_{in} + 2P$。

**Step 2 — 确定核的滑动位置**

卷积核宽度为 $K$。第一个核覆盖位置 $[0,\ K-1]$。若输出共 $O$ 个位置，步长 $S$，则最后一个核的起始位置为 $(O-1) \times S$，其覆盖范围终点为：
$$(O-1) \times S + K - 1 \leq W_{in} + 2P - 1$$

**Step 3 — 解出最大整数 $O$**

移项得：
$$(O-1) \times S \leq W_{in} + 2P - K$$
$$O \leq \frac{W_{in} + 2P - K}{S} + 1$$

$O$ 取满足条件的最大整数：
$$\boxed{O = \left\lfloor \frac{W_{in} + 2P - K}{S} \right\rfloor + 1}$$

**Part B：感受野递推公式推导**

**定义**：设 $j_l$ 为第 $l$ 层输出中相邻两个像素的中心在原始输入图像上的间距（jump）。

**Base case（第 1 层）**：
- 每个输出像素直接看 $K_1 \times K_1$ 区域，$RF_1 = K_1$
- 相邻输出像素间距为步长 $S_1$，故 $j_1 = S_1$

**递推关系 — jump 的传递**：

第 $l$ 层的输入即第 $(l-1)$ 层的输出。第 $l$ 层步长为 $S_l$ 时，其输出中相邻像素在第 $(l-1)$ 层输出中相距 $S_l$ 个像素，而第 $(l-1)$ 层每个像素在原始输入上的间距为 $j_{l-1}$，故：
$$j_l = j_{l-1} \times S_l$$

递推展开得：
$$j_{l-1} = \prod_{i=1}^{l-1} S_i$$

**递推关系 — 感受野的累积**：

第 $l$ 层每个输出像素覆盖第 $(l-1)$ 层中 $K_l$ 个连续像素。这 $K_l$ 个像素的中心范围跨度（在原始输入上）为 $(K_l - 1) \times j_{l-1}$。加上两端像素各自已有的感受野，得到：
$$RF_l = RF_{l-1} + (K_l - 1) \times j_{l-1}$$

代入 $j_{l-1}$ 的表达式：
$$\boxed{RF_l = RF_{l-1} + (K_l - 1) \times \prod_{i=1}^{l-1} S_i}$$

**验证示例**：3 层 $3{\times}3$ 卷积，每层 $K{=}3,\ S{=}1,\ P{=}1$（VGG 风格）：
- $RF_1 = 3,\ j_1 = 1$
- $RF_2 = 3 + (3-1) \times 1 = 5,\ j_2 = 1$
- $RF_3 = 5 + (3-1) \times 1 = 7,\ j_3 = 1$

三层 $3{\times}3$ 卷积感受野 = $7{\times}7$，等效一层 $7{\times}7$ 卷积，但参数量仅 $3 \times 3^2 \times C^2 = 27C^2$（远小于 $7^2 C^2 = 49C^2$），且通过了 3 次非线性激活，表达能力更强。

🧠 直觉解释

输出尺寸公式本质是「有效宽度减去核宽度后，按步长能放几个核」；感受野递推本质是「每层新增的感受野 = 核边缘 $(K-1)$ 个像素 × 前面所有层的步长累积」，步长越大、层越深，感受野增长越快。
AI面试问答 ⭐⭐ 第 4 题

KV Cache 原理：为什么能加速 Transformer 自回归推理？

在 Transformer 大模型自回归推理（如 GPT 生成文本）时，KV Cache 是最核心的推理优化技术之一。请解释 KV Cache 的原理、如何减少计算量、它的内存开销以及常见的优化方案。
--- 以下为答案与解析 ---

📌 回答要点

  • **问题本质**：自回归生成时，每生成一个 token 都要对前面所有 token 做 attention。若不缓存，每步都要重新计算前面所有 token 的 K 和 V 矩阵（$K = X W_K,\ V = X W_V$），产生大量重复计算。
  • **KV Cache 机制**：将每层已计算的 K 和 V 缓存在显存中。生成新 token 时，只需计算该 token 的 $q_{new}, k_{new}, v_{new}$，将 $k_{new}$ 和 $v_{new}$ 追加到 cache 末尾，然后用 $q_{new}$ 与整个 cached $K$ 做注意力计算。
  • **复杂度对比**：无 cache 时，第 $t$ 步需计算 $t \times t$ 的注意力矩阵和 $t$ 个 token 的 K/V，总计 $O(n^2 \cdot d)$ 且每步重复。有 cache 后，每步只需 $O(t \cdot d)$ 的 QK^T + softmax × V 计算，避免了对前 $t-1$ 个 token 重复计算 K/V 矩阵乘法，计算量常数大幅下降。
  • **Prefill vs Decode**：Prefill 阶段一次性处理 prompt（计算量大、并行），将所有 K/V 存入 cache；Decode 阶段逐 token 生成，每步只追加 1 行 K/V 到 cache（计算量小、串行）。Prefill 是 compute-bound，Decode 是 memory-bound。
  • **内存代价**：KV Cache 存储所有层的 K 和 V，内存正比于 $O(n \cdot L \cdot d)$（序列长度 × 层数 × 隐藏维度）。长序列 + 多层时显存占用巨大，如 LLaMA-2-70B 生成 4K 序列时 KV Cache 约需 ~32GB 显存。

⭐ 加分项

  • **Multi-Query Attention (MQA) / Grouped-Query Attention (GQA)**：让多个 query head 共享同一组 K/V head，KV Cache 内存降低 $h$ 倍或 $h/g$ 倍，LLaMA-2 和 Gemini 均采用 GQA，在推理速度与质量间取得平衡。
  • **PagedAttention (vLLM)**：借鉴 OS 虚拟内存分页机制，将 KV Cache 按固定大小 block 管理，消除内部碎片，支持更大 batch size 和动态内存分配，吞吐量提升 2-4 倍。
  • **KV Cache 量化**：将 FP16 的 K/V 缓存压缩为 FP8/INT8，内存减半、吞吐提升，精度损失可控。部分场景下甚至可用 INT4。
  • **Sliding Window Attention**：只缓存最近 $W$ 个 token 的 K/V，超窗口的自动淘汰，使 KV Cache 内存从 $O(n)$ 降为 $O(W)$，Mistral 等模型采用此策略实现无限上下文。

🔮 追问预测

  • 追问：为什么 Decode 阶段是 memory-bound 而非 compute-bound？ → 每步只计算 1 个 token 的 attention（约 $n \cdot d$ 次乘加），但需从显存读取整个 KV Cache（$O(n \cdot d)$ 字节），计算/访存比（arithmetic intensity）极低，GPU 算力利用率通常不到 5%。GQA 和量化正是为了减少访存。
  • 追问：KV Cache 和训练时的 attention有什么区别？ → 训练时用 teacher forcing 全序列并行计算，无需 cache（所有 token 同时处理）；推理时是自回归串行生成，必须 cache 前文 K/V 才能逐 token 推进。训练用 FlashAttention 优化 $O(n^2)$ 计算，推理用 KV Cache 减少重复计算。
  • 追问：Speculative Decoding 如何利用 KV Cache？ → 用小模型（draft model）快速生成候选 token 序列，大模型一次性验证，正确部分直接复用已生成的 KV Cache，推测命中的 token 无需重新计算 K/V，减少 decode 步数提升 2-3 倍吞吐。
