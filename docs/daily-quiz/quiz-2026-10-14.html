算法编程 ⭐⭐ 第 1 题

最长不含重复字符的子串（滑动窗口）

给定一个字符串 s，找出其中**不含重复字符**的**最长子串**的长度。

实现函数 solve(s)，返回满足「子串内所有字符各不相同」的最大长度。要求用**滑动窗口**在 O(n) 内完成（配合哈希表记录每个字符最近一次出现的位置）。
输入
一个字符串 s，仅含可打印字符（字母/数字等），长度 0 <= len(s) <= 10^5。
输出
一个整数，表示最长不含重复字符子串的长度。
示例 1
输入："abcabcbb"
输出：3
最长不含重复字符的子串是 "abc"（或 "bca"/"cab"），长度为 3。
示例 2
输入：s="pwwkew"
输出：3
最长子串是 "wke"，长度为 3；"pwke" 含 "p"、"w"、"k"、"e" 也长度为 4？不，"pwke" 子串需连续，从下标2起是 "wke" 长度为 3。
约束
0 <= len(s) <= 10^5。时间复杂度 O(n)，空间 O(字符集大小)（通常视为 O(1)）。
🧑‍💻 在线代码编辑器
def solve(s): # s: str，返回不含重复字符的最长子串长度 last = {} # 字符 -> 最近一次出现下标 left = 0 ans = 0 for right, ch in enumerate(s): # TODO: # 1. 若 ch 已出现在窗口内（last[ch] >= left），把 left 上移到 last[ch]+1 # 2. 更新 last[ch] = right # 3. ans = max(ans, 窗口长度 right-left+1) pass return ans
--- 以下为答案与解析 ---

💡 解题思路

用**滑动窗口** [left, right] 维护当前不含重复字符的子串：右指针 right 逐个扩展，遇到已在窗口内出现过的字符 ch 时，把左边界 left 上移到 last[ch]+1（即跳过上次出现的位置），保证窗口内永无重复。哈希表 last 记录每个字符最近一次出现下标，用于 O(1) 判断与跳转。窗口长度 right-left+1 不断更新答案。

📝 参考代码（python）

def solve(s):
    # 最长不含重复字符的子串长度（滑动窗口 + 哈希表记录最近位置）
    last = {}   # 字符 -> 最近一次出现的下标
    left = 0    # 窗口左边界
    ans = 0
    for right, ch in enumerate(s):
        # 若 ch 已在当前窗口内（last[ch] >= left），左边界跳到上次出现之后
        if ch in last and last[ch] >= left:
            left = last[ch] + 1
        last[ch] = right               # 更新/记录该字符最近位置
        ans = max(ans, right - left + 1)  # 窗口长度
    return ans

⚡ 复杂度分析

时间 O(n)（左右指针各至多移动 n 次） 空间 O(1)（哈希表最多存字符集大小个键）

🎯 考点

滑动窗口 + 哈希记录最近位置；left 上移要用 max(_, last[ch]+1) 保证不回退（窗口只增不减）；窗口内无重复的维护
算法概念 ⭐⭐ 第 2 题

最小生成树算法辨析（Kruskal vs Prim）

关于求无向连通带权图最小生成树（MST）的两种经典算法 Kruskal 与 Prim，**以下哪个说法正确**？
--- 以下为答案与解析 ---
✅ 正确答案：A

💡 解题思路

判断两个关键点：①Kruskal 判环用**并查集（Union-Find）**而非 DFS；②两种算法的**适用场景**（稀疏 vs 稠密）与复杂度。

🎯 考点

Kruskal=边排序+并查集、适合稀疏图；Prim=点扩展、适合稠密图；两者均基于贪心且有 MST 最优性保证；负权不影响 MST 正确性（只影响最短路）。

🔍 逐项分析

  • A 正确：Kruskal 将 E 条边升序排序（O(E log E)），从小到大逐条尝试，用并查集合并两端顶点、发现两端已在同一连通分量则跳过（O(α(V)) 近似 O(1) 均摊）。E 较小时整体高效，适合稀疏图。
  • B 错误：Prim 从顶点出发「点扩展」式生长，稠密图用邻接矩阵实现达到 O(V²)；稀疏图应优先选 Kruskal。选项把两者的适用场景说反了。
  • C 错误：Kruskal 判环用**并查集**而非 DFS；若每步都用 DFS 判环，总复杂度退化到 O(E·(V+E))。且 Kruskal 适合稀疏而非稠密图。
  • D 错误：MST 完全允许负权边，负权不影响「切割性质/环性质」保证的贪心正确性，Kruskal 与 Prim 对负权图仍能得到最小生成树。负权只会破坏**最短路**的某些假设（如 Dijkstra），与 MST 无关。
AI公式推导 ⭐⭐ 第 3 题

LSTM 门控单元的前向计算与梯度消失缓解推导

请推导 LSTM（长短期记忆）的前向计算：给出**遗忘门、输入门、输出门、候选记忆**以及**细胞状态 c_t、隐状态 h_t** 的完整更新式；并在此基础上，从反向传播角度说明**为什么门控机制能缓解普通 RNN 的梯度消失**（与 RNN 的隐状态连乘对比）。要求符号定义清楚、推导到公式级。
--- 以下为答案与解析 ---

🎯 考点

三个门(遗忘/输入/输出)+候选门的公式；c_t=f_t⊙c_{t-1}+i_t⊙c̃_t 的加法长程通道；∂c_t/∂c_{t-1}=f_t 使梯度可直通；对比普通 RNN 的 diag(tanh')W 连乘谱收缩。

📐 推导过程

记输入 $x_t$、上一时刻隐状态 $h_{t-1}$、上一细胞状态 $c_{t-1}$，权重与偏置对每个门分别写为 $W_{\cdot}, b_{\cdot}$，$\odot$ 表示逐元素乘（Hadamard）。

**第 1 步：三个门与候选记忆**（激活：$\sigma$ 为 sigmoid，输出 0~1 起「开关」作用；$\tanh$ 为双曲正切）
$$
\begin{aligned}
f_t &= \sigma\big(W_f [h_{t-1}, x_t] + b_f\big) \\
i_t &= \sigma\big(W_i [h_{t-1}, x_t] + b_i\big) \\
o_t &= \sigma\big(W_o [h_{t-1}, x_t] + b_o\big) \\
\tilde{c}_t &= \tanh\big(W_c [h_{t-1}, x_t] + b_c\big)
\end{aligned}
$$
$[h_{t-1}, x_t]$ 为拼接向量。$f_t$=遗忘门（保留多少旧记忆）、$i_t$=输入门（写入多少新候选）、$o_t$=输出门（放出多少记忆到隐状态）、$\tilde{c}_t$=候选记忆。

**第 2 步：细胞状态更新（加法式长程通道）**
$$
c_t = f_t \odot c_{t-1} + i_t \odot \tilde{c}_t
$$
细胞状态通过「遗忘门 × 旧记忆 + 输入门 × 新候选」**逐元素更新**，形成一条跨越时间步的**近似恒等/残差通道**。

**第 3 步：隐状态输出**
$$
h_t = o_t \odot \tanh(c_t)
$$

**第 4 步：反向传播与梯度消失分析（与普通 RNN 对比）**
普通 RNN：$h_t=\tanh(W h_{t-1}+U x_t+b)$，误差沿时间步回传时
$$
\frac{\partial h_t}{\partial h_{t-1}} = \mathrm{diag}\big(\tanh'\big)\,W
$$
梯度是 $\prod_{k}\,\mathrm{diag}(\tanh') W$ 的**矩阵连乘**；$\tanh'$ 在饱和时接近 0，$W$ 的谱范数若 <1 则乘积范数指数级收缩——这就是梯度消失（>1 则爆炸）。

对 LSTM，关键看 $c_t$ 对 $c_{t-1}$ 的偏导：
$$
\frac{\partial c_t}{\partial c_{t-1}} = f_t + \frac{\partial\big(i_t \odot \tilde{c}_t\big)}{\partial c_{t-1}}
$$
其中第一项 $f_t$ 是**逐元素的门控系数**，落在 $[0,1]$。当遗忘门 $f_t \approx 1$（需要长期记忆）时，该项接近单位阵，误差沿细胞状态通道几乎**不被压缩**地反向传递；相比普通 RNN 的矩阵连乘，这里退化为「标量门 × 单位阵」的累加式通道，消除了谱范数连乘的指数级收缩/爆炸。

**第 5 步：直觉**
门控把「在时间上传递信息」从「矩阵乘法连乘」改为「选加式（门控相加）」——遗忘门决定旧的细胞记忆以多大比例保留，输入门决定新候选以多大比例写入，从而网络可以自主学会「需要长期保留的就让遗忘门≈1」，梯度沿这条干净通道长距离传播，缓解梯度消失（配合梯度裁剪与门控初始化可缓解梯度爆炸）。

🧠 直觉解释

LSTM 用「门控 + 加法更新细胞状态」把时间维度上的信息传递从连乘变成选择式累加——遗忘门≈1 时，细胞状态是一条误差可直通长距离的残差通道，从机制上缓解了普通 RNN 因隐状态矩阵连乘导致的梯度消失。
AI面试问答 ⭐⭐ 第 4 题

多查询注意力 MQA/GQA 为什么能省 KV 显存并加速解码？

自回归（解码）阶段，Transformer 为每个 token 计算注意力都要读取/更新过去所有 token 的键值对，KV 缓存是显存与带宽的瓶颈。请解释：**多查询注意力（Multi-Query Attention, MQA）**与**分组查询注意力（Grouped-Query Attention, GQA）**相比标准**多头注意力（MHA）**做了什么改动，为什么能显著减少 KV 显存、提升生成吞吐，代价又是什么？
--- 以下为答案与解析 ---

📌 回答要点

  • 解码瓶颈定位：自回归每步要读取全部历史 token 的 K、V。MHA 中 K、V 的「头数 = Q 的头数」，KV 缓存 ≈ 层数 × 序列长 × 头数 × 每头维度 × 2（K+V）× 字节，在长上下文与多层下可达数百 MB～数 GB；且 decode 阶段是**访存密集（memory-bound）**，KV 缓存带宽直接决定生成吞吐。
  • MQA 的改动：让**所有 Q 头共享同一份 K 与 V**（即 K、V 只保留 1 组，而 Q 保持多头）。KV 缓存因此从头数份降为 1 份，直接缩减约 H 倍（如 32 头 → 约 1/32），decode 每次只读/写一组 K、V，访存带宽与显存显著下降，生成吞吐随之提升。
  • GQA（LLaMA-2-70B、LLaMA-3 采用）是折中：把 Q 头分成 G 组，每组共享一份 K/V（K、V 头数 = G，而非 MHA 的 H 或 MQA 的 1）。G 取 1 即退化为 MQA，G=H 即 MHA；GQA 以较小的表达力损失换取与 MQA 接近的显存/带宽收益，质量上优于纯 MQA。
  • 代价与取舍：共享 K/V 削弱了各头独立建模注意力的表达能力（理论上损失多头的多样性），故常用 GQA 而非极端 MQA；且 KV 共享只发生在**推理的 KV 缓存与每步读取**层面，训练复杂度基本不变，适合大模型大规模部署（降低每卡可承载并发/上下文长度）。
  • 工程配合：GQA/MQA 可叠加 KV 量化（INT8/INT4）、PagedAttention 分页管理与位置编码长度外推，进一步省显存；在超长上下文场景收益最明显，是当前主流大模型（LLaMA-2/3、Mistral、DeepSeek 等）的标准设计。

⭐ 加分项

  • KV 显存展开式（fp16、L 层、h 头、d_k 每维、序列 T）：约 2×L×T×h×d_k×2 bytes；MHA→MQA 将该式中的 h 置 1，直接给出数量级缩减证明。
  • GQA 出处：Ainslie et al. (2023)；LLaMA-2-70B、LLaMA-3、Mistral 均实证验证 GQA 在大模型上的质量/效率平衡点。
  • 权重转换：MHA 权重可由 GQA 共享组内取平均（或直接复制）初始化，无需从零训练；也可在训练时直接采用 GQA 配置。
  • 对比维度：MQA 省显存最多但质量略降；GQA 在中间档；若再加 KV 量化（如 4-bit NF4）能再省约 4 倍。多管齐下是当前长上下文大模型的标准做法。

🔮 追问预测

  • 追问：为什么 decode 阶段是 memory-bound 而不是 compute-bound？回答思路：每步只新增一个 token 的 Q，但要对全部历史 K 计算注意力，运算量随序列增长，而计算能力 GPU 富余；瓶颈在重复读取/写入 KV 缓存（访存带宽），故减少 KV 数据规模直接提速——这正是 MQA/GQA 的动机。
  • 追问：MQA 共享 KV 为什么只损失一点点？回答思路：K、V 携带的是「键位置的信息/被查询的内容」，多个头关注的点不同但被查询的『键空间』在语义上可共享；共享只是让一组 KV 服务多个 Q，损失的是各头独立建模键的细微差异，换取显存/带宽的倍数收益，故效果足够好。
  • 追问：GQA 的 G 取多少合适？回答思路：G 是「省显存 vs 保质量」的滑杆——G 越大越接近 MHA 质量但省得少，越小越接近 MQA；主流取 8（LLaMA-2-70B）或随参数增大，需按目标显存与质量评测实验确定。
