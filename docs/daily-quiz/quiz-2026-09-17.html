算法编程 ⭐⭐ 第 1 题

最长严格递增子序列（LIS）

给你一个整数数组 nums，请返回其中**最长严格递增子序列**的长度。

子序列是由原数组删除（或不删除）一些元素后得到的新序列，**不要求连续**；严格递增指子序列中任意相邻两个元素都满足 $a_i < a_{i+1}$。

本题为 LeetCode 300 改编，是动态规划（知识点池 Topic 13）的首次轮换练习。
输入
一个整数数组 nums
输出
一个整数，表示最长严格递增子序列的长度
示例 1
输入：nums = [10,9,2,5,3,7,101,18]
输出：4
最长递增子序列是 [2,3,7,101]（或 [2,3,7,18]），长度为 4。注意子序列不要求连续。
示例 2
输入：nums = [0,1,0,3,2,3]
输出：4
最长递增子序列是 [0,1,2,3]，长度为 4。
约束
0 <= nums.length <= 10^4；-10^9 <= nums[i] <= 10^9

from typing import List def solve(nums: List[int]) -> int: # 返回最长严格递增子序列的长度 pass
--- 以下为答案与解析 ---

💡 解题思路

**思路一（动态规划，O(n²)）**：设 dp[i] 表示以 nums[i] 结尾的最长严格递增子序列长度。对每个 i，遍历 j < i，若 nums[j] < nums[i] 则 dp[i] = max(dp[i], dp[j] + 1)。答案为 max(dp)。

**思路二（贪心 + 二分，O(n log n)，推荐）**：维护一个递增数组 tails，其中 tails[k] 表示长度为 k+1 的递增子序列的**最小末尾元素**。遍历每个元素 x：
- 在 tails 中二分查找第一个 >= x 的位置 i（bisect_left）；
- 若 i == len(tails)，说明 x 能接出更长的子序列，直接追加；
- 否则用 x 替换 tails[i]（保持同长度下末尾更小，为后续留下更大空间）。

注意：tails 数组**只是长度正确，不一定是一条真实子序列**，但这不影响长度答案的正确性。

📝 参考代码（python）

from typing import List
import bisect

def solve(nums: List[int]) -> int:
    tails = []
    for x in nums:
        i = bisect.bisect_left(tails, x)
        if i == len(tails):
            tails.append(x)
        else:
            tails[i] = x
    return len(tails)

⚡ 复杂度分析

时间 O(n log n)（贪心+二分）/ O(n²)（DP） 空间 O(n)

🎯 考点

动态规划最优子结构；贪心+二分的 tails 数组思想（耐心排序）；严格递增用 bisect_left 而非 bisect_right；边界（空数组返回 0、全相同返回 1）
算法概念 ⭐ 第 2 题

分治算法性质判断

关于**分治算法**（Divide and Conquer）的说法，下列哪一项是正确的？

（知识点池 Topic 14 分治算法，首次轮换）
--- 以下为答案与解析 ---
✅ 正确答案：B

💡 解题思路

分治三步：① 分解（Divide）把原问题拆成规模更小、**结构相同**的子问题；② 递归求解（Conquer）；③ 合并（Combine）把子问题的解拼成原问题的解。正确性依赖子问题**相互独立**（不重叠、无相互依赖），这正是它与动态规划的关键区别：DP 处理**重叠子问题**（子问题会被复用），分治处理**独立子问题**。

🎯 考点

分治三步骤；分治 vs 动态规划（独立 vs 重叠子问题）；主定理适用条件（T(n)=aT(n/b)+f(n)，a≥1, b>1）；分治不必然更快

🔍 逐项分析

  • A 错误：子问题相互依赖、答案可复用是**动态规划**（重叠子问题 + 最优子结构）的特征；分治要求子问题相互独立，否则合并时会重复计算甚至无法正确合并。
  • B 正确：分治三步曲为分解（Divide）→ 递归求解（Conquer）→ 合并（Combine），且要求子问题互不重叠，归并排序、快速排序、最接近点对均符合。
  • C 错误：分治并不必然更快，复杂度由递推式决定。反例：用朴素递归分治计算斐波那契数是 O(2^n)，远慢于迭代 O(n)；且分治合并步骤（如归并的合并）本身也有额外开销。
  • D 错误：主定理只适用于形如 T(n) = aT(n/b) + f(n)（a≥1, b>1）的标准递推，并非所有分治都适用；且条件不要求 a ≥ b（归并排序 a=2, b=2 即 a=b）。递推不满足标准形式时需要换用展开、递归树等方法。
AI公式推导 ⭐⭐ 第 3 题

Softmax 交叉熵损失的梯度推导

多分类任务中，网络最后一层输出 logits $z = (z_1, \dots, z_K)$，经 softmax 得到概率分布

$$p_j = \frac{e^{z_j}}{\sum_{k=1}^{K} e^{z_k}}$$

以 one-hot 标签 $y$（样本属于类别 $c$，$y_c = 1$）计算交叉熵损失

$$L = -\sum_{k=1}^{K} y_k \log p_k$$

**请推导 $\partial L / \partial z_j$ 的解析表达式**（对每个 logits 的梯度），并说明 j = c 与 j ≠ c 两种情况下的取值，最后给出数值稳定计算方案。（神经网络基础 Topic AI-9 反向传播的经典应用，不重复四公式本身）
--- 以下为答案与解析 ---

🎯 考点

softmax 的 softmax 分两类导数（δij 形式）；链式法则与求和展开；结论 p_j − y_j 的反向传播式简洁形式；减去 max 的数值稳定技巧；softmax+CE 融合算子

📐 推导过程

**符号定义**：$S = \sum_{k=1}^{K} e^{z_k}$ 为归一化常数，$p_j = e^{z_j} / S$；标签向量 $y$ 满足 $\sum_k y_k = 1$（one-hot 是其特例）。

---

**Step 1：softmax 对 logits 的偏导数**

当 $i = j$（对自身求导）时，用商法则：

$$\frac{\partial p_j}{\partial z_j} = \frac{e^{z_j} S - e^{z_j} e^{z_j}}{S^2} = \frac{e^{z_j}}{S}\left(1 - \frac{e^{z_j}}{S}\right) = p_j (1 - p_j)$$

当 $i \neq j$（$z_i$ 只出现在分母 $S$ 中）时：

$$\frac{\partial p_j}{\partial z_i} = \frac{0 - e^{z_j} e^{z_i}}{S^2} = - \frac{e^{z_j}}{S} \cdot \frac{e^{z_i}}{S} = - p_j p_i$$

用 Kronecker delta 合并两种情形：

$$\frac{\partial p_j}{\partial z_i} = p_j (\delta_{ij} - p_i), \quad \delta_{ij} = \begin{cases}1 & i=j\\ 0 & i\neq j\end{cases}$$

---

**Step 2：链式法则计算 $\partial L / \partial z_j$**

$$L = -\sum_{k=1}^{K} y_k \log p_k \quad\Rightarrow\quad \frac{\partial L}{\partial z_j} = -\sum_{k=1}^{K} y_k \cdot \frac{1}{p_k} \cdot \frac{\partial p_k}{\partial z_j}$$

代入 Step 1 的结果（注意此刻求导变量是 $z_j$，求和变量是 $k$）：

$$\frac{\partial L}{\partial z_j} = -\sum_{k=1}^{K} y_k \cdot \frac{1}{p_k} \cdot p_k (\delta_{kj} - p_j) = -\sum_{k=1}^{K} y_k (\delta_{kj} - p_j)$$

逐项展开：第一项 $\sum_k y_k \delta_{kj} = y_j$；第二项 $\sum_k y_k p_j = p_j \sum_k y_k = p_j$（因为 $y$ 是概率分布，和为 1）。于是：

$$\frac{\partial L}{\partial z_j} = -(y_j - p_j) = p_j - y_j$$

---

**Step 3：one-hot 特写与结论**

$$\boxed{\frac{\partial L}{\partial z_j} = p_j - y_j}$$

若 $y_c = 1$：

- $j = c$（真实类别）：$\partial L / \partial z_c = p_c - 1 \leq 0$，梯度为负，梯度下降会把 $z_c$ **增大**；
- $j \neq c$：$\partial L / \partial z_j = p_j \geq 0$，梯度为正，会把其它类别的 logits **压低**。

整个更新规则就是“把正确类别的得分往上抬、错误类别往下压”，幅度由概率差决定。

---

**Step 4：数值稳定性**

直接算 $e^{z_j}$ 在 $z$ 很大时会溢出。标准做法是减去最大值 $m = \max_k z_k$：

$$p_j = \frac{e^{z_j - m}}{\sum_{k=1}^{K} e^{z_k - m}}$$

分子分母同乘 $e^{-m}$ 概率不变，且 $e^{z_j - m} \leq 1$ 不再溢出。工程上更常用的是把 softmax 与交叉熵**融合**（如 tf.nn.softmax_cross_entropy_with_logits / PyTorch 的 CrossEntropyLoss(logits)），直接对 logits 回传 $p_j - y_j$，跳过中间量 $\log p_k$ 的精度损失。

🧠 直觉解释

梯度等于「预测概率 − one-hot 标签」：正确类概率偏低（p_c < 1）时被抬高，错误类概率偏高时被压低，logits 被整体推向正确类别的方向。
AI面试问答 ⭐⭐ 第 4 题

RLHF 对齐三阶段：PPO 与 DPO 对比

面试官问：**“请介绍基于人类反馈的强化学习（RLHF）的整体流程，以及 DPO 相比 PPO 做了哪些关键简化？为什么 DPO 不需要显式的奖励模型？”**

（知识点池 AI Topic 17 训练全链路 RLHF/PPO/DPO，首次轮换；衔接 09-15 算法推送中学习的 RLVR/GRPO 主题）
--- 以下为答案与解析 ---

📌 回答要点

  • **三阶段流程**：① SFT：在指令数据上监督微调得到基础模型；② 奖励建模（RM）：收集人类对模型回答的偏好排序，训练奖励模型 $r_\phi(x,y)$ 拟合人类偏好；③ 策略优化：用 PPO 让生成模型在最大化奖励的同时，用 KL 惩罚约束其不要偏离 SFT 参考模型太远。
  • **PPO 的核心机制**：属于 on-policy 强化学习，策略与环境（奖励模型）交互采样；用重要性采样比率 $\rho = \pi_\theta/\pi_{\theta_{\rm old}}$ 配合 clip 截断限制每步更新幅度；奖励中叠加 KL 惩罚项 $-\beta\log(\pi_\theta/\pi_{\rm ref})$；配合 GAE 估计优势、减小方差。
  • **DPO 的关键简化**：把“奖励建模 + 策略优化”两个训练阶段合并成一个分类目标。RLHF 的最优策略存在闭式解 $\pi^*(y|x) \propto \pi_{\rm ref}(y|x)e^{r(x,y)/\beta}$，反解出隐式奖励 $r(x,y) = \beta\log\frac{\pi_\theta(y|x)}{\pi_{\rm ref}(y|x)} + C$，把它代入 Bradley-Terry 偏好模型，得到只依赖策略网络的二元交叉熵损失——**无需单独训练 RM，也无需在线采样**。
  • **为什么 DPO 不需要 RM**：偏好数据的对数胜率（log-odds）本身就能编码奖励信息；DPO 把奖励建模隐含在策略网络的比值中，用固定偏好数据集做监督式训练（offline），省去了 RM 训练与策略采样两套系统。
  • **两者权衡**：PPO 通用性更强、上限更高（可接任意奖励，含可验证奖励），但工程复杂（通常要 4 个模型、在线采样、调参敏感）；DPO 简单稳定、显存和训练成本低，但对偏好数据质量和超参数 β 更敏感，且无在线探索。
  • **与 RLVR/GRPO 的联系（衔接今日学习）**：可验证奖励（如代码运行结果）替代 RM 可规避 reward hacking；GRPO 在 PPO 基础上进一步去掉 value 网络，用组内相对优势做归一化，显著降低显存——三者同属一条“对齐奖励”的演化线。

⭐ 加分项

  • 能写闭式解推导：RLHF 目标 $\max E_{x,y}[r(x,y)] - \beta \cdot D_{\rm KL}(\pi_\theta \| \pi_{\rm ref})$ 在无约束下用拉格朗日乘子可得最优解 $\pi^*(y|x) = \frac{1}{Z(x)}\pi_{\rm ref}(y|x)e^{r(x,y)/\beta}$，这是 DPO 合法性的理论根基。
  • 能点出 DPO 的隐含假设：偏好数据服从 Bradley-Terry 模型、奖励函数本身可被策略的比值表示（忽略 reward 与参考策略的耦合），以及 DPO 对偏好数据质量的敏感性（数据毒化时比 PPO 更容易过拟合）。
  • 能聊工程实践：RLHF 中 reward hacking 的检测（奖励分布监控）、KL 系数的动态调节（如 SliC 自适应）、以及 InstructGPT 中 RM 用单头输出而策略初始化来自 SFT 等细节。

🔮 追问预测

  • 追问一：为什么 DPO 可以不做在线采样？回答思路：DPO 的损失只依赖数据集里的（x, 偏好对），优化目标与当前策略的分布无关地写成监督式最大似然；PPO 需要在线 rollout 是因为它要估计旧策略分布下的优势。
  • 追问二：PPO 中 KL 惩罚项的作用是什么？回答思路：防止策略在奖励优化中偏离参考模型导致输出退化/模式崩溃，等价于给更新一个信任域约束；KL 系数过大会抑制学习，过小会偏离。
  • 追问三：什么是 reward hacking？为什么可验证奖励能缓解？回答思路：模型找到奖励函数的漏洞钻空子刷高分（如编造格式正确的错误答案）；可验证奖励（编译器/判定器/数学验证器）的反馈不可被虚假格式欺骗，且可自动生成与扩展。
