算法编程 ⭐⭐ 第 1 题

实现 strStr()：KMP 字符串匹配

给定两个字符串 haystack 与 needle，返回 needle 在 haystack 中第一次出现的起始下标；若不存在则返回 -1。若 needle 为空串，按约定返回 0。

要求使用 KMP 算法，时间复杂度必须是 $O(n+m)$，不得调用语言内置的 find / indexOf。
输入
两个参数：`haystack`（主串）与 `needle`（模式串），均为小写英文字母组成的字符串。
输出
返回一个整数：首次匹配的起始下标，未匹配返回 `-1`；`needle` 为空返回 `0`。
示例 1
输入：haystack = "sadbutsad", needle = "sad"
输出：0
下标 0 处出现 "sad"，因此返回 0。
示例 2
输入：haystack = "leetcode", needle = "leeto"
输出：-1
"leeto" 不是 "leetcode" 的子串，返回 -1。
示例 3
输入：haystack = "mississippi", needle = "issip"
输出：4
下标 4 开始为 "issip"。
约束
$0 \le |haystack|, |needle| \le 10^5$；字符串仅含小写英文字母。

💡 解题思路

KMP 的核心是预处理模式串的 lps（longest proper prefix which is also suffix）数组：lps[i] 表示 needle[0..i] 的最长相等真前后缀长度。匹配时主串指针 i 永不回退，失配时只把模式串指针 j 沿 j = lps[j-1] 回跳，跳过已经确认相等的部分。构造 lps 本身就是模式串自己匹配自己，同样用该回跳规则，因此总时间 $O(n+m)$。

📝 参考代码（python）

def build_lps(p):
    """构造 next / lps 数组：lps[i] = p[0..i] 的最长相等真前后缀长度"""
    lps = [0] * len(p)
    j = 0
    for i in range(1, len(p)):
        while j and p[i] != p[j]:
            j = lps[j - 1]
        if p[i] == p[j]:
            j += 1
        lps[i] = j
    return lps


def solve(haystack: str, needle: str) -> int:
    if needle == "":
        return 0
    lps = build_lps(needle)
    j = 0
    for i, ch in enumerate(haystack):
        while j and ch != needle[j]:
            j = lps[j - 1]
        if ch == needle[j]:
            j += 1
        if j == len(needle):
            return i - j + 1
    return -1

⚡ 复杂度分析

时间 O(n + m)：构造 lps 为 O(m)，匹配扫描为 O(n)，j 的回跳次数被此前的前进次数摊还 空间 O(m)：lps 数组；若不计返回值则除 lps 外为 O(1)

🎯 考点

① 理解 lps 的「最长相等真前后缀」语义；② 失配回跳 j = lps[j-1] 而不是从头再来；③ 空模式串约定返回 0；④ 与朴素 BF 的 O(nm) 对比，说明主串指针不回退是线性的根源。

💡 解题思路

逐项核对状态定义、转移方程与复杂度。状压 DP 把「集合」压进整数的二进制位，第一维必然是 $2^n$ 而不是 $n^2$；固定起点只是消除环的旋转对称、方便输出路径，不固定同样能求最优；$2^{20}\times 20 \approx 2.1\times 10^7$ 个状态、每个状态 O(n) 转移约 $4\times 10^8$ 次简单加法比较，在编译型语言中配合滚动/稀疏枚举完全可在数秒内完成，并非只能贪心。

🎯 考点

状压 DP 三要素：① 状态用二进制位表示集合；② 转移只向「未选元素」扩展（j not in mask）；③ 复杂度 $O(2^n \cdot n^2)$，适合 $n \le 20$。常见变体还有「子集枚举」$O(3^n)$（如分成若干合法子集）。

🔍 逐项分析

  • A 正确：mask 的每一位表示对应城市是否已访问，转移「从 i 走到未访问的 j」并把 j 并入集合，共 $2^n \cdot n$ 个状态、每个状态枚举 $n$ 个后继，时间 $O(n^2 2^n)$，空间 $O(n 2^n)$（可压掉一维或按 mask 递增顺序原地更新）。
  • B 错误：状压的第一维是集合编码，大小是 $2^n$ 而非 $n^2$；且状压 DP 与图是否稠密无关，稠密图只是转移常数更大。
  • C 错误：固定起点 0 是为了去重（一个环有 n 种旋转写法），但不固定起点同样可以求最优——只要最终在所有「回到起点」的闭合状态里取最小即可；固定起点不是正确性的必要条件。
  • D 错误：$n=20$ 时约 $2.1\times10^7$ 个状态，$O(n)$ 转移约 $4\times10^8$ 次运算，C++ 中通常 1~3 秒可完成，内存约 $20\times2^{20}\times4$ B ≈ 80 MB；用「只枚举 mask 中的 1 作为当前点」等技巧还能大幅减少实际状态数，绝非只能贪心。
AI公式推导 ⭐⭐⭐ 第 3 题

FlashAttention 的 online softmax 递推与 IO 复杂度

标准注意力需要显式构造 $N\times N$ 的分数矩阵 $S=QK^\top$ 与概率矩阵 $P=\mathrm{softmax}(S)$，在长序列下 HBM 读写成为瓶颈。FlashAttention 通过分块 + online softmax 在不物化 $N\times N$ 矩阵的前提下得到精确结果。请完成两件事：

1. 推导分块 online softmax 的递推公式（运行最大值 $m$、分母 $l$、累加器 $\mathrm{acc}$ 的更新），并证明其结果与一次性 softmax 完全一致；
2. 设 SRAM 容量为 $M$、每个 head 的维度为 $d$，推导 FlashAttention 的 HBM 访问量为何是 $O(N^2d^2/M)$，并与标准实现的 $O(N^2)$（忽略 $d$ 常数时）比较。
--- 以下为答案与解析 ---

🎯 考点

① online softmax 的核心恒等式 $e^{a-b}=e^{a-m}e^{m-b}$；② 证明的关键是「累加器始终等于真实和乘 $e^{-m}$」，因此 $\mathrm{acc}/l$ 与 $m$ 无关；③ IO 复杂度按「每个 Q 块搬运 2Nd 元素 × N/B_r 个块」估算，$B_r\approx M/d$；④ FlashAttention 是精确算法，省访存与激活显存，FLOPs 不变；⑤ 反向用重算（recomputation）换显存。

📐 推导过程

一、标准注意力与瓶颈

对一行 query $q\in\mathbb{R}^d$，记 $s_j = q^\top k_j$，则
$$o=\sum_{j=1}^{N} p_j v_j,\qquad p_j=\frac{e^{s_j-m}}{\sum_{t=1}^{N}e^{s_t-m}},\quad m=\max_t s_t .$$
减去 $m$ 只是数值稳定技巧，不改变结果。标准实现把 $S,P\in\mathbb{R}^{N\times N}$ 写入 HBM 再读回，HBM 流量为 $\Theta(N^2)$（每元素至少一写一读），当 $N\gg d$ 时远大于计算量。

二、online softmax 的三个不变量

处理到第 $t$ 个分块时，维护
$$m^{(t)}=\max_{j\le tN_c} s_j,\qquad l^{(t)}=\sum_{j\le tN_c} e^{s_j-m^{(t)}},\qquad \mathrm{acc}^{(t)}=\sum_{j\le tN_c} e^{s_j-m^{(t)}} v_j .$$
关键在于：$\mathrm{acc}^{(t)}/l^{(t)}$ 不依赖当前最大值 $m^{(t)}$ 的具体取值——分子分母同乘 $e^{m^{(t)}}$ 即还原为未归一化的 $\sum e^{s_j}v_j$ 与 $\sum e^{s_j}$，比值恒等于真实输出。

三、分块递推

设新分块的最大值为 $\tilde m=\max_{j\in\text{block}} s_j$，令 $m'=\max(m,\tilde m)$。旧累加器需要按新最大值重新缩放：
$$\mathrm{acc}' = e^{m-m'}\,\mathrm{acc} + \sum_{j\in\text{block}} e^{s_j-m'}\,v_j,$$
$$l' = e^{m-m'}l + \sum_{j\in\text{block}} e^{s_j-m'},$$
$$m \leftarrow m'.$$

正确性证明：设旧部分真实未归一化和为 $A=\sum_{j\le tN_c}e^{s_j}v_j$，$L=\sum_{j\le tN_c}e^{s_j}$，则 $\mathrm{acc}=e^{-m}A$、$l=e^{-m}L$。更新后
$$\mathrm{acc}'=e^{m-m'}e^{-m}A+\sum_{\text{block}}e^{s_j-m'}v_j=e^{-m'}\Big(A+\sum_{\text{block}}e^{s_j}v_j\Big)=e^{-m'}A',$$
同理 $l'=e^{-m'}L'$。因此每个分块处理后始终满足「累加器 = 真实和 × $e^{-m}$」，归纳可得最终 $o=\mathrm{acc}/l=\big(e^{-m}A\big)/\big(e^{-m}L\big)=A/L$，与一次性 softmax 逐元素相同。整个过程只用了恒等式 $e^{a-b}=e^{a-m}e^{m-b}$，没有近似。

四、IO 复杂度推导

将 $Q$ 按行分成大小 $B_r$ 的块、$K,V$ 按行分成大小 $B_c$ 的块（$B_r,B_c$ 取 $\Theta(M/d)$，使一块 $B\times d$ 的矩阵能放进 SRAM）。对每个 $Q$ 块：
- 该块常驻 SRAM，遍历全部 $N/B_c$ 个 $K,V$ 块，每个块读入 $B_c d$ 个元素；
- 每处理一个 $K$ 块，同时更新该 $Q$ 块所有行的 $m,l,\mathrm{acc}$，$Q$ 块本身不重复写回 HBM。

于是每个 $Q$ 块搬运 $\frac{N}{B_c}\cdot 2B_c d = 2Nd$ 个元素（K 与 V 各一份），共有 $N/B_r$ 个 $Q$ 块：
$$\text{HBM traffic}=O\!\left(\frac{N}{B_r}\cdot Nd\right)=O\!\left(\frac{N^2 d}{B_r}\right).$$
取 $B_r=\Theta(M/d)$ 得
$$\text{HBM traffic}=O\!\left(\frac{N^2d^2}{M}\right).$$
而 FLOPs 仍为 $O(N^2d)$，与标准注意力相同——FlashAttention 省的是访存不是计算。当 $d^2/M \ll 1$（如 $d=64$、SRAM 数十 KB 量级折算到片上）时，IO 比标准实现低一个量级以上；反向传播时用保存的 $m,l$ 重算 $S,P$，把激活显存从 $O(N^2)$ 降到 $O(N)$。

🧠 直觉解释

把 softmax 的「先求全局最大值再统一指数化」改成「边扫描边把旧结果按新最大值重新缩放」，就能一块一块地算完而不用保存整个 $N\times N$ 矩阵；分块让 $QK^\top$ 在片上 SRAM 内完成，HBM 只搬运 $O(Nd)$ 量级的 $Q,K,V$ 块，于是 IO 从 $N^2$ 级降到 $N^2d^2/M$ 级。
AI面试问答 ⭐⭐ 第 4 题

PagedAttention 如何把 KV Cache 的显存浪费降到 4% 以下？

面试官问：vLLM 的 PagedAttention 解决了什么问题？它为什么能显著提升大模型推理吞吐？请说明其核心机制、与操作系统虚拟内存的类比，以及工程上的取舍。
--- 以下为答案与解析 ---

📌 回答要点

  • 问题定位：自回归解码时每个请求都要缓存历史 token 的 K/V（KV Cache）。传统实现按「最大序列长度」为每个请求预分配一整块连续显存，实际生成长度远小于上限，造成大量内部碎片；请求间的分配释放又产生外部碎片。实测浪费可达 60%~80%（vLLM 论文数据），直接限制了可并发的 batch 大小，而 decode 阶段是 memory-bound，batch 越大吞吐越高。
  • 核心机制：把 KV Cache 切成长度固定的小块（block，默认 16 个 token），逻辑上连续的 KV 由块表（block table）映射到物理上不必连续的块，按需分配、用完回收。这与操作系统「虚拟地址 → 页表 → 物理页」的虚拟内存/分页机制完全同构，因此得名 PagedAttention。注意力计算时按块表逐块 gather K/V，再做正常的 $QK^\top$ 与加权求和。
  • 利用率为何能到 96% 以上：只有最后一个块可能因序列未填满而浪费，平均浪费不超过「块大小的一半 / 平均序列长度」，块小则浪费更小；块表让不同请求的物理块可以任意拼接，外部碎片几乎消失。省下的显存直接转化为更大的 batch，从而提升吞吐。
  • 共享与写时复制：并行采样（一个 prompt 生成多个回复）、beam search、前缀相同的请求，可以让多个逻辑序列的块表指向同一批物理块，引用计数为 1 时直接复用；某序列要写入新 token 且该块被共享时，才复制出私有块（copy-on-write）。这让共享前缀的显存开销接近 1 份而不是 N 份。
  • 调度配合：PagedAttention 与 continuous batching 天然契合——新请求可随时插入、结束的请求立即释放块；显存不足时可选择 swap（换出到 CPU）或 recompute（丢弃后重算）来抢占（preemption）；块表还便于实现 prefix caching，跨请求复用相同前缀的 KV。

⭐ 加分项

  • 它不是近似算法：分页只改变 KV 的存放位置与寻址方式，注意力数值结果与连续存放完全一致，精度无损。
  • 块大小的权衡：块太小则块表项多、寻址与 kernel 开销大；块太大则最后一个块的内部浪费变大。16 是常见折中，实际需按模型维度与 GPU 显存对齐。
  • 与 GQA/MLA、KV 量化正交：GQA/MQA 减少「头数」、MLA 压缩「表示维度」、量化减少「位宽」，PagedAttention 优化「分配与碎片」，四者可叠加使用。
  • 边界与代价：非连续块导致 attention kernel 需要 gather，访存模式不如连续块规整；块表本身也占显存（序列数 × 块数 × 项大小）；prefix caching 的命中依赖精确前缀匹配与块哈希，长尾请求收益有限。

🔮 追问预测

  • 追问：PagedAttention 和 FlashAttention 有什么区别？ 答题思路：FlashAttention 解决的是单次注意力计算的 IO 与显存（不物化 $N\times N$ 矩阵、分块 online softmax），作用于 prefill/训练；PagedAttention 解决的是多请求 KV Cache 的显存分配与共享，作用于 decode 服务调度。两者层次不同，可同时使用。
  • 追问：为什么 decode 阶段 memory-bound，增大 batch 能提吞吐？ 答题思路：每生成一个 token 要把全部权重和该请求的 KV Cache 从 HBM 读一遍，算术强度低；权重读取可由 batch 内请求共享，batch 越大每字节访存对应的计算越多，GPU 利用率越高，直到显存或带宽饱和。
  • 追问：显存不够时 vLLM 怎么处理？ 答题思路：先按调度策略抢占部分序列，选择 swap（把块换到 CPU 内存，之后换回）或 recompute（释放 KV，后续用已有 token 重新前向），两者在延迟与带宽之间权衡；也可降低 max_num_seqs、开启 KV 量化或缩短最大长度。
  • 追问：prefix caching 怎么判断能否复用？ 答题思路：对 token 前缀分块做哈希（通常结合块内 token 与父块哈希形成 Merkle 式链），哈希相同且模型/位置一致才复用，避免不同请求的随机前缀误命中。
