算法编程 ⭐⭐⭐ 第 1 题

树中距离之和（换根 DP）

给定一棵无向、连通的树：$n$ 个节点编号 $0 \sim n-1$，恰好 $n-1$ 条边，edges[i] = [a, b] 表示节点 $a$ 与 $b$ 之间有一条边，每条边长度为 1。

返回长度为 $n$ 的数组 answer，其中 answer[i] 是节点 $i$ 到其余所有节点的距离之和。

如果对每个节点各做一次 BFS，总复杂度 $O(n^2)$，在 $n$ 较大时会超时。请设计 $O(n)$ 的算法。

⚠️ 进阶要求：测试数据中包含 1200 层的深链，而 Python 默认递归深度约 1000 —— 请使用迭代（显式队列/栈）实现，避免递归爆栈。
输入
整数 n 和边列表 edges，edges[i] = [a_i, b_i]
输出
长度为 n 的整数列表 answer，answer[i] 为节点 i 到其他所有节点的距离之和
示例 1
输入：n = 6, edges = [[0,1],[0,2],[2,3],[2,4],[2,5]]
输出：[8, 12, 6, 10, 10, 10]
树形如：0 的孩子是 1、2，2 的孩子是 3、4、5。dist(0,1)+dist(0,2)+dist(0,3)+dist(0,4)+dist(0,5) = 1+1+2+2+2 = 8，其余节点类推。
示例 2
输入：n = 1, edges = []
输出：[0]
只有一个节点，没有其他节点，距离和为 0。
约束
1 ≤ n ≤ 10^4；edges[i] = [a_i, b_i] 且 0 ≤ a_i, b_i < n；保证输入是一棵连通无环的树（n-1 条边）。测试含 n=2000 随机树与 1200 层深链，n=10^4 须在约 1 秒内完成。

--- 以下为答案与解析 ---

💡 解题思路

换根 DP（两次线性扫描）——前两期的打家劫舍 III、二叉树最大路径和都是「固定根、一次后序 DP」；本题答案随根变化，需要换根递推。

1. BFS 建树：以节点 0 为根，迭代 BFS 记录 parent[] 与 BFS 序 order[]（先访问父再访问子，天然按层排列，同时规避深链递归爆栈）。
2. 一遍线性扫描求基础量：逆序扫 order 累加子树大小 size[u]（孩子先于父亲被处理）；正序扫 order 时每个节点的深度 = 父深度 + 1，累加得根节点的答案 ans[0] = Σ depth。
3. 换根递推（核心）：正序扫 order，对每个非根节点 u（其父 p 的 ans 已经算出）：
$$ans[u] = ans[p] - size[u] + (n - size[u])$$
推导：当根从 p 移动到 u 时——u 子树内的 size[u] 个节点到根的距离全部 减 1（它们离 u 更近）；u 子树外的 n - size[u] 个节点到根的距离全部 加 1（都要多经过 p→u 这条边）。两者一减一加即得上式。

这样每个节点恰好被 O(1) 处理一次完成换根，总复杂度 $O(n)$。

📝 参考代码（python）

from collections import deque


def sum_of_distances_in_tree(n, edges):
    if n == 1:
        return [0]
    # 1) 邻接表
    g = [[] for _ in range(n)]
    for u, v in edges:
        g[u].append(v)
        g[v].append(u)
    # 2) BFS 建树：parent 与 BFS 序（迭代，深链安全）
    parent = [-1] * n
    order = []
    visited = [False] * n
    q = deque([0])
    visited[0] = True
    while q:
        u = q.popleft()
        order.append(u)
        for v in g[u]:
            if not visited[v]:
                visited[v] = True
                parent[v] = u
                q.append(v)
    # 3) 逆序扫 BFS 序：子树大小 size（孩子先处理，汇聚到父亲）
    size = [1] * n
    for u in reversed(order):
        p = parent[u]
        if p != -1:
            size[p] += size[u]
    # 4) 正序扫：深度累加得根的答案 ans[0]
    depth = [0] * n
    total = 0
    for u in order:
        p = parent[u]
        if p != -1:
            depth[u] = depth[p] + 1
            total += depth[u]
    ans = [0] * n
    ans[0] = total
    # 5) 正序换根：ans[u] = ans[p] - size[u] + (n - size[u])
    for u in order:
        p = parent[u]
        if p != -1:
            ans[u] = ans[p] - size[u] + (n - size[u])
    return ans

⚡ 复杂度分析

时间 O(n) 空间 O(n)

🎯 考点

换根 DP 是「每个节点当一次根」类问题的标准武器：先固定根做一次自底向上 DP 求出根的答案与辅助量（子树大小），再自顶向下用 O(1) 递推把答案从父亲传给孩子。核心公式 ans[u] = ans[p] − size[u] + (n − size[u]) 来自「子树内全部 −1、子树外全部 +1」的双向观察。工程上：BFS 序天然满足「父先于子」，逆序=自底向上、正序=自顶向下，两趟扫描即可，且迭代实现天然免疫深链爆栈。

DFS 三色标记判环与逆序拓扑

💡 解题思路

正确答案是 A。三色标记的灵魂在于 GRAY 的定义：在当前 DFS 递归栈（即当前路径）上。判环的充要条件是「存在一条边指向 GRAY 节点（回边）」——有向图无环 ⟺ DFS 永远遇不到回边。而拓扑序的来源是完成时间的逆序，不是发现顺序。

🎯 考点

① 回边定义：指向 GRAY（递归栈中祖先）的边，存在回边 ⟺ 有环；② 拓扑序 = DFS 完成时间的逆序（对任意边 (u,v)，v 先完成）；③ 前向边/交叉边指向 BLACK，与环无关；④ 三色标记每点每边各处理一次，O(V+E)。与 Kahn 算法对比：Kahn 用入度 + 队列从「源头」剥离节点，输出节点数 < n 判环；DFS 用颜色 + 栈上祖先关系判环，完成逆序即拓扑序——两者互为镜像，LeetCode 210 要求字典序最小拓扑序时用 Kahn + 小根堆。

🔍 逐项分析

  • A 正确：GRAY 表示该节点正在当前递归栈中，即从它出发沿着栈能走到当前节点 u；此时又有一条边 u→GRAY 节点 v，恰好闭合 v →…→ u → v 的环。这正是回边（back edge）的定义。LeetCode 207「课程表」的 DFS 解法、图着色判环、死锁检测（等待图）都用这个性质。
  • B 错误：BLACK 表示 v 的整棵 DFS 子树已完全处理完（所有出边都扫过了）。指向 BLACK 的边是前向边（祖先→已完成的子孙）或交叉边（另一条已完成的分支），它们在 DAG 中大量存在。反例：边 1→3、1→2、2→3（邻接顺序 [3,2]）：DFS(1) 先访问 3，3 变 BLACK；回到 1 再访问 2，2 沿 2→3 走到 BLACK 节点 3——图中没有任何环。把「走到 BLACK」当判环条件会大量误报。
  • C 错误：拓扑序对应完成时间（由 GRAY 变 BLACK）的逆序。关键引理：对任意边 (u,v)，v 的完成时间必早于 u——分类讨论：树/前向边（u 是 v 的祖先，v 先完成）；交叉边（v 所在分支整体先完成）。因此按完成时间从晚到早输出即为拓扑序。反例（发现序不成立）：边 0→2、0→1、1→2，邻接顺序 [2,1]：DFS(0) 先发现 2（2 变 BLACK），再发现 1。发现序 = 0,2,1，把 2 排在 1 前面，违反 1→2 的依赖；而完成逆序 = 0,1,2 才是合法拓扑序。
  • D 错误：三色标记保证每个节点只被「开始访问」一次（发现后立即变 GRAY，永不回到 WHITE），每条边只在出发端扫描邻接表时被看一次，总复杂度 O(V+E)，与 Kahn 算法同级。若实现成「每个节点都重复扫所有邻接点」，说明没有用 visited/颜色数组去重，是错误实现。
AI公式推导 ⭐⭐⭐ 第 3 题

KTO：从前景理论到只需「赞/踩」的偏好对齐损失

KTO（Kahneman-Tversky Optimization，arXiv:2402.01306）是与 DPO 同期的大模型偏好对齐方法。与 DPO 需要 $(y_w, y_l)$ 成对偏好不同，KTO 只需要「点赞/点踩」式的二元标签——这正是它名字里行为经济学家的由来。

设 $\pi_\theta$ 为策略、$\pi_{\text{ref}}$ 为冻结的参考模型，对样本 $(x, y)$ 定义：

- $h_\theta(x,y) = \log \pi_\theta(y \mid x)$（序列级 log 概率）
- $v(x,y) = h_\theta(x,y) - h_{\text{ref}}(x,y)$（策略相对参考的未归一化优势）
- $\beta > 0$ 为偏离步长系数，$\sigma(z) = 1/(1+e^{-z})$，$z_{\text{ref}}$ 为 KL 基准

请完成以下推导：

(1) 从 RLHF 的 KL 约束目标出发，说明为什么要把「效用」做成 $\sigma(\beta v)$ 的 S 形映射，而不是线性奖励；

(2) 写出 KTO 对 desirable（好样本）与 undesirable（坏样本）两个分支的损失函数，分别推导损失对 $v$ 的梯度，并解释梯度方向的含义；

(3) 解释 $z_{\text{ref}}$ 的定义与作用：为什么它能防止模型整体漂移、起到类似 DPO 中参考模型锚定的效果；

(4) 说明权重 $\lambda_w / \lambda_{lr}$ 的不对称设计如何体现前景理论的损失厌恶，数据不均衡时如何校准；

(5) 对比 DPO：为什么 KTO 不需要成对偏好就能训练？
--- 以下为答案与解析 ---

🎯 考点

① v = h_θ − h_ref 是未归一化优势，σ(βv) 复刻前景理论的 S 形效用（收益凹/损失凸/饱和限幅）；② 好分支梯度 −λ_w βσ(1−σ) < 0 推高 v、坏分支 +λ_lr βσ(1−σ) > 0 压低 v，梯度幅值在基准附近最大（学得猛）、远离基准趋 0（防过度优化）；③ z_ref 把 KL 惩罚内化为损失偏移项，防止整体漂移，对应 DPO 的参考模型锚定；④ λ_w/λ_lr 不对称 = 损失厌恶（λ≈2.25），按数据比例校准；⑤ DPO 学成对排序（v_w−v_l）、KTO 学单样本对基准的绝对高低——这是它只需赞/踩数据的原因。

📐 推导过程

### Step 0 · 符号与出发点

$h_\theta(x,y)=\log\pi_\theta(y\mid x)$，$v(x,y)=h_\theta-h_{\text{ref}}$ 是「策略比参考模型更青睐该样本多少」的未归一化优势；$\beta$（默认 0.1）控制允许偏离参考的步长。

### Step 1 · 为什么用 S 形效用（第 1 问）

RLHF 的目标是 KL 约束下的效用最大化：
$$\max_{\pi}\; \mathbb{E}_{x,y\sim\pi}\,[\,r(x,y)\,] \; - \; \beta\, \mathrm{KL}\!\left(\pi \,\|\, \pi_{\text{ref}}\right)$$

若直接线性最大化 $v$（把好样本的 log 概率无上限推高），会带来两个问题：一是无饱和地过度优化单条反馈（过拟合某几条点赞），二是整个分布可以整体漂移而损失看不出「相对排序」信息。

前景理论（Kahneman & Tversky, 1979）对人类偏好的刻画：收益侧是凹函数（边际递减）、损失侧是凸函数、损失比等量收益更痛（$\lambda \approx 2.25$）。KTO 用 $\sigma(\beta v)$ 近似这种 S 形效用：值域 $(0,1)$、单调、在 $|\beta v|$ 大处饱和——廉价地复刻「收益凹、损失凸」，天然限幅，把优化集中在「还没推够」的样本上。

### Step 2 · KTO 损失与梯度（第 2 问）

对好样本（desirable）与坏样本（undesirable）分别定义损失：
$$\mathcal{L}_{\text{KTO}} = \mathbb{E}_{(x,y)\sim\mathcal{D}}\Big[
\mathbf{1}[y \text{ 好}]\;\lambda_w\big(1-\sigma\big(\beta\,(v(x,y)-z_{\text{ref}})\big)\big)
+ \mathbf{1}[y \text{ 坏}]\;\lambda_{lr}\big(1-\sigma\big(\beta\,(z_{\text{ref}}-v(x,y))\big)\big)\Big]$$

好样本分支梯度（记 $z = \beta\,(v - z_{\text{ref}})$）：
$$\frac{\partial}{\partial v}\Big[\lambda_w\,(1-\sigma(z))\Big] \;=\; -\,\lambda_w\;\beta\;\sigma(z)\,\big(1-\sigma(z)\big)\;<\;0$$

损失对 $v$ 单调递减 → 梯度下降会增大 $v$，即提高 $\pi_\theta(y\mid x)$ 相对参考的倾向，让模型更愿意生成好样本。$\sigma(z)(1-\sigma(z))$ 在 $z\approx 0$（样本离基准近）处最大、远离基准处趋于 0：基准附近学得最猛，已经学「够」的样本自动停止更新——这正是收益凹性/边际递减的体现，也是防过拟合单条反馈的关键。

坏样本分支梯度（记 $z' = \beta\,(z_{\text{ref}} - v)$）：
$$\frac{\partial}{\partial v}\Big[\lambda_{lr}\,(1-\sigma(z'))\Big] \;=\; +\,\lambda_{lr}\;\beta\;\sigma(z')\,\big(1-\sigma(z')\big)\;>\;0$$

损失对 $v$ 单调递增 → 梯度下降会压低 $v$，即降低坏样本相对参考的倾向，模型学会远离坏回答；对称地，压得越远梯度越小（凸性饱和）。

### Step 3 · $z_{\text{ref}}$ 的锚定作用（第 3 问）

$$z_{\text{ref}} \;\approx\; \mathbb{E}_{x,y\,\text{好}}\big[\mathrm{KL}(h_\theta \,\|\, h_{\text{ref}})\big] + \mathbb{E}_{x,y\,\text{坏}}\big[\mathrm{KL}(h_\theta \,\|\, h_{\text{ref}})\big]$$

实现上是两个可学习标量（初始化为 0，前向统计、梯度 detach），分别追踪当前策略在好样本集与坏样本集上的平均 KL 偏移。作用：

- 没有 $z_{\text{ref}}$ 时：模型可以让所有输出的概率「一起抬高」，$v$ 普遍为正，损失照样下降——这是整体漂移（reward hacking 的雏形），相对排序信息为零；
- 有了 $z_{\text{ref}}$：「好」必须高于当前平均偏移、「坏」必须低于平均偏移，只有相对于基准的排序才算数；
- 它把 RLHF 目标中的显式 KL 惩罚内化为损失里的偏移项，等价于 DPO 中 $\pi_{\text{ref}}$ 的锚定：约束模型不要偏离参考模型太远，保住通用能力。

### Step 4 · 不对称权重与损失厌恶（第 4 问）

前景理论：损失带来的负效用约是等量收益正效用的 $\lambda \approx 2.25$ 倍。KTO 把这一点做成两分支权重不对称：

- 同等幅度下，坏样本分支的权重调得更重（对「踩」的惩罚 > 对「赞」的奖励），训练出的模型对坏输出避得更远；
- 当好坏样本数量不均衡（真实场景中点踩往往远多于/少于点赞）时，按两类样本数比例校准 $\lambda_w / \lambda_{lr}$，使两类样本对总损失的贡献量级相当，避免某类梯度淹没另一类。

### Step 5 · 与 DPO 对比（第 5 问）

$$\mathcal{L}_{\text{DPO}} = -\log\sigma\Big(\beta\,\big(v_w - v_l\big)\Big)$$

DPO 学的是同一 prompt 下两个回答的相对排序，$(y_w, y_l)$ 必须成对出现；$v_w - v_l$ 是「减法」消掉了个体偏移。KTO 用 $z_{\text{ref}}$ 基准把「相对」改造成「对基准的绝对」：单样本 + 二元标签即可训练。现实反馈（点赞/点踩、用户接受/重写、客服质检合格/不合格、A/B 测试的采纳信号）天然是二元的，收集成本远低于人工成对比较；KTO 论文证明在温和假设下其最优解逼近 KL 约束下的效用最大化，且超参更少、小数据集上更稳。

🧠 直觉解释

KTO 给每条二元反馈单独「称重」：好样本只要比 KL 基准高就往上推、坏样本只要比基准低就往下压，推和压都随距离饱和（边际递减），压得比推更狠（损失厌恶），所有动作都以参考模型为锚、以平均偏移为基准线。
AI面试问答 ⭐⭐ 第 4 题

ZeRO 一/二/三级显存账：每个参数到底占多少字节

面试官提问：

「大模型训练中，混合精度 + Adam 优化器下，一个参数量为 $\psi$ 的模型，训练时的模型状态要占多少显存？请把账算到具体字节数。ZeRO 的 1/2/3 级分别把什么切分到多张卡上，每卡显存降到多少？ZeRO-3 相比 1/2 级的额外代价是什么？」
--- 以下为答案与解析 ---

📌 回答要点

  • 先算总账：模型状态 = 16ψ 字节（混合精度 + Adam）。构成：fp16 参数 2ψ + fp16 梯度 2ψ + 优化器状态 12ψ。优化器状态里是三个 fp32 张量：参数主副本 4ψ、一阶动量 m 4ψ、二阶方差 v 4ψ。以 ψ = 7.5B 为例：15 + 15 + 60 = 90 GB 模型状态（再加激活值等，就是 ZeRO 论文图里 7.5B 模型单卡放不下的经典账）。
  • 为什么优化器必须 fp32：fp16 只有约 10 位尾数。动态 loss scaling 只救得了前向/反向的瞬时梯度，救不了 m、v 与权重主值在数万步长跑中的累积舍入误差——小梯度反复累加进动量后有效位会被吃掉，二阶统计 v 更容易下溢。通行做法：计算用 fp16/bf16，权重/动量/方差以 fp32 维护（即「混合精度」的准确含义）。
  • ZeRO 三级（设 N 卡，忽略激活）：① ZeRO-1（Pos，只切优化器状态）：每卡 4ψ + 12ψ/N；② ZeRO-2（再切梯度）：每卡 2ψ + 14ψ/N；③ ZeRO-3（参数也切）：每卡 16ψ/N。以 64 卡、ψ=7.5B 粗算：ZeRO-1 每卡约 33.75 GB、ZeRO-3 每卡约 1.9 GB。
  • 通信代价：ZeRO-1/2 不增加通信量——把 DDP 的梯度 all-reduce 换成 reduce-scatter（各卡只留自己那份梯度）+ 反向后参数按需 all-gather，总流量与 DDP 相同；ZeRO-3 则在前向与反向各要一次参数 all-gather，通信量约为基线 DP 的 1.5 倍，靠 prefetch 与计算重叠缓解。
  • 选型直觉：参数+梯度（4ψ）放得下、优化器放不下 → ZeRO-1/2；参数本身就放不下 → ZeRO-3（注意 ZeRO-3 仍要求单层参数经 all-gather 后能完整进入单卡显存，超大单层还得叠加张量并行）。

⭐ 加分项

  • ZeRO-Infinity：进一步把优化器状态/参数 offload 到 CPU 内存与 NVMe，突破「显存上限 = 可训练模型上限」，配合 bf16 状态压缩；这是 DeepSpeed 跑百亿~万亿参数的底座。
  • 与 TP/PP 正交：ZeRO 切的是训练状态（数据并行维度）；张量并行 TP 切算子内的矩阵（模型并行维度，通信量大、适合单机内 NVLink）；两者可叠加（DeepSpeed ZeRO + Megatron TP/PP 是经典组合）。
  • FSDP ≈ ZeRO-3：PyTorch 原生 FSDP 的 full-shard 模式就是 ZeRO-3 思路的官方实现（分片参数 + 按层 all-gather + 梯度 reduce-scatter），工程细节（prefetch、通信桶）不同，思路同源。
  • ZeRO++：对梯度/参数做量化通信（qGSD 等），把 ZeRO-3 的跨机流量再砍一档。

🔮 追问预测

  • 追问「ZeRO-2 和 ZeRO-3 实际怎么选？」——先看单卡能否放下 fp16 参数+梯度（4ψ）与最大激活；放不下参数才上 ZeRO-3；跨机带宽差时优先 ZeRO-2 或加 TP，因为 ZeRO-3 的参数 all-gather 对带宽敏感。
  • 追问「FSDP 和 ZeRO-3 什么关系？」——FSDP 是 PyTorch 对 ZeRO-3 full-shard 的原生实现：flat param 分片、前向按需 all-gather、梯度 reduce-scatter，逻辑等价、生态不同（原生 vs DeepSpeed 引擎）。
  • 追问「能不能把优化器状态也 fp16，再省 8ψ？」——不建议：fp16 动量/方差长跑累积误差与下溢是训练后期 loss 尖刺、权重不收敛的常见根因；若显存吃紧，宁可 offload（ZeRO-Infinity）或用 8-bit 优化器（bitsandbytes，量化的是统计量且带动态缩放），也别裸用 fp16。
