动态规划：最长递增子序列（LIS）

类别：动态规划 | 难度：中等

算法简介

最长递增子序列（Longest Increasing Subsequence，LIS）是动态规划领域最经典的入门问题之一：给定一个长度为 $ n $ 的数组 nums，找出其中不要求连续、但保持原相对顺序、且元素严格递增的子序列的最长长度。例如 [10,9,2,5,3,7,101,18] 的 LIS 长度为 4，其中一个解为 [2,3,7,101]。注意两点：①「子序列」与「子数组」不同，子序列允许跳过任意元素；②「严格递增」要求后一个元素必须大于前一个（若允许相等则是「最长不递减子序列」）。

求解有两种经典思路：动态规划 $ O(n^2) $（定义 dp[i] 为以第 $ i $ 个元素结尾的 LIS 长度，逐个向前扫描转移），以及贪心 + 二分 $ O(n \log n) $（维护 tails 数组，tails[k] 表示长度为 $ k+1 $ 的递增子序列的最小可能末尾元素，配合 bisect_left 二分定位替换位置）。后者基于「纸牌游戏 Patience Sorting」的直觉：末尾元素越小，越有利于后续元素接上去形成更长的序列。面试中两者都必须掌握：前者体现 DP 建模能力，后者体现贪心 + 二分优化思维。

原理示意图

数学公式

① DP 状态转移方程（$ O(n^2) $ 版）

$$ dp[i] = \max\left(1,\ \max_{\substack{0 \le j < i \\ nums[j] < nums[i]}} (dp[j] + 1)\right) $$

  • $ n $：数组长度
  • $ nums[i] $：数组中第 $ i $ 个元素（下标从 0 起）
  • $ dp[i] $：以第 $ i $ 个元素结尾的最长递增子序列长度
  • $ j $：枚举的 $ i $ 之前的下标，要求 $ nums[j] < nums[i] $ 才能接续
  • $ dp[j] + 1 $：在「以 $ j $ 结尾的 LIS」末尾接上 $ nums[i] $ 后的新长度
  • 外层 $ \max $：至少为 1（单个元素本身即长度为 1 的递增子序列）
  • 最终答案：$ LIS = \max_{0 \le i < n} dp[i] $（不一定以最后一个元素结尾）

② 贪心 + 二分的不变量（$ O(n \log n) $）

$$ tails[k] = \min\{\ \text{长度为 } k+1 \text{ 的递增子序列的最小末尾元素}\ \} $$

  • $ k $：子序列长度减一（0 起始），$ len(tails) $ 即当前已知最大 LIS 长度
  • 处理元素 $ x $ 时：pos = bisect_left(tails, x)——第一个满足 $ \ge x $ 的位置
  • 若 pos == len(tails)：说明 $ x $ 大于所有末尾元素，追加形成更长序列；
  • 否则：tails[pos] = x，把「长度为 pos+1 的序列的最小末尾」更新为更小的 $ x $，为未来接续留出更大空间
  • 该数组天然严格递增，这是二分查找可行的前提

③ 复杂度推导

  • DP 法：外层 $ n $ 个元素，每个内层扫描至多 $ n $ 次 → 时间 $ O(n^2) $；仅需一维 dp 数组 → 空间 $ O(n) $
  • 贪心二分法：$ n $ 个元素，每次 bisect_left 在长度至多 $ n $ 的数组上二分 $ O(\log n) $ → 时间 $ O(n \log n) $；空间 $ O(n) $

核心要点

  • 严格递增（>）用 bisect_left；若题目允许相等（非降序）则改用 bisect_right，否则相等元素会因「替换自己」而丢失候选序列
  • tails 数组不直接等于一个合法 LIS，它只维护「各长度的最小末尾」，用于贪心 + 二分加速长度计算
  • 若需输出具体子序列，须额外记录每个元素被插入 tails 的位置（pos），再逆序遍历还原
  • $ O(n^2) $ DP 天然可得到具体序列（记录转移前驱）；$ O(n \log n) $ 版本还原序列稍复杂，两者面试都要会
  • nums 为空时 LIS 长度为 0，这是边界测试点

技术细节与参数详解

LIS 是纯算法问题，无外部 API 参数，但「贪心+二分」实现中的每个环节都相当于一个可调参数，面试与工程中必须精确掌握其语义。

#### 参数 1：tails 数组（核心数据结构）

  • 含义：tails[k] 记录长度为 $ k+1 $ 的递增子序列的最小可能末尾值
  • 类型：列表 list[int]，与 nums 元素同型
  • 默认值：初始为空列表
  • 取值范围：长度 0 ~ $ n $；内部元素在迭代中不断被替换为更小值
  • 对结果的影响：它不直接等于 LIS，只影响二分查找的落点与最终长度；tails 的最终长度即答案
  • 推荐设置：无外部配置，理解其「尾部越小越优」的贪心思想即可

#### 参数 2：二分定位函数（bisect_left vs bisect_right）

  • 含义：确定元素 $ x $ 在 tails 中的插入/替换位置
  • 类型：bisect 模块函数（Python）
  • 默认值：bisect_left（找第一个 $ \ge x $ 的位置）
  • 取值范围：bisect_left ∈ $ [0, \text{len}(tails)] $；bisect_right 找第一个 $ > x $ 的位置
  • 对结果的影响：这是「严格递增」与「非递减」的分水岭——严格递增用 bisect_left，允许相等（如最长不递减子序列）用 bisect_right。用错会导致相等元素被错误替换、长度统计失真
  • 推荐设置：先确定题目是否严格递增，再选择对应函数

#### 参数 3：比较规则（严格递增 > vs 非递减 >=）

  • 含义：接续条件「$ nums[j] < nums[i] $」还是「$ nums[j] \le nums[i] $」
  • 类型：布尔语义
  • 默认值：LeetCode 300 默认严格递增（>）
  • 取值范围：仅两种
  • 对结果的影响：[1,1,1] 严格递增答案为 1，非递减答案为 3；判定规则直接影响转移条件与二分方向
  • 推荐设置：与 bisect_left/right 配对使用，严格递增 ⟷ bisect_left

#### 参数 4：DP 转移实现（dp 数组初始化与双循环）

  • 含义：DP 版的状态表
  • 类型：list[int]
  • 默认值：dp = [1] * n（每个元素自成长度 1）
  • 取值范围：$ dp[i] \in [1, i+1] $
  • 对结果的影响：初值必须全为 1 而非 0，否则单元素序列被漏算；内层 $ j $ 从 0 到 $ i $ 全扫保证不漏最优前驱
  • 推荐设置：无，纯实现细节；面试先写 DP 保正确，再写二分版展示优化能力

#### 参数 5：predecessor 还原数组（需要输出具体序列时）

  • 含义：记录每个下标的最优前驱下标
  • 类型：list[int]，值为 -1 表示无前驱
  • 默认值：全 -1
  • 取值范围：$ -1 $ 或合法下标
  • 对结果的影响：不记录则只能得到长度；记录后可从尾部回溯得到完整序列（注意结果不唯一，任取其一）
  • 推荐设置：需要输出序列时开启；仅求长度可省

代码示例

# -*- coding: utf-8 -*-
"""最长递增子序列 LIS：O(n^2) DP 与 O(n log n) 贪心+二分 双解法 + 边界测试"""
from bisect import bisect_left, bisect_right  # 二分查找库：bisect_left 用于严格递增

def lis_dp(nums):
    """动态规划解法，时间复杂度 O(n^2)，空间 O(n)"""
    n = len(nums)                 # 数组长度
    if n == 0:                    # 空数组直接返回 0（边界）
        return 0
    dp = [1] * n                  # dp[i] 初始化为 1：单个元素自成子序列
    ans = 1                       # 答案至少为 1
    for i in range(n):            # 遍历每个结尾位置 i
        for j in range(i):        # 枚举 i 之前的所有下标 j
            if nums[j] < nums[i]: # 只有更小的前驱才能接续成递增序列
                # 状态转移：取「以 j 结尾的长度+1」与当前值的较大者
                dp[i] = max(dp[i], dp[j] + 1)
        ans = max(ans, dp[i])      # 实时更新全局最大长度
    return ans                     # 返回 LIS 长度

def lis_nlogn(nums, strict=True):
    """贪心+二分解法，时间复杂度 O(n log n)，空间 O(n)
    strict=True 严格递增（bisect_left）；False 允许相等（bisect_right）"""
    tails = []                     # tails[k] 存长度为 k+1 的递增子序列最小末尾值
    fn = bisect_left if strict else bisect_right  # 按严格性选择二分函数
    for x in nums:                  # 逐个处理数组元素
        pos = fn(tails, x)          # 找第一个满足条件的位置（二分 O(log n)）
        if pos == len(tails):       # 若 x 大于所有末尾：追加，序列长度 +1
            tails.append(x)
        else:                       # 否则：用更小的 x 替换该长度下的末尾值
            tails[pos] = x          # 尾部越小，未来可接的元素越多（贪心）
    return len(tails)               # tails 的长度即 LIS 长度

if __name__ == "__main__":
    tests = [
        ([10, 9, 2, 5, 3, 7, 101, 18], 4),  # 经典用例：LIS=[2,3,7,101]
        ([3, 1, 4, 1, 4], 3),                  # 含重复值：严格递增答案为 3
        ([], 0),                               # 空数组：答案为 0
        ([5], 1),                              # 单元素：答案为 1
        ([5, 4, 3, 2, 1], 1),                  # 严格递减：答案为 1
        ([1, 2, 3, 4, 5], 5),                  # 全递增：答案为 n
        ([1, 1, 1], 1),                        # 全相等（严格）：答案为 1
    ]
    for arr, expect in tests:              # 逐组验证边界与无解情况
        r1, r2 = lis_dp(arr), lis_nlogn(arr)
        # 断言：两种解法输出一致，且等于期望值
        assert r1 == r2 == expect, f"{arr}: dp={r1} nlogn={r2} expect={expect}"
    print("全部 7 组测试用例通过：DP 与贪心+二分结果一致且正确")

复杂度分析

  • 时间：DP 版双层循环 $ \sum_{i=0}^{n-1} i = \frac{n(n-1)}{2} = O(n^2) $；贪心+二分版 $ n $ 次二分、每次 $ O(\log n) $，总 $ O(n \log n) $
  • 空间：两者均为 $ O(n) $（DP 的 dp 数组 / 贪心的 tails 数组）
  • 优化空间：$ O(n \log n) $ 已接近理论下界（比较模型下不可能优于 $ O(n \log n) $）；若需更快的常数，可用 Patience Sorting 的堆栈实现等价逻辑

应用场景

  • LeetCode 300 / 最长递增子序列：面试笔试基础题，常作进阶题（俄罗斯套娃信封、最长数对链）的底层组件
  • 基因/序列比对：生物信息学中找两条序列的保守递增结构（配合 LCS 使用）
  • 股票与时间序列分析：寻找「最长连续上涨趋势段」的近似建模
  • 任务调度与依赖排序：在保持相对顺序的前提下挑选可行子集，如最长可执行任务链

AI生成

GRPO 组相对策略优化（Group Relative Policy Optimization）

类别：大模型对齐 | 难度：困难

算法简介

GRPO（Group Relative Policy Optimization，组相对策略优化）是 DeepSeek 在 DeepSeekMath / DeepSeek-R1 中提出的强化学习（RL）后训练算法，用于对齐大语言模型的推理能力。它针对 PPO（近端策略优化）在 LLM 场景下的两大痛点做了外科手术式改造：① 去掉价值网络（Critic）——PPO 需要额外训练一个与策略同规模的 Critic 来估计优势函数（Advantage），而 LLM 场景下这会让显存/算力开销翻倍；② 用「组内相对基线」替代 Critic 基线——对同一个 prompt 采样 $ G $ 条响应（rollout），用规则或奖励模型打分，再以该组的均值与标准差做归一化得到优势值：$ A_i = (r_i - \text{mean}(\mathbf r)) / \text{std}(\mathbf r) $。高于组内平均的回答被强化，低于的被压制，从而在不引入任何额外模型的前提下获得低方差的优势估计。

GRPO 同时继承了 PPO 的「裁剪替代目标（clipped surrogate objective）」机制限制单步策略更新幅度，并加入对参考模型（ref model）的 KL 散度惩罚防止策略漂移。它被成功应用于 DeepSeek-R1 系列，在数学推理（GSM8K、MATH）与代码生成任务上取得了显著效果，已成为开源社区 RL 对齐的事实标准之一。

原理示意图

数学公式

① GRPO 目标函数（DeepSeekMath 论文式）

$$ J_{GRPO}(\theta) = \mathbb{E}\left[\frac{1}{G}\sum_{i=1}^{G}\sum_{t=1}^{|o_i|}\Big(\min\big(\text{ratio}_{i,t}\cdot A_{i,t},\ \text{clip}(\text{ratio}_{i,t}, 1-\varepsilon, 1+\varepsilon)\cdot A_{i,t}\big) - \beta\, D_{KL}\big(\pi_\theta \| \pi_{ref}\big)\Big)\right] $$

  • $ \theta $：待更新的策略参数（LLM 权重）
  • $ G $：组大小，即对同一 prompt 采样的响应条数
  • $ o_i $：组内第 $ i $ 条采样输出；$ |o_i| $ 为其 token 数；$ t $ 为 token 位置下标
  • $ \text{ratio}_{i,t} = \dfrac{\pi_\theta(o_{i,t}\mid q, o_{i,1 表示新策略更愿意生成该 token
  • $ \text{clip}(x, 1-\varepsilon, 1+\varepsilon) $：把 $ x $ 截断到 $ [1-\varepsilon, 1+\varepsilon] $ 区间，$ \varepsilon $ 为裁剪系数（如 0.2），防止单步更新过猛
  • $ A_{i,t} $：token 级优势值；GRPO 中通常 $ A_{i,t} = A_i $（见公式②）
  • $ \beta $：KL 惩罚系数，控制「策略不能偏离参考模型太远」的强度
  • $ D_{KL}(\pi_\theta \| \pi_{ref}) $：策略与参考模型的 KL 散度，用低方差估计式（见公式③）
  • 外层 $ \mathbb{E} $：对所有 prompt $ q $ 的期望，实践中用 mini-batch 平均近似

② 组内归一化优势（无 Critic 的关键）

$$ \hat{A}_i = \frac{r_i - \text{mean}(\{r_1,\dots,r_G\})}{\text{std}(\{r_1,\dots,r_G\})} $$

  • $ r_i $：第 $ i $ 条响应的奖励（规则验证或奖励模型打分）
  • $ \text{mean} $ / $ \text{std} $：组内 $ G $ 条奖励的均值与标准差
  • $ \hat{A}_i $：归一化优势，以「组内相对表现」取代 PPO 的 Critic 基线
  • 效果：奖励绝对尺度（例如奖励值普遍偏高或偏低）被消除，只保留组内相对排序信息；同时组内比较天然抗奖励噪声

③ KL 散度的低熵近似（作者用无偏估计式）

$$ D_{KL}\big(\pi_\theta \| \pi_{ref}\big) = \mathbb{E}\left[\log\frac{\pi_\theta(o|q)}{\pi_{ref}(o|q)} - 1\right] + \text{const} \approx \frac{\pi_{ref}(o|q)}{\pi_\theta(o|q)} - \log\frac{\pi_{ref}(o|q)}{\pi_\theta(o|q)} - 1 $$

  • $ \pi_{ref} $：固定的参考模型（通常是 SFT 后的模型），不参与梯度更新
  • 两个策略生成同 token 的概率比取对数即 KL 的采样估计；等价式（$ x - \log x - 1 $ 型）保证方差更小、梯度更稳

核心要点

  • 无 Critic：GRPO 最大的工程红利——不再训练与 LLM 同规模的价值网络，显存占用与训练成本大幅下降，这是 DeepSeek-R1 能在有限算力下完成 RL 的根基
  • 组内归一化 $ \hat{A}_i = (r_i - \mu)/\sigma $ 替代 PPO 的 GAE（广义优势估计），以采样组为基线消偏
  • 裁剪 + KL 双保险：裁剪机制限制 ratio 变化范围，KL 惩罚防止策略漂移，两者共同保证训练稳定
  • 每条响应复用同一次 rollout：采样 $ G $ 条响应来自旧策略，全部用于更新，样本利用充分
  • 适用场景：可验证奖励（数学答案、代码测试通过）最合适；开放生成任务的奖励函数设计较难

技术细节与参数详解

GRPO 在训练框架（如 TRL 的 GRPOConfig）中暴露以下核心超参数，理解其语义是调优的前提。

#### 参数 1：group_size（组内采样条数 G）

  • 含义：对每个 prompt 采样的响应条数，组内相对统计（mean/std）基于这 G 条
  • 类型：int
  • 默认值：TRL 中 num_generations=8（DeepSeekMath 论文实验用 4~64 不等）
  • 取值范围：推荐 4 ~ 64；太小归一化噪声大，太大采样开销与内存暴涨
  • 对结果的影响：G 越小，组内基线越不稳定、优势噪声越大；G 越大，优势估计越稳但每步显存/时间成本近似线性上升（G 条 rollout 全在内存中）
  • 推荐设置：显存允许的前提下取 8~16；小模型练推理可 4~8，大模型练复杂推理 16~64

#### 参数 2：clip_range（裁剪系数 ε）

  • 含义：概率比 ratio 的允许偏离区间 $ [1-\varepsilon, 1+\varepsilon] $
  • 类型：float
  • 默认值：0.2（PPO/GRPO 通用默认）
  • 取值范围：一般 0.05 ~ 0.3
  • 对结果的影响：ε 过小 → 每步更新幅度受限，收敛慢；ε 过大 → 单步更新过猛，策略崩溃风险升高。它直接控制「探索 vs 稳定」的平衡
  • 推荐设置：默认 0.2；训练不稳时调小到 0.1，冷启动时可暂用 0.3 加速

#### 参数 3：beta（KL 正则系数）

  • 含义：对 $ \pi_\theta $ 与 $ \pi_{ref} $ 间 KL 散度的惩罚权重
  • 类型：float
  • 默认值：0.04（DeepSeekMath 论文实验常用 0.04）
  • 取值范围：$ 10^{-4} $ ~ $ 10^{-1} $ 量级
  • 对结果的影响：β 太大 → 策略被钉死在参考模型附近，RL 学不到新知识，reward 提升受限；β 太小 → 策略漂移过远，可能退化、话痨或重复
  • 推荐设置：0.01~0.05 起步；观察「奖励上升 + KL 可控」则保持，KL 涨太快则上调 β

#### 参数 4：reward_model / 奖励来源（规则奖励 vs 奖励模型）

  • 含义：给响应打分的来源——可验证规则（数学/代码）或训练好的 RM
  • 类型：可调用对象 / 模型
  • 默认值：规则验证器（规则型奖励）
  • 取值范围：规则型（正确率、代码通过率）、过程型（每步验证）、RM 型
  • 对结果的影响：规则型奖励信号强且无偏，GRPO 效果最好；RM 型奖励质量直接决定对齐上限；错误奖励会系统性带偏策略
  • 推荐设置：能用规则验证的任务优先规则奖励；确实需要 RM 时与 SFT 对齐质量挂钩

#### 参数 5：ref_model（参考模型）

  • 含义：KL 惩罚的目标分布，固定不更新
  • 类型：与策略同架构的模型
  • 默认值：SFT 后的模型（DeepSeek 实践即如此）
  • 取值范围：任何同词表的 LLM；与策略相同或为冻结的历史版本
  • 对结果的影响：参考模型质量高则 KL 正则自然，防止策略在奖励图上钻空子；选择不当会让策略朝错误方向平滑
  • 推荐设置：采用 SFT 模型或训练开始的策略快照

#### 参数 6：rollout 采样超参数（temperature / top_p / max_tokens）

  • 含义：从 π_old 采样的生成参数
  • 类型：float / int
  • 默认值：temperature=1.0（采样多样性最大）、max_tokens 按任务设
  • 取值范围：temperature ∈ (0, 1.6]；max_tokens 由任务输出长度决定
  • 对结果的影响：温度过高 → 组内响应差异大但噪声大；过低 → 组内几乎相同，组内归一化失效。max_tokens 太小会截断正确答案
  • 推荐设置：推理任务 temperature=1.0 保持探索；max_tokens 留足思考长度（如 1024~4096）

#### 参数 7：lr（策略学习率）

  • 含义：优化器学习率，控制每步参数更新幅度
  • 类型：float
  • 默认值：7e-6（DeepSeek-R1 实际用的极小 lr）
  • 取值范围：$ 1\times10^{-7} $ ~ $ 3\times10^{-5} $（LLM RL 普遍远小于 SFT）
  • 对结果的影响：过大 → 策略剧烈漂移、奖励震荡；过小 → RL 步数爆炸成本高
  • 推荐设置：从 1e-6 ~ 1e-5 量级起，模型越大 lr 越小

#### 参数 8：adv_coef / 优势归一化开关（是否用组内 std 归一化）

  • 含义：是否对优势做「除以组内 std」的标准化
  • 类型：bool
  • 默认值：True（DeepSeek 论文式归一化）
  • 取值范围：True / False
  • 对结果的影响：开启后奖励尺度不变影响，梯度更稳；关闭后仅减均值（只做居中），奖励绝对值大小会直接缩放梯度——reward 设计不良时更易爆
  • 推荐设置：True，除非奖励设计需要保留原始尺度语义

代码示例

# -*- coding: utf-8 -*-
"""GRPO 单步更新的最小可运行示例（核心逻辑，基于 PyTorch 风格）"""
import torch
import torch.nn.functional as F

def grpo_update(policy_logprobs, ref_logprobs, old_logprobs, rewards,
                group_size=8, clip_eps=0.2, beta=0.04):
    """
    组相对策略优化单步更新（此处演示向量化核心公式）
    policy_logprobs : [N, L] 新策略 πθ 的逐 token 对数概率
    ref_logprobs    : [N, L] 参考模型 πref 的逐 token 对数概率（冻结）
    old_logprobs    : [N, L] 旧策略 π_old 采样时保存的逐 token 对数概率
    rewards         : [N]    每条响应的奖励
    group_size      : G，同一 prompt 采样的响应条数（须整除 N）
    """
    N, L = policy_logprobs.shape          # N=总响应数（G×组数），L=序列长度
    assert N % group_size == 0              # 保证能按组切分

    # ① 计算概率比 ratio = exp(logπθ - logπ_old)，并逐 token 求和得到序列级比值
    ratio = torch.exp(policy_logprobs - old_logprobs)      # [N, L]
    ratio = ratio.sum(dim=1)                               # [N] 序列级 ratio

    # ② 组内归一化优势：A = (r - mean) / std（按组切分计算）
    r = rewards.view(-1, group_size)                       # [组数, G] 重排成组
    mu = r.mean(dim=1, keepdim=True)                      # 每组的均值 μ
    sigma = r.std(dim=1, keepdim=True) + 1e-8            # 每组的 std（+1e-8 防除零）
    adv = (r - mu) / sigma                                # 归一化优势 [组数, G]
    adv = adv.view(-1)                                    # 展平回 [N]

    # ③ 裁剪替代目标：min(ratio·A, clip(ratio,1-ε,1+ε)·A)
    clip_ratio = torch.clamp(ratio, 1 - clip_eps, 1 + clip_eps)  # 截断到允许区间
    loss_policy = -torch.min(ratio * adv, clip_ratio * adv).mean()  # 负号：梯度上升

    # ④ KL 惩罚项（低方差估计式：log(ref/θ) + ref/θ - 1，见数学公式③）
    log_ratio_ref = ref_logprobs - policy_logprobs        # log(πref/πθ)
    kl = (torch.exp(log_ratio_ref) - log_ratio_ref - 1).sum(dim=1).mean()  # 序列级 KL
    loss = loss_policy + beta * kl                          # 总损失：策略项 + KL 惩罚

    # ⑤ 返回损失（调用方执行 loss.backward() 与 optimizer.step()）
    return loss

if __name__ == "__main__":
    torch.manual_seed(42)                     # 固定随机种子保证可复现
    G, groups, L = 4, 2, 8                  # 每提示 4 条响应、2 组、序列长 8
    N = G * groups                         # 总响应数 = 8
    # 随机生成三类对数概率模拟一次 mini-batch
    plp = torch.randn(N, L) * 0.3          # 新策略 logprob
    olp = torch.randn(N, L) * 0.3          # 旧策略 logprob
    rlp = torch.randn(N, L) * 0.3          # 参考模型 logprob
    rew = torch.tensor([1.0, 0.0, 0.5, -0.2, 2.0, 1.5, 0.1, 0.8])  # 8 条奖励
    loss = grpo_update(plp, rlp, olp, rew, group_size=G)   # 计算总损失
    loss.backward()                       # 反传（示例中参数为占位，实际接入模型）
    print(f"GRPO loss = {loss.item():.4f}（含策略损失与 KL 惩罚）")

复杂度分析

  • 时间：每步 = G 条响应的前向生成（rollout，$ O(G \cdot T_{gen} \cdot D) $） + 一次策略/参考模型前向（$ O(G \cdot L \cdot D) $）＋梯度反传（$ O(N \cdot L \cdot D) $）。相比 PPO，GRPO 省去 Critic 的同步前向/反传，省约 30%~50% 计算；相比 PPO+GAE 多步优势累积，GRPO 单组归一化直接出优势，无递归计算
  • 空间：核心开销在缓存 G 条响应的 logprob（新/旧/参考 三份），即 $ O(3 \cdot G \cdot L \cdot D) $ 量级；无 Critic 权重存储，模型内存比 PPO 约省一半显存（这是 GRPO 最大的工程红利）
  • 收敛分析：组内归一化使优势分布恒为「均值 0、方差 1」，梯度的尺度与奖励绝对大小解耦，收敛对奖励尺度的敏感性大幅下降

应用场景

  • 大模型推理对齐（DeepSeek-R1 类）：数学、代码、逻辑推理任务，规则型奖励驱动思维链涌现
  • 代码生成 RL：单元测试通过率作为奖励，训练模型自我纠错（可验证奖励完美适配）
  • Agent 工具调用对齐：组内相对比较天然适合「多个候选动作选优」
  • 小模型蒸馏后微调：无 Critic 的低成本 RL 路线，适合受限算力环境

AI生成

t-SNE 降维（t-Distributed Stochastic Neighbor Embedding）

类别：降维 | 难度：中等

算法简介

t-SNE（t-分布随机邻域嵌入，t-Distributed Stochastic Neighbor Embedding）是 van der Maaten & Hinton 于 2008 年提出的非线性降维算法，被誉为「高维数据可视化的黄金标准」。它的核心思想是概率分布匹配：在高维空间，用高斯分布把点对间的欧氏距离转成「相似性条件概率」$ p_{j|i} $（每个点只关心自己的邻域，perplexity 控制邻域大小）；在低维空间（2D/3D），用重尾的学生 t 分布定义相似性 $ q_{ij} $，使 $ q $ 去拟合 $ p $。两者之间的差异用 KL 散度度量，通过梯度下降逐步调整低维坐标，直到 $ q $ 与 $ p $ 尽量一致。

相比 PCA 只保留全局线性方差结构，t-SNE 擅长保留局部邻域结构：相似的点在低维空间靠拢，不同的簇被拉开，因此特别适合把深度网络的特征（如 ResNet 输出的 2048 维）投影到二维平面观察聚类效果。它有两个显著特点：① t 分布重尾缓解了 SNE 的「拥挤问题」（高维中相距远的点不会被压到一堆）；② 损失函数非凸、计算量大（精确版 $ O(N^2) $），大数据集需 Barnes-Hut 近似。

原理示意图

数学公式

① 高维条件概率（高斯核）

$$ p_{j|i} = \frac{\exp\left(-\frac{\|x_i - x_j\|^2}{2\sigma_i^2}\right)}{\sum_{k \neq i}\exp\left(-\frac{\|x_i - x_k\|^2}{2\sigma_i^2}\right)} $$

  • $ x_i, x_j $：高维空间中第 $ i $、$ j $ 个样本点
  • $ \|x_i - x_j\|^2 $：两点的欧氏距离平方
  • $ \sigma_i $：第 $ i $ 个点的高斯带宽（由 perplexity 二分搜索确定）
  • $ k $：归一化分母的遍历下标，排除自身 $ k \neq i $
  • $ p_{j|i} $：给定 $ x_i $ 时选 $ x_j $ 作为邻居的概率——距离越近概率越大

② 对称化 + 低维 t 分布

$$ p_{ij} = \frac{p_{j|i} + p_{i|j}}{2N},\qquad q_{ij} = \frac{(1 + \|y_i - y_j\|^2)^{-1}}{\sum_{k \neq l}(1 + \|y_k - y_l\|^2)^{-1}} $$

  • $ p_{ij} $：对称联合概率（两方向条件概率取平均再除以 $ N $，消除不对称性）
  • $ y_i, y_j $：低维（2D/3D）中的嵌入点坐标（待优化变量）
  • $ q_{ij} $：低维联合概率，用自由度为 1 的 t 分布（即柯西分布核 $ (1+d^2)^{-1} $）
  • 重尾特性：高维中相距较远的点对，在低维不必挤在一起，缓解「拥挤问题」

③ 损失函数（KL 散度）与梯度

$$ C = KL(P\|Q) = \sum_{i \neq j} p_{ij}\log\frac{p_{ij}}{q_{ij}},\qquad \frac{\partial C}{\partial y_i} = 4\sum_j (p_{ij} - q_{ij})(y_i - y_j)(1 + \|y_i - y_j\|^2)^{-1} $$

  • $ C $：KL 散度损失，$ P $ 与 $ Q $ 越接近损失越小
  • $ p_{ij} - q_{ij} $：驱动项——若低维中 $ q_{ij} $ 过小（两点该近却远了），梯度把 $ y_i, y_j $ 拉近；反之推远
  • $ (y_i - y_j) $：方向项，决定拉扯的方向
  • $ (1 + \|y_i - y_j\|^2)^{-1} $：t 分布核权重，距离越远影响越小
  • 梯度式中的系数 4：来自 $ q_{ij} $ 定义的常数，实践中直接采用

核心要点

  • 局部优先：t-SNE 忠实保留邻域（哪些点簇在一起），但簇间距离、全局几何不可解读
  • perplexity 是灵魂参数：控制每个点的邻域规模，需与样本量匹配，经验上取 5~50 且 < 样本数
  • 结果不可复现：初始化随机 → 必须固定 random_state；不同 seed 布局可能不同，结论依赖宏观结构
  • t 分布重尾 解决 SNE 拥挤问题；低维只需 2~3 维，嵌入参数直接可画
  • 大数据集用 Barnes-Hut：method='barnes_hut' 把复杂度从 $ O(N^2) $ 降到 $ O(N \log N) $
  • PCA 预处理：高维（>50）先 PCA 降噪，再喂 t-SNE，速度与质量双提升

技术细节与参数详解

以下为 sklearn.manifold.TSNE 的核心参数，全部逐项说明。

#### 参数 1：n_components

  • 含义：低维嵌入空间的维度（可视化目标维度）
  • 类型：int
  • 默认值：2
  • 取值范围：2 或 3（更高维度无可视化意义且计算量爆炸）
  • 对结果的影响：2 便于散点图展示；3 可做交互式三维图，但计算与渲染成本上升，且 KL 优化更难
  • 推荐设置：默认 2；需立体观察时 3

#### 参数 2：perplexity

  • 含义：每个点的「有效近邻数」，直接决定高维带宽 $ \sigma_i $（等价于邻居数量感受野）
  • 类型：float
  • 默认值：30.0
  • 取值范围：典型 5 ~ 50；必须 $ < N $（经验上 $ (N-1)/3 $ 封顶，超过会报错或退化）
  • 对结果的影响：太小 → 只见局部、碎片化簇多；太大 → 全局平均化、簇混在一起；与 $ N $ 不匹配时结果质量骤降（小样本配大 perplexity 尤其糟糕）
  • 推荐设置：从 30 起步，用 5~50 网格搜索，观察簇分离度；大数据集可随 $ N $ 上调

#### 参数 3：learning_rate

  • 含义：梯度下降的步长，也是 n_iter_without_progress 判定「无进展」的尺度
  • 类型：float
  • 默认值：200.0（1.0 版本起默认 200）
  • 取值范围：典型 100~1000；官方建议 10~1000
  • 对结果的影响：过小 → 点挤在中心不散开、收敛极慢；过大 → 点疯狂跳跃、「爆炸」成规则环状/线状分布；100~500 是常用甜区
  • 推荐设置：默认 200 起步；点聚成「死团」调大至 300~800，剧烈震荡调小

#### 参数 4：n_iter

  • 含义：最大优化迭代轮数
  • 类型：int
  • 默认值：1000
  • 取值范围：≥ 250；建议 ≥ 1000
  • 对结果的影响：太少 → 未收敛、结构混乱；足够多 → 损失进入平台期。n_iter_without_progress（默认 300）会提前停止
  • 推荐设置：默认 1000；大数据或复杂结构加到 2000~5000，并配合监控 KL 损失曲线

#### 参数 5：early_exaggeration

  • 含义：前期（前 250 次迭代）对 $ p_{ij} $ 的放大倍数，人为拉开簇
  • 类型：float
  • 默认值：12.0
  • 取值范围：≥ 1；典型 4~25
  • 对结果的影响：放大后簇间排斥更强，帮助形成分离的簇骨架；太小 → 簇难分离；太大 → 布局过分散、细节丢失
  • 推荐设置：默认 12；数据量大时可适度调大

#### 参数 6：min_grad_norm

  • 含义：梯度范数阈值，梯度范数低于它即视为「梯度为 0」（提前停止）
  • 类型：float
  • 默认值：1e-7
  • 取值范围：≥ 0（0 表示不启用该阈值）
  • 对结果的影响：加速收敛、避免无意义迭代；过大可能过早停住
  • 推荐设置：默认 1e-7；不要轻易调大

#### 参数 7：init

  • 含义：低维嵌入 $ Y $ 的初始化方式
  • 类型：str 或 ndarray
  • 默认值：'random'（sklearn 1.1+ 建议 'pca'）
  • 取值范围：'random'、'pca' 或用户提供 $ N \times D $ 的数组
  • 对结果的影响：'pca' 初始更稳定、可复现性更好且收敛更快；'random' 引入更多随机性；自定义数组可嵌入先验
  • 推荐设置：init='pca'（配合 random_state 保证可复现）；或显式 random

#### 参数 8：random_state

  • 含义：随机种子，控制初始化和打乱
  • 类型：int 或 RandomState
  • 默认值：None（每次运行不同结果）
  • 取值范围：任意整数（如 42）
  • 对结果的影响：不设置 → 结果每次不同，无法复现实验；固定 → 相同输入得相同嵌入
  • 推荐设置：必须设置（生产/论文环境铁律），推荐 42 等固定整数

#### 参数 9：method

  • 含义：梯度计算算法
  • 类型：str
  • 默认值：'barnes_hut'
  • 取值范围：'exact'（精确 $ O(N^2) $）、'barnes_hut'（近似 $ O(N \log N) $）
  • 对结果的影响：exact 精确但 $ N>10000 $ 时极慢/内存爆炸；barnes_hut 用空间树近似，速度显著提升（精度约 97%）
  • 推荐设置：$ N < 1000 $ 可用 exact；更大一律 barnes_hut（默认）

#### 参数 10：angle

  • 含义：Barnes–Hut 树的空间划分角度阈值（method='barnes_hut' 时有效）
  • 类型：float
  • 默认值：0.5
  • 取值范围：0~1 之间（典型 0.2~0.8）
  • 对结果的影响：越小 → 近似越精确但越慢；越大 → 越快但近似误差越大（点会出现「网格状」伪影）
  • 推荐设置：默认 0.5；对精度敏感调到 0.2~0.3，对速度敏感调到 0.7~0.8

#### 参数 11：n_iter_without_progress

  • 含义：连续多少轮损失无下降即提前停止
  • 类型：int
  • 默认值：300
  • 取值范围：≥ 0（0 表示禁用早停）
  • 对结果的影响：太小 → 提前停、结构未成型；太大 → 收敛后空跑浪费时间
  • 推荐设置：默认 300；一般不必改

#### 参数 12：verbose

  • 含义：是否输出训练日志
  • 类型：int
  • 默认值：0（静默）
  • 取值范围：0 / 1（>0 输出迭代与损失）

复杂度分析

  • 时间：精确法每轮梯度计算 $ O(N^2) $，$ T $ 轮迭代总 $ O(T N^2) $；Barnes–Hut 用空间树（四分树/八分树）把每轮降到 $ O(N\log N) $，总 $ O(T N \log N) $
  • 空间：精确法需存储 $ N\times N $ 的距离/概率矩阵，$ O(N^2) $；Barnes–Hut 只需 $ O(N) $ 树结构，内存压力大幅缓解
  • 推导要点：$ N=10^4 $ 时 $ N^2=10^8 $ 次操作已是秒级到分钟级边界，这就是必须用 Barnes–Hut 的原因；perplexity 确定 $ \sigma_i $ 需对每个点做一次二分搜索，开销 $ O(N\log N) $
