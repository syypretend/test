快速幂（Fast Exponentiation）

类别：数学算法 | 难度：入门

算法简介

快速幂（Fast Exponentiation，又称"二进制取幂" Exponentiation by Squaring）是一种在 $ O(\log n) $ 时间内计算 $ a^n $（尤其是 $ a^n \bmod p $）的高效算法。朴素做法是循环连乘 $ n $ 次，复杂度 $ O(n) $，当 $ n $ 达到 $ 10^9 $ 级别时（如 RSA 解密、模逆元、斐波那契矩阵加速），普通循环会超时，而快速幂只需要约 $ \log_2 n $ 次乘法。

核心思想是把指数 $ n $ 按二进制展开：$ n = \sum_{i} b_i \cdot 2^i $（$ b_i \in \{0,1\} $ 是 $ n $ 的第 $ i $ 个二进制位），那么 $ a^n = a^{\sum b_i 2^i} = \prod_{i: b_i=1} a^{2^i} $。于是只需要预先依次计算 $ a^1, a^2, a^4, a^8, \dots $（每一项是上一项的平方，共 $ \log n $ 项），再挑出二进制位为 1 的项相乘即可。通过"指数右移、底数平方"的迭代或"指数折半"的递归，算法在 $ O(\log n) $ 时间内完成，且配合模运算 $ (x\cdot y)\bmod p = (x\bmod p)\cdot(y\bmod p)\bmod p $ 可避免大整数溢出。

原理示意图

快速幂原理示意（指数二进制分解与平方倍增）

上图展示指数为奇数时的模运算递推：$ n $ 为奇数时先拆分 $ a^n = a^{n-1}\cdot a $，再把 $ n-1 $ 折半为 $ \lfloor n/2 \rfloor $，配合 $ (x\cdot y)\bmod m = [(x\bmod m)\cdot(y\bmod m)]\bmod m $ 逐步化简，复杂度从 $ O(n) $ 降到 $ O(\log n) $。

数学公式

核心公式：$ a^n $ 的二进制分解

$$ n = b_{k-1}2^{k-1} + b_{k-2}2^{k-2} + \cdots + b_1 2^1 + b_0 2^0, \quad b_i \in \{0,1\} $$

$$ a^n = \prod_{i=0}^{k-1} a^{b_i 2^i} = \prod_{i:\, b_i = 1} (a^{2^i}) $$

取模形式（用于避免溢出、密码学场景）：

$$ a^n \bmod p = \left(\prod_{i:\, b_i=1} (a^{2^i} \bmod p)\right) \bmod p $$

平方递推关系（迭代式每一步）：

$$ a^{2^{i+1}} = \left(a^{2^i}\right)^2 $$

变量解释：

  • $ n $：指数（幂次），$ k=\lceil \log_2(n+1)\rceil $ 为 $ n $ 的二进制位数
  • $ b_i $：$ n $ 的二进制表示中第 $ i $ 位的取值，只能为 0 或 1，决定对应项是否乘入结果
  • $ a^{2^i} $：底数 $ a $ 的"平方塔"第 $ i $ 项，由上一项平方得到（倍增）
  • $ p $：模数（可选），取模让中间结果始终小于 $ p $，防止溢出
  • $ a^n \bmod p $：最终要计算的模幂结果

核心要点

  • 核心原理：指数二进制分解 + 底数平方倍增，将连乘次数从 $ n $ 降为 $ \log_2 n $
  • 只乘"二进制位为 1"的项，位为 0 的项只平方不乘入
  • 迭代版空间 $ O(1) $、递归版空间 $ O(\log n) $
  • 取模版每步取模，全程数值不超 $ p^2 $，避免大数溢出
  • 扩展：矩阵快速幂可 $ O(\log n) $ 求斐波那契等线性递推
  • 与内置 pow(a, n, mod) 等价（Python 内置即快速幂）

技术细节与参数详解

#### 参数1：底数 base（$ a $）

  • 含义：被乘方对象，可以是整数、矩阵、模数环元素
  • 类型：int / float / 矩阵（矩阵快速幂）
  • 默认值：无（必填）
  • 取值范围：任意；取模场景通常先做 a %= mod 归一化
  • 对结果的影响：底数直接决定结果数值；$ a=1 $ 时结果恒 1，$ a=0 $ 且 $ n>0 $ 时结果恒 0
  • 推荐设置：取模场景先 a %= mod，将底数收敛到 $ [0, mod) $

#### 参数2：n（指数 exponent）

  • 含义：幂次，决定迭代轮数
  • 类型：非负整数（负指数需先求逆元）
  • 默认值：无（必填）
  • 取值范围：任意非负整数，$ 10^{18} $ 级别均轻松处理；$ n=0 $ 时结果为 1
  • 对结果的影响：$ n $ 的二进制位数 $ k=\lfloor \log_2 n\rfloor + 1 $ 直接决定循环轮数，是 $ O(\log n) $ 的来源
  • 推荐设置：循环条件 while n:，每轮 n >>= 1（右移一位）

#### 参数3：mod（模数，可选）

  • 含义：取模运算的模，用于模幂计算（RSA、费马小定理求逆元等）
  • 类型：正整数
  • 默认值：None（不取模）
  • 取值范围：任意正整数；竞赛常取 $ 10^9+7 $ 或 $ 998244353 $（质数）
  • 对结果的影响：决定中间值上限；模数小则更省内存但可能改变结果语义
  • 推荐设置：无特殊要求用 $ 10^9+7 $；密码学用 RSA 模数 $ n=pq $

#### 参数4：res（结果累积变量）

  • 含义：累乘结果
  • 类型：int
  • 默认值：1（乘法的单位元）
  • 取值范围：$ [0, mod) $（取模时）
  • 对结果的影响：初始化为 1 才能保证 $ n=0 $ 时输出 1；每轮按二进制位决定是否累乘
  • 推荐设置：取模版 res = 1 % mod（当 mod=1 时避免除零问题）

#### 参数5：base_sq（底数平方，迭代中间量）

  • 含义：$ a^{2^i} $ 的当前值，每轮自乘一次
  • 类型：int
  • 默认值：初始为 a % mod
  • 对结果的影响：体现"平方倍增"；每轮 base_sq = base_sq * base_sq % mod
  • 推荐设置：务必先取模再平方，防止中间结果膨胀

代码示例（Python，每行注释）

# 快速幂迭代实现（二进制分解 + 平方倍增）
def fast_pow(a: int, n: int, mod: int = None) -> int:
    """
    计算 a^n，可选模 mod
    :param a:   底数
    :param n:   指数（非负整数）
    :param mod: 模数，None 表示不取模
    :return:    a^n 或 a^n % mod
    """
    # 取模版本先把底数归一，防止中间结果过大
    if mod is not None:
        a %= mod
        # 结果初始化为模意义下的单位元 1
        res = 1 % mod
    else:
        # 不取模时结果就是 1
        res = 1
    # 只要指数还有剩余二进制位就继续循环
    while n > 0:
        # 检查当前最低位是否为 1
        if n & 1:
            # 位为 1 时把当前底数乘入结果
            res = (res * a) % mod if mod is not None else res * a
        # 底数平方，准备下一高位对应的项 a^(2^(i+1))
        a = (a * a) % mod if mod is not None else a * a
        # 指数右移一位，相当于 n //= 2，处理下一个二进制位
        n >>= 1
    # 返回最终结果
    return res

# 测试：计算 2^10 = 1024
print(fast_pow(2, 10))                 # 输出 1024
# 测试模幂：2^1000000000 % 1000000007（朴素循环必超时，快速幂瞬间完成）
print(fast_pow(2, 1000000000, 1000000007))   # 输出 140625001
# Python 内置 pow 三参形式也是快速幂实现，结果一致
print(pow(2, 1000000000, 1000000007))        # 输出 140625001

# 矩阵快速幂：以斐波那契数列为例，O(log n) 求第 n 项
def mat_mul(A, B, mod=10**9+7):
    """2x2 矩阵乘法（取模）"""
    # 返回 2x2 结果矩阵，每个元素是两个点积之和取模
    return [[(A[0][0]*B[0][0] + A[0][1]*B[1][0]) % mod,
             (A[0][0]*B[0][1] + A[0][1]*B[1][1]) % mod],
            [(A[1][0]*B[0][0] + A[1][1]*B[1][0]) % mod,
             (A[1][0]*B[0][1] + A[1][1]*B[1][1]) % mod]]

def mat_pow(M, n, mod=10**9+7):
    """矩阵快速幂：M^n"""
    # 单位矩阵作为乘法单位元
    res = [[1, 0], [0, 1]]
    # 指数二进制分解循环
    while n:
        # 最低位为 1 时乘入结果矩阵
        if n & 1:
            res = mat_mul(res, M, mod)
        # 矩阵自乘实现"平方"
        M = mat_mul(M, M, mod)
        # 指数右移一位
        n >>= 1
    # 返回最终矩阵
    return res

# 斐波那契：F = [[1,1],[1,0]]^n，结果左上角即 F(n)
F = mat_pow([[1, 1], [1, 0]], 10)
print(F[0][0])  # 输出 55，即第 10 个斐波那契数

复杂度分析

时间复杂度推导：

  • 指数 $ n $ 的二进制位数为 $ k = \lfloor \log_2 n \rfloor + 1 $
  • 迭代版每轮常数次操作（判断、至多 2 次乘法、1 次右移），共 $ k $ 轮
  • 单次乘法代价 $ O(1) $（固定位数）或 $ O(\log p) $（取模大数）
  • 总复杂度 $ O(k) = O(\log n) $
  • 朴素连乘 $ O(n) $，指数越大优势越明显（$ n=10^{18} $ 时 $ 10^{18} $ vs 60）

空间复杂度推导：

  • 迭代版只用了 a、res、n 三个变量，$ O(1) $
  • 递归版每层递归压栈，深度 $ k=\log_2 n $，空间 $ O(\log n) $
  • 结论：迭代版 O(1) 空间，且无栈溢出风险

应用场景

  • RSA 加密/解密：$ c = m^e \bmod n $，$ e $ 指数极大，必须快速幂
  • 模逆元求解：费马小定理 $ a^{-1} \equiv a^{p-2} \pmod p $（$ p $ 为质数）
  • 矩阵快速幂：线性递推（斐波那契、线性同余）$ O(\log n) $ 求第 $ n $ 项
  • 组合数学：大组合数取模 $ C(n,k) \bmod p $（配合阶乘预计算）
  • 哈希与伪随机数：线性同余生成器 $ x_{n+1}=(ax_n+c)\bmod m $ 的快速跳转
  • 算法竞赛/面试：pow 取模、LeetCode 50 题"Pow(x,n)"

投机解码（Speculative Decoding）

类别：大模型推理加速 | 难度：困难

算法简介

投机解码（Speculative Decoding）是近年来大模型推理加速领域最实用的技术之一。它的出发点很朴素：自回归生成太慢了。每生成一个 token，模型都要把全部权重从显存读一遍（内存带宽墙），700 亿参数意味着每 token 约 140GB 的读取量，GPU 大量时间在等数据而不是算数据。投机解码的巧妙思路是"以小博大"：用一个小而快的草稿模型（draft model）先快速猜出未来 K 个 token，再用大目标模型（target model）一次性并行验证这 K 个 token。如果草稿猜得准（大概率接受），大模型一次前向就"产出"了多个 token，速度提升 2~3 倍。更关键的是，通过精巧的"拒绝采样"规则，投机解码在数学上保证输出分布与目标模型直接生成完全一致——加速但不损失质量。这项技术如今已是 vLLM、TensorRT-LLM 等主流推理框架的标配能力（speculative_model 参数）。

原理示意图

投机解码原理：草稿模型生成 K 个候选 + 目标模型并行验证

上图对比了传统自回归解码与投机解码：左侧每步只生成 1 个 token；右侧先由草稿模型（小）快速生成一批候选，再由目标模型（大）一次性并行验证，接受的 token 直接作为输出，被拒的 token 从目标分布重新采样。

数学公式

自回归解码（基线）：每个位置依赖已生成的前缀 $ x_{

$$ x_t \sim p_\theta(x_t \mid x_{

草稿模型生成候选：草稿模型 $ q_\phi $ 先自回归生成 $ K $ 个候选 token $ \tilde{x}_{t+1}, \dots, \tilde{x}_{t+K} $

目标模型并行验证：对每个候选位置计算目标模型真实分布 $ p_\theta $

拒绝采样（接受/拒绝规则）：对第 $ i $ 个候选 token，以概率接受

$$ \min\left(1, \frac{p_\theta(\tilde{x}_i \mid \text{prefix})}{q_\phi(\tilde{x}_i \mid \text{prefix})}\right) $$

期望接受数量（加速的关键指标）：

$$ \mathbb{E}[\#\text{accepted}] \approx \sum_{i=1}^{K} \alpha^i = \frac{\alpha(1-\alpha^{K})}{1-\alpha} $$

加速比：

$$ \text{Speedup} \approx \frac{\mathbb{E}[\#\text{accepted}] + 1}{\text{总前向次数}} \approx \frac{1 + \mathbb{E}[\#\text{accepted}]}{1 + \frac{\text{draft 计算量}}{\text{target 计算量}}\cdot\frac{1}{\text{前向次数归一}}} $$

变量解释：

  • $ x_{
  • $ p_\theta $：目标（大）模型的概率分布，$ \theta $ 为其参数
  • $ q_\phi $：草稿（小）模型的概率分布，$ \phi $ 为其参数
  • $ \tilde{x}_i $：草稿模型生成的第 $ i $ 个候选 token
  • $ K $：每轮生成的草稿 token 数量（典型 3~8）
  • $ \alpha $：接受率（草稿与目标分布一致的概率，期望值），$ \alpha \in [0,1] $
  • $ \mathbb{E}[\#\text{accepted}] $：期望接受的 token 数，越大加速越明显

核心要点

  • 草稿-验证两阶段：小模型猜，大模型校，一次大模型前向产出多个 token
  • 分布保持性：拒绝采样保证输出分布严格等于目标模型（无质量损失）
  • 加速比取决于草稿模型与目标模型的"契合度"（接受率 $ \alpha $）
  • 典型效果：接受率 0.8、$ K=5 $ 时前向次数降为 1/4，端到端约 2~3 倍
  • 选型：草稿模型须与目标模型共享词表（tokenizer），通常同族（如 Llama-3-8B 配 70B）
  • 工程成熟：vLLM --speculative-model 一行开启；EAGLE、Medusa 等改进变体继续刷新速度

技术细节与参数详解（vLLM / TensorRT-LLM 中的核心参数）

#### 参数1：speculative_model（草稿模型路径/名称）

  • 含义：指定作为草稿模型的小模型
  • 类型：字符串（模型 ID 或本地路径）
  • 默认值：None（默认不启用投机解码）
  • 取值范围：任何与目标模型词表一致的轻量模型
  • 对结果的影响：草稿质量直接决定接受率与加速比；选错模型可能不加速甚至变慢
  • 推荐设置：优先用同族小模型（如 Llama-3-8B 配 Llama-3-70B）；或专用草稿头（EAGLE-3、Medusa）

#### 参数2：num_speculative_tokens（草稿长度 K）

  • 含义：每轮草稿模型生成的候选 token 数量
  • 类型：int
  • 默认值：5（vLLM 常见默认）
  • 取值范围：一般 3~8，也可更大
  • 对结果的影响：K 越大单轮吞吐越高，但草稿出错概率累积，存在最优值；过大时被拒后浪费计算
  • 推荐设置：先试 5，观察接受率调优；接受率高可增大 K

#### 参数3：speculative_max_model_len

  • 含义：投机解码允许的最大序列长度
  • 类型：int
  • 默认值：默认同 max_model_len
  • 取值范围：不超过模型最大上下文
  • 对结果的影响：限制草稿验证的 KV 缓存范围，防止超长序列时显存爆炸
  • 推荐设置：与 max_model_len 一致即可

#### 参数4：speculative_draft_tensor_parallel_size

  • 含义：草稿模型自身的张量并行度
  • 类型：int
  • 默认值：1（草稿模型不并行）
  • 取值范围：1~GPU 数
  • 对结果的影响：草稿模型小，通常单卡即可，过大反而引入通信开销
  • 推荐设置：1（除非草稿模型也很大）

#### 参数5：gpu_memory_utilization

  • 含义：允许使用的显存比例
  • 类型：float
  • 默认值：0.9
  • 取值范围：0~1
  • 对结果的影响：投机解码需要同时驻留两个模型，显存不足会导致 OOM 或草稿被挤掉
  • 推荐设置：留足两个模型的显存；显存紧时用 0.85~0.9

#### 参数6：temperature（采样温度）

  • 含义：解码采样的温度系数
  • 类型：float
  • 默认值：0.7（vLLM 常见）
  • 取值范围：0~2+
  • 对结果的影响：温度越低分布越尖锐、接受率越高；投机解码常配合贪心或低温度使用
  • 推荐设置：追求速度设 0（贪心）；需要多样性与速度折中设 0.3~0.6

#### 参数7：top_p / top_k（核采样与 top-k 采样参数）

  • 含义：控制候选词集合大小
  • 类型：float / int
  • 默认值：top_p=1.0，top_k=-1（不限制）
  • 取值范围：top_p ∈ (0,1]；top_k ≥ 1
  • 对结果的影响：收窄采样空间可提升与草稿一致的概率，间接提高接受率
  • 推荐设置：top_p=0.9，top_k=40~100 的常用组合

#### 参数8：n（批内生成序列数）与 best_of

  • 含义：每条提示生成几条候选序列
  • 类型：int
  • 默认值：1
  • 对结果的影响：投机解码对批量处理友好，batch 越大吞吐收益越明显
  • 推荐设置：服务场景保持默认；压测关注吞吐时加大并发而非 n

代码示例（vLLM 一行开启，每行注释）

# 方式一：vLLM Python API 启用投机解码
from vllm import LLM, SamplingParams

# 初始化推理引擎：目标模型 + 草稿模型
llm = LLM(
    model="meta-llama/Llama-3-70B-Instruct",      # 目标大模型
    speculative_model="meta-llama/Llama-3-8B-Instruct",  # 草稿小模型（同族）
    num_speculative_tokens=5,                     # 每轮生成 5 个草稿 token
    tensor_parallel_size=4,                       # 目标模型 4 卡并行
    gpu_memory_utilization=0.9,                   # 显存利用率
    dtype="float16",                              # 半精度推理
)

# 采样参数：低温度提高接受率
sampling_params = SamplingParams(

复杂度分析

时间复杂度推导：

  • 传统自回归：生成 $ T $ 个 token 需 $ T $ 次大模型前向，每次代价 $ O(L_{\text{target}}) $（$ L $ 为每层计算量×层数）
  • 投机解码：每轮 1 次草稿前向（$ K $ 个 token 自回归，代价约 $ K \times L_{\text{draft}} $）+ 1 次大模型前向（一次验证 $ K $ 个位置，代价约 $ L_{\text{target}} $）
  • 若期望接受数 $ \mathbb{E}[A] $，则总前向次数约为 $ T / (\mathbb{E}[A]+1) $
  • 总代价 $ T \cdot L_{\text{target}} \to \frac{T}{1+\mathbb{E}[A]}\cdot(L_{\text{target}} + K\cdot L_{\text{draft}}) $
  • 当草稿模型足够小（$ L_{\text{draft}}\ll L_{\text{target}} $）且接受率高时，加速比 ≈ $ 1+\mathbb{E}[A] $，即 2~4 倍
  • 空间：需额外驻留草稿模型（约 1/10~1/8 目标大小），总体空间 $ O(L_{\text{target}} + L_{\text{draft}}) $

应用场景

  • 生产 LLM 服务：vLLM/TensorRT-LLM 部署 Chat 模型，吞吐提升 2~3 倍，成本减半
  • 批量离线生成：摘要、代码补全、数据提取等大规模批处理任务
  • 低延迟在线推理：配合小模型先答再验证，首 token 延迟与整体延迟双优化
  • 受限显存环境：小目标模型也能受益（如 8B 目标 + 1B 草稿）
  • 不适合：短输出（<50 token）、超高并发小请求、草稿与目标差异大的跨族组合

注意力机制变体（Attention Mechanism Variants）

类别：深度学习/大模型架构 | 难度：困难

算法简介

注意力机制是 Transformer 的基石：每个 token 与序列中所有其他 token 计算相关性权重并加权聚合，这让模型能捕捉长程依赖，但代价是 $ O(n^2) $ 的时间和空间复杂度——序列一长（例如几十万 token 的上下文），显存与算力都吃不消。于是诞生了一大批"注意力机制变体"来突破这个平方瓶颈，核心诉求是在不损失效果的前提下降低复杂度或常数。主流方向包括：①线性注意力（Linear Attention）：用核函数近似 softmax，将 $ QK^T $ 的平方矩阵乘法改写为 $ Q(K^TV) $，复杂度降到 $ O(n) $；②稀疏注意力（Sparse Attention）：让每个 token 只看固定窗口或随机选择的少数 token（如 Longformer、BigBird）；③FlashAttention：通过 IO 感知分块计算，不物化 $ n\times n $ 矩阵，把常数系数优化到极致（这是当今大模型训练的标准配置）；④滑动窗口/局部注意力：限定每个 token 只看邻域窗口（如 Mistral 的 sliding window）；⑤线性注意力循环化（Mamba 等）：把注意力重写为循环，序列长度无关。注意力变体的本质，是在"表达能力"与"计算/显存效率"之间做取舍的工程-算法平衡。

原理示意图

注意力机制变体：全注意力 vs 稀疏/窗口/线性注意力对比

上图展示了多种稀疏注意力模式：Random（随机稀疏）、Window（窗口/局部）、Global（全局，如 BERT 的 [CLS]）、BigBird（三合一）。方格中的点表示该位置的 query-key 对被计算；空白表示被跳过，从而减少计算量。线性注意力（左下角常见表达）则把矩阵结构变为线性 RNN 式的循环。

数学公式

标准缩放点积注意力（基线）：

$$ \text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}\right)V $$

其中 $ Q \in \mathbb{R}^{n\times d_k} $，$ K \in \mathbb{R}^{n\times d_k} $，$ V \in \mathbb{R}^{n\times d_v} $。

复杂度：时间 $ O(n^2 d_k) $，空间 $ O(n^2) $。

线性注意力（用核函数近似 softmax，消去 $ QK^\top $ 大矩阵）：

$$ \text{Attn}_{\text{lin}}(Q,K,V)_i = \frac{\phi(Q_i)^\top \sum_j \phi(K_j) V_j^\top}{\phi(Q_i)^\top \sum_j \phi(K_j)} $$

复杂度：时间 $ O(n d_k d_v) $（先算 $ \sum_j \phi(K_j)V_j^\top $ 每行再乘以 $ \phi(Q_i) $），空间 $ O(n) $。

稀疏注意力（窗口模式）：只允许每个 query 关注窗口内 $ w $ 个 key

$$ \text{Attn}_{\text{win}}(Q,K,V)_i = \text{softmax}\left(\frac{Q_i K_{[i-w, i+w]}^\top}{\sqrt{d_k}}\right)V_{[i-w,i+w]} $$

复杂度：$ O(n\cdot w \cdot d_k) $，$ w\ll n $ 时为 $ O(n) $。

FlashAttention 公式（在线 softmax 分块）：将注意力分解为 $ B_c $ 个块，维护运行最大 $ m $ 与运行归一和 $ \ell $：

$$ \ell^{(t)} \gets \ell^{(t-1)} + \exp(m^{(t-1)} - m^{(t)}) \cdot \sum_j e^{s_{ij} - m^{(t)}} $$

变量解释：

  • $ n $：序列长度（token 数）
  • $ d_k $：key 维度；$ d_v $：value 维度
  • $ Q,K,V $：query、key、value 矩阵
  • $ w $：窗口大小（滑动窗口注意力）
  • $ \phi(\cdot) $：核函数（如 ReLU/指数核），把 $ Q,K $ 投影到正数空间
  • $ m^{(t)} $：第 $ t $ 块的运行最大值；$ \ell^{(t)} $：运行归一化因子；$ s_{ij} $：注意力 logit

核心要点

  • 线性注意力把 $ O(n^2) $ 降为 $ O(n) $，但弱化了 softmax 的归一化/稀疏性，容易退化
  • 稀疏注意力用窗口/全局 token 的稀疏结构近似全注意力，本质仍是 $ O(n) $ 计算
  • FlashAttention 在不改动输出的前提下把 HBM 访问降到最优，是训练超长上下文的硬件级优化
  • 滑动窗口（如 Mistral、Gemma2）在固定开销下近似长上下文，适配滚动 KV 缓存
  • 变体的共同目标：在保持核心"查询-键相关性"语义的同时打破平方瓶颈
  • 生产选型：训练用 FlashAttention（保精度）；长上下文在线推理用滑动窗口+KV cache 量化

技术细节与参数详解（以 FlashAttention / 窗口注意力的实现参数为例）

#### 参数1：block_size（FlashAttention 的分块大小）

  • 含义：计算时把 Q/K/V 分成多少行一块，逐块加载到 SRAM
  • 类型：int
  • 默认值：由内核决定（如 128）
  • 取值范围：通常 64~256（受 SRAM 大小限制）
  • 对结果的影响：块越大，HBM 往返越少但 SRAM 占用越高；需在吞吐与容量间平衡
  • 推荐设置：用默认；显存极小的设备可调小

#### 参数2：num_heads（注意力头数）

  • 含义：多头注意力的头数量
  • 类型：int
  • 默认值：8（Transformer 论文默认 8）
  • 取值范围：1~64（需整除 embed_dim）
  • 对结果的影响：头越多并行子空间越多，可捕获更多类型关系；头过大每头维度变小效果变差
  • 推荐：head_dim=64 附近（embed_dim/num_heads ≈ 64）

#### 参数3：head_dim（每头维度）

  • 含义：每个注意力头的投影维度 $ d_k=d_v $
  • 类型：int
  • 默认值：64（经典设置）
  • 取值范围：16~128 常用
  • 对结果的影响：决定每头表达力与总参数量；过小表达能力不足，过大则显存（QK^T）
  • 推荐：64 或 128，遵循模型惯例

#### 参数4：window_size（滑动窗口注意力窗口）

  • 含义：每个 token 只能注意前后 window_size 个 token
  • 类型：int
  • 默认值：如 Mistral 使用 4096
  • 取值范围：1~n
  • 对结果的影响：窗口太小丢长程信息，窗口太大近似全注意力失去优化意义
  • 推荐：根据任务最长依赖长度设置（如 4096/8192）

#### 参数5：softmax_scale（缩放因子）

  • 含义：QK^T 除以的缩放值（通常 $ \sqrt{d_k} $）
  • 类型：float
  • 默认值：$ \sqrt{head\_dim} $
  • 取值范围：正数
  • 对结果的影响：缩放保持数值稳定；错误缩放会破坏 softmax 分布
  • 推荐：使用默认 $ 1/\sqrt{d_k} $

#### 参数6：num_blocks（分块数，PagedAttention/分页 KV 缓存）

  • 含义：KV 缓存按块管理时的块数量
  • 类型：int
  • 默认值：根据序列长度计算
  • 取值范围：≥1
  • 对结果的影响：控制 KV 缓存的内存分配粒度，影响缓存利用率
  • 推荐：交由推理引擎（vLLM）自动管理

#### 参数7：recompute_kv（重计算开关）

  • 含义：反向传播是否重算 K、V 以减少显存
  • 类型：bool
  • 默认值：取决于框架
  • 对结果的影响：训练显存占用减半，代价是额外的计算
  • 推荐：长上下文训练开启

代码示例（PyTorch 实现窗口注意力 + FlashAttention 调用，每行注释）

import torch
import torch.nn.functional as F

def window_attention(q, k, v, window_size):
    """
    滑动窗口注意力：每个 query 只看前后 window_size 个 key
    :param q: (B, H, N, d) query
    :param k: (B, H, N, d) key
    :param v: (B, H, N, d) value
    :param window_size: 窗口半径（单侧）
    """
    B, H, N, d = q.shape
    # 计算所有位置的缩放点积分数（临时矩阵，注意力实现时用掩码避免全量）
    scores = torch.matmul(q, k.transpose(-2, -1)) / (d ** 0.5)  # (B,H,N,N)
    # 构造窗口掩码：距离大于 window_size 的位置置为 -inf
    idx = torch.arange(N, device=q.device)
    dist = (idx[None, :] - idx[:, None]).abs()                  # 相对距离矩阵
    mask = dist > window_size                                    # 超窗位置掩码
    scores = scores.masked_fill(mask, float('-inf'))            # 屏蔽窗口外位置
    attn = torch.softmax(scores, dim=-1)                       # 归一化
    out = torch.matmul(attn, v)                                # 加权求和
    return out

# FlashAttention 内核（在线 softmax 的高效分块实现示意）
# 实际生产中直接使用 fused 内核（如 triton 实现），下面给出分块计算逻辑
import math

def flash_attention_blocks(q, k, v, block=64):
    """分块注意力（示意）：不物化 NxN 矩阵，逐块更新运行统计"""
    B, H, N, d = q.shape
    out = torch.zeros_like(q)                     # 输出缓存
    for i in range(0, N, block):                 # 外层循环：query 块
        q_blk = q[:, :, i:i+block]               # 当前 query 块
        m = torch.full((B, H, block, 1), -float('inf'), device=q.device)  # 运行 max
        l = torch.zeros((B, H, block, 1), device=q.device)                 # 运行 sum exp
        acc = torch.zeros((B, H, block, d), device=q.device)               # 累加器
        for j in range(0, N, block):             # 内层循环遍历 key/value 块
            k_j = k[:, :, j:j+block]             # key 块
            v_j = v[:, :, j:j+block]             # value 块
            s = torch.matmul(q_i, k_j.transpose(-2, -1)) / math.sqrt(d)  # 分数
            m_new = torch.maximum(m, s.max(dim=-1, keepdim=True).values) # 新 max
            p = torch.exp(s - m_new)             # 稳定指数
            l = l * torch.exp(m - m_new) + p.sum(dim=-1, keepdim=True)   # 更新 l
            acc = acc * torch.exp(m - m_new) + torch.matmul(p, v_j)      # 更新累加
            m = m_new                            # 同步 max
        out[:, :, i:i+block] = acc / l           # 归一化输出
    return out

复杂度分析

标准注意力：时间 $ O(n^2 d) $，空间 $ O(n^2) $——序列长度平方膨胀。

线性注意力：把计算顺序从 $ QK^T V $ 变为 $ Q (K^T V) $，时间 $ O(n d_k d_v) $，空间 $ O(n d_v) $；不再有 $ n^2 $ 项。

滑动窗口注意力：每个 query 只算 $ 2w+1 $ 个 key，时间 $ O(n w d) $，空间 $ O(n w) $；$ w $ 远小于 $ n $ 时线性。

FlashAttention：时间与标准注意力同阶 $ O(n^2 d) $，但 HBM 访问从 $ O(n^2) $ 降到 $ O(n) $，实际加速 2~10 倍（因 I/O 占主导），空间 O(n)。

应用场景

  • 长上下文大模型训练：GPT-4、Llama-3、Qwen 系列等都依赖 FlashAttention 训练 8K~128K 上下文
  • 在线流式推理：滑动窗口 + KV 缓存（如 Mistral、Gemma 2）支持无限滚动生成
  • 长文档/长代码理解：BigQuery、Longformer 稀疏注意力处理 1M token 文档
  • 视觉 Transformer：窗口化注意力（Swin）平衡图像 patch 之间的计算
  • 高效记忆系统：线性注意力（Mamba 类）让状态随时间增长而 O(1) 更新
