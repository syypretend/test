快速选择（Quickselect）

类别：查找算法 | 难度：入门

算法简介

快速选择（Quickselect）是 Tony Hoare 于 1961 年提出的选择算法，最初以 "Algorithm 65: FIND" 的名字发表，因此也被称为 Hoare 选择算法。它要解决的问题是：在无序数组中找出升序意义下第 $ k $ 个元素（第 $ k $ 小），而不需要对整个数组排序。它的思想与快速排序同源：选一个主元（pivot），把数组划分成"小于主元""等于主元""大于主元"三段；划分完成后，主元的最终下标就已经确定。此时把目标排名 $ k $ 与主元下标比较，若相等则直接返回；若 $ k $ 更小，说明答案一定在左段，右段可以整体丢弃；反之只在右段继续。与快速排序"两侧都要递归"不同，快速选择每次只进入一侧，因此工作量按几何级数衰减：$ n + n/2 + n/4 + \cdots < 2n $，平均时间复杂度为 $ O(n) $。最坏情况下（每次划分极不均衡）会退化为 $ O(n^2) $，用随机主元可以把这种概率压到极低，用"中位数的中位数"（BFPRT）则可以获得确定性的最坏 $ O(n) $。

原理示意图

图中上半部分是划分过程：以 5 为主元做三路划分后，小于 5 的四个元素在左、等于 5 的在下标 4、大于 5 的三个元素在右。因为目标 $ k=6 $ 大于主元下标 4，左半段连同主元可以整体丢弃，只在右半段继续，规模从 8 降到 3 再降到 1。下半部分说明总工作量是 $ 8+3+1=12 $，小于 $ 2n=16 $，这正是几何级数收敛带来的线性代价。

数学公式

1. 期望递归式与线性时间

$$ T(n) = T\!\left(\frac{n}{2}\right) + cn \;\Longrightarrow\; T(n) = cn\left(1 + \frac{1}{2} + \frac{1}{4} + \cdots\right) < 2cn = O(n) $$

变量解释：

  • $ T(n) $：在 $ n $ 个元素中查找第 $ k $ 小的期望代价。
  • $ T(n/2) $：理想情况下每次划分把问题缩小一半，只递归一侧的代价。
  • $ cn $：一次划分需要扫描整个区间，$ c $ 是每次比较与交换的常数开销。
  • 等比级数 $ 1 + 1/2 + 1/4 + \cdots = 2 $，因此总代价不超过 $ 2cn $。

严格地说，随机主元下的划分比例不是固定的一半，而是服从均匀分布；但期望意义上的递推上限仍然成立。更精细的分析给出：查找中位数的期望比较次数约为 $ 3.39n $，任意排名的期望比较次数不超过 $ 4n $。

2. 期望比较次数的递推上界

$$ C(n) \le n - 1 + \frac{1}{n}\sum_{i=1}^{n}\max\{C(i-1),\,C(n-i)\} \le 4n $$

变量解释：

  • $ C(n) $：在 $ n $ 个元素上执行快速选择的比较次数。
  • $ n-1 $：一次划分中主元与其余 $ n-1 $ 个元素各比较一次。
  • $ i $：主元最终落在第 $ i $ 个位置（1-indexed），左段有 $ i-1 $ 个元素，右段有 $ n-i $ 个元素。
  • $ \max\{C(i-1), C(n-i)\} $：因为只递归包含 $ k $ 的那一侧，代价取两段中较大的那个。
  • $ 1/n $：主元等概率落在 $ n $ 个位置中的任意一个。
  • $ 4n $：该递推的上界，说明期望比较次数是线性的。

3. 中位数的中位数（BFPRT）的最坏情况递推

$$ T(n) \le T\!\left(\frac{n}{5}\right) + T\!\left(\frac{7n}{10}\right) + O(n) \;\Longrightarrow\; T(n) = O(n) $$

变量解释：

  • $ T(n/5) $：把 $ n $ 个元素每 5 个一组，共 $ n/5 $ 组，递归求各组中位数的中位数。
  • $ T(7n/10) $：以该中位数为 pivot 划分后，至少有 $ 3n/10 $ 个元素不大于它、也至少有 $ 3n/10 $ 个元素不小于它，因此需要继续处理的规模至多为 $ 7n/10 $。
  • $ O(n) $：分组、求每组中位数、划分扫描的线性开销。
  • 因为 $ 1/5 + 7/10 = 9/10 < 1 $，递归规模按 $ 0.9 $ 倍衰减，总代价是 $ O(n) $ 的等比级数。

4. 第 k 大与第 k 小的下标换算

$$ k_{\text{small}} = n - k_{\text{large}} \qquad (k_{\text{large}} \text{ 为 1-indexed}) $$

变量解释：

  • $ n $：数组长度。
  • $ k_{\text{large}} $：第 $ k $ 大，从 1 开始计数，$ k_{\text{large}}=1 $ 表示最大值。
  • $ k_{\text{small}} $：对应的 0-indexed 升序下标。
  • 例：$ n=8 $、第 3 大，对应升序下标 $ 8-3=5 $，即第 6 小。

5. 最坏情况的二次递推

$$ T_{\text{worst}}(n) = T_{\text{worst}}(n-1) + O(n) = \sum_{i=1}^{n} O(i) = O(n^2) $$

变量解释：

  • $ T_{\text{worst}}(n-1) $：每次划分只排除一个元素（主元落在端点），问题规模只减 1。
  • $ O(n) $：本次划分仍需扫描当前区间。
  • 求和 $ \sum_{i=1}^{n} i = n(n+1)/2 $，因此最坏为二次时间。

核心要点

  • 只递归一侧：这是快速选择与快速排序的本质区别，也是它能做到期望 $ O(n) $ 的根本原因。
  • 划分后主元归位：一次划分结束，pivot 的最终下标就确定了；此后它不会再移动。
  • 排名比较决定方向：$ k < p $ 去左段，$ k > p $ 去右段，$ k = p $ 直接命中；等于区的处理让重复元素也能一次跳过。
  • 三路划分是工程刚需：面对大量重复值（评分、年龄、状态码、枚举），两路划分会退化成 $ O(n^2) $，三路划分仍是 $ O(n) $。
  • 随机化是对抗退化输入的最低成本手段：对已排序、逆序、锯齿形等"快排杀手"输入，随机主元把期望代价拉回线性。
  • 确定性最坏 $ O(n) $ 需要 BFPRT 或 introselect：前者常数大，后者在平均性能与最坏保证之间折中，是 C++ std::nth_element 的主流实现思路。
  • 原地但不稳定：快速选择只保证第 $ k $ 位正确、左侧不大于它、右侧不小于它，不保证左右两侧内部有序，也不保证相等元素的相对次序。
  • 不要用它替代排序：如果后续还要全部有序，直接排序更划算；快速选择只适合"只关心一个或前几个排名"的场景。

技术细节与参数详解

快速选择不是某个固定库函数，它的"参数"是决定正确性、性能与语义的一组结构性选择。下面按 API 参数的标准逐项拆解；最后再给出 C++ std::nth_element 的真实签名参数，便于对照工业实现。

参数 1：k（目标排名）

  • 含义：目标元素在升序意义下的位置。k=0 表示最小值，k=n-1 表示最大值，k=n//2 表示下中位数。
  • 类型：整数 int（Python 中任意精度整数均可）。
  • 默认值：无默认值，必填；在 C++ 中对应迭代器位置 nth。
  • 取值范围：$ 0 \le k < n $。越界必须显式报错，否则会出现死循环或返回错误元素。
  • 对结果的影响：直接决定每一步递归的方向；k 取中位数时问题规模期望减半，取端点时退化为"找最小/最大"，一趟扫描即可。
  • 推荐设置：统一使用 0-indexed，避免"第 k 小"与"下标 k"混淆；求第 $ k $ 大（1-indexed）时先换算为 n-k；封装函数时第一行做边界检查。

参数 2：pivot_strategy（主元选择策略）

  • 含义：决定用哪个元素作为划分基准。
  • 类型：枚举或可调用对象（传入数组与区间，返回下标）。
  • 默认值：教学实现常用 last 或 first；工业实现常用随机主元或 median-of-three。
  • 取值范围：first、last、random、median_of_three、ninther（九数取中）、median_of_medians（BFPRT）。
  • 对结果的影响：决定期望常数与最坏情况。first/last 对有序数组会每次只排除一个元素，退化为 $ O(n^2) $；random 使期望为 $ O(n) $；median_of_three 能抵抗常见的锯齿输入，但仍可被构造性数据攻击；median_of_medians 保证最坏 $ O(n) $，但常数通常是随机的 3 到 10 倍。
  • 推荐设置：通用场景用 random；面向不可信输入或硬实时场景用 introselect（随机 + 深度上限 + BFPRT 兜底）；小数组（$ n<50 $）可用 median_of_three 降低随机数开销。

参数 3：partition_scheme（划分方式）

  • 含义：如何把区间分成"小于、等于、大于"主元的三部分。
  • 类型：枚举。
  • 默认值：教学代码多用 Lomuto；工业代码多用 Hoare 或三路划分。
  • 取值范围：Lomuto 单指针、Hoare 双指针、三路 Dutch National Flag。
  • 对结果的影响：Lomuto 写法简单但交换次数多，且所有元素相等时会把全部元素分到一侧，退化为 $ O(n^2) $；Hoare 双指针交换次数少、划分更均衡，但边界条件容易写错；三路划分把等于主元的元素集中到中间，全等数组可以一趟结束，是含重复值数据的正确选择。
  • 推荐设置：数据可能大量重复时必须三路；一般数据用 Hoare 或三路；只在教学演示中用 Lomuto。

参数 4：lo / hi（搜索区间）

  • 含义：当前仍在候选范围内的闭区间 [lo, hi]。
  • 类型：整数下标。
  • 默认值：lo=0、hi=n-1。
  • 取值范围：$ 0 \le lo \le hi < n $；空区间用 lo > hi 表示。
  • 对结果的影响：区间语义不统一是快速选择最常见的 bug 来源。闭区间配 while lo <= hi，半开区间配 while lo < hi；混用会导致死循环、漏掉端点或数组越界。
  • 推荐设置：全程统一闭区间；每次递归前显式判断 lo <= hi；把区间收缩写成 hi = lt - 1 / lo = gt + 1，不要写成 lt / gt。

参数 5：key / comp（比较键与比较器）

  • 含义：定义"大小"的规则。Python 用 key 把元素映射为可比较的键；C++ 用 comp 传入严格弱序比较器。
  • 类型：可调用对象（Python Callable[[T], Any]，C++ bool(const T&, const T&)）。
  • 默认值：None，即直接比较元素本身。
  • 取值范围：任意全序函数；C++ 比较器必须满足严格弱序（非自反、传递、不可比传递）。
  • 对结果的影响：决定"第 k 小"的语义。对记录按多字段排序时，键应是元组；对浮点数含 NaN 时，比较不满足全序，结果未定义，需要先过滤或自定义 NaN 规则。
  • 推荐设置：Python 中预先物化键（decorate），避免每次比较都调用昂贵函数；C++ 中确保比较器对相等元素返回 false；对结构体排序时用 std::tie 生成字典序。

参数 6：random_seed（随机种子）

  • 含义：随机主元的随机源种子。
  • 类型：整数、None 或随机数生成器对象。
  • 默认值：None，使用系统熵源。
  • 取值范围：任意整数；相同种子会复现相同的 pivot 序列。
  • 对结果的影响：不影响正确性，只影响性能与可复现性。固定种子便于复现实验和排查性能问题，但在对抗场景下可能被对手利用，制造固定退化路径。
  • 推荐设置：单元测试固定种子；生产环境不固定；分布式训练/批处理记录种子，便于复现。

参数 7：depth_limit（递归深度上限，introselect）

  • 含义：允许连续随机划分的最大深度，超过后切换到 BFPRT 的确定性选主元，防止最坏情况。
  • 类型：整数。
  • 默认值：常见实现取 2 * floor(log2(n))。
  • 取值范围：大于等于 0；0 表示立即使用 BFPRT。
  • 对结果的影响：太小会让算法过早进入高常数路径，平均性能下降；太大则失去最坏情况保护，退化为 $ O(n^2) $ 的风险上升。
  • 推荐设置：2 floor(log2(n))；对尾延迟敏感的服务可降到 1.5 floor(log2(n))，用少量平均性能换更稳的最坏保证。

参数 8：insertion_threshold（小区间阈值）

  • 含义：当区间长度小于该阈值时，改用插入排序或直接线性扫描，避免递归与函数调用开销。
  • 类型：整数。
  • 默认值：工业实现常见 16 到 32。
  • 取值范围：1 到 64。
  • 对结果的影响：适度增大能减少递归层数、改善缓存局部性；过大则让小区间退化为 $ O(m^2) $，整体常数上升。
  • 推荐设置：C/C++ 取 16；Python 因解释器开销大，可取 32；若区间已经很小且只需要最小值，直接用 min() 扫描。

参数 9：duplicate_policy（重复元素策略）

  • 含义：如何处理与主元相等的元素。
  • 类型：枚举。
  • 默认值：两路划分，不单独处理相等元素。
  • 取值范围：两路、三路、先检测全等再直接返回。
  • 对结果的影响：全等数组在两路划分下每次只能排除一个元素，复杂度 $ O(n^2) $；三路划分一次把全部相等元素归位，复杂度 $ O(n) $。对 top-k 场景，重复值还会影响"第 k 个"的稳定性语义。
  • 推荐设置：默认三路；如果业务保证元素互异，可用两路以减少一次比较。

参数 10：return_mode（返回语义）

  • 含义：函数返回什么，以及是否修改原数组。
  • 类型：枚举。
  • 默认值：返回第 $ k $ 个元素的值。
  • 取值范围：返回值、返回下标、返回前 $ k $ 个元素、原地重排后返回 None。
  • 对结果的影响：决定是否需要复制数组、是否需要额外 $ O(k) $ 空间。std::nth_element 返回 void，但保证 nth 位置上的元素就是排序后该位置的元素，且左侧元素都不大于它、右侧元素都不小于它。
  • 推荐设置：只取一个值用返回值模式；要 top-k 集合，先复制再划分，然后取前 $ k $ 个；不允许修改输入时务必先 copy。

代码示例

下面给出一个可直接运行的 Python 实现：随机主元 + 三路划分 + 迭代收缩。每一行都加了注释，末尾附带随机对照测试与全等数组测试。

import random
from typing import List


def quickselect(nums: List[int], k: int) -> int:
    """返回升序意义下第 k 个元素（0-indexed），原地重排 nums。"""
    if not 0 <= k < len(nums):                     # 边界检查：k 必须在 [0, n-1] 内
        raise IndexError(f"k={k} 越界，应在 [0, {len(nums) - 1}] 内")  # 越界立即报错，避免后续死循环

    a = nums                                       # 用局部变量指向原列表，明确"原地修改"语义
    lo, hi = 0, len(a) - 1                         # 当前搜索区间为闭区间 [lo, hi]

    while lo <= hi:                                # 区间非空时继续；空区间说明逻辑有误
        pivot_pos = random.randint(lo, hi)         # 在区间内均匀随机选一个下标作为主元
        a[lo], a[pivot_pos] = a[pivot_pos], a[lo]  # 把主元交换到区间最左端，便于后续扫描
        pivot = a[lo]                              # 保存主元的值，后续比较都用它

        lt, i, gt = lo, lo + 1, hi                 # lt 指向"小于区"的右边界，gt 指向"大于区"的左边界
        while i <= gt:                             # i 是当前扫描指针，直到与 gt 相遇
            if a[i] < pivot:                       # 情况一：当前元素小于主元
                a[lt], a[i] = a[i], a[lt]          # 把它换到小于区末尾
                lt += 1                            # 小于区向右扩张一格
                i += 1                             # 当前元素已处理，扫描指针右移
            elif a[i] > pivot:                     # 情况二：当前元素大于主元
                a[i], a[gt] = a[gt], a[i]          # 把它换到大于区开头
                gt -= 1                            # 大于区向左扩张一格
            else:                                  # 情况三：当前元素等于主元
                i += 1                             # 留在等于区，扫描指针右移

        # 划分结束：a[lo:lt] < pivot，a[lt:gt+1] == pivot，a[gt+1:hi+1] > pivot
        if k < lt:                                 # 目标排名落在小于区
            hi = lt - 1                            # 丢弃等于区和大于区，只保留左段
        elif k > gt:                               # 目标排名落在大区
            lo = gt + 1                            # 丢弃小于区和等于区，只保留右段
        else:                                      # 目标排名落在等于区
            return a[k]                            # 等于区所有元素都等于 pivot，直接返回

    raise RuntimeError("unreachable: 区间收缩逻辑错误")  # 正常情况下不会到达这里


def test_quickselect() -> None:
    """随机对照测试：与 sorted 的结果逐一比较。"""
    random.seed(20261106)                          # 固定随机种子，保证测试可复现
    for n in range(1, 60):                         # 覆盖从 1 到 59 的各种规模
        for _ in range(200):                       # 每个规模跑 200 组随机数据
            arr = [random.randint(-20, 20) for _ in range(n)]  # 故意制造大量重复值
            k = random.randrange(n)                # 随机选择一个目标排名
            got = quickselect(arr[:], k)           # 传入副本，避免测试之间互相影响
            want = sorted(arr)[k]                  # 用排序得到标准答案
            assert got == want, (arr, k, got, want)  # 任何不一致都立即失败
    all_equal = [7] * 1000                         # 构造全等数组，专门测试三路划分
    assert quickselect(all_equal, 500) == 7        # 全等数组应能在 O(n) 内返回
    print("all tests passed")                      # 全部通过后输出提示


if __name__ == "__main__":                         # 作为脚本直接运行时执行测试
    test_quickselect()                             # 调用测试函数

对应的 C++ 工业用法如下，std::nth_element 内部通常就是 introselect：

#include <algorithm>                           // 提供 std::nth_element
#include <vector>                              // 提供 std::vector
#include <iostream>                            // 提供 std::cout

int main() {
    std::vector<int> v{3, 7, 1, 9, 5, 2, 8, 4};   // 待选择的数组
    std::size_t k = 6;                              // 目标排名，0-indexed
    std::nth_element(v.begin(), v.begin() + k, v.end());  // 原地重排，使 v[k] 为第 k 小

}

复杂度分析

时间复杂度

  • 最好情况：第一次选中的主元恰好落在目标位置，只需一趟划分，比较 $ n-1 $ 次，$ O(n) $。
  • 平均情况：随机主元下，每次划分的期望规模按几何级数衰减。设第 $ i $ 层处理的区间长度为 $ n_i $，则 $ E[n_{i+1}] \le n_i/2 $，总代价为 $ n + n/2 + n/4 + \cdots < 2n $，故期望 $ O(n) $。更精细的比较次数上界为 $ 4n $，查找中位数的期望比较次数约为 $ 3.39n $。
  • 最坏情况：每次主元都落在区间端点，问题规模只减 1，总代价为 $ \sum_{i=1}^{n} i = n(n+1)/2 = O(n^2) $。对已排序数组使用"取第一个元素"作为主元，就会精确触发这种退化。
  • 确定性最坏 $ O(n) $：BFPRT（median of medians）通过分组取中位数保证划分比例至少 $ 3:7 $，递推 $ T(n) \le T(n/5) + T(7n/10) + O(n) $，因 $ 1/5 + 7/10 = 0.9 < 1 $，总代价为 $ O(n) $；代价是常数显著增大，工程中通常只在深度超限时启用。
  • 与全排序对比：全排序的决策树下界是 $ \Omega(n \log n) $；快速选择只关心一个排名，期望 $ O(n) $，在 $ n=10^6 $ 时通常只需几百万次比较，而排序需要约两千万次。

空间复杂度

  • 迭代版本：只使用 lo、hi、lt、i、gt、pivot 等常数个变量，额外空间 $ O(1) $。
  • 递归版本：期望递归深度 $ O(\log n) $，最坏 $ O(n) $；如果编译器不做尾递归优化，栈空间分别为 $ O(\log n) $ 与 $ O(n) $。
  • BFPRT：分组需要 $ O(n) $ 的临时空间（或原地分组），递归栈 $ O(\log n) $。

工程常数

  • 划分是顺序扫描，缓存友好；随机主元只引入一次随机访问。
  • 三路划分在重复值多时显著减少无效递归；两路划分在重复值多时会产生大量"空划分"。
  • 对小数组，函数调用与递归开销可能超过比较本身，插入排序阈值能明显降低常数。
  • 在 GPU 或向量化场景，快速选择的分支预测不友好，反而不如基于直方图的选择算法。

应用场景

  • Top-K 与排行榜：只找出第 $ K $ 名的阈值，再线性扫一遍收集所有不小于阈值的元素，整体 $ O(n) $；比全排序后再截断更适合大数组。
  • 分位数统计：计算 P50、P95、P99 延迟、收入分布、成绩分布；监控系统常用快速选择避免对百万级样本全排序。
  • 中位数滤波：图像去噪、信号去噪中，对滑动窗口求中位数；窗口较小时可用插入排序，窗口较大时可用快速选择或双堆。
  • C++ 标准库与数值库：std::nth_element、NumPy 的 np.partition、Pandas 的 quantile 在底层都使用选择算法。
  • 数据库 top-k 查询：ORDER BY ... LIMIT K 在无法利用索引时，常用堆或选择算法先定位阈值，再回表取数。
  • 机器学习：kNN 中找第 $ k $ 近邻的距离、DBSCAN 的 k-距离图、K-Means++ 的加权采样，都需要频繁做选择。
  • 快速排序的优化：三路快排的划分逻辑与快速选择完全一致；理解快速选择有助于写出正确的三路划分。
  • 面试高频题：LeetCode 215「数组中的第 K 个最大元素」、剑指 Offer 40「最小的 k 个数」、LeetCode 973「最接近原点的 K 个点」都可以用快速选择求解。

OPTICS 聚类（Ordering Points To Identify the Clustering Structure）

类别：无监督学习 | 难度：中等

算法简介

OPTICS 由 Ankerst、Breunig、Kriegel 与 Sander 在 1999 年 SIGMOD 上提出，全称 Ordering Points To Identify the Clustering Structure。它要解决 DBSCAN 最棘手的问题：DBSCAN 的邻域半径 $ \varepsilon $ 是全局固定的，当数据中同时存在高密度簇与低密度簇时，一个 $ \varepsilon $ 要么把高密度簇过度合并，要么把低密度簇整体判为噪声。OPTICS 不再输出"某个固定 $ \varepsilon $ 下的扁平簇"，而是按照密度可达关系把样本排成一个序列，并记录每个样本的可达距离，形成一张可达距离图。图中每一个"山谷"对应一个簇，山谷越深代表该处密度越高；山谷之间的高峰则是簇边界或噪声。用户可以在这张图上按任意密度尺度切分，也可以让算法用 $ \xi $ 参数自动提取簇。因此 OPTICS 常被理解为"一次运行，输出所有 $ \varepsilon $ 下的 DBSCAN 结果"的算法，特别适合密度不均匀、簇数未知的数据。

原理示意图

左图展示两个密度不同的簇：绿色簇点间距小、密度高，蓝色簇点间距大、密度低。对核心点 $ p $ 而言，其 $ \varepsilon $-邻域内至少包含 min_samples 个点，因此 $ p $ 的核心距离较小；从 $ p $ 看向 $ q $ 时，可达距离取"$ p $ 的核心距离"与"$ p $、$ q $ 的实际距离"中的较大者。右图是把所有点按 OPTICS 的访问顺序排列后画出的可达距离曲线：曲线下探形成的山谷对应簇，山谷越深说明密度越高；两个山谷之间的高峰是簇边界；孤立的低密度点会形成接近顶部的高原。由于高密度簇与低密度簇的谷底深度不同，OPTICS 能在一张图上同时保留两种密度的结构，而单一 $ \varepsilon $ 的 DBSCAN 做不到。

数学公式

1. ε-邻域与核心距离

$$ N_\varepsilon(p) = \{\, q \in D \mid d(p,q) \le \varepsilon \,\}, \qquad d_{\text{core}}(p) = \min\{\, r \ge 0 \;\big|\; |N_r(p)| \ge \text{min\_samples} \,\} $$

变量解释：

  • $ D $：样本集合，共 $ n $ 个点。
  • $ p $：当前考察的样本点。
  • $ N_\varepsilon(p) $：与 $ p $ 距离不超过 $ \varepsilon $ 的所有样本构成的邻域。
  • $ d(p,q) $：度量函数，默认是 Minkowski 距离（$ p=2 $ 时为欧氏距离）。
  • $ \text{min\_samples} $：成为核心点所需的最小邻域样本数（包含 $ p $ 自身）。
  • $ d_{\text{core}}(p) $：使 $ p $ 的邻域至少包含 min_samples 个点的最小半径；若在 max_eps 内都达不到，则记为 $ \infty $，$ p $ 永远不是核心点。
  • 等价说法：$ d_{\text{core}}(p) $ 是 $ p $ 到第 min_samples 个最近邻的距离，计数时把 $ p $ 自己算作第 1 个（距离为 0）。

2. 可达距离

$$ r(p,q) = \max\{\, d_{\text{core}}(p),\; d(p,q) \,\} $$

变量解释：

  • $ r(p,q) $：从核心点 $ p $ 出发观察 $ q $ 时的可达距离。
  • $ d_{\text{core}}(p) $：$ p $ 的核心距离，起"下限"作用。
  • $ d(p,q) $：$ p $ 与 $ q $ 的实际距离。
  • 取最大值意味着：只要 $ q $ 落在 $ p $ 的核心邻域内，无论多近，可达距离都不小于 $ p $ 的核心距离；这让同一核心点周围的点拥有相近的可达距离，避免曲线因个别近邻而剧烈抖动。

3. 排序过程中的可达距离更新

$$ r_{\text{new}}(q) = \min\{\, r_{\text{old}}(q),\; \max(d_{\text{core}}(p),\, d(p,q)) \,\} $$

变量解释：

  • $ r_{\text{old}}(q) $：$ q $ 当前记录的可达距离，初始为 $ \infty $。
  • $ p $：刚刚被处理的核心点。
  • $ q $：$ p $ 的邻域中尚未处理的点。
  • 取最小值表示：一个点可能被多个核心点"看到"，最终记录的是所有可能路径中最短的那条可达距离，这也是"密度可达"的最优路径。

4. ξ 陡峭度与簇边界

$$ \text{上升陡坡：}\; r_{i+1} \le (1-\xi)\,r_i \qquad\qquad \text{下降陡坡：}\; r_{i+1} \ge \frac{r_i}{1-\xi} $$

变量解释：

  • $ r_i $、$ r_{i+1} $：按 ordering_ 排列后相邻两个样本的可达距离。
  • $ \xi \in (0,1) $：最小陡峭度阈值，默认 0.05。
  • $ 1-\xi $：允许的相对下降比例。$ \xi=0.05 $ 表示相邻两点的可达距离若下降超过 5%，就认为进入了"陡峭上升沿"（在图中从左向右看，可达距离突然变小）。
  • 下降陡坡的判别式等价于 $ r_{i+1}(1-\xi) \ge r_i $，即从谷底离开时可达距离突然变大。
  • 簇的起点通常在一个陡峭上升沿之后，终点在随后的陡峭下降沿之前；min_cluster_size 用于过滤过短的区间。

5. DBSCAN 式切分

$$ \text{core}(p) \iff d_{\text{core}}(p) \le \varepsilon, \qquad q \text{ 与 } p \text{ 密度相连} \iff \exists\, p_1,\dots,p_m:\ p_1=p,\ p_m=q,\ d(p_{i+1},p_i) \le \varepsilon $$

变量解释：

  • $ \varepsilon $：cluster_method='dbscan' 时使用的全局半径。
  • $ \text{core}(p) $：核心点判定，等价于邻域内至少有 min_samples 个点。
  • 密度相连：存在一条链，链上相邻点的距离都不超过 $ \varepsilon $，且中间点都是核心点；所有互相密度相连的点构成一个簇。
  • 在 OPTICS 中，这个 $ \varepsilon $ 只是对可达距离图做一条水平切线，切线以下的连续区间就是一个簇。

核心要点

  • 一次运行，多尺度输出：OPTICS 不把 $ \varepsilon $ 写死，而是输出可达距离图；不同 $ \varepsilon $ 等价于在图上画不同高度的水平线。
  • 核心距离是密度的局部度量：它随点的局部密度自适应变化，高密度区域核心距离小，低密度区域核心距离大。
  • 可达距离是"从核心点看世界"的距离：它把核心距离作为下限，使同一簇内的可达距离保持平滑。
  • 排序不是聚类结果：ordering_ 只是访问顺序，真正的簇标签要靠 xi 或 dbscan 提取。
  • xi 提取看的是"形状"而不是"高度"：它寻找可达距离曲线的陡峭沿，因此能同时发现不同密度的簇。
  • min_samples 同时影响核心距离与最小簇规模：它是 OPTICS 最关键的参数，比 DBSCAN 的 eps 更稳健，但仍需按数据密度调整。
  • 高维会削弱密度概念：维度升高后距离趋于集中，任何基于距离的密度聚类都会退化，建议先降维或使用余弦距离。
  • sklearn 实现是 $ O(n^2) $：官方文档明确说明未使用堆来管理候选点，因此大数据集要谨慎，或改用 HDBSCAN。

技术细节与参数详解

sklearn.cluster.OPTICS 的完整签名如下（scikit-learn 1.9 文档）：

OPTICS(*, min_samples=5, max_eps=inf, metric='minkowski', p=2,
       metric_params=None, cluster_method='xi', eps=None, xi=0.05,
       predecessor_correction=True, min_cluster_size=None,
       algorithm='auto', leaf_size=30, memory=None, n_jobs=None)

下面逐参数拆解。

参数 1：min_samples

  • 含义：一个点的邻域内至少要有多少个样本（包含该点自身）才算核心点；同时决定核心距离取第几个近邻。
  • 类型：int 或 float。
  • 默认值：5。
  • 取值范围：整数必须大于 1；浮点数必须在 $ (0,1) $ 之间，表示样本总数的比例，实际取 $ \lceil \text{min\_samples} \times n \rceil $，且至少为 2。
  • 对结果的影响：增大它会让密度估计更平滑、核心距离更大、更多点被判为噪声，簇数量减少且更保守；减小它会提高敏感度，容易把噪声误判为簇，也容易产生碎片化的小簇。维度越高，需要的 min_samples 越大，经验值为 $ 2 \times $ 维度。
  • 推荐设置：从 5 到 10 起调；样本量很大时用比例（如 0.01 到 0.02）；用 k-距离图的拐点辅助选择；对含噪数据宁大勿小。

参数 2：max_eps

  • 含义：邻域搜索的最大半径，也是可达距离的上限；超过该半径的点不再认为与当前点密度可达。
  • 类型：float。
  • 默认值：np.inf。
  • 取值范围：$ (0, +\infty] $。
  • 对结果的影响：取 $ \infty $ 时会考虑所有尺度，结构最完整但运行最慢；减小它能显著加速，并截断大尺度结构，但可能把低密度簇整体丢掉。它只影响"搜索范围"，不是最终的簇边界。
  • 推荐设置：探索阶段用默认 $ \infty $；生产环境用样本距离的高分位数（如 90% 到 99%）作为上限，兼顾速度与召回。

参数 3：metric

  • 含义：距离度量函数。
  • 类型：str 或可调用对象。
  • 默认值：'minkowski'。
  • 取值范围：scikit-learn 支持的 cityblock、cosine、euclidean、l1、l2、manhattan，以及 scipy.spatial.distance 中的 braycurtis、canberra、chebyshev、correlation、dice、hamming、jaccard、mahalanobis、minkowski、seuclidean、sqeuclidean 等；也可传 'precomputed'，此时 X 必须是方阵距离矩阵。
  • 对结果的影响：决定"邻域"的形状与语义。连续特征用欧氏距离；文本嵌入或高维稀疏向量用余弦距离；经纬度用 haversine；集合型特征用 Jaccard；特征量纲差异大时用马氏距离或先标准化。
  • 推荐设置：连续数值特征先 StandardScaler 再用欧氏距离；嵌入向量用 cosine；地理坐标用 haversine；稀疏计数用 jaccard。

参数 4：p

  • 含义：Minkowski 距离的幂次。
  • 类型：float。
  • 默认值：2。
  • 取值范围：$ p \ge 1 $；$ p=1 $ 等价曼哈顿距离，$ p=2 $ 等价欧氏距离，$ p \to \infty $ 等价切比雪夫距离。
  • 对结果的影响：$ p $ 越小，距离对异常维度越鲁棒，邻域偏向菱形；$ p $ 越大，邻域偏向正方形，最大维度差异主导距离。它只在 metric='minkowski' 时生效。
  • 推荐设置：默认 2；高维稀疏或含异常值时试 $ p=1 $；需要"任一维度超标即远"时用大 $ p $。

参数 5：metric_params

  • 含义：传给距离函数的额外关键字参数。
  • 类型：dict 或 None。
  • 默认值：None。
  • 取值范围：取决于所选度量；例如 mahalanobis 需要 VI（协方差矩阵的逆），seuclidean 需要 V（方差向量）。
  • 对结果的影响：只在特定度量下生效；参数错误会直接报错或得到无意义的距离。
  • 推荐设置：使用马氏距离时传入稳健估计的协方差逆矩阵；其余情况保持 None。

参数 6：cluster_method

  • 含义：从可达距离图中提取簇的方法。
  • 类型：str，二选一。
  • 默认值：'xi'。
  • 取值范围：'xi' 或 'dbscan'。
  • 对结果的影响：'xi' 按陡峭度自动识别簇边界，能同时处理不同密度，簇数由数据决定；'dbscan' 按单一 eps 水平切分，结果等价于在该 eps 下运行 DBSCAN，适合需要可控密度阈值或复现实验的场景。
  • 推荐设置：探索性分析用 'xi'；生产环境若已有明确密度阈值，用 'dbscan' 更可解释。

参数 7：eps

  • 含义：cluster_method='dbscan' 时使用的全局邻域半径。
  • 类型：float。
  • 默认值：None，此时自动取 max_eps。
  • 取值范围：$ (0, \text{max\_eps}] $。
  • 对结果的影响：越大，簇越少、越大，更多边界点被吸收；越小，簇越多、噪声越多。它是 DBSCAN 式的"一刀切"密度阈值。
  • 推荐设置：用 k-距离图的拐点，或先跑 xi 找到山谷对应的可达距离，再把它作为 eps；不要超过 max_eps。

参数 8：xi

  • 含义：判定"陡峭沿"的最小相对陡峭度。
  • 类型：float。
  • 默认值：0.05。
  • 取值范围：$ (0, 1) $。
  • 对结果的影响：越小，越容易把微小的起伏判为边界，簇更多、更碎；越大，越保守，只保留显著的密度变化，簇更少。0.05 表示相邻可达距离变化超过 5% 才算陡坡。
  • 推荐设置：从 0.05 起，在 0.01 到 0.1 之间扫描；配合 min_cluster_size 抑制碎片。

参数 9：predecessor_correction

  • 含义：是否用 OPTICS 计算出的前驱关系修正簇边界。
  • 类型：bool。
  • 默认值：True。
  • 取值范围：True 或 False。
  • 对结果的影响：开启后可以减少 $ \xi $ 方法把本应分离的簇错误合并的情况；官方文档指出对大多数数据集影响很小，但在边界复杂的数据上更稳。
  • 推荐设置：保持 True；若怀疑簇被过度合并，可关闭后对比。

参数 10：min_cluster_size

  • 含义：一个簇允许的最小样本数。
  • 类型：int 或 float。
  • 默认值：None，此时使用 min_samples 的值。
  • 取值范围：整数大于 1；浮点数在 $ (0,1) $ 之间表示比例，实际取 $ \lceil \text{min\_cluster\_size} \times n \rceil $，至少为 2。
  • 对结果的影响：增大它会把小簇判为噪声，抑制碎片；过大会丢掉业务上重要的小群体。只在 cluster_method='xi' 时生效。
  • 推荐设置：按业务最小群体规模设定；没有先验时用 1% 到 5% 的比例。

参数 11：algorithm

  • 含义：最近邻搜索使用的算法。
  • 类型：str。
  • 默认值：'auto'。
  • 取值范围：'auto'、'ball_tree'、'kd_tree'、'brute'。
  • 对结果的影响：只影响速度与内存，不影响数学结果。kd_tree 适合低维稠密数据，ball_tree 适合维度稍高或非均匀数据，brute 是暴力搜索；稀疏输入会强制使用 brute。
  • 推荐设置：默认 'auto'；低维大数据用 'kd_tree'；高维（几十维以上）直接用 'brute'，因为树结构会退化。

参数 12：leaf_size

  • 含义：传给 BallTree 或 KDTree 的叶节点大小。
  • 类型：int。
  • 默认值：30。
  • 取值范围：一般 10 到 100。
  • 对结果的影响：影响树构建与查询的速度和内存；叶节点太小会让树更深、查询分支更多，太大则叶内线性扫描变慢。
  • 推荐设置：30 到 50；数据量大时可适当增大以减少内存。

参数 13：memory

  • 含义：缓存树计算结果的路径或 joblib.Memory 对象。
  • 类型：str 或具有 joblib.Memory 接口的对象。
  • 默认值：None，不缓存。
  • 取值范围：可写的目录路径。
  • 对结果的影响：只影响重复计算的速度，不影响结果；缓存会占用磁盘。
  • 推荐设置：调参阶段设置缓存目录；生产环境若数据只跑一次可不设。

参数 14：n_jobs

  • 含义：并行执行邻域搜索的进程数。
  • 类型：int 或 None。
  • 默认值：None，表示 1。
  • 取值范围：正整数；-1 表示使用所有处理器。
  • 对结果的影响：只影响速度，不影响结果；进程数过多会增加内存开销。
  • 推荐设置：离线批处理用 -1；内存受限时设为物理核数的一半。

代码示例

下面的代码构造两个密度不同的簇并加入均匀噪声，先标准化，再运行 OPTICS，最后把可达距离图与聚类结果画在一起。每一行都加了注释。

import numpy as np                                  # 数值计算与数组拼接
import matplotlib.pyplot as plt                     # 绘图
from sklearn.cluster import OPTICS, DBSCAN          # 对比两种密度聚类
from sklearn.datasets import make_blobs             # 生成合成簇
from sklearn.preprocessing import StandardScaler    # 标准化，避免量纲影响距离

rng = np.random.RandomState(42)                     # 固定随机种子，保证结果可复现

X_dense, _ = make_blobs(                            # 生成高密度簇
    n_samples=400,                                  # 400 个样本
    centers=[[0.0, 0.0]],                           # 簇心在原点
    cluster_std=0.35,                               # 标准差小，密度高
    random_state=1                                  # 固定种子
)

X_sparse, _ = make_blobs(                           # 生成低密度簇
    n_samples=120,                                  # 120 个样本
    centers=[[4.0, 4.0]],                           # 簇心在 (4, 4)
    cluster_std=1.10,                               # 标准差大，密度低
    random_state=2                                  # 固定种子
)

noise = rng.uniform(low=-2.0, high=6.0, size=(30, 2))  # 在较大范围内撒 30 个均匀噪声点
X = np.vstack([X_dense, X_sparse, noise])           # 按行拼接成完整数据集
X = StandardScaler().fit_transform(X)               # 标准化到零均值、单位方差

optics = OPTICS(                                    # 初始化 OPTICS
    min_samples=10,                                 # 邻域至少 10 个点（含自身）才算核心点
    max_eps=np.inf,                                 # 不限制最大半径，保留所有尺度
    metric="euclidean",                             # 标准化后用欧氏距离
    cluster_method="xi",                            # 用 xi 自动提取簇
    xi=0.1,                                         # 最小陡峭度 10%，更保守，避免把密度波动切成碎片
    min_cluster_size=0.03,                          # 簇至少占样本的 3%
    algorithm="auto",                               # 自动选择最近邻算法
    n_jobs=-1                                       # 使用全部 CPU 核
)

labels = optics.fit_predict(X)                      # 拟合并直接返回簇标签，噪声为 -1
n_clusters = len(set(labels)) - (1 if -1 in labels else 0)  # 统计簇数，排除噪声标签

print(f"簇数量: {n_clusters}")                       # 输出发现的簇数
print(f"噪声点: {(labels == -1).sum()}")             # 输出噪声点数量

space = np.arange(len(X))                           # x 轴：样本在 ordering 中的位置
reachability = optics.reachability_[optics.ordering_]  # 按 ordering 重排可达距离
core_dist = optics.core_distances_[optics.ordering_]   # 按 ordering 重排核心距离

fig, axes = plt.subplots(2, 2, figsize=(12, 8))     # 2x2 画布：可达图、OPTICS、DBSCAN、核心距离
ax = axes[0, 0]                                     # 第一个子图：可达距离图
ax.plot(space, reachability, color="#6366f1", linewidth=1.0)  # 绘制可达距离曲线
ax.set_xlabel("Sample index in ordering_")          # x 轴标签
ax.set_ylabel("Reachability distance")              # y 轴标签
ax.set_title("OPTICS reachability plot")            # 子图标题

ax = axes[0, 1]                                     # 第二个子图：OPTICS 聚类结果
unique_labels = sorted(set(labels))                 # 取出所有标签并排序
colors = plt.cm.tab10(np.linspace(0, 1, 10))        # 准备 10 种颜色
for idx, label in enumerate(unique_labels):         # 遍历每个标签
    mask = labels == label                          # 当前标签的布尔掩码
    if label == -1:                                 # 噪声单独用黑色叉号表示
        ax.scatter(X[mask, 0], X[mask, 1], s=14, c="k", marker="x", label="noise")
    else:                                           # 普通簇用彩色圆点表示
        ax.scatter(X[mask, 0], X[mask, 1], s=14, color=colors[idx % 10], label=f"cluster {label}")
ax.set_title("OPTICS labels (xi method)")           # 子图标题
ax.legend(fontsize=8, loc="best")                   # 显示图例

dbscan = DBSCAN(eps=0.25, min_samples=10)           # 用固定 eps 的 DBSCAN 作为对照
db_labels = dbscan.fit_predict(X)                   # 拟合 DBSCAN
ax = axes[1, 0]                                     # 第三个子图：DBSCAN 结果
for idx, label in enumerate(sorted(set(db_labels))):  # 遍历 DBSCAN 的标签
    mask = db_labels == label                       # 当前标签的掩码
    if label == -1:                                 # 噪声用黑色叉号
        ax.scatter(X[mask, 0], X[mask, 1], s=14, c="k", marker="x", label="noise")
    else:                                           # 普通簇用彩色圆点
        ax.scatter(X[mask, 0], X[mask, 1], s=14, color=colors[idx % 10], label=f"cluster {label}")
ax.set_title("DBSCAN labels (eps=0.25)")            # 子图标题
ax.legend(fontsize=8, loc="best")                   # 显示图例

ax = axes[1, 1]                                     # 第四个子图：核心距离曲线
ax.plot(space, core_dist, color="#22c55e", linewidth=1.0)  # 绘制核心距离
ax.set_xlabel("Sample index in ordering_")          # x 轴标签
ax.set_ylabel("Core distance")                      # y 轴标签
ax.set_title("Core distance along ordering")        # 子图标题

plt.tight_layout()                                  # 自动调整子图间距，避免标签重叠
plt.savefig("optics_demo.png", dpi=150)             # 保存图片到当前目录
plt.show()                                          # 在交互环境中显示图片

运行这段代码会得到四个子图：左上角的可达距离曲线会出现两个明显深浅不同的山谷，分别对应高密度簇与低密度簇；右上角是 xi 方法提取的簇；左下角是固定 eps=0.25 的 DBSCAN 结果，通常会丢掉低密度簇或把它大量判为噪声；右下角是核心距离曲线，可以用来辅助选择 min_samples 和 eps。

复杂度分析

时间复杂度

  • 原始论文：使用空间索引（如 R 树）时，邻域查询的平均代价为 $ O(\log n) $，总时间约为 $ O(n \log n) $；不使用索引时退化为 $ O(n^2) $。
  • sklearn 实现：官方文档明确指出，它先对每个点做 k 近邻搜索以确定核心距离，然后在构造簇序时只对未处理点计算可达距离；由于没有使用堆管理候选点，时间复杂度为 $ O(n^2) $。
  • 参数影响：减小 max_eps 会缩小邻域搜索范围，实际运行时间下降；增大 min_samples 会让每次 k 近邻查询变重；n_jobs 可以并行化邻域搜索，但不改变渐进复杂度。
  • 高维退化：基于树的方法在高维空间失效，最近邻查询退化为暴力扫描，实际时间接近 $ O(n^2 d) $，$ d $ 为维度。

空间复杂度

  • kneighbors 需要为每个点保存 min_samples 个邻居的下标与距离，空间为 $ O(n \cdot \text{min\_samples}) $。
  • ordering_、reachability_、core_distances_、predecessor_ 各占 $ O(n) $。
  • 若使用 brute 且一次性物化距离矩阵，最坏可达到 $ O(n^2) $；通常实现会分块计算，不会完整存储。
  • cluster_hierarchy_ 在最坏情况下可包含 $ O(n) $ 个区间。

应用场景

  • 地理空间热点识别：把基站、订单地址、POI 的经纬度作为特征，用 haversine 距离聚类；城市中心密度高、郊区密度低，OPTICS 能同时识别而不必为每个区域调 eps。
  • 异常检测：可达距离很大、且不属于任何山谷的点就是低密度异常点；与孤立森林、LOF 相比，OPTICS 还能给出异常点所在的密度尺度。
  • 客户分群：消费频次、金额、活跃度等特征标准化后聚类；高价值客户群与长尾客户群密度不同，单一 eps 的 DBSCAN 容易把长尾群判为噪声。
  • 图像颜色量化：把像素的 RGB 或 Lab 值作为三维样本，用 OPTICS 找出主要颜色簇；不同图片的颜色分布密度差异很大，自适应密度更稳。
  • 轨迹与传感器数据分析：对停留点、速度、方向等特征聚类，识别不同密度的行为模式。
  • 天文与生物信息学：星体分布、细胞群体、基因表达数据中常出现密度差异极大的子群，OPTICS 的可达距离图便于人工判读。
  • 作为 HDBSCAN 的前置探索：先用 OPTICS 的可达图观察密度结构，再用 HDBSCAN 做生产级自动聚类，二者思想一脉相承。

AI生成

DPO 直接偏好优化（Direct Preference Optimization）

类别：大模型对齐 | 难度：困难

算法简介

DPO（Direct Preference Optimization）由 Rafailov、Sharma、Mitchell 等人在 2023 年提出，论文标题是 Direct Preference Optimization: Your Language Model is Secretly a Reward Model，发表于 NeurIPS 2023。它要解决的是 RLHF（基于人类反馈的强化学习）流程过重的问题：传统 RLHF 需要先训练一个奖励模型（Reward Model），再用 PPO 在线采样、估计优势、裁剪策略，工程链路长、超参数多、训练不稳定。DPO 的核心洞察是：在"最大化奖励减去 KL 正则"的目标下，最优策略与奖励函数之间存在闭式对应关系，因此可以把奖励函数用策略与参考模型的概率比表示出来，直接把它代入 Bradley-Terry 偏好模型，得到一个只依赖偏好对 $ (x, y_w, y_l) $ 的监督式损失。这样既不需要显式训练奖励模型，也不需要在线采样和 PPO，只需一次离线前向、一次反向，就能让模型提高"被选中回答"的相对概率、降低"被拒绝回答"的相对概率。DPO 因此成为大模型对齐中最常用的离线偏好优化方法之一。

原理示意图

图中左侧是数据流：同一个 prompt 分别送入可训练策略 $ \pi_\theta $ 与冻结参考 $ \pi_{\mathrm{ref}} $，得到被选中回答 $ y_w $ 与被拒绝回答 $ y_l $ 的 log 概率。中间把四组 log 概率组合成"策略相对参考的概率比"之差 $ \Delta_w-\Delta_l $，再乘以温度系数 $ \beta $ 得到 margin $ m $。右侧用 sigmoid 把 margin 映射成"偏好被选中的概率"，取负对数就是 DPO 损失；梯度只回传到策略，参考模型始终冻结。底部对比了 RLHF 的三阶段链路与 DPO 的两阶段链路，并给出 Bradley-Terry 偏好模型与隐式奖励的定义。

数学公式

1. Bradley-Terry 偏好模型

$$ P(y_w \succ y_l \mid x) = \sigma\big(r(x,y_w) - r(x,y_l)\big) = \frac{1}{1 + \exp\big[-\big(r(x,y_w) - r(x,y_l)\big)\big]} $$

变量解释：

  • $ x $：输入 prompt。
  • $ y_w $：被人类标注为更好的回答（winner / chosen）。
  • $ y_l $：被标注为更差的回答（loser / rejected）。
  • $ r(x,y) $：奖励函数，表示回答 $ y $ 在 prompt $ x $ 下的质量分数。
  • $ \sigma(\cdot) $：sigmoid 函数，把任意实数压缩到 $ (0,1) $，作为"$ y_w $ 优于 $ y_l $"的概率。
  • 这个模型假设：两个回答的偏好概率只取决于它们奖励的差值，而不取决于奖励的绝对大小。

2. KL 正则化的 RLHF 目标

$$ \max_{\pi_\theta}\ \mathbb{E}_{x\sim\mathcal{D},\,y\sim\pi_\theta(\cdot\mid x)}\big[r(x,y)\big] - \beta\,\mathbb{D}_{\mathrm{KL}}\big(\pi_\theta(\cdot\mid x)\,\|\,\pi_{\mathrm{ref}}(\cdot\mid x)\big) $$

变量解释：

  • $ \pi_\theta $：待优化的策略（语言模型），参数为 $ \theta $。
  • $ \mathcal{D} $：prompt 分布。
  • $ r(x,y) $：奖励函数。
  • $ \beta $：KL 正则系数，控制"追求高奖励"与"不要偏离参考模型"之间的权衡。
  • $ \pi_{\mathrm{ref}} $：参考策略，通常是 SFT 后的模型，冻结不更新。
  • $ \mathbb{D}_{\mathrm{KL}} $：KL 散度，衡量策略与参考模型在同一 prompt 下输出分布的差异。
  • 目标含义：在获得高奖励的同时，不要离 SFT 模型太远，以保住语言能力与安全性。

3. 最优策略的闭式解

$$ \pi^*(y\mid x) = \frac{1}{Z(x)}\,\pi_{\mathrm{ref}}(y\mid x)\,\exp\!\left(\frac{r(x,y)}{\beta}\right), \qquad Z(x) = \sum_{y}\pi_{\mathrm{ref}}(y\mid x)\exp\!\left(\frac{r(x,y)}{\beta}\right) $$

变量解释：

  • $ \pi^* $：上述 KL 正则目标的最优策略。
  • $ Z(x) $：配分函数（partition function），对所有可能回答求和，保证概率归一化。
  • $ \exp(r/\beta) $：用奖励对参考概率做指数加权；$ \beta $ 越小，奖励的影响越强，策略越激进。
  • 这个式子说明：最优策略就是把参考模型的分布按"奖励的指数"重新加权。

4. 隐式奖励（把奖励反解出来）

$$ r(x,y) = \beta \log\frac{\pi^*(y\mid x)}{\pi_{\mathrm{ref}}(y\mid x)} + \beta \log Z(x) $$

变量解释：

  • $ \pi^*(y\mid x)/\pi_{\mathrm{ref}}(y\mid x) $：最优策略相对参考模型的概率比。
  • $ \beta \log(\cdot) $：把 log 概率比缩放成奖励的量纲。
  • $ \beta \log Z(x) $：只与 prompt 有关的常数；在比较同一 prompt 下的两个回答时会被抵消。
  • 关键洞察：奖励不需要单独训练一个网络，它隐含在策略的概率比里。

5. DPO 损失函数

$$ \mathcal{L}_{\mathrm{DPO}}(\theta) = -\mathbb{E}_{(x,y_w,y_l)\sim\mathcal{D}}\left[\log\sigma\!\left(\beta\log\frac{\pi_\theta(y_w\mid x)}{\pi_{\mathrm{ref}}(y_w\mid x)} - \beta\log\frac{\pi_\theta(y_l\mid x)}{\pi_{\mathrm{ref}}(y_l\mid x)}\right)\right] $$

变量解释：

  • $ \pi_\theta(y\mid x) $：当前策略对回答 $ y $ 的（长度归一化或求和后的）log 概率。
  • $ \pi_{\mathrm{ref}}(y\mid x) $：参考模型对同一回答的 log 概率。
  • 第一个括号：被选中回答的"策略相对参考的对数概率比"，乘以 $ \beta $ 后就是隐式奖励 $ r(x,y_w) $（差一个只与 $ x $ 有关的常数）。
  • 第二个括号：被拒绝回答的隐式奖励 $ r(x,y_l) $。
  • 两者相减得到 margin；外层 sigmoid + 负对数，就是"让 $ y_w $ 的隐式奖励高于 $ y_l $"的交叉熵损失。
  • 整个损失只依赖策略与参考模型在四个位置上的 log 概率，不需要奖励模型，也不需要在线采样。

6. 对策略参数的梯度

$$ \nabla_\theta \mathcal{L}_{\mathrm{DPO}} = -\beta\,\sigma(-m)\Big[\nabla_\theta \log\pi_\theta(y_w\mid x) - \nabla_\theta \log\pi_\theta(y_l\mid x)\Big] $$

变量解释：

  • $ m = \beta\big[(\log\pi_\theta(y_w)-\log\pi_{\mathrm{ref}}(y_w)) - (\log\pi_\theta(y_l)-\log\pi_{\mathrm{ref}}(y_l))\big] $：当前 margin。
  • $ \sigma(-m) = 1-\sigma(m) $：模型"判错"的程度；margin 越负，权重越大。
  • $ \nabla_\theta \log\pi_\theta(y_w\mid x) $：提高被选中回答对数概率的方向。
  • $ \nabla_\theta \log\pi_\theta(y_l\mid x) $：提高被拒绝回答对数概率的方向；前面带负号，表示要压低它。
  • 梯度含义：提高 $ y_w $ 的概率、降低 $ y_l $ 的概率，权重由模型当前有多"意外"决定；已经分得很开的偏好对权重接近 0，不再浪费梯度。

7. 奖励准确率

$$ \text{Reward Accuracy} = \frac{1}{N}\sum_{i=1}^{N}\mathbb{1}\big[m_i > 0\big] $$

变量解释：

  • $ N $：验证集偏好对数量。
  • $ m_i $：第 $ i $ 对样本的 margin。
  • $ \mathbb{1}[\cdot] $：指示函数，条件成立为 1，否则为 0。
  • 该指标衡量"模型认为被选中回答更好的比例"，是 DPO 训练中最常用的监控指标；但它只看排序，不看绝对质量，仍需人工或强模型评估。

核心要点

  • 把奖励模型"消掉"：DPO 不是不要奖励，而是用策略与参考模型的概率比解析地表示奖励，从而省掉奖励模型。
  • 参考模型是锚点：$ \pi_{\mathrm{ref}} $ 通常就是 SFT 模型，冻结不训练；它通过 KL 正则约束策略不要跑偏，去掉它容易退化。
  • 离线、监督式训练：只需要 $ (x, y_w, y_l) $ 三元组，不需要在线 rollout，也不需要 PPO 的裁剪、优势估计和价值网络。
  • β 控制"敢不敢偏离"：β 小 → 更激进地追求偏好，容易过拟合、冗长、语言退化；β 大 → 更保守，接近 SFT，但学习信号弱。
  • 梯度只抬相对概率：它提高 $ y_w $ 相对 $ y_l $ 的概率，不保证 $ y_w $ 的绝对概率上升；训练中 chosen 的 logprob 也可能下降。
  • 长度偏差是天然缺陷：log 概率是逐 token 求和，长回答天然更负；虽然参考模型会抵消一部分，但仍可能导致"越长越容易被选中"。
  • 数据质量决定上限：偏好对若有标注噪声、位置偏差、长度偏差，DPO 会忠实地把它们学进去；数据清洗比调参更重要。
  • 不是 RLHF 的完全替代：DPO 适合离线偏好数据充足、追求工程简洁的场景；需要在线探索、过程奖励或复杂推理时，PPO/GRPO 仍有优势。

技术细节与参数详解

下面以 Hugging Face TRL 的 DPOConfig 与 DPOTrainer 为主线。TRL 版本迭代较快，具体默认值以所安装版本的官方文档为准；这里给出的是 0.9 到 0.12 系列广泛使用的默认值与工程推荐。

参数 1：beta（β，KL 正则强度）

  • 含义：控制策略允许偏离参考模型的程度，同时是隐式奖励的缩放系数。
  • 类型：float。
  • 默认值：0.1。
  • 取值范围：大于 0；常用 0.01 到 0.5。
  • 对结果的影响：β 越小，奖励项相对 KL 项越强，策略越敢偏离 SFT，学习信号大但容易过拟合、产生冗长或重复输出；β 越大，策略越保守，接近 SFT，偏好区分学得慢。β 还会缩放 margin，β 过大时 sigmoid 很快饱和，简单样本的梯度接近 0。
  • 推荐设置：从 0.1 起；数据质量高且与 SFT 分布接近可用 0.05；安全对齐、防止语言退化用 0.2 到 0.5；同时监控 reward accuracy 与相对参考模型的 KL。

参数 2：loss_type（偏好损失形式）

  • 含义：选择 DPO 及其变体的具体损失函数。
  • 类型：str。
  • 默认值：'sigmoid'。
  • 取值范围：'sigmoid'、'hinge'、'ipo'、'exo'、'bpo'、'orpo'、'robust'（不同 TRL 版本略有差异）。
  • 对结果的影响：sigmoid 是标准 DPO；hinge 对超过 margin 的样本不再惩罚，抗噪但可能欠拟合；ipo 用平方损失，强约束策略不要偏离参考，适合小数据防过拟合；bpo 针对长度偏差做修正；orpo 不需要参考模型；robust 对噪声标签更稳。
  • 推荐设置：默认 sigmoid；数据少、易过拟合用 ipo；标注噪声大用 robust 或 hinge；显存不足以加载参考模型时考虑 orpo。

参数 3：label_smoothing（标签平滑）

  • 含义：把"被选中"的硬标签 1 平滑为 $ 1-\varepsilon $，避免模型对偏好对过度自信。
  • 类型：float。
  • 默认值：0.0。
  • 取值范围：$ [0, 0.5) $。
  • 对结果的影响：适度平滑能缓解过拟合与标注噪声；过大会削弱 chosen 与 rejected 的区分度，导致学不动。
  • 推荐设置：0 到 0.1；标注一致性较差时用 0.05 到 0.1。

参数 4：reference_free（无参考模型）

  • 含义：是否完全去掉参考模型，直接把策略的 log 概率比当作隐式奖励。
  • 类型：bool。
  • 默认值：False。
  • 取值范围：True 或 False。
  • 对结果的影响：开启后省掉参考模型的前向与显存，但失去 KL 锚点，策略容易退化、长度失控、语言能力下降；它改变的是目标函数，不只是工程优化。
  • 推荐设置：仅在显存极度受限时尝试；生产环境建议保留参考模型，或改用 ORPO、SimPO 等专门的无参考方法。

参数 5：rpo_alpha（RPO 的 SFT 正则系数）

  • 含义：在 DPO 损失中加入 chosen 回答的负对数似然（NLL）项，系数为 rpo_alpha，用于缓解 DPO 训练中 chosen 概率下降的问题。
  • 类型：float 或 None。
  • 默认值：None，表示关闭。
  • 取值范围：大于等于 0；常用 0.1 到 1.0。
  • 对结果的影响：增大它会让模型更愿意保持 chosen 的绝对似然，训练更稳，但可能削弱偏好区分；太小则起不到正则作用。
  • 推荐设置：观察到 chosen logprob 明显下降或输出退化时设 0.1 到 0.5。

参数 6：sync_ref_model（同步参考模型）

  • 含义：是否在训练过程中周期性把当前策略复制为新的参考模型。
  • 类型：bool。
  • 默认值：False。
  • 取值范围：True 或 False。
  • 对结果的影响：开启后参考模型会跟着策略走，KL 锚点动态更新，适合长训练或多轮迭代；但它破坏了"固定参考"的理论假设，可能让策略漂移更快。
  • 推荐设置：大数据、多 epoch 或迭代式偏好训练可开启；单轮小数据保持关闭。

参数 7：ref_model_mixup_alpha（参考模型插值系数）

  • 含义：同步参考模型时，新旧参考模型的指数滑动平均系数。
  • 类型：float。
  • 默认值：0.6。
  • 取值范围：$ [0,1] $。
  • 对结果的影响：越大越偏向旧参考，锚点更稳；越小越快跟上当前策略，约束更弱。
  • 推荐设置：0.6 起步；希望更稳可调到 0.8。

参数 8：ref_model_sync_steps（参考模型同步步数）

  • 含义：每隔多少优化步同步一次参考模型。
  • 类型：int。
  • 默认值：512。
  • 取值范围：大于等于 1。
  • 对结果的影响：越小参考越新、约束越弱、训练越激进；越大参考越旧、越稳定但可能过时。
  • 推荐设置：512 到 1024；数据量大时可适当减小。

参数 9：max_length（最大总长度）

  • 含义：prompt 与 completion 拼接后的最大 token 数，超出部分按 truncation_mode 截断。
  • 类型：int。
  • 默认值：1024。
  • 取值范围：不超过模型上下文窗口；常见 512 到 4096。
  • 对结果的影响：截断会破坏偏好对的完整性，尤其是长回答被截掉后半段后，chosen 与 rejected 的差异可能消失，标签变得噪声化；长度越大显存占用越高。
  • 推荐设置：覆盖数据长度的 95 分位；推理链、代码、长文摘要用 2048 到 4096；不要为了省显存把长样本拦腰截断。

参数 10：max_prompt_length（最大 prompt 长度）

  • 含义：prompt 部分允许的最大 token 数。
  • 类型：int。
  • 默认值：512。
  • 取值范围：小于 max_length。
  • 对结果的影响：prompt 被截断可能丢失关键指令或系统提示；同时会挤压 completion 的可用长度。
  • 推荐设置：覆盖 prompt 的 95 分位；确保 max_length - max_prompt_length 足够容纳完整回答；长系统提示场景建议预处理时保留系统段。

参数 11：truncation_mode（截断方向）

  • 含义：超长时保留开头还是结尾。
  • 类型：str。
  • 默认值：'keep_end'。
  • 取值范围：'keep_end' 或 'keep_start'。
  • 对结果的影响：keep_end 保留最近的对话内容，适合多轮对话；keep_start 保留系统提示与开头指令，适合长文档问答。选错会丢掉最关键的信息。
  • 推荐设置：对话与指令跟随用 keep_end；系统提示很长且必须保留时用 keep_start，或在数据预处理阶段单独处理。

参数 12：precompute_ref_log_probs（预计算参考 log 概率）

  • 含义：是否在训练前一次性算好参考模型对所有偏好对的 log 概率，训练时不再前向参考模型。
  • 类型：bool。
  • 默认值：False。
  • 取值范围：True 或 False。
  • 对结果的影响：开启后显著降低训练显存与时间（省掉参考模型前向），但需要额外的内存/磁盘存储，且参考模型或数据变化后必须重算；如果数据集很大，预处理本身也很耗时。
  • 推荐设置：单卡显存紧张、数据量中等时开启；数据频繁变动或使用 sync_ref_model 时必须关闭。

参数 13：use_weighting（样本加权）

  • 含义：是否使用数据集中提供的样本权重对损失加权。
  • 类型：bool。
  • 默认值：False。
  • 取值范围：True 或 False。
  • 对结果的影响：开启后高质量偏好对可以占更大权重，低质量或争议样本降权；权重设计不当会放大偏差。
  • 推荐设置：有可靠的标注置信度、难度或来源权重时开启；否则保持关闭。

参数 14：disable_dropout（关闭 dropout）

  • 含义：训练时是否把模型中的 dropout 置零。
  • 类型：bool。
  • 默认值：False。
  • 取值范围：True 或 False。
  • 对结果的影响：关闭 dropout 能让策略与参考模型的对比更稳定，减少随机噪声；但可能略微降低泛化，尤其在数据很少时。
  • 推荐设置：DPO 常用 True，尤其是小数据、短训练；大数据可保持默认。

参数 15：learning_rate（学习率）

  • 含义：优化器步长。
  • 类型：float。
  • 默认值：由 TrainingArguments 决定（常见 5e-5），但 DPO 通常需要更小的学习率。
  • 取值范围：全参数微调常用 5e-7 到 5e-6；LoRA 常用 1e-5 到 1e-4。
  • 对结果的影响：过大容易导致策略崩溃、重复输出、语言能力下降；过小学得慢，可能欠拟合。
  • 推荐设置：全参数 5e-7 到 5e-6；LoRA 1e-5 到 1e-4；配合 5% 到 10% 的 warmup 与梯度裁剪。

参数 16：per_device_train_batch_size 与 gradient_accumulation_steps

  • 含义：单卡 batch 大小与梯度累积步数，二者相乘再乘以卡数得到有效 batch。
  • 类型：int。
  • 默认值：batch 通常 1 到 8；累积步数通常 1。
  • 取值范围：受显存限制；有效 batch 常见 32 到 128。
  • 对结果的影响：有效 batch 太小，梯度噪声大、训练不稳定；太大则每组偏好对的多样性下降，且显存压力大。
  • 推荐设置：有效 batch 32 到 128；显存不足时用梯度累积，不要盲目减小到 1。

参数 17：num_train_epochs（训练轮数）

  • 含义：完整遍历偏好数据集的次数。
  • 类型：int 或 float。
  • 默认值：常见 1 到 3。
  • 取值范围：1 到 5；DPO 通常 1 到 2。
  • 对结果的影响：轮数过多会过拟合偏好数据，reward accuracy 上升但真实胜率下降，出现"训练集刷分"；轮数过少则学不动。
  • 推荐设置：1 epoch 起步，配合验证集胜率/奖励准确率早停；数据量小用 1 到 2 epoch。

参数 18：bf16、gradient_checkpointing、activation_offloading（显存相关）

  • 含义：bf16 使用 bfloat16 混合精度；gradient_checkpointing 用重算换显存；activation_offloading 把激活卸载到 CPU。
  • 类型：bool。
  • 默认值：通常 False。
  • 取值范围：True 或 False。
  • 对结果的影响：bf16 几乎不影响效果，能显著省显存；梯度检查点降低激活显存但训练慢 20% 到 30%；激活卸载进一步省显存但更慢，且依赖硬件带宽。
  • 推荐设置：支持 bf16 的显卡一律开；长序列训练开梯度检查点；显存极度紧张再开激活卸载。

参数 19：LoRA 的 r、lora_alpha、lora_dropout、target_modules

  • 含义：低秩适配的秩、缩放系数、dropout 与作用模块。
  • 类型：int、int、float、list[str]。
  • 默认值：TRL 不设默认，需在 LoraConfig 中指定；常见 r=16、lora_alpha=32、lora_dropout=0.05。
  • 取值范围：r 常见 8 到 64；lora_alpha 常取 2r；lora_dropout 0 到 0.1；target_modules 至少覆盖注意力投影，通常加上 MLP 的 gate_proj、up_proj、down_proj。
  • 对结果的影响：r 越大容量越强但显存与过拟合风险上升；只调 q_proj、v_proj 容量有限，全线性层效果更好；lora_alpha/r 的比例影响更新幅度。
  • 推荐设置：r=16、alpha=32、dropout=0.05，覆盖全部线性层；数据量小降到 r=8。

参数 20：dataset_num_proc（数据预处理并行度）

  • 含义：数据集 map、tokenize 的并行进程数。
  • 类型：int 或 None。
  • 默认值：None。
  • 取值范围：正整数。
  • 对结果的影响：只影响预处理速度，不影响训练结果；进程过多可能爆内存。
  • 推荐设置：设为 CPU 核数的一半到全部，视内存而定。

代码示例

先给出一个从零实现 DPO 损失的版本，帮助理解四个 log 概率如何组合；每一行都加了注释，末尾带一个可运行的小例子。

import torch                                       # 张量计算
import torch.nn.functional as F                    # 提供 logsigmoid 等函数


def dpo_loss(
    policy_chosen_logps: torch.Tensor,              # 策略对 chosen 回答的 log 概率，形状 (B,)
    policy_rejected_logps: torch.Tensor,            # 策略对 rejected 回答的 log 概率，形状 (B,)
    ref_chosen_logps: torch.Tensor,                 # 参考模型对 chosen 的 log 概率，形状 (B,)
    ref_rejected_logps: torch.Tensor,               # 参考模型对 rejected 的 log 概率，形状 (B,)
    beta: float = 0.1,                              # KL 正则强度 / 隐式奖励温度
    label_smoothing: float = 0.0,                   # 标签平滑系数，0 表示不平滑
):
    """返回 (平均损失, chosen 奖励, rejected 奖励, 奖励准确率)。"""
    chosen_logratios = policy_chosen_logps - ref_chosen_logps      # chosen 的策略/参考对数概率比
    rejected_logratios = policy_rejected_logps - ref_rejected_logps  # rejected 的策略/参考对数概率比
    logits = chosen_logratios - rejected_logratios                  # margin 去掉 β 后的原始差值
    losses = -F.logsigmoid(beta * logits)                           # 标准 DPO：-log σ(β·margin)
    if label_smoothing > 0:                                         # 若启用标签平滑
        losses = (1 - label_smoothing) * losses + label_smoothing * (-F.logsigmoid(-beta * logits))  # 对反向标签也加一项
    chosen_rewards = beta * chosen_logratios.detach()               # 隐式奖励 r_w = β·log(π/π_ref)，detach 只用于监控
    rejected_rewards = beta * rejected_logratios.detach()           # 隐式奖励 r_l = β·log(π/π_ref)，detach 只用于监控
    reward_accuracy = (chosen_rewards > rejected_rewards).float().mean()  # 奖励准确率：有多大比例 chosen 奖励更高
    return losses.mean(), chosen_rewards, rejected_rewards, reward_accuracy  # 返回损失与监控指标


if __name__ == "__main__":                          # 直接运行时做一个数值自检
    torch.manual_seed(0)                            # 固定随机种子，保证输出可复现
    pc = torch.tensor([-12.0, -20.0])               # 策略对两个 chosen 的 log 概率
    pr = torch.tensor([-18.0, -19.0])               # 策略对两个 rejected 的 log 概率
    rc = torch.tensor([-13.0, -18.0])               # 参考模型对 chosen 的 log 概率
    rr = torch.tensor([-17.0, -18.5])               # 参考模型对 rejected 的 log 概率
    loss, cr, rj, acc = dpo_loss(pc, pr, rc, rr, beta=0.1)  # 计算损失与指标
    print(f"loss={loss.item():.4f}, chosen_reward={cr.tolist()}, rejected_reward={rj.tolist()}, acc={acc.item():.2f}")  # 打印结果

再给出一个基于 TRL 的完整训练脚本。数据文件 prefs.jsonl 每行是一个 JSON 对象，至少包含 prompt、chosen、rejected 三个字段；每一行代码都加了注释。

import torch                                       # 深度学习框架
from datasets import load_dataset                  # 读取 jsonl 偏好数据
from transformers import AutoModelForCausalLM, AutoTokenizer  # 加载基座模型与分词器
from peft import LoraConfig                        # LoRA 低秩适配配置
from trl import DPOConfig, DPOTrainer              # TRL 的 DPO 配置与训练器

MODEL_NAME = "Qwen/Qwen2.5-0.5B-Instruct"          # 示例模型，可替换为任意因果语言模型

tokenizer = AutoTokenizer.from_pretrained(MODEL_NAME)  # 加载分词器
if tokenizer.pad_token is None:                    # 很多因果模型没有 pad token

复杂度分析

时间复杂度

设模型参数量为 $ P $，每个样本的 token 数为 $ L $，batch 大小为 $ B $。Transformer 的一次前向约需 $ 2PL $ 次浮点运算，一次反向约需 $ 4PL $ 次。标准 DPO 的每个优化步包含：

  • 策略对 chosen 与 rejected 的前向：约 $ 2 \times 2PBL = 4PBL $。
  • 参考模型对 chosen 与 rejected 的前向：约 $ 4PBL $（若未预计算）。
  • 策略的反向传播：约 $ 4PBL $。
  • 合计约 $ 12PBL $ 次浮点运算，是同等 batch 下 SFT（前向 + 反向约 $ 6PBL $）的两倍左右。

与 PPO 相比，DPO 省掉了在线 rollout 生成（通常占总开销的大头）、奖励模型前向、价值网络前向与反向，以及多轮 PPO epoch 的重复计算；因此同样的 GPU 预算下，DPO 通常比 PPO 快数倍，且不需要维护复杂的采样与优势估计管线。

空间复杂度

  • 模型权重：策略与参考各一份。全参数微调 7B 模型，bf16 权重每份约 14 GB，两份约 28 GB；再加上 Adam 优化器状态（约 8 倍参数量字节），单卡很难放下。
  • LoRA：只训练低秩适配器，优化器状态只针对 adapter；参考模型可以复用基座（关闭 adapter），显存大幅下降。
  • 激活：与 batch、序列长度、层数成正比；梯度检查点把激活显存从 $ O(BL \cdot d \cdot \text{layers}) $ 降到 $ O(BL \cdot d) $ 量级，代价是额外一次前向。
  • 预计算参考 log 概率：每个样本只存一个标量，空间 $ O(N) $，非常划算；但参考模型变化后需要重算。

训练稳定性

  • DPO 的损失是交叉熵形式，比 PPO 的裁剪目标更稳定，但仍对学习率、β、数据分布敏感。
  • 常见失败模式：β 过小导致策略退化、输出变长；学习率过大导致重复；参考模型与策略初始化不一致导致 margin 一开始就很大或很小。
  • 监控指标：loss、reward accuracy、chosen/rejected 的隐式奖励、相对参考模型的 KL、输出长度、重复率、人工胜率。

应用场景

  • 对话模型对齐：用人类偏好对提升有用性、无害性、指令遵循能力；这是 DPO 最主流的应用。
  • 安全与拒答：构造"安全回答 vs 不安全回答"的偏好对，让模型学会拒绝危险请求，同时保持正常问题上的帮助性。
  • 风格与语气控制：客服话术、品牌语气、正式/口语风格；偏好对比比 SFT 更能表达"哪种更好"。
  • 摘要与翻译：同一原文的多个候选摘要/译文，由人工或强模型标注偏好，DPO 直接优化偏好排序。
  • 代码生成：用单元测试通过率、代码评审意见构造偏好对，提升代码正确性与可读性。
  • RAG 与引用：偏好"有依据、引用准确"的回答，降低幻觉；比单纯 SFT 更能约束引用行为。
  • 工具调用与 Agent 轨迹：对成功/失败轨迹做偏好学习，提升工具选择与参数填写质量。
  • RLAIF：用强模型代替人类做偏好标注，低成本扩大偏好数据规模；DPO 是其最常用的离线优化器。
  • 奖励模型蒸馏：把已有奖励模型的排序结果转成偏好对，用 DPO 把奖励"蒸馏"进策略，省去在线 RL。
