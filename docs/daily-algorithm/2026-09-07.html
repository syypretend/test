Trie 树（前缀树）

类别：数据结构 | 难度：中等

原理

Trie（发音 "try"）是一种树形数据结构，专门用于高效存储和检索字符串数据集中的键。其核心思想是利用字符串的公共前缀来共享节点，从而减少存储空间并加速查找。

每个节点包含两部分：子节点映射（children，通常用字典或数组表示）和终止标记（is_end，标记此处是否为一个完整单词的结尾）。从根节点到某个节点的路径上的字符序列即为该节点代表的前缀。

对于 n 个长度为 L 的字符串，Trie 的插入和查找时间复杂度均为 O(L)，与数据规模 n 无关，这是相比哈希表的优势之一——Trie 支持前缀匹配查询（如自动补全），而哈希表无法做到。

核心要点

  • 公共前缀共享：相同前缀的字符串复用路径，节省存储
  • 前缀匹配：天然支持"以 xxx 开头的所有字符串"查询
  • 字符集大小影响空间复杂度：每个节点的子指针数为字符集大小 Σ
  • 终止标记区分"前缀"与"完整词"
  • 可用于词典分词、自动补全、拼写检查、IP 路由表

技术细节与参数详解

#### 数据结构定义

#### children：子节点映射

  • 含义：存储当前节点的所有子节点，键为字符，值为子节点引用
  • 类型：dict（Python）或 array（定长，按字符集大小分配）
  • 默认值：空字典 {}
  • 取值范围：键为字符集中的任意字符，值为 TrieNode 实例
  • 对结果的影响：使用 dict 可支持任意字符集且按需分配空间；使用 array 则查找 O(1) 但空间固定为 O(Σ)
  • 推荐设置：通用场景用 dict；仅处理 a-z 时可用 26 元素数组加速

#### is_end：终止标记

  • 含义：标记从根到当前节点的路径是否构成一个完整单词
  • 类型：bool
  • 默认值：False
  • 取值范围：True / False
  • 对结果的影响：True 表示此处存储了一个完整词；False 表示仅是某个词的前缀中间节点
  • 推荐设置：插入单词末尾节点设为 True；查找时必须检查此标记

#### word：存储完整单词（可选）

  • 含义：在终止节点存储完整单词字符串，便于直接返回结果
  • 类型：str 或 None
  • 默认值：None
  • 取值范围：任意字符串
  • 对结果的影响：设为完整词可在查找命中时直接返回，无需回溯路径拼接
  • 推荐设置：自动补全场景建议设置，减少拼接开销

#### insert(word) 方法参数

#### word：待插入的单词

  • 含义：要加入 Trie 的字符串
  • 类型：str
  • 取值范围：任意非空字符串
  • 对结果的影响：逐字符遍历，对每个字符在 children 中查找或创建子节点
  • 注意：空字符串需特殊处理（直接标记根节点 is_end=True）

#### search(word) 方法参数

#### word：待查找的完整单词

  • 含义：检查该单词是否存在于 Trie 中
  • 返回值：bool，True 表示存在且 is_end=True
  • 注意：与 startsWith 的区别——search 要求路径终点 is_end=True

#### startsWith(prefix) 方法参数

#### prefix：待查找的前缀

  • 含义：检查 Trie 中是否存在以该前缀开头的任意单词
  • 返回值：bool，True 表示存在
  • 注意：不需要检查 is_end，只需确认前缀路径存在

代码示例

class TrieNode:
    """Trie 树节点"""
    def __init__(self):
        self.children = {}      # 子节点映射：字符 -> TrieNode
        self.is_end = False      # 是否为完整单词的终止节点
        self.word = None         # 存储完整单词（可选，便于直接返回）


class Trie:
    """前缀树（Trie）实现"""
    def __init__(self):
        self.root = TrieNode()  # 根节点，不存储任何字符

    def insert(self, word: str) -> None:
        """插入单词：逐字符向下遍历，不存在则创建新节点"""
        node = self.root
        for char in word:                    # 遍历单词的每个字符
            if char not in node.children:    # 字符不在子节点中
                node.children[char] = TrieNode()  # 创建新节点
            node = node.children[char]       # 移动到子节点
        node.is_end = True                   # 标记单词结尾
        node.word = word                     # 存储完整单词

    def search(self, word: str) -> bool:
        """精确查找：路径存在且终点 is_end=True"""
        node = self._find_node(word)
        return node is not None and node.is_end

    def starts_with(self, prefix: str) -> bool:
        """前缀查找：路径存在即可，不要求 is_end"""
        return self._find_node(prefix) is not None

    def _find_node(self, text: str) -> TrieNode:
        """辅助方法：沿路径查找节点，返回终点节点或 None"""
        node = self.root
        for char in text:
            if char not in node.children:    # 路径断裂
                return None
            node = node.children[char]
        return node

    def autocomplete(self, prefix: str, limit: int = 10) -> list:
        """自动补全：返回以 prefix 开头的所有单词（最多 limit 个）"""
        node = self._find_node(prefix)
        if node is None:
            return []                        # 前缀不存在
        results = []
        self._dfs_collect(node, prefix, results, limit)
        return results

    def _dfs_collect(self, node, prefix, results, limit):
        """DFS 收集所有以当前节点为根的完整单词"""
        if len(results) >= limit:
            return                           # 达到数量上限
        if node.is_end:
            results.append(node.word or prefix)  # 找到完整词
        for char, child in node.children.items():
            self._dfs_collect(child, prefix + char, results, limit)

    def delete(self, word: str) -> bool:
        """删除单词：需回溯清理无用的孤立节点"""
        def _delete_helper(node, word, depth):
            if depth == len(word):            # 到达单词末尾
                if not node.is_end:
                    return False               # 单词不存在
                node.is_end = False            # 取消终止标记
                node.word = None
                return len(node.children) == 0  # 无子节点则可删除
            char = word[depth]
            if char not in node.children:
                return False                   # 路径不存在
            should_delete = _delete_helper(node.children[char], word, depth + 1)
            if should_delete:
                del node.children[char]       # 删除孤立子节点
                return len(node.children) == 0 and not node.is_end
            return False
        return _delete_helper(self.root, word, 0)


# 使用示例
trie = Trie()
words = ["apple", "app", "application", "apply", "banana"]
for w in words:
    trie.insert(w)                           # 逐个插入

print(trie.search("app"))                    # True（完整词存在）
print(trie.search("appl"))                   # False（"appl" 不是完整词）
print(trie.starts_with("app"))               # True（存在 app 前缀）
print(trie.autocomplete("app", 5))           # ['app', 'apple', 'application', 'apply']
trie.delete("app")
print(trie.search("app"))                    # False（已删除）
print(trie.search("apple"))                  # True（apple 仍存在）

复杂度分析

  • 插入：O(L)，L 为单词长度。每个字符做一次字典查找/插入
  • 查找（精确/前缀）：O(L)，沿路径遍历
  • 自动补全：O(L + M)，L 为前缀长度，M 为匹配结果的总字符数
  • 删除：O(L)，需回溯
  • 空间：O(N × L)，N 为单词数，L 为平均长度；公共前缀可压缩

应用场景

  • 搜索引擎自动补全（输入"算法"提示"算法导论""算法与数据结构"）
  • 拼写检查与纠错（Levenshtein 距离 + Trie 剪枝）
  • 中文分词（前缀词典匹配，如 jieba 分词的前缀扫描）
  • IP 路由表最长前缀匹配
  • DNS 解析中的域名查找

LoRA 低秩微调

类别：大模型微调 | 难度：困难

原理

LoRA（Low-Rank Adaptation）是一种参数高效微调方法，其核心假设是：大模型在微调过程中权重的变化矩阵 ΔW 具有低秩特性，可以用两个小矩阵的乘积来近似。

具体来说，原始权重矩阵 W（维度 d×k）保持冻结不训练，在其旁边新增两个低秩矩阵 A（维度 r×k）和 B（维度 d×r），使得 ΔW = B×A。前向传播变为：output = W·x + B·A·x。训练时只更新 A 和 B 的参数，参数量从 d×k 降低到 r×(d+k)，通常仅为原模型的 0.1%-1%。

训练完成后，可将 B×A 与 W 融合（W' = W + B×A），推理时无额外计算开销。这使得 LoRA 成为目前大模型微调的主流方案。

核心要点

  • 低秩假设：微调权重变化 ΔW 可用低秩矩阵近似
  • 冻结原始权重：仅训练 A、B 两个小矩阵
  • 参数量极低：通常为原模型 0.1%-1%
  • 推理零开销：训练后可将 B×A 融合到 W 中
  • QLoRA 扩展：结合 4-bit 量化进一步降低显存

技术细节与参数详解

#### LoraConfig 核心参数（基于 PEFT 库）

#### r（秩，rank）

  • 含义：低秩矩阵 A 和 B 的中间维度，决定了 ΔW 的表达能力上限
  • 类型：int
  • 默认值：8（PEFT 库默认）
  • 取值范围：通常 4-256
  • 对结果的影响：r 越大，可表达的变化越复杂，模型能力越强，但参数量和训练开销增加
  • 推荐设置：
  • 简单风格适配：r=8 或 16
  • 知识注入/复杂任务：r=32 或 64
  • r 过小（1-2）→ 表达能力不足，效果差
  • r 过大（>64）→ 逼近全量微调，丧失轻量化优势

#### lora_alpha（缩放系数）

  • 含义：控制 LoRA 贡献的缩放因子，实际缩放比例为 alpha/r
  • 类型：int
  • 默认值：8（通常设为 r 的 1-2 倍）
  • 取值范围：通常与 r 相近或为其 2 倍
  • 对结果的影响：output = W·x + (B·A)·x·(alpha/r)；alpha/r 越大，LoRA 对输出影响越大
  • 推荐设置：alpha = 2×r（如 r=8 时 alpha=16），使缩放比例约为 2，保持与原始权重量级匹配
  • 经验法则：固定 alpha/r = 2 时效果稳定；若 alpha/r = 1 则等效于不缩放

#### target_modules（目标模块）

  • 含义：指定 LoRA 应用到模型的哪些层/模块
  • 类型：list[str] 或 str
  • 默认值：["q_proj", "v_proj"]（注意力层的 Q 和 V 投影）
  • 可选值：q_proj, k_proj, v_proj, o_proj, gate_proj, down_proj, up_proj, embed_tokens, lm_head 等
  • 对结果的影响：
  • 仅 q_proj, v_proj：参数最少，适合风格调整、轻量适配
  • 扩展到 k_proj, o_proj：更多注意力层参与，效果提升
  • 扩展到 FFN 层（gate_proj, down_proj, up_proj）：适合知识注入
  • 全部层（all-linear）：最强但参数最多
  • 推荐设置：从 q_proj+v_proj 开始尝试；效果不足时逐步扩展

#### lora_dropout（Dropout 比率）

  • 含义：LoRA 层的 Dropout 比率，训练时随机置零激活值
  • 类型：float
  • 默认值：0.0（不启用）
  • 取值范围：0.0-0.5
  • 对结果的影响：防止过拟合，数据量小时效果显著；过高会阻碍学习
  • 推荐设置：
  • 数据量大（>10万条）：0.0（不启用）
  • 数据量中等：0.05-0.1
  • 数据量小（<1万条）：0.1-0.2
  • 超过 0.3 通常有害

#### bias（偏置训练策略）

  • 含义：控制是否训练偏置参数
  • 类型：str
  • 默认值："none"
  • 可选值：none / lora_only / all
  • 对结果的影响：
  • none：不训练任何 bias，保持原始值，能力集中到 LoRA 矩阵
  • lora_only：仅训练 LoRA 层的 bias
  • all：训练所有 bias
  • 推荐设置：大多数场景用 none；若模型无法收敛可尝试 all

#### task_type（任务类型）

  • 含义：指定微调任务的类型，影响 LoRA 的应用方式
  • 类型：str
  • 默认值：None（自动推断）
  • 可选值：CAUSAL_LM / SEQ_2_SEQ_LM / TOKEN_CLS / SEQ_CLS / FEATURE_EXTRACTION 等
  • 对结果的影响：不同任务类型影响模型输出的处理方式和损失计算
  • 推荐设置：对话/生成任务用 CAUSAL_LM；分类用 TOKEN_CLS

#### fan_in_fan_out

  • 含义：权重矩阵是否为 fan-in/fan-out 格式（GPT-2 风格）
  • 类型：bool
  • 默认值：False
  • 对结果的影响：True 时需要对权重做转置处理
  • 推荐设置：使用 GPT-2 系列模型时设为 True，其他通常 False

#### modules_to_save

  • 含义：指定除了 LoRA 层之外需要完整训练并保存的模块
  • 类型：list[str]
  • 默认值：None
  • 对结果的影响：列出的模块将以全量微调方式训练，参数量增加
  • 推荐设置：如需微调分类头，设为 ["classifier", "score"]

#### 训练超参数

#### learning_rate（学习率）

  • 含义：LoRA 参数的优化学习率
  • 类型：float
  • 默认值：1e-4 ~ 3e-4
  • 推荐设置：LoRA 学习率通常比全参数微调高 10 倍（全量微调约 1e-5 ~ 5e-5）
  • 经验：loss 不下降 → 检查学习率是否太低；loss 震荡 → 学习率过高

#### warmup_ratio / warmup_steps

  • 含义：训练初期的学习率预热步数占比
  • 类型：float（比例）或 int（步数）
  • 默认值：0.03（3%）
  • 推荐设置：至少 3%-5% 预热，避免初期不稳定

#### QLoRA 特有参数

#### quantization_config

  • 含义：量化配置
  • 类型：dict
  • 关键参数：
  • load_in_4bit：True 启用 4-bit 量化
  • bnb_4bit_quant_type："nf4"（推荐，专为正态分布设计）或 "fp4"
  • bnb_4bit_use_double_quant：True 启用双重量化，进一步压缩
  • bnb_4bit_compute_dtype：计算精度，推荐 torch.bfloat16

代码示例

from peft import LoraConfig, get_peft_model, TaskType
from transformers import AutoModelForCausalLM, TrainingArguments, Trainer
import torch

# 1. 加载预训练模型
model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-2-7b-hf",
    torch_dtype=torch.float16,          # 半精度加载
    device_map="auto",                   # 自动分配 GPU
)

# 2. 配置 LoRA 参数
lora_config = LoraConfig(
    r=16,                                # 秩：低秩矩阵维度，推荐 8-64
    lora_alpha=32,                       # 缩放系数：通常为 r 的 2 倍
    lora_dropout=0.1,                    # Dropout：防止过拟合，数据小时设 0.1
    bias="none",                         # 不训练 bias，能力集中到 LoRA 矩阵
    task_type=TaskType.CAUSAL_LM,        # 因果语言模型（生成任务）
    target_modules=["q_proj", "v_proj", "k_proj", "o_proj"],  # 注意力层全覆盖
)

# 3. 将 LoRA 应用到模型
model = get_peft_model(model, lora_config)
model.print_trainable_parameters()
# 输出示例: trainable params: 13,631,488 || all params: 6,751,064,064 || trainable%: 0.20%

# 4. 训练参数
training_args = TrainingArguments(
    output_dir="./lora-output",
    num_train_epochs=3,                  # 训练轮数
    per_device_train_batch_size=4,       # 每设备 batch 大小
    gradient_accumulation_steps=4,       # 梯度累积步数（等效 batch=16）
    learning_rate=2e-4,                  # LoRA 学习率（比全量微调高 10 倍）
    warmup_ratio=0.05,                   # 5% 预热步数
    lr_scheduler_type="cosine",         # 余弦退火调度器
    fp16=True,                           # 混合精度训练
    logging_steps=10,                    # 每 10 步记录日志
    save_strategy="epoch",               # 每个 epoch 保存检查点
)

# 5. 训练
trainer = Trainer(
    model=model,
    args=training_args,
    train_dataset=train_dataset,        # 训练数据集
)
trainer.train()

# 6. 保存 LoRA 权重（仅保存增量参数，体积很小）

复杂度分析

  • 训练参数量：O(r × (d + k))，相比全量微调 O(d × k) 降低约 r/min(d,k) 倍
  • 显存占用：标准 LoRA 降低约 80%；QLoRA（4-bit）可降低 90%+
  • 训练速度：与全量微调相当（前向计算量几乎不变，反向传播只更新小矩阵）
  • 推理开销：训练后融合为零额外开销

应用场景

  • 在单张消费级 GPU（如 RTX 3090/4090）上微调 7B-13B 大模型
  • 多任务适配：为不同任务训练不同 LoRA 权重，共享同一基础模型
  • 个性化对话助手：针对不同用户风格微调
  • 知识注入：将领域知识注入到通用大模型

PPO 人类反馈强化学习（RLHF）

类别：大模型对齐 | 难度：困难

原理

PPO（Proximal Policy Optimization）是 RLHF（Reinforcement Learning from Human Feedback）流程中最核心的强化学习算法，用于将大语言模型的输出与人类偏好对齐。

RLHF 完整流程分三步：

1. SFT（监督微调）：用高质量指令数据微调预训练模型，得到初始策略模型

2. Reward Model（奖励模型）：用人类偏好数据训练打分模型，学习"什么是好回答"

3. PPO 强化学习：用奖励模型的分数作为信号，通过强化学习优化语言模型

PPO 训练涉及四个模型协同工作：

  • Actor（演员）：要优化的语言模型，生成回答，参数更新
  • Critic（评论家）：估计状态价值 V(s)，辅助计算优势函数，参数更新
  • Reference（参考模型）：冻结的 SFT 模型，计算 KL 散度防止偏离过远
  • Reward Model（奖励模型）：冻结的打分模型，提供奖励信号

核心要点

  • 四模型架构：Actor + Critic + Reference + Reward，显存需求极大
  • Clip 机制：限制策略更新幅度，防止训练崩溃
  • KL 散度惩罚：约束 Actor 不偏离 Reference 模型太远
  • GAE（广义优势估计）：平衡偏差与方差，稳定优势函数计算
  • 奖励黑客问题：模型可能找到骗奖励模型的捷径，KL 约束缓解此问题

技术细节与参数详解

#### PPO 核心超参数

#### clip_ratio（裁剪比率，ε）

  • 含义：限制新旧策略概率比率的范围，防止单次更新步子过大
  • 类型：float
  • 默认值：0.2
  • 取值范围：0.1-0.3
  • 对结果的影响：
  • 策略比率 ratio = π_new(a|s) / π_old(a|s)
  • 裁剪目标：min(ratio × A, clip(ratio, 1-ε, 1+ε) × A)
  • ε 越小 → 更新越保守，训练稳定但收敛慢
  • ε 越大 → 更新越激进，收敛快但可能不稳定
  • 推荐设置：0.2 是经过大量验证的最佳默认值，RLHF 场景通常 0.1-0.2

#### beta / kl_coef（KL 惩罚系数）

  • 含义：控制 Actor 偏离 Reference 模型的惩罚强度
  • 类型：float
  • 默认值：0.1-0.5
  • 取值范围：0.01-1.0
  • 对结果的影响：
  • β 大 → Actor 紧贴 Reference，安全但保守，创新性低
  • β 小 → 允许大幅偏离，可能奖励黑客
  • 总目标：reward - β × KL(π_actor || π_ref)
  • 推荐设置：从 0.1 开始；部分实现使用自适应 KL 系数（根据偏离程度动态调整）

#### gamma（折扣因子，γ）

  • 含义：未来奖励的折扣率，控制对长期收益的重视程度
  • 类型：float
  • 默认值：1.0（RLHF 中通常不折扣，因为生成任务总奖励在最后给出）
  • 取值范围：0.9-1.0
  • 对结果的影响：
  • γ=1.0：完全重视未来奖励（无折扣）
  • γ<1.0：更重视即时奖励，远期奖励被打折
  • 推荐设置：RLHF 中通常设为 1.0，因为评价在回答结束后一次性给出

#### lam（GAE 平滑系数，λ）

  • 含义：广义优势估计（GAE）中的偏差-方差权衡参数
  • 类型：float
  • 默认值：0.95
  • 取值范围：0.0-1.0
  • 对结果的影响：
  • λ=0：纯 TD 估计，偏差大、方差小
  • λ=1：纯 Monte Carlo，偏差小、方差大
  • λ=0.95：平衡偏差与方差的最佳折中
  • 推荐设置：0.95 是通用最佳值

#### ppo_epochs / ppo_steps（PPO 更新轮数）

  • 含义：每批数据重复使用的次数（mini-batch 更新轮数）
  • 类型：int
  • 默认值：4
  • 取值范围：2-10
  • 对结果的影响：
  • 值越大：数据利用率越高，但旧数据分布偏离风险增大
  • 值太小：数据利用率低，收敛慢
  • 推荐设置：RLHF 中通常 2-4，配合 clip 机制防止过度更新

#### batch_size（批量大小）

  • 含义：每次 PPO 更新使用的样本数
  • 类型：int
  • 默认值：64-512
  • 对结果的影响：影响梯度估计的稳定性和显存占用
  • 推荐设置：512-1024（RLHF 中通常较大以稳定训练）

#### learning_rate（学习率）

  • 含义：Actor 和 Critic 的优化学习率
  • 类型：float
  • 默认值：1e-5 ~ 5e-6
  • 对结果的影响：过高导致训练不稳定；过低收敛太慢
  • 推荐设置：Actor 学习率通常略高于 Critic；warmup 后逐步衰减

#### value_loss_coef（价值损失系数）

  • 含义：Critic 损失在总损失中的权重
  • 类型：float
  • 默认值：0.5
  • 对结果的影响：控制 Critic 对训练的影响程度
  • 推荐设置：0.5 为标准值

#### entropy_coef（熵正则系数）

  • 含义：鼓励策略多样性的正则化项
  • 类型：float
  • 默认值：0.0-0.01
  • 对结果的影响：
  • 值越大 → 鼓励探索，防止策略过早收敛
  • 值为 0 → 纯利用，可能陷入局部最优
  • 推荐设置：RLHF 中通常设为 0 或很小值（0.001）

#### max_grad_norm（梯度裁剪）

  • 含义：梯度的最大范数，防止梯度爆炸
  • 类型：float
  • 默认值：1.0
  • 对结果的影响：裁剪超过此值的梯度，稳定训练
  • 推荐设置：1.0 为通用标准值

#### Critic 裁剪

  • 含义：与 Actor 的 clip 类似，Critic 更新时也做截断
  • 公式：取 max(clipped_loss, unclipped_loss)，保守更新
  • 对结果的影响：防止 Critic 价值估计更新过猛

#### 四模型参数详解

##### Actor Model（演员模型 π_θ）

  • 初始化：来自 SFT 后的模型
  • 参数更新：是（通过 PPO 目标函数反向传播）
  • 输入：prompt x
  • 输出：自回归生成回答 y
  • 优化目标：max [reward - β × KL(π_actor || π_ref)]

##### Critic Model（评论家模型 V_φ）

  • 初始化：与 Actor 结构相同，最后一层改为输出标量
  • 参数更新：是（通过 MSE 损失）
  • 输入：已生成部分 (x, y≤t)
  • 输出：标量 V(s_t)，估计未来预期奖励
  • 损失函数：MSE(V_pred, V_target)，V_target 来自 GAE

##### Reference Model（参考模型 π_ref）

  • 初始化：SFT 后的模型（与 Actor 初始相同）
  • 参数更新：否（完全冻结）
  • 作用：计算 KL 散度，防止 Actor 偏离太远
  • 关键：不加约束 → 奖励黑客（Reward Hacking）

##### Reward Model（奖励模型 r(x,y)）

  • 初始化：预训练模型 + 线性头，训练后冻结
  • 参数更新：否（PPO 阶段冻结）
  • 输入：完整 (prompt, answer) 对
  • 输出：标量奖励分数
  • 训练损失：基于 Bradley-Terry 偏好模型的二分类交叉熵

代码示例

import torch
import torch.nn as nn
from transformers import AutoModelForCausalLM, AutoTokenizer

class PPOTrainer:
    """PPO RLHF 训练器（简化版，展示核心逻辑）"""

    def __init__(
        self,
        actor_model,              # Actor：要优化的语言模型
        critic_model,             # Critic：价值估计模型
        reference_model,          # Reference：冻结的参考模型
        reward_model,             # Reward：冻结的奖励模型
        tokenizer,
        # PPO 超参数
        clip_ratio=0.2,           # 裁剪比率 ε：限制策略更新幅度
        kl_coef=0.1,              # KL 惩罚系数 β：控制偏离 Reference 的程度
        gamma=1.0,                # 折扣因子 γ：RLHF 中通常为 1.0
        lam=0.95,                 # GAE 平滑系数 λ：偏差-方差权衡
        ppo_epochs=4,             # PPO 更新轮数：每批数据重复使用次数
        batch_size=256,            # 批量大小
        learning_rate=5e-6,       # 学习率：RLHF 中通常很小
        value_loss_coef=0.5,      # 价值损失权重
        entropy_coef=0.001,       # 熵正则系数：鼓励多样性
        max_grad_norm=1.0,        # 梯度裁剪：防止梯度爆炸
    ):
        self.actor = actor_model
        self.critic = critic_model
        self.reference = reference_model
        self.reward = reward_model
        self.tokenizer = tokenizer
        self.clip_ratio = clip_ratio
        self.kl_coef = kl_coef
        self.gamma = gamma
        self.lam = lam
        self.ppo_epochs = ppo_epochs
        self.batch_size = batch_size
        self.value_loss_coef = value_loss_coef
        self.entropy_coef = entropy_coef
        self.max_grad_norm = max_grad_norm

        # Actor 和 Critic 使用不同的优化器
        self.actor_optimizer = torch.optim.Adam(
            self.actor.parameters(), lr=learning_rate
        )
        self.critic_optimizer = torch.optim.Adam(
            self.critic.parameters(), lr=learning_rate
        )

    def compute_advantages(self, rewards, values):
        """使用 GAE（广义优势估计）计算优势函数

        GAE 公式：A_t = Σ (γλ)^k × δ_{t+k}
        其中 δ_t = r_t + γV(s_{t+1}) - V(s_t) 为 TD 误差
        """
        advantages = []
        gae = 0.0                                    # 累积 GAE 值
        next_value = 0.0                             # 最后一步的未来价值为 0

        for t in reversed(range(len(rewards))):
            delta = rewards[t] + self.gamma * next_value - values[t]  # TD 误差
            gae = delta + self.gamma * self.lam * gae  # GAE 递推
            advantages.insert(0, gae)
            next_value = values[t]

        advantages = torch.tensor(advantages)
        advantages = (advantages - advantages.mean()) / (advantages.std() + 1e-8)  # 标准化
        return advantages

    def compute_kl_penalty(self, prompts, responses):
        """计算 Actor 与 Reference 之间的 KL 散度

        KL(π_actor || π_ref) = Σ π_actor(x) × log(π_actor(x) / π_ref(x))
        """
        with torch.no_grad():
            ref_logits = self.reference(prompts + responses).logits  # Reference 模型 logits
        actor_logits = self.actor(prompts + responses).logits          # Actor 模型 logits

        # 逐 token 的 KL 散度
        log_ratio = torch.log_softmax(actor_logits, dim=-1) - \
                    torch.log_softmax(ref_logits, dim=-1)
        kl = (torch.softmax(actor_logits, dim=-1) * log_ratio).sum(dim=-1)
        return kl.mean()

    def ppo_step(self, prompts, responses, old_log_probs, advantages):
        """执行一步 PPO 更新"""
        # Actor 前向传播
        actor_logits = self.actor(prompts + responses).logits
        new_log_probs = torch.log_softmax(actor_logits, dim=-1)

        # 策略比率 ratio = π_new / π_old
        ratio = torch.exp(new_log_probs - old_log_probs)

        # PPO Clip 目标
        surrogate1 = ratio * advantages
        surrogate2 = torch.clamp(ratio, 1 - self.clip_ratio, 1 + self.clip_ratio) * advantages
        actor_loss = -torch.min(surrogate1, surrogate2).mean()  # 取较小值（保守更新）

        # Critic 更新
        values = self.critic(prompts + responses).squeeze(-1)
        critic_loss = ((values - advantages) ** 2).mean()       # MSE 损失
        # Critic 也做 clip（取较大损失，保守更新）
        clipped_values = old_values + torch.clamp(
            values - old_values, -self.clip_ratio, self.clip_ratio
        )
        critic_loss = torch.max(
            ((values - returns) ** 2),
            ((clipped_values - returns) ** 2)
        ).mean()

        # 熵正则（鼓励探索）
        entropy = -(torch.softmax(actor_logits, dim=-1) *
                     torch.log_softmax(actor_logits, dim=-1)).sum(dim=-1).mean()

        # 总损失
        total_loss = actor_loss + self.value_loss_coef * critic_loss - self.entropy_coef * entropy

        # 梯度裁剪 + 反向传播
        self.actor_optimizer.zero_grad()
        self.critic_optimizer.zero_grad()
        total_loss.backward()
        torch.nn.utils.clip_grad_norm_(self.actor.parameters(), self.max_grad_norm)
        torch.nn.utils.clip_grad_norm_(self.critic.parameters(), self.max_grad_norm)
        self.actor_optimizer.step()
        self.critic_optimizer.step()

        return {
            "actor_loss": actor_loss.item(),
            "critic_loss": critic_loss.item(),
            "entropy": entropy.item(),
        }

复杂度分析

  • 显存：4 个模型同时加载（Actor + Critic + Reference + Reward），显存需求约为单模型的 4 倍。7B 模型需约 4×14GB = 56GB（fp16），是 PPO 的最大痛点
  • 训练时间：每步包含 4 个模型的前向 + 2 个模型反向传播，训练成本约为 SFT 的 3-5 倍
  • GRPO 优化：DeepSeek 提出的 GRPO 去掉 Critic 模型，用组内相对奖励替代，显存减少约 25%

应用场景

  • ChatGPT / GPT-4 对齐训练：通过 RLHF 使模型输出符合人类偏好
  • 安全性对齐：防止模型输出有害、有偏见或虚构内容
  • 代码生成优化：通过执行反馈作为奖励信号优化代码质量
  • 数学推理增强：通过正确性反馈提升链式推理能力
