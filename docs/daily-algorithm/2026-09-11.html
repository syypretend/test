B+ 树

类别：数据结构 | 难度：中等

算法简介

B+ 树（B+ Tree）是现代关系型数据库（MySQL InnoDB、PostgreSQL、Oracle）和文件系统中最核心的索引数据结构，是 B 树的增强版本。它的核心设计思想是：所有数据（或指向数据的指针）只存储在叶子节点，内部节点（非叶子节点）只存储键值用于路由导航，同时叶子节点通过双向链表串联，形成一个有序的序列。

这种设计带来了三大优势：第一，扇出（fanout）极高——每个节点容纳大量键，树高极低（通常 3~4 层即可支撑上千万条数据），每次查询只需 3~4 次磁盘 I/O；第二，范围查询高效——找到下界后沿叶子链表顺序扫描即可，无需回溯内部节点；第三，磁盘友好——每个节点恰好对应一个磁盘页（page），读写按页进行，充分利用磁盘块局部性。相比 AVL 树/红黑树（内存结构），B+ 树是专门为"磁盘块存储 + 范围查询"优化的多路平衡树。

原理示意图

数学公式

1. B+ 树高度与容量关系

设 B+ 树的阶（order）为 $ m $（每个节点最多 $ m $ 个孩子，即最多 $ m-1 $ 个键），则高度为 $ h $ 的 B+ 树最多能存储的键数：

$$ N_{\max} = (m-1) \cdot m^{h-1} \cdot \text{(叶子指针/叶子容量)} $$

变量解释：

  • $ m $：B+ 树的阶（内部节点最多孩子数），即扇出度
  • $ h $：树的高度（根为第 1 层）
  • $ N_{\max} $：叶子节点最多可容纳的数据条目数

简化理解（每个节点 $ m $ 个孩子）：总键数 $ N \approx m^h $，因此 $ h \approx \log_m N $。当 $ m = 500 $（MySQL InnoDB 典型值）时，3 层树即可存储 $ 500^3 = 1.25 $ 亿条记录。

2. 查询/插入/删除的时间复杂度

$$ T_{\text{search}} = O(\log_m n) $$

$$ T_{\text{insert}} = T_{\text{delete}} = O(\log_m n) $$

变量解释：

  • $ n $：树中数据条目总数
  • $ m $：阶数（扇出度）
  • 由于 $ m $ 通常数百，$ \log_m n $ 极小（如 $ m=500, n=10^8 $ 时 $ \log_m n = 3 $）

3. 范围查询复杂度

$$ T_{\text{range}} = O(\log_m n + k) $$

变量解释：

  • $ k $：范围内命中的数据条目数
  • $ O(\log_m n) $：定位下界的成本
  • $ O(k) $：沿叶子链表顺序扫描 $ k $ 个条目的成本
  • 相比 B 树的范围查询 $ O(\log_m n + k \cdot \log_m n) $（B 树需要反复回溯内部节点），B+ 树效率高得多

核心要点

  • B+ 树是 B 树的增强版：数据只存叶子，内部节点只存键
  • 叶子节点之间通过双向链表连接，天然支持高效范围查询
  • 树高与磁盘 I/O 次数直接挂钩，通常 3~4 层支撑上亿数据
  • 插入时节点满则分裂（split），删除时节点过空则合并（merge）/借位（borrow）
  • 所有叶子节点深度相同（完美平衡），查询路径固定
  • MySQL InnoDB 主键索引、二级索引、文件系统目录索引都基于 B+ 树

技术细节与参数详解

#### 结构参数

#### 参数1：order（m，阶数）

  • 含义：B+ 树中一个节点最多拥有的子节点数，阶数 = 扇出度
  • 类型：int（正整数）
  • 默认值：MySQL InnoDB 中由页大小（16KB）和键大小决定，典型约 500
  • 取值范围：$ m \geq 3 $，实际取 $ m = \lfloor \text{page\_size} / \text{key\_size} \rfloor $ 附近
  • 对结果的影响：阶数越大，树越矮（磁盘 I/O 越少），但节点分裂/合并时移动的键越多
  • 推荐设置：数据库系统自动按页大小推导；应用层手写时常用 $ m=4 \sim 8 $

#### 参数2：节点容量（键/孩子上限）

  • 含义：一个节点最多可容纳的键数（内部节点）= $ m-1 $，叶子节点可容纳数据条目上限 = 页容量
  • 类型：int
  • 默认值：由页大小与条目大小决定（InnoDB 中一页 16KB 约容纳 15 条 ~ 数千条）
  • 取值范围：由 order 和页大小共同决定
  • 对结果的影响：决定分裂频率和树高
  • 推荐设置：让节点尽量填满以降低树高

#### 参数3：分裂策略（Split）

  • 含义：插入后节点超过容量时，将节点分成两半的机制
  • 类型：策略（2-3 分裂 / 50% 分裂 / 80% 分裂）
  • 默认值：50% 分裂（把一半键上移到父节点）
  • 对结果的影响：50% 分裂实现简单但会产生较多半空节点；延迟分裂可提高空间利用率
  • 推荐设置：InnoDB 默认按页半满分裂

#### 参数4：合并策略（Merge / Underflow）

  • 含义：删除后节点键数低于下限（一般 $ \lceil m/2 \rceil - 1 $）时，与兄弟合并或从兄弟借位
  • 类型：策略
  • 默认值：先尝试从兄弟借位（Borrow），失败则合并（Merge）
  • 对结果的影响：借位保持空间利用率高；合并减少树高但增加 I/O
  • 推荐设置：工程上优先借位，其次合并

#### 参数5：叶子指针（Leaf Pointer）

  • 含义：指向叶子节点实际存储数据记录的指针（或行 ID）
  • 类型：指针 / 聚簇键
  • 默认值：InnoDB 中指向主键行数据
  • 对结果的影响：决定"覆盖索引"能否免回表查询
  • 推荐设置：覆盖索引（把查询字段全部放入索引）避免回表

#### 参数6：兄弟链表指针（Sibling Pointer）

  • 含义：叶子节点之间的双向链接，实现范围扫描
  • 类型：指针
  • 默认值：左/右兄弟
  • 对结果的影响：缺失此链表的 B+ 树范围查询性能急剧下降
  • 推荐设置：必须保留，这是 B+ 树相对 B 树的关键优势

#### 参数7：页大小（Page Size）

  • 含义：磁盘一次读写的最小单位，也是 B+ 树节点的物理尺寸
  • 类型：int（字节）
  • 默认值：MySQL InnoDB 16KB
  • 取值范围：4KB / 8KB / 16KB / 32KB / 64KB
  • 对结果的影响：页越大，单节点容量越大、树越矮，但内存缓冲池占用越多
  • 推荐设置：SSD 上可用 4KB~8KB，HDD 上 16KB 更合适

代码示例

# B+ 树核心概念演示：阶数、容量、分裂逻辑（演示数据层面，不实现磁盘 I/O）
# 关键注释见每行

class BPlusNode:                    # B+ 树节点类
    def __init__(self, order):      # 初始化节点
        self.order = order          # 阶数（最多孩子数）
        self.keys = []              # 节点中的键列表
        self.children = []          # 子节点指针（内部节点用）
        self.records = []           # 叶子节点存储的记录（叶子用）
        self.next = None            # 叶子节点右兄弟指针（范围扫描用）
        self.is_leaf = False        # 是否为叶子节点

def calc_capacity(order):           # 计算节点容量
    max_keys = order - 1            # 内部节点最多键数 = 阶 - 1
    max_children = order            # 节点最多孩子数 = 阶
    print(f"阶={order}: 内部节点最多 {max_keys} 个键, 最多 {max_children} 个孩子")
    return max_keys, max_children   # 返回键上限和孩子上限

def calc_height(order, n):          # 计算 B+ 树高度
    import math
    # 总数据量 n，叶子容量约 order，树高 h ≈ log_m(n)
    height = math.ceil(math.log(n, order))   # 以 order 为底的对数向上取整
    print(f"阶={order}, 数据量 n={n}: 树高 ≈ {height} 层")
    return height                   # 返回高度

def should_split(node):             # 判断节点是否需要分裂
    max_keys = node.order - 1       # 节点键数上限
    if len(node.keys) > max_keys:   # 若键数超过上限
        print("需要分裂!")            # 输出提示
        return True                 # 返回需要分裂
    return False                     # 否则不需分裂

def split_leaf(node):                # 叶子节点分裂演示
    mid = len(node.keys) // 2        # 计算中点
    new_node = BNode(node.order, is_leaf=True)   # 新叶子
    new_node.keys = node.keys[mid:]  # 右半键分给新节点
    node.keys = node.keys[:mid]      # 左半键保留原节点
    new_node.next = node.next        # 新节点指向原右兄弟
    node.next = new_node             # 原节点指向新节点
    print(f"分裂后: 左[{node.keys}], 右[{new_node.keys}]")  # 输出分裂结果

# 示例演示
calc_capacity(order=4)               # 输出: 阶=4: 内部节点最多 3 个键, 最多 4 个孩子
calc_height(order=500, n=125_000_000)  # 输出: 3 层可容纳 1.25 亿条
split_leaf(order=4, keys=[10,20,30,40])  # 输出: 左[10,20], 右[30,40]

复杂度分析

时间复杂度：

操作时间复杂度推导
查找$ O(\log_m n) $从根到叶子沿路径下钻，每层做一次二分定位，树高 $ h = \log_m n $
插入$ O(\log_m n) $下钻定位 + 分裂可能逐层上溢，分裂次数 $ O(h) $
删除$ O(\log_m n) $下钻定位 + 借位/合并逐层调整，最坏 $ O(h) $
范围查询$ O(\log_m n + k) $定位下界 $ O(\log_m n) $ + 沿叶子链表扫 $ k $ 条

空间复杂度：

  • 内部节点：$ O(n/m) $ 个节点，存键约 $ O(n) $ 量级
  • 叶子节点：$ O(n/m) $ 个节点，每个存 $ O(m) $ 键值 → 总体 $ O(n) $
  • 节点空间利用率通常约 50%~70%（半满原则）

应用场景

  • 数据库主键索引：MySQL InnoDB 聚簇索引（主键）的底层实现
  • 数据库二级索引：InnoDB 二级索引叶子存主键值，通过回表查询
  • 文件系统：NTFS、ext4 的目录索引、文件块分配
  • OLTP 高并发查询：亿级记录下仅需 3~4 次磁盘 I/O
  • 范围/区间查询：BETWEEN、ORDER BY、分页查询高效利用叶子链表
  • LSM-Tree 的辅助：RocksDB 的 MemTable 用跳表，但磁盘层用 SST 索引（B+ 树思想）

GPT 系列

类别：NLP / 大模型 | 难度：困难

算法简介

GPT（Generative Pre-trained Transformer）是 OpenAI 提出的一系列自回归（Autoregressive）Decoder-only 预训练语言模型。核心思想是：只用 Transformer 的解码器部分（去掉编码器和交叉注意力），通过因果注意力（Causal Attention）——每个 token 只能看到它左边的 token——用"预测下一个词"（Next Token Prediction）的目标在超大规模文本上预训练，然后通过提示（Prompt）直接用于各类下游任务。

GPT 系列沿革：GPT-1（2018，12 层，117M 参数，无监督预训练）→ GPT-2（2019，15 亿参数，零样本能力）→ GPT-3（2020，1750 亿参数，Few-shot 能力）→ InstructGPT / ChatGPT（RLHF 对齐）→ GPT-4（2023，多模态、更强）。Decoder-only 架构因其单向自回归、推理高效（KV Cache）、通用生成特性，成为当今大模型（LLaMA、Qwen、DeepSeek 等）的主流选择。

GPT 的采样参数（temperature、top_k、top_p、frequency_penalty、presence_penalty、max_tokens 等）决定了生成文本的随机性、多样性与连贯性，是 API 调用和工程调优的核心。

原理示意图

数学公式

1. 语言模型（条件概率分解）

$$ P(w_1, w_2, \ldots, w_T) = \prod_{t=1}^{T} P(w_t \mid w_1, \ldots, w_{t-1}) $$

变量解释：

  • $ w_t $：第 $ t $ 个词（token）
  • $ P(w_t \mid w_1, \ldots, w_{t-1}) $：给定前 $ t-1 $ 个词后，下一个词的条件概率
  • 语言模型的任务就是学习这个条件概率分布

#### 2. Softmax 与温度缩放

$$ P(w_t) = \frac{\exp(z_{w_t} / T)}{\sum_{v \in V} \exp(z_v / T)} $$

变量解释：

  • $ z_v $：模型输出的 logit（对词汇表第 $ v $ 个词的得分）
  • $ T $：温度参数（temperature）
  • $ V $：词汇表大小
  • $ T \to 0 $：概率分布变得尖锐，趋于 argmax（贪婪）
  • $ T \to \infty $：分布趋于均匀（完全随机）
  • $ T = 1 $：保持模型原始分布

#### 3. Top-k 截断

$$ V_{k} = \{v : z_v \in \text{Top-}k \text{ of } z\} $$

$$ P(w_t) = \frac{\exp(z_{w_t} / T)}{\sum_{v \in V_k} \exp(z_v / T)} \cdot \mathbb{1}(w_t \in V_k) $$

变量解释：

  • $ V_k $：概率最高的 $ k $ 个 token 的集合
  • $ \mathbb{1}(w_t \in V_k) $：指示函数，只在 $ w_t $ 属于 top-k 时保留概率
  • 作用：丢弃低概率尾巴，防止生成低质量词

#### 4. Top-p 核采样

$$ V_p = \min_{k} \left\{ \text{累积概率} \sum_{i=1}^{k} p_{(i)} \geq p \right\} $$

变量解释：

  • $ p_{(i)} $：按概率降序排列后的第 $ i $ 个 token 的概率
  • $ V_p $：累积概率达到 $ p $ 的最小 token 集合
  • 动态选择候选集：分布尖锐时集合小、平缓时集合大

5. 惩罚项（Penalty）

$$ \text{logit}'_v = z_v - \text{frequency\_penalty} \cdot f_v - \text{presence\_penalty} \cdot \mathbb{1}(v \in S) $$

变量解释：

  • $ f_v $：token $ v $ 在已有生成文本中出现的次数
  • $ \mathbb{1}(v \in S) $：指示函数，表示 token $ v $ 是否已出现在生成文本中
  • frequency_penalty：按次数惩罚，抑制重复
  • presence_penalty：二值惩罚，只要出现过就惩罚

核心要点

  • GPT 是 Decoder-only、自回归、因果注意力的预训练语言模型
  • 预训练任务 = 预测下一个词（最大化条件概率）
  • 采样参数控制输出的随机性与多样性，需与任务匹配
  • KV Cache 是推理优化关键（解码时缓存所有层的历史 K/V）
  • GPT-3 起具备上下文学习（In-Context Learning）能力
  • 与 BERT（Encoder-only）对比：BERT 适合理解任务，GPT 适合生成任务

技术细节与参数详解

#### 模型架构参数

#### 参数1：hidden_size（隐藏维度）

  • 含义：Transformer 每层特征向量维度
  • 类型：int
  • 默认值：GPT-2 small 768；GPT-3 12288
  • 取值范围：正偶数，常为 512~12288
  • 对结果的影响：决定模型表示能力与显存占用
  • 推荐设置：按任务数据量与算力平衡

#### 参数2：num_hidden_layers（Decoder 层数）

  • 含义：Decoder 堆叠层数
  • 类型：int
  • 默认值：GPT-2 12 层；GPT-3 96 层
  • 取值范围：1~100+
  • 对结果的影响：层数越深语义越抽象，但梯度与显存成本上升
  • 推荐设置：小模型 12 层，大规模 40~96 层

#### 参数3：num_attention_heads

  • 含义：多头自注意力头数
  • 类型：int
  • 默认值：GPT-2 small 12；GPT-3 96
  • 取值范围：需满足 hidden_size % heads == 0
  • 对结果的影响：多头并行捕获不同子空间关系
  • 推荐设置：每头维度 64 左右

#### 参数4：intermediate_size（FFN 中间维）

  • 含义：前馈网络隐层宽度
  • 类型：int
  • 默认值：GPT-2 3072；GPT-3 49152
  • 取值范围：通常 4×hidden_size
  • 对结果的影响：FFN 是非线性的主体，容量主要来自这里
  • 推荐设置：4×hidden_size

#### 采样参数（API 常用）

#### 参数5：temperature

  • 含义：控制输出随机性的温度参数，缩放 logits
  • 类型：float
  • 默认值：OpenAI API 默认 1.0
  • 取值范围：$ (0, 2] $，0 以上任意正数
  • 对结果的影响：temperature 越低，分布越尖锐（贪婪），越高越均匀（随机）
  • 推荐设置：数学/代码/结构化输出：0~0.3；创意写作：0.7~1.0；头脑风暴：1.2~1.5

#### 参数6：top_k

  • 含义：只从概率最高的 k 个 token 中采样
  • 类型：int
  • 默认值：OpenAI 无默认（通常不设置，用 top_p 代替）
  • 取值范围：1 ~ 词表大小
  • 对结果的影响：top_k 过小限制多样性，过大失去过滤效果
  • 推荐设置：30~100 之间，或配合 top_p 使用

#### 参数7：top_p（核采样）

  • 含义：只从累积概率达到 p 的最小 token 集合中采样
  • 类型：float
  • 默认值：OpenAI API 默认 1.0（不截断）
  • 取值范围：$ (0, 1] $
  • 对结果的影响：动态过滤低概率 token，比 top_k 更自适应
  • 推荐设置：0.9~0.95 兼顾质量与多样性

#### 参数8：frequency_penalty

  • 含义：按 token 出现次数施加惩罚，抑制重复
  • 类型：float
  • 默认值：0.0
  • 取值范围：$ [-2.0, 2.0] $（正值抑制重复）
  • 对结果的影响：越大，模型越倾向避免重复使用的词
  • 推荐设置：0.5~1.0 用于长文本生成；0 用于对话

#### 参数9：presence_penalty

  • 含义：只要 token 出现过就惩罚（不管次数）
  • 类型：float
  • 默认值：0.0
  • 取值范围：$ [-2.0, 2.0] $（正值鼓励新词）
  • 对结果的影响：鼓励模型引入新主题词，增加多样性
  • 推荐设置：0.3~0.6 鼓励探索；0 保连贯

#### 参数10：max_tokens

  • 含义：一次生成的最大 token 数（输入+输出 ≤ 上下文窗口）
  • 类型：int
  • 默认值：OpenAI 中 max_completion_tokens 默认 4096
  • 取值范围：1 ~ 模型上下文窗口
  • 对结果的影响：决定输出长度上限；超过会被截断
  • 推荐设置：根据任务需求设定，不要无脑拉满

#### 参数11：stop（停止序列）

  • 含义：遇到指定字符串停止生成
  • 类型：list[str]
  • 默认值：None
  • 取值范围：字符串数组
  • 对结果的影响：可控制生成何时结束（如 \n、\n\n、EOF）
  • 推荐设置：多轮对话常用 ["\n", "User:", "Human:"] 等

#### 参数12：n / best_of / logprobs

  • 含义：返回多少条候选输出 / 采多少个最优 / 是否返回 logprobs
  • 类型：int / bool
  • 默认值：n=1, best_of=1, logprobs=False
  • 取值范围：n=1~多条；logprobs True/False
  • 对结果的影响：logprobs 可分析模型置信度
  • 推荐设置：调试用 logprobs=True，常规 n=1

#### 参数13：echo / user / stream

  • 含义：回显输入 / 用户标识 / 流式输出
  • 类型：bool / str / bool
  • 默认值：echo=False, user=None, stream=False
  • 对结果的影响：stream 开启可边生成边返回（SSE）
  • 推荐设置：对话场景开启 stream=True 提升体验

早停策略

类别：训练技巧 | 难度：入门

算法简介

早停（Early Stopping）是深度学习中最常用的防止过拟合的正则化技术之一。核心思想：训练过程中持续监控验证集上的某个指标（如 val_loss），当该指标不再改善时，停止训练，并（可选）恢复到验证指标最优时的模型权重。

原理：训练初期模型欠拟合，训练损失和验证损失同时下降；随着训练推进，模型开始在训练集上"死记硬背"，训练损失继续下降但验证损失开始上升——这就是过拟合。早停在此刻终止训练，避免模型记住噪声。它无需改变模型结构或损失函数，是一种"免费的"正则化，且同时节省大量计算时间。

早停的关键超参数包括：monitor（监控什么指标）、patience（容忍多少轮不改善）、min_delta（最小改善阈值）、mode（min/max/auto）、baseline（基线阈值）、restore_best_weights（是否恢复最优权重）。Keras/TF、PyTorch（手动实现）、PaddlePaddle 均提供内置支持。

原理示意图

数学公式

#### 1. 停止条件

$$ E_{\text{stop}} = \arg\min_{e} \text{val\_metric}(e) + \text{patience} $$

变量解释：

  • $ e $：epoch 编号
  • $ \text{val\_metric}(e) $：第 $ e $ 轮的验证指标
  • $ \text{patience} $：容忍的连续不改善轮数
  • 当连续 patience 轮验证指标未超过历史最优（+min_delta）时停止

#### 2. 最优权重恢复

$$ \theta^* = \arg\min_{\theta_e} \text{val\_loss}(e) $$

变量解释：

  • $ \theta_e $：第 $ e $ 轮的模型权重
  • $ \theta^* $：验证损失最小的权重，早停后应恢复到它

#### 3. 改善判定（mode=min）

$$ \text{improved} = \text{val\_loss}(e) < \text{best\_val\_loss} - \text{min\_delta} $$

变量解释：

  • 只有验证指标改善幅度超过 min_delta 才视为"改善"
  • 未改善则 patience 计数 +1，达到上限则停止

核心要点

  • 早停是"免费"的正则化：不需要改模型结构，节省训练时间
  • 必须监控验证集指标，而非训练集（训练集 loss 总在降）
  • monitor 与 model.compile() 中 metrics 名称需严格匹配（带 val_ 前缀）
  • restore_best_weights=True 保证返回最优权重而非最后权重
  • 与 ModelCheckpoint 配合可持久化最优权重
  • 早停与 Dropout、Weight Decay、Label Smoothing 可叠加使用

技术细节与参数详解（以 Keras EarlyStopping 为例）

#### 参数1：monitor（监控指标）

  • 含义：监控哪个验证指标来判断是否停止
  • 类型：str
  • 默认值：'val_loss'
  • 取值范围：任何 model.fit() 记录的量，如 'val_loss'、'val_accuracy'、'val_auc'
  • 对结果的影响：监控 loss 更通用；监控 accuracy 需配合 mode='max'
  • 推荐：默认 'val_loss'（分类任务注意用 val_loss 而非 loss）

#### 参数2：mode（模式）

  • 含义：指标是越小越好还是越大越好
  • 类型：str
  • 默认值：'auto'（自动判断）
  • 取值范围：'min'（loss 类）、'max'（accuracy/auc 类）、'auto'
  • 对结果的影响：选错会停止在错误时机
  • 推荐：loss 用 'min'，准确率/AUC 用 'max'

#### 参数3：patience（容忍轮数）

  • 含义：验证指标连续多少轮不改善才停止
  • 类型：int
  • 默认值：0（Keras），PyTorch 教程常用 5~10
  • 取值范围：$ [0, \text{总epoch}] $
  • 对结果的影响：太小提前停止（欠拟合），太大浪费计算/过拟合
  • 推荐：小模型 3~10；大模型 10~20；训练波动大时加大 patience

#### 参数4：min_delta（最小改善阈值）

  • 含义：指标至少改善多少才认为"改善"
  • 类型：float
  • 默认值：0
  • 取值范围：$ [0, \infty) $
  • 对结果的影响：过小对噪声敏感，过大无视微小提升
  • 推荐：loss 场景 1e-4~1e-3；指标小（如 AUC 0.001 级）可用 1e-5

#### 参数5：verbose（日志）

  • 含义：是否打印早停信息
  • 类型：int
  • 默认值：0（Keras）
  • 取值范围：0 / 1 / 2
  • 对结果的影响：verbose=1 打印停止/恢复信息
  • 推荐：训练时 1 便于观察

#### 参数6：baseline（基线）

  • 含义：历史最优必须超过的基线值
  • 类型：float
  • 默认值：None
  • 取值范围：与指标同量级
  • 对结果的影响：设置基线可过滤早期噪声（必须超过 baseline 才算改善）
  • 推荐：当你想保证最低质量时可设置

#### 参数7：restore_best_weights

  • 含义：训练结束后是否恢复验证最优时的权重
  • 类型：bool
  • 默认值：False（Keras 2.x）
  • 对结果的影响：False 时返回最后 epoch 权重（通常较差）；True 返回最优权重
  • 推荐：必须设为 True（这是实践中的常见坑）

# ---------- PyTorch 手动实现 ----------
import torch

def train_with_early_stopping(model, train_loader, val_loader, optimizer, epochs=50, patience=5):
    best_val_loss = float('inf')    # 最佳验证损失
    best_state = None               # 最佳权重副本
    no_improve = 0                  # 连续无改善计数

    for epoch in range(epochs):
        model.train()               # 训练模式
        for x, y in train_loader:   # 遍历训练集
            optimizer.zero_grad()   # 清零梯度
            out = model(x)          # 前向
            loss = F.cross_entropy(out, y)  # 损失
            loss.backward()         # 反向
            optimizer.step()        # 更新

        # 验证
        model.eval()                # 评估模式
        val_loss = 0.0
        with torch.no_grad():
            for x, y in val_loader:
                out = model(x)
                val_loss += F.cross_entropy(out, y).item()
        val_loss /= len(val_loader) # 平均验证损失

        if val_loss < best_val_loss - 1e-4:  # 是否改善超过 min_delta
            best_val_loss = val_loss          # 更新最优
            best_state = model.state_dict().copy()  # 保存最优权重
            no_improve = 0                    # 重置计数
        else:
            no_improve += 1                   # 无改善计数+1
            if no_improve >= patience:        # 达到耐心值
                print(f"Early stop at epoch {epoch}")
                model.load_state_dict(best_state)  # 恢复最优权重
                break                          # 退出训练

复杂度分析

时间复杂度：

  • 额外开销：每个 epoch 一次验证集前向，$ O(V \cdot d) $（$ V $ 为验证集大小）
  • 总训练时间：取决于早停时机，通常节省 20%~60%
  • 早停不改变单步复杂度

空间复杂度：

  • 需要保存一份最优权重副本（$ O(\text{param\_count}) $，通常 1 个模型大小）

应用场景

  • 所有神经网络的训练（分类、回归、生成）
  • 大模型微调（LoRA）时防止灾难性遗忘
  • 训练时间受限、算力有限的场景
  • 与其他正则化技术叠加使用
