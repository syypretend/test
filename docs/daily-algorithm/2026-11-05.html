二分查找（Binary Search）

类别：查找算法 | 难度：入门

算法简介

二分查找（Binary Search，又称折半查找）是在有序序列上把搜索区间反复对半收缩的查找算法。它每一轮取区间中点 $ mid $，把 $ a[mid] $ 与目标值 $ x $ 比较：若 $ a[mid] < x $，则目标只可能落在右半区间；若 $ a[mid] > x $，则只可能落在左半区间；相等则命中。由于每轮都把候选规模减半，$ n $ 个元素最多只需约 $ \lfloor \log_2 n \rfloor + 1 $ 次比较，$ 10^9 $ 个元素也只需 30 次比较，是线性查找无法企及的效率。

二分查找真正的难点不在"折半"这个想法，而在边界语义：区间是闭区间 $ [lo, hi] $ 还是左闭右开 $ [lo, hi) $？循环条件是 $ lo \le hi $ 还是 $ lo < hi $？返回的是"任意一个相等位置"还是"第一个大于等于 $ x $ 的位置"？只要这三处有一处不匹配，就会写出死循环、漏查边界或重复元素定位错误。工程上更常用的是它的插入点变体 lower_bound / upper_bound（Python 的 bisect_left / bisect_right），因为"第一个 $ \ge x $"和"第一个 $ > x $"可以统一表达查找、去重、计数、区间统计等一整套操作。

更进一步，二分查找不只用于"在数组里找数"，还可用于在答案空间里找数：只要问题的判定条件具有单调性（$ P(x) $ 为真则 $ P(x+1) $ 也为真），就能对答案二分，把最优化问题转成 $ O(\log) $ 次判定，这就是"二分答案"。

数学公式

1. 递归式与时间复杂度

二分查找每比较一次就把问题规模缩小为原来的一半，其递归式为：

$$ T(n) = T\left(\left\lfloor \frac{n}{2} \right\rfloor\right) + O(1), \qquad T(1) = O(1) $$

变量解释：

  • $ n $：当前候选区间的元素个数
  • $ T(n) $：在 $ n $ 个元素中完成一次查找所需的比较次数
  • $ \lfloor \cdot \rfloor $：向下取整，因为元素个数只能是整数
  • $ O(1) $：一次中点计算加一次比较，是常数开销

展开递归式：$ T(n) = T(n/2) + c = T(n/4) + 2c = \cdots = T(1) + c\log_2 n $，因此 $ T(n) = O(\log_2 n) $，即对数时间复杂度。

2. 最多比较次数

对长度 $ n $ 的数组，二分查找的最坏比较次数为：

$$ k_{\max} = \left\lfloor \log_2 n \right\rfloor + 1 $$

变量解释：

  • $ k_{\max} $：最坏情况下执行的比较轮数
  • $ \lfloor \log_2 n \rfloor $：把 $ n $ 连续除以 2 直到不大于 1 所需的次数
  • $ +1 $：最后一次区间只剩 1 个元素时仍需比较一次

例如 $ n = 10^9 $ 时 $ k_{\max} = 29 + 1 = 30 $；而线性查找最坏要 $ 10^9 $ 次，差距约 3300 万倍。

3. 中点公式与防溢出写法

$$ mid = lo + \left\lfloor \frac{hi - lo}{2} \right\rfloor \quad \text{而不是} \quad mid = \left\lfloor \frac{lo + hi}{2} \right\rfloor $$

变量解释：

  • $ lo $：当前候选区间的左端点下标
  • $ hi $：当前候选区间的右端点下标
  • $ mid $：本轮参与比较的下标
  • 当 $ lo + hi $ 超过 32 位有符号整数上限（约 $ 2.15 \times 10^9 $）时，先加后除会溢出为负数，导致数组越界；先减后加则始终不超过 $ hi $，因此在 C/C++/Java 中必须使用左边这种写法（Python 整数无上限，但养成习惯仍有必要）。

4. 循环不变式（正确性的核心）

以 lower_bound（第一个 $ \ge x $ 的位置）为例，采用左闭右开区间 $ [lo, hi) $ 时，循环全程保持：

$$ a[lo] < x \quad \text{且} \quad a[hi] \ge x \quad (\text{越界视为哨兵}) $$

每轮令 $ mid = lo + \lfloor (hi-lo)/2 \rfloor $：若 $ a[mid] < x $，说明 $ mid $ 及其左侧都不可能成为答案，令 $ lo = mid + 1 $；否则答案在 $ mid $ 或更左，令 $ hi = mid $。当 $ lo = hi $ 时循环结束，$ lo $ 即第一个 $ \ge x $ 的位置。不变式成立 ⇒ 终止时 $ lo $ 就是答案，这是比"背模板"更可靠的推导方式。

5. 二分答案的复杂度

设答案区间为 $ [L, R] $，单次判定代价为 $ C $，浮点精度要求为 $ \epsilon $，则：

$$ T = O\left(\log_2 \frac{R-L}{\epsilon} \times C\right) $$

变量解释：

  • $ L, R $：答案的上下界（必须保证最优解落在其中）
  • $ \epsilon $：浮点二分允许的误差
  • $ C $：一次 check(x) 判定的时间开销
  • $ \log_2 \frac{R-L}{\epsilon} $：区间每轮减半，缩小到 $ \epsilon $ 所需轮数

整数二分答案时 $ \epsilon = 1 $，轮数约为 $ \log_2(R-L+1) $。

核心要点

  • 前提是单调有序：数组必须按比较键升序（或降序）排列，否则"折半排除"的逻辑不成立。
  • 区间语义必须唯一：闭区间 $ [lo, hi] $ 配 while lo <= hi；左闭右开 $ [lo, hi) $ 配 while lo < hi。两套模板不能混用。
  • 收缩必须排除 mid：闭区间下 lo = mid + 1 或 hi = mid - 1；左闭右开下 hi = mid。写成 lo = mid 会死循环。
  • 重复元素要选对变体：找任意一个用普通二分；找第一个用 lower_bound；找最后一个用 upper_bound - 1；统计出现次数用 upper_bound - lower_bound。
  • 答案空间二分的关键是单调性：check(x) 必须满足"若 $ x $ 可行，则所有 $ \ge x $（或所有 $ \le x $）也可行"，否则二分不成立。
  • 边界与空集：lo = 0, hi = n 时返回 $ n $ 表示"所有元素都小于 $ x $"，调用方必须判越界。
  • 不要对链表、无序数据、频繁插入删除的结构用数组二分：前者无法 $ O(1) $ 随机访问，后者维护有序的成本高于收益。

技术细节与参数详解

二分查找没有"库函数式"的十几个超参数，它的"参数"是决定正确性与语义的一组结构性选择。下面把每个可调项按 API 参数的标准逐项拆开；最后再单列 Python bisect 的真实函数签名参数。

参数 1：搜索空间 a（有序数组）

  • 含义：被查找的序列，要求按比较键单调不减（允许重复）或单调不增。
  • 类型：支持 $ O(1) $ 随机访问的序列，如 list、array.array、numpy.ndarray、C 数组；不能是 list 之外的链式结构。
  • 默认值：无默认值，必须由调用方保证有序。
  • 取值范围：长度 $ n \ge 0 $；元素类型必须支持 < 比较（或提供 key 函数）。
  • 对结果的影响：若数组无序，二分可能返回错误下标且不会报错，是最隐蔽的 bug 来源；若有重复元素，"找到哪一个"取决于变体。
  • 推荐设置：一次性排序后复用（排序 $ O(n\log n) $，之后每次查找 $ O(\log n) $）；若需要频繁插入，改用 bisect.insort（插入仍 $ O(n) $）或平衡树/跳表。

参数 2：目标值 x（target）

  • 含义：要查找的值，或要确定插入位置的值。
  • 类型：与数组元素同类型且可比较；使用 key 时，x 是未经过 key 变换的原始值（Python 文档明确说明 key 不作用于 x）。
  • 默认值：无。
  • 取值范围：任意可比较值；可以小于最小值（返回 0）或大于最大值（返回 $ n $）。
  • 对结果的影响：x 不存在时，普通二分返回 -1，bisect 返回插入点；两者语义不同。
  • 推荐设置：查找"精确值"时优先用 bisect_left + 一次相等判断，避免自己处理边界。

参数 3：左边界 lo

  • 含义：搜索区间的左端点，包含在候选范围内。
  • 类型：整数下标。
  • 默认值：0（Python bisect 的默认值）。
  • 取值范围：$ 0 \le lo \le n $；允许 $ lo = n $（空区间）。
  • 对结果的影响：把查找限制在子数组中；若 $ lo $ 大于真实答案位置，会漏掉答案；若 $ lo > hi $，返回 $ lo $ 且不查找。
  • 推荐设置：分段查找（如按时间分片）时显式传入；普通全数组查找用默认值即可。

参数 4：右边界 hi

  • 含义：搜索区间的右端点。注意语义随模板而变：闭区间模板中 hi 是"最后一个候选下标"（初始 $ n-1 $）；左闭右开模板中 hi 是"候选区间后一位"（初始 $ n $）。
  • 类型：整数下标。
  • 默认值：len(a)（Python bisect 采用左闭右开，默认 hi = len(a)）。
  • 取值范围：$ 0 \le hi \le n $。
  • 对结果的影响：hi 少 1 会漏掉最后一个元素；hi 多 1 在闭区间模板中会越界。
  • 推荐设置：统一采用左闭右开 [lo, hi)，可以直接用 hi = len(a)，天然支持空数组，且 hi = mid 的写法不易死循环。

参数 5：循环条件（lo <= hi 还是 lo < hi）

  • 含义：决定区间非空判定方式，必须与区间语义配对。
  • 类型：布尔表达式。
  • 默认值：无（模板的一部分）。
  • 取值范围：lo <= hi（闭区间）或 lo < hi（左闭右开）。
  • 对结果的影响：闭区间配 lo < hi 会漏查最后一个元素；左闭右开配 lo <= hi 会在 $ lo = hi $ 时访问 a[hi] 越界。
  • 推荐设置：初学阶段只掌握一套——左闭右开 + while lo < hi + hi = mid，可同时覆盖查找、插入点、二分答案。

参数 6：中点计算 mid

  • 含义：本轮参与比较的下标。
  • 类型：整数。
  • 默认值：无。
  • 取值范围：$ lo \le mid < hi $（左闭右开）或 $ lo \le mid \le hi $（闭区间）。
  • 对结果的影响：(lo + hi) // 2 在大数下可能溢出（C/Java）；取整方向影响重复元素的定位（向下取整配合 hi = mid 才能找到第一个）。
  • 推荐设置：mid = lo + (hi - lo) // 2，既防溢出又保证向下取整。

参数 7：收缩规则（比较后的赋值）

  • 含义：根据 a[mid] 与 x 的大小关系丢弃不可能的一半。
  • 类型：赋值语句。
  • 默认值：无。
  • 取值范围：lo = mid + 1 / hi = mid - 1（闭区间）或 lo = mid + 1 / hi = mid（左闭右开）。
  • 对结果的影响：收缩过少（如 lo = mid）会死循环；收缩过多（如 hi = mid - 2）会漏解。
  • 推荐设置：牢记"mid 已经被比较过，必须被排除"；左闭右开时 hi = mid 是因为 mid 本身不在 [lo, hi) 内，等价于排除。

参数 8：返回值语义（命中下标 / 插入点 / 布尔）

  • 含义：函数返回什么，决定调用方如何处理"未找到"。
  • 类型：整数下标或布尔值。
  • 默认值：无。
  • 取值范围：$ -1 $（未找到）、$ [0, n-1] $（命中）、$ [0, n] $（插入点）。
  • 对结果的影响：返回 $ n $ 是合法的"插入到末尾"，调用方若直接 a[ans] 会越界；返回 -1 与返回 $ n $ 的区别常被混淆。
  • 推荐设置：库函数风格统一用"插入点 + 越界检查"；业务代码可封装成 index_of() 返回 -1。

参数 9：bisect_left / bisect_right 的选择

  • 含义：bisect_left(a, x) 返回第一个 $ \ge x $ 的位置（左侧插入点）；bisect_right(a, x) 返回第一个 $ > x $ 的位置（右侧插入点）。
  • 类型：枚举式选择。
  • 默认值：无（两个独立函数）。
  • 取值范围：left 或 right。
  • 对结果的影响：对重复元素，left 指向第一个，right 指向最后一个之后；两者之差即 $ x $ 的出现次数。
  • 推荐设置：找下界用 left，找上界用 right；统计频次用 right - left。

参数 10：key（Python 3.10+ 的比较键函数）

  • 含义：从每个数组元素中提取用于比较的键，类似于 list.sort(key=...)。
  • 类型：可调用对象 Callable[[T], K] 或 None。
  • 默认值：None（直接比较元素本身）。
  • 取值范围：任意单参数函数；不会作用于待查找的 x。
  • 对结果的影响：可以对字典、对象、元组按某个字段二分；若 key 开销大且循环调用，会重复计算同一元素的键，拖慢查找。
  • 推荐设置：key 较贵时，预计算 keys = [key(e) for e in a] 并对 keys 二分，再用下标取原元素；或给 key 加 functools.cache。

参数 11：二分答案的判定函数 check(x)

  • 含义：判断"答案取 $ x $ 时是否可行"的单调谓词。
  • 类型：Callable[[int|float], bool]。
  • 默认值：无。
  • 取值范围：必须在答案区间上呈现 False...False, True...True（或相反）的单调形态。
  • 对结果的影响：谓词不单调是二分答案最常见的错误，会得到看似合理但完全错误的结果；check 内部若修改全局状态，还会破坏多次判定的独立性。
  • 推荐设置：先用小数据暴力验证 check 的单调性，再上二分；check 尽量写成无副作用的纯函数。

参数 12：浮点二分的终止条件（eps 或固定迭代次数）

  • 含义：决定何时停止对实数答案的逼近。
  • 类型：浮点数 eps 或整数 iterations。
  • 默认值：无；常见 eps = 1e-7，或固定迭代 60～100 次。
  • 取值范围：eps > 0；迭代次数 $ [1, 200] $。
  • 对结果的影响：eps 过大会精度不足；过小会因浮点舍入陷入死循环（lo 与 hi 相邻但中点仍等于端点）。
  • 推荐设置：固定迭代 80～100 次最稳（每轮区间减半，100 轮足以把任何 double 区间压到机器精度），不要依赖 while hi - lo > eps。

代码示例

示例 1：标准闭区间二分（查找任意一个等于 target 的下标）

def binary_search(a, target):
    lo, hi = 0, len(a) - 1          # 闭区间 [lo, hi]，hi 指向最后一个元素
    while lo <= hi:                 # 区间非空时继续（lo == hi 时还有一个元素）
        mid = lo + (hi - lo) // 2   # 防溢出的中点写法，向下取整
        if a[mid] == target:        # 命中目标
            return mid              # 立即返回下标
        elif a[mid] < target:       # 中点值偏小，目标只可能在右半
            lo = mid + 1            # 排除 mid 本身，区间变为 [mid+1, hi]
        else:                       # 中点值偏大，目标只可能在左半
            hi = mid - 1            # 排除 mid 本身，区间变为 [lo, mid-1]
    return -1                       # 区间耗尽仍未命中，返回 -1

示例 2：lower_bound / upper_bound（左闭右开，工程最常用）

def lower_bound(a, x):
    lo, hi = 0, len(a)              # 左闭右开 [lo, hi)，hi 可以等于 n
    while lo < hi:                  # 区间非空（至少一个候选）
        mid = lo + (hi - lo) // 2   # 向下取整，保证 mid < hi
        if a[mid] < x:              # mid 及其左侧都 < x，不可能是答案
            lo = mid + 1            # 答案在右半
        else:                       # a[mid] >= x，mid 可能是第一个
            hi = mid                # 保留 mid，区间缩为 [lo, mid]
    return lo                       # 循环结束时 lo == hi，即第一个 >= x 的位置


def upper_bound(a, x):
    lo, hi = 0, len(a)              # 同样使用左闭右开区间
    while lo < hi:                  # 区间非空
        mid = lo + (hi - lo) // 2   # 取中点
        if a[mid] <= x:             # mid 及其左侧都 <= x，可以安全丢弃
            lo = mid + 1            # 答案在右半
        else:                       # a[mid] > x，mid 可能是第一个 > x 的位置
            hi = mid                # 保留 mid
    return lo                       # 返回第一个 > x 的位置（可能为 n）


def count_equal(a, x):
    return upper_bound(a, x) - lower_bound(a, x)   # 两者之差就是 x 的出现次数


nums = [1, 3, 3, 3, 5, 7, 9]        # 有序数组，含重复元素 3
print(lower_bound(nums, 3))         # 输出 1：第一个 3 的下标
print(upper_bound(nums, 3))         # 输出 4：最后一个 3 的下标 + 1
print(count_equal(nums, 3))         # 输出 3：3 一共出现 3 次
print(lower_bound(nums, 4))         # 输出 4：4 应插入的位置（保持有序）
print(upper_bound(nums, 100))       # 输出 7：等于 n，表示插入到末尾

示例 3：使用 Python 标准库 bisect（含 key 与区间限制）

import bisect                       # 导入标准库的二分模块

scores = [60, 70, 80, 90]           # 有序的分数分界点
print(bisect.bisect(scores, 85))    # 输出 3：85 应插入到 90 之前
print(bisect.bisect_left(scores, 80))   # 输出 2：第一个 >= 80 的位置
print(bisect.bisect_right(scores, 80))  # 输出 3：第一个 > 80 的位置

movies = [("Jaws", 1975), ("Titanic", 1997), ("Aliens", 1986)]  # 待排序的电影列表
movies.sort(key=lambda m: m[1])    # 按上映年份升序排序
years = [m[1] for m in movies]     # 预计算年份键，避免 key 在二分中被反复调用
pos = bisect.bisect_left(years, 1990)   # 找第一个年份 >= 1990 的位置
print(movies[pos])                  # 输出 ("Titanic", 1997)：1990 年之后的第一部

sub = [10, 20, 30, 40, 50, 60]      # 演示 lo/hi 限定子区间
print(bisect.bisect_left(sub, 30, 2, 5))   # 只在 [2,5) 中查找，输出 2

示例 4：二分答案（LeetCode 875「爱吃香蕉的珂珂」）

def min_eating_speed(piles, h):
    def check(k):
        hours = 0                              # 累计吃完所有香蕉所需小时数
        for p in piles:                        # 遍历每一堆
            hours += (p + k - 1) // k          # 向上取整：吃完 p 根需要 ceil(p/k) 小时
        return hours <= h                      # 在 h 小时内吃完则速度 k 可行

    lo, hi = 1, max(piles)                     # 答案下界 1，上界为最大堆（再快也只吃一堆）
    while lo < hi:                             # 左闭右开式二分找最小可行速度
        mid = lo + (hi - lo) // 2              # 取中点速度
        if check(mid):                         # 若 mid 可行
            hi = mid                           # 尝试更小的速度，保留 mid
        else:                                  # 若 mid 不可行
            lo = mid + 1                       # 速度必须更大
    return lo                                  # 循环结束时 lo 即最小可行速度


print(min_eating_speed([3, 6, 7, 11], 8))      # 输出 4：速度 4 时 1+2+2+3=8 小时
print(min_eating_speed([30, 11, 23, 4, 20], 5))  # 输出 30：必须一小时吃完最大堆
print(min_eating_speed([30, 11, 23, 4, 20], 6))  # 输出 23

示例 5：浮点二分（求平方根，固定迭代次数）

def sqrt_binary(x):
    if x < 0:                                  # 负数没有实数平方根
        raise ValueError("x must be non-negative")   # 抛出异常而不是返回 NaN
    lo, hi = 0.0, max(1.0, x)                  # 答案区间：[0, max(1, x)] 保证覆盖
    for _ in range(100):                       # 固定迭代 100 次，避免浮点死循环
        mid = (lo + hi) / 2                    # 取区间中点
        if mid * mid < x:                      # 中点的平方仍小于 x
            lo = mid                           # 答案在右半，抬高下界
        else:                                  # 中点的平方不小于 x
            hi = mid                           # 答案在左半，压低上界
    return (lo + hi) / 2                       # 返回区间中点作为近似值


print(sqrt_binary(2))                          # 输出约 1.414213562373095
print(sqrt_binary(1e-12))                      # 输出约 1e-06：小数值也能正确处理
print(sqrt_binary(1e12))                       # 输出 1000000.0：大数值不溢出

复杂度分析

时间复杂度

设数组长度为 $ n $。每一轮循环把候选区间长度从 $ m $ 变为 $ \lfloor m/2 \rfloor $ 或 $ \lceil m/2 \rceil - 1 $，即规模至少减半。设经过 $ k $ 轮后区间长度降为 1，则：

$$ \frac{n}{2^k} \approx 1 \;\Rightarrow\; k \approx \log_2 n $$

因此循环最多执行 $ \lfloor \log_2 n \rfloor + 1 $ 次，每次只做一次加法、一次除法和一次比较，均为 $ O(1) $，故：

$$ T(n) = O(\log n) $$

  • 最好情况：第一次就命中，$ O(1) $；
  • 最坏情况：查找到区间为空，$ O(\log n) $；
  • 平均情况：$ O(\log n) $。

空间复杂度

  • 迭代版本只使用 lo、hi、mid 三个整数变量，$ S(n) = O(1) $；
  • 递归版本每层产生一个栈帧，深度为 $ \log_2 n $，$ S(n) = O(\log n) $，工程上应优先写迭代版。

二分答案的复杂度

若答案区间大小为 $ R-L $，单次 check 代价为 $ C $，则总时间：

$$ T = O(C \log(R-L)) $$

以「珂珂吃香蕉」为例，$ C = O(n) $（遍历所有堆），答案区间为 $ [1, \max(piles)] $，故总复杂度 $ O(n \log \max(piles)) $，远优于动态规划或枚举。

工程常数

二分查找的比较次数虽少，但每次比较都可能触发缓存未命中。对 $ 10^8 $ 级别的数组，二分的随机访问模式会导致大量 cache miss，实际耗时可能比"数据局部性好"的线性扫描更差；数据库因此使用 B+ 树（一次读一个页、页内再用二分），而不是直接在裸数组上二分。

应用场景

  • 有序数组精确查找：配置表、字典、白名单的快速命中判断。
  • 插入位置定位：bisect.insort 维护有序列表，如排行榜、时间序列、订单簿价格档位。
  • 区间统计：upper_bound - lower_bound 统计某个值的出现次数；配合前缀和可做范围计数。
  • 版本/提交定位：git bisect 用二分在提交历史中定位引入 bug 的那一次提交；发布系统用二分定位"从哪个版本开始出错"。
  • 二分答案：最小化最大值（分割数组、装船问题）、最大化最小值（Aggressive Cows）、最小可行速度/容量/时间。
  • 数值计算：单调函数求根、平方根/对数/三角函数反解、浮点方程求解。
  • 数据库与存储引擎：B+ 树页内二分、LSM-Tree 的 SSTable 索引块查找、列式存储的字典页定位。
  • 日志与监控：按时间戳有序的日志文件中二分定位时间窗口的起止行。

高斯混合模型 GMM

类别：无监督学习 | 难度：中等

算法简介

高斯混合模型（Gaussian Mixture Model，GMM）用 $ K $ 个高斯分布的加权和来刻画数据的整体分布：

$$ p(x) = \sum_{k=1}^{K} \pi_k \, \mathcal{N}(x \mid \mu_k, \Sigma_k) $$

它假设每个样本都由某个隐变量 $ z \in \{1,\dots,K\} $ 生成：先按概率 $ \pi_k $ 选择第 $ k $ 个高斯分量，再从该分量中采样出 $ x $。因此 GMM 是一种生成式概率模型，既能做密度估计（给出任意点的概率密度），也能做软聚类（给出样本属于每个簇的后验概率，而不是像 K-Means 那样硬性分配）。

GMM 的参数估计用 EM 算法（Expectation-Maximization）：E 步在给定当前参数下计算每个样本属于各分量的后验概率（责任度 $ \gamma_{ik} $）；M 步把这些责任度当作"软标签"，用加权最大似然重新估计 $ \pi_k $、$ \mu_k $、$ \Sigma_k $；两步交替，对数似然单调不降，直到收敛。相比 K-Means，GMM 允许簇具有不同的形状、方向和大小（由完整协方差矩阵描述），因此能拟合椭球状、倾斜、尺度差异很大的簇；代价是参数更多、对初始化更敏感、计算量更大（$ d $ 维下每次迭代含 $ d^3 $ 的矩阵分解）。

原理示意图

数学公式

1. 混合模型的定义

$$ p(x \mid \theta) = \sum_{k=1}^{K} \pi_k \, \mathcal{N}(x \mid \mu_k, \Sigma_k) $$

变量解释：

  • $ K $：高斯分量的个数，即"软簇"的数量，对应 n_components
  • $ \pi_k $：第 $ k $ 个分量的混合权重（先验概率），满足 $ \pi_k \ge 0 $ 且 $ \sum_{k=1}^{K}\pi_k = 1 $
  • $ \mu_k \in \mathbb{R}^{d} $：第 $ k $ 个分量的均值向量（$ d $ 为特征维数）
  • $ \Sigma_k \in \mathbb{R}^{d \times d} $：第 $ k $ 个分量的协方差矩阵，必须对称正定
  • $ \mathcal{N}(x \mid \mu_k, \Sigma_k) $：多元高斯密度函数
  • $ \theta = \{\pi_k, \mu_k, \Sigma_k\}_{k=1}^{K} $：全部待估参数

多元高斯密度的展开式为：

$$ \mathcal{N}(x \mid \mu, \Sigma) = \frac{1}{(2\pi)^{d/2}|\Sigma|^{1/2}} \exp\left(-\frac{1}{2}(x-\mu)^{\top}\Sigma^{-1}(x-\mu)\right) $$

其中 $ |\Sigma| $ 是协方差矩阵的行列式，$ \Sigma^{-1} $ 是逆矩阵，$ (x-\mu)^{\top}\Sigma^{-1}(x-\mu) $ 是马氏距离的平方（考虑了特征间的相关性与尺度）。

2. 对数似然与隐变量

对 $ N $ 个独立样本 $ X = \{x_1,\dots,x_N\} $，对数似然为：

$$ \ln p(X \mid \theta) = \sum_{i=1}^{N} \ln \left( \sum_{k=1}^{K} \pi_k \, \mathcal{N}(x_i \mid \mu_k, \Sigma_k) \right) $$

变量解释：

  • $ N $：样本总数
  • $ x_i $：第 $ i $ 个样本（$ d $ 维向量）
  • 外层求和遍历样本，内层求和遍历分量

由于对数内有求和号，直接求导无法得到闭式解，因此引入隐变量 $ z_i \in \{1,\dots,K\} $ 表示"第 $ i $ 个样本由哪个分量生成"，并用 EM 算法迭代求解。

3. E 步：责任度（后验概率）

$$ \gamma_{ik} = \frac{\pi_k \, \mathcal{N}(x_i \mid \mu_k, \Sigma_k)}{\sum_{j=1}^{K} \pi_j \, \mathcal{N}(x_i \mid \mu_j, \Sigma_j)} $$

变量解释：

  • $ \gamma_{ik} $：第 $ i $ 个样本属于第 $ k $ 个分量的后验概率（责任度），满足 $ \sum_k \gamma_{ik} = 1 $
  • 分子：先验权重 × 该分量下的似然
  • 分母：所有分量的加权似然之和，即样本的边缘密度 $ p(x_i) $

$ \gamma_{ik} $ 就是"软聚类"的归属度：$ \gamma_{ik} = 0.9 $ 表示该样本有 90% 的概率来自第 $ k $ 个分量。K-Means 可以看作 $ \gamma_{ik} $ 取 0/1 的硬分配极限。

4. M 步：参数更新

$$ \pi_k = \frac{N_k}{N}, \qquad \mu_k = \frac{1}{N_k}\sum_{i=1}^{N}\gamma_{ik}x_i, \qquad \Sigma_k = \frac{1}{N_k}\sum_{i=1}^{N}\gamma_{ik}(x_i-\mu_k)(x_i-\mu_k)^{\top} $$

变量解释：

  • $ N_k = \sum_{i=1}^{N}\gamma_{ik} $：第 $ k $ 个分量的有效样本数（软计数）
  • $ \pi_k $：该分量的权重，等于它"分到"的样本比例
  • $ \mu_k $：以责任度为权重的样本均值
  • $ \Sigma_k $：以责任度为权重的协方差，刻画该簇的形状、方向和尺度

这三个公式就是"加权最大似然估计"：把每个样本按 $ \gamma_{ik} $ 拆分到各个分量，再分别计算均值与协方差。

5. 数值稳定的对数似然（log-sum-exp）

直接计算 $ \ln\sum_k \exp(\cdot) $ 时，若密度极小会下溢为 0，若极大则上溢为 inf。工程实现统一用：

$$ \ln p(x_i) = m_i + \ln \sum_{k=1}^{K}\exp\left(\ln \pi_k + \ln \mathcal{N}(x_i \mid \mu_k,\Sigma_k) - m_i\right), \quad m_i = \max_k\left(\ln \pi_k + \ln \mathcal{N}(x_i \mid \mu_k,\Sigma_k)\right) $$

变量解释：

  • $ m_i $：第 $ i $ 个样本在所有分量上的最大对数得分，用来把指数项平移到 $ \le 0 $ 的安全区间
  • 减去 $ m_i $ 再在外部加回，数学上恒等，数值上避免溢出
  • sklearn 内部同样使用对数域计算与 Cholesky 分解，而不是直接算概率密度

6. 模型选择：BIC / AIC

$$ \mathrm{BIC} = -2\ln \hat{L} + p\ln N, \qquad \mathrm{AIC} = -2\ln \hat{L} + 2p $$

变量解释：

  • $ \hat{L} $：收敛后的最大似然值（model.lower_bound_ 指数值）
  • $ p $：模型自由参数个数（随 covariance_type 变化，见下表）
  • $ N $：样本数
  • BIC 对参数个数惩罚更重（$ \ln N > 2 $ 当 $ N > 7 $），更倾向简单模型；AIC 更倾向拟合优度

参数个数 $ p $ 的计算（$ K $ 个分量、$ d $ 维特征）：

covariance_type每个分量的协方差参数总参数个数 $ p $
full$ d(d+1)/2 $$ K\cdot d(d+1)/2 + Kd + (K-1) $
tied$ d(d+1)/2 $（共享）$ d(d+1)/2 + Kd + (K-1) $

核心要点

  • GMM 是生成模型，不是判别模型：它建模 $ p(x) $，因此可以采样新样本、计算任意点的密度、做异常检测。
  • 软聚类：predict_proba 给出归属概率，比 K-Means 的硬标签包含更多信息；不确定性高的样本（最大概率接近 $ 1/K $）往往位于簇边界。
  • 协方差类型决定模型容量：full 最灵活但参数最多、最易过拟合；diag/spherical 参数少、更稳，适合高维或小样本。
  • EM 只保证收敛到局部最优：结果依赖初始化，n_init > 1 多次重启取最优是必要实践。
  • 协方差可能奇异：当某个分量只剩极少数样本、或特征高度共线时，$ \Sigma_k $ 接近奇异，似然会发散到无穷；reg_covar 在对角线加一个小常数是标准修复。
  • 特征尺度必须统一：GMM 用马氏距离，理论上对线性缩放不变，但数值优化与正则项受尺度影响，实践上仍建议标准化。
  • 标签不可识别：分量的编号是任意的，多次运行可能得到"交换了编号"的同一解，比较结果时要先对齐标签。
  • K 的选择没有唯一答案：优先用 BIC 扫一遍 $ K $，再结合业务可解释性与轮廓系数综合判断。

技术细节与参数详解

以下参数以 sklearn.mixture.GaussianMixture 为准（scikit-learn 1.9 文档），默认值与形状均按官方 API 说明。每个参数都给出含义、类型、默认值、取值范围、影响与推荐设置。

参数 1：n_components（分量个数 K）

  • 含义：混合模型中高斯分量的数量，等价于"软簇"的个数。
  • 类型：int。
  • 默认值：1。
  • 取值范围：$ 1 \le K \le N $；实际建议 $ 2 \le K \le 10 $ 起步，再按 BIC 扩展。
  • 对结果的影响：$ K $ 太小欠拟合（多峰被压成单峰）；$ K $ 太大过拟合（每个分量退化到单个样本，似然趋于无穷），且训练时间线性增长。
  • 推荐设置：用 BIC 在候选集合 $ \{1,2,\dots,10\} $ 上扫描；若无监督信息，选 BIC 最小且分量权重不出现大量接近 0 的模型。

参数 2：covariance_type（协方差类型）

  • 含义：约束各分量协方差矩阵的结构，控制模型容量与参数数量。
  • 类型：str，枚举 {'full', 'tied', 'diag', 'spherical'}。
  • 默认值：'full'。
  • 取值范围：四选一。
  • 对结果的影响：
  • full：每个分量独立的完整协方差，可拟合任意方向的椭球，参数最多（$ O(Kd^2) $），小样本易过拟合；
  • tied：所有分量共享一个协方差，只学"整体形状"，适合各簇形状相似、样本量不均衡的场景；
  • diag：每个分量独立的对角协方差，椭圆轴与坐标轴平行，忽略特征相关性，参数量 $ O(Kd) $；
  • spherical：每个分量只有一个方差，簇为球体，容量最小、最稳。
  • 推荐设置：样本充足（$ N \gg Kd^2 $）用 full；高维（$ d > 50 $）或样本少用 diag；各簇形状一致用 tied；做基线或超大数据用 spherical。

参数 3：tol（收敛阈值）

  • 含义：EM 迭代的停止条件——平均下界增益低于该值时停止。
  • 类型：float。
  • 默认值：1e-3。
  • 取值范围：$ (0, +\infty) $，常用 $ 10^{-3} \sim 10^{-6} $。
  • 对结果的影响：越大越早停、速度快但参数未充分收敛；越小迭代越久、精度更高，但过小可能因浮点误差空转。
  • 推荐设置：默认 1e-3 适合大多数场景；对参数精度要求高（如科学计算）用 1e-6，同时把 max_iter 提高到 300～500。

参数 4：reg_covar（协方差正则项）

  • 含义：加在协方差矩阵对角线上的非负常数，保证其正定、可逆。
  • 类型：float。
  • 默认值：1e-6。
  • 取值范围：$ [0, +\infty) $，常用 $ 10^{-6} \sim 10^{-3} $。
  • 对结果的影响：太小无法阻止奇异（似然爆炸、lower_bound_ 变成很大的正数）；太大会把所有簇"撑圆"，抹掉真实的形状差异。
  • 推荐设置：特征已标准化时用 1e-6；特征量纲大或存在共线特征时用 1e-4～1e-3；出现 ConvergenceWarning 或似然异常时优先调大它。

参数 5：max_iter（最大迭代次数）

  • 含义：EM 允许执行的最大轮数，防止不收敛时无限循环。
  • 类型：int。
  • 默认值：100。
  • 取值范围：$ [1, +\infty) $，常用 100～1000。
  • 对结果的影响：太小会未收敛就停止（converged_ = False）；太大只影响最坏情况耗时，不影响已收敛的结果。
  • 推荐设置：默认 100 通常够用；若 n_iter_ 接近 max_iter，说明未收敛，提高到 300～500 并检查 tol、reg_covar 与特征尺度。

参数 6：n_init（初始化次数）

  • 含义：独立运行 EM 的次数，保留下界（对数似然）最高的那次结果。
  • 类型：int。
  • 默认值：1。
  • 取值范围：$ [1, +\infty) $，常用 3～10。
  • 对结果的影响：EM 对初值敏感，单次运行可能落入较差局部最优；多次初始化能显著提升解的质量，代价是时间线性增加。
  • 推荐设置：生产环境用 n_init=5～10；调试阶段可先用 1 快速试跑。

参数 7：init_params（初始化方式）

  • 含义：指定权重、均值、精度的初始化策略。
  • 类型：str，枚举 {'kmeans', 'k-means++', 'random', 'random_from_data'}。
  • 默认值：'kmeans'。
  • 取值范围：四选一（k-means++ 与 random_from_data 在 1.1 版本加入）。
  • 对结果的影响：
  • kmeans：先跑 K-Means 用其簇标签初始化责任度，通常最稳、收敛最快；
  • k-means++：用 k-means++ 的分散策略选初始均值，兼顾稳定性与随机性；
  • random：随机初始化责任度，方差大、可能很慢；
  • random_from_data：从数据中随机选点作为初始均值，简单但可能选到离群点。
  • 推荐设置：默认 'kmeans'；若 K-Means 因簇形状非球形而失效，试 'k-means++' 或 'random_from_data'。

参数 8：weights_init（初始权重）

  • 含义：用户直接指定的各分量初始混合权重。
  • 类型：array-like，形状 (n_components,)。
  • 默认值：None（由 init_params 决定）。
  • 取值范围：每个元素 $ \ge 0 $，总和为 1。
  • 对结果的影响：给定后不再使用 init_params 初始化权重；不合理的权重（如某个分量接近 0）会让该分量永远得不到样本。
  • 推荐设置：有先验业务比例时使用（如已知三类客户占比 5:3:2）；否则保持 None。

参数 9：means_init（初始均值）

  • 含义：用户直接指定的各分量初始均值。
  • 类型：array-like，形状 (n_components, n_features)。
  • 默认值：None。
  • 取值范围：任意实数矩阵，形状必须与数据维度一致。
  • 对结果的影响：好的初值能让 EM 快速收敛到合理解；错误初值会导致分量"抢样本"或直接退化。
  • 推荐设置：可用 K-Means 的 cluster_centers_、或业务上已知的典型样本作为初值；一般保持 None。

参数 10：precisions_init（初始精度矩阵）

  • 含义：用户直接指定的初始精度矩阵（协方差矩阵的逆）。
  • 类型：array-like，形状随 covariance_type 变化。
  • 默认值：None。
  • 取值范围：形状必须为 (K,)（spherical）、(d,d)（tied）、(K,d)（diag）、(K,d,d)（full），且每个矩阵对称正定。
  • 对结果的影响：直接决定初始簇形状；设置不当会导致奇异或收敛到退化解。
  • 推荐设置：除非有强先验，否则保持 None；需要热启动时优先用 warm_start。

参数 11：random_state（随机种子）

  • 含义：控制初始化与 sample() 采样的随机数生成器。
  • 类型：int、RandomState 实例或 None。
  • 默认值：None。
  • 取值范围：任意整数；相同整数保证可复现。
  • 对结果的影响：影响 kmeans/random 初始化的具体取值，进而影响最终局部最优；不影响算法本身。
  • 推荐设置：实验与线上训练固定为某个整数（如 42），保证结果可复现、问题可追溯。

参数 12：warm_start（热启动）

  • 含义：为 True 时，用上一次 fit() 的结果作为下一次 fit() 的初值。
  • 类型：bool。
  • 默认值：False。
  • 取值范围：True / False。
  • 对结果的影响：在相似数据上重复拟合时可加速收敛；此时 n_init 被忽略，只在第一次调用时做一次初始化。
  • 推荐设置：在线学习/增量更新场景设为 True；一次性批量训练保持 False，以免继承坏初值。

参数 13：verbose 与 verbose_interval（日志与打印间隔）

  • 含义：verbose 控制是否打印初始化与每轮迭代信息；verbose_interval 控制每隔多少轮打印一次。
  • 类型：int。
  • 默认值：verbose=0，verbose_interval=10。
  • 取值范围：verbose 取 0/1/2（≥2 还会打印对数似然与耗时）；verbose_interval >= 1。
  • 对结果的影响：只影响日志输出，不影响数值结果；高频打印会拖慢训练。
  • 推荐设置：调试时 verbose=1，生产环境保持 0。

输出属性（模型的"返回值参数"）

  • weights_：形状 (K,)，各分量权重，和为 1；可用于判断哪些分量是"死分量"（权重接近 0）。
  • means_：形状 (K, d)，各分量均值，即软簇中心。
  • covariances_：形状随类型变化（(K,d,d) / (d,d) / (K,d) / (K,)），描述每个簇的形状。
  • precisions_ / precisions_cholesky_：协方差的逆及其 Cholesky 分解，预测时用于高效计算马氏距离。
  • converged_：布尔值，是否在 max_iter 内达到 tol；为 False 时应增大迭代次数或放宽阈值。
  • n_iter_：实际迭代轮数；接近 max_iter 是"未收敛"的信号。
  • lower_bound_：收敛解的对数似然下界（越大越好）；可用于比较不同初始化/不同 K。
  • lower_bounds_：每轮的下界序列，可画收敛曲线，正常应单调不减。
  • aic(X) / bic(X)：信息准则，越小越好；bic 对复杂模型惩罚更重。
  • predict(X)：返回硬标签（责任度最大的分量）。
  • predict_proba(X)：返回形状 (N, K) 的责任度矩阵，即软聚类结果。
  • score_samples(X)：返回每个样本的对数似然 $ \ln p(x_i) $，可直接用于异常检测。
  • score(X)：返回所有样本的平均对数似然。
  • sample(n_samples)：按拟合出的分布生成新样本，返回 (X, y)，y 为分量标签。

示例 1：从零实现 GMM 的 EM 算法（NumPy）

import numpy as np                                  # 导入数值计算库

def log_gaussian(X, mean, cov, reg=1e-6):
    d = X.shape[1]                                  # 特征维度 d
    cov = cov + reg * np.eye(d)                     # 对角线加正则项，保证正定可逆
    L = np.linalg.cholesky(cov)                     # Cholesky 分解：cov = L @ L.T
    diff = X - mean                                 # 每个样本相对均值的偏差，形状 (N, d)
    sol = np.linalg.solve(L, diff.T)                # 解 L @ z = diff.T，避免显式求逆
    maha = np.sum(sol ** 2, axis=0)                 # 马氏距离平方 (x-μ)ᵀΣ⁻¹(x-μ)
    logdet = 2.0 * np.sum(np.log(np.diag(L)))       # ln|Σ| = 2 * Σ ln(diag(L))
    return -0.5 * (d * np.log(2 * np.pi) + logdet + maha)   # 多元高斯对数密度

def gmm_em(X, K, max_iter=200, tol=1e-6, reg=1e-6, seed=0):
    rng = np.random.default_rng(seed)               # 固定随机种子，保证可复现
    N, d = X.shape                                  # 样本数与特征维度
    idx = rng.choice(N, size=K, replace=False)      # 随机选 K 个样本作为初始均值
    mu = X[idx].copy()                              # 初始均值，形状 (K, d)
    sigma = np.array([np.cov(X.T) + reg * np.eye(d) for _ in range(K)])  # 每个分量用全局协方差初始化
    pi = np.full(K, 1.0 / K)                        # 初始权重平均分配
    prev_ll = -np.inf                               # 上一轮对数似然，初始为负无穷
    for it in range(max_iter):                      # EM 主循环
        log_prob = np.zeros((N, K))                 # 存放 ln(π_k) + ln N(x_i|μ_k,Σ_k)
        for k in range(K):                          # 遍历每个分量
            log_prob[:, k] = np.log(pi[k]) + log_gaussian(X, mu[k], sigma[k], reg)  # 对数域累加
        m = log_prob.max(axis=1, keepdims=True)     # 每行最大值，用于 log-sum-exp 平移
        log_norm = m + np.log(np.exp(log_prob - m).sum(axis=1, keepdims=True))  # ln p(x_i)
        gamma = np.exp(log_prob - log_norm)         # E 步：责任度 γ_ik，形状 (N, K)
        ll = float(log_norm.sum())                  # 当前模型的对数似然
        if abs(ll - prev_ll) < tol:                 # 增益小于阈值则判定收敛
            break                                   # 提前结束迭代
        prev_ll = ll                                # 更新上一轮似然
        Nk = gamma.sum(axis=0) + 1e-12              # 每个分量的软计数 N_k（加小量防除零）
        pi = Nk / N                                 # M 步：更新权重 π_k = N_k / N
        mu = (gamma.T @ X) / Nk[:, None]            # M 步：更新均值 μ_k = Σγx / N_k
        for k in range(K):                          # 逐个分量更新协方差
            diff = X - mu[k]                        # 样本相对新均值的偏差
            sigma[k] = (gamma[:, k, None] * diff).T @ diff / Nk[k] + reg * np.eye(d)  # 加权协方差 + 正则
    return pi, mu, sigma, gamma, ll                  # 返回参数、责任度与最终对数似然

def predict_proba(model, X):
    pi, mu, sigma, _, _ = model                     # 解包模型参数
    N, K = X.shape[0], len(pi)                      # 样本数与分量数
    log_prob = np.zeros((N, K))                     # 预分配对数得分矩阵
    for k in range(K):                              # 遍历分量
        log_prob[:, k] = np.log(pi[k]) + log_gaussian(X, mu[k], sigma[k])  # 计算对数得分
    m = log_prob.max(axis=1, keepdims=True)         # 行最大值
    log_norm = m + np.log(np.exp(log_prob - m).sum(axis=1, keepdims=True))  # 对数归一化项
    return np.exp(log_prob - log_norm)              # 归一化得到后验概率

if __name__ == "__main__":                          # 简单的自测入口

复杂度分析

设样本数 $ N $、特征维数 $ d $、分量数 $ K $、EM 迭代轮数 $ I $。

E 步：对每个样本、每个分量计算一次马氏距离。若协方差已预分解，单次计算为 $ O(d^2) $，总计：

$$ O(N K d^2) $$

M 步：每个分量的加权协方差需要计算 $ \sum_i \gamma_{ik}(x_i-\mu_k)(x_i-\mu_k)^{\top} $，单分量 $ O(N d^2) $，总计：

$$ O(N K d^2) $$

协方差分解：每轮对每个分量做 Cholesky 分解，代价 $ O(K d^3) $（diag/spherical 可降为 $ O(Kd) $）。

总时间复杂度：

$$ O\left(I \cdot (N K d^2 + K d^3)\right) $$

当 $ N \gg d $ 时主导项是 $ O(I N K d^2) $；高维小样本时 $ K d^3 $ 不可忽略。

空间复杂度：

  • 责任度矩阵 $ \gamma $：$ O(NK) $（这是 GMM 比 K-Means 多出的主要内存开销）；
  • 参数：full 为 $ O(Kd^2) $，diag 为 $ O(Kd) $；
  • 预测阶段只需存储参数，单样本推断为 $ O(Kd^2) $。

与 K-Means 的对比：K-Means 每轮 $ O(NKd) $，GMM（full）每轮 $ O(NKd^2) $，高维下慢一个数量级；但 GMM 能表达椭球簇并输出概率，信息量更大。

应用场景

  • 客户分层/用户画像：按消费频次、客单价、活跃度等特征做软聚类，输出"高价值概率""流失风险概率"，比硬分群更适合精细化运营。
  • 异常检测：用 score_samples 得到样本对数密度，低密度样本判为异常；广泛用于工业设备监测、网络入侵检测、金融反欺诈。
  • 密度估计与非参数近似：作为任意连续分布的通用 approximator，用于生成采样、重要性采样、蒙特卡洛模拟。
  • 语音与说话人识别：GMM-UBM 是经典的文本无关说话人确认方案；GMM-HMM 曾是语音识别的声学模型主力。
  • 图像与视频处理：GMM 背景建模（每个像素的颜色分布用 GMM 拟合）用于运动目标检测；颜色分布建模用于图像分割。
  • 缺失数据插补与半监督学习：用 GMM 的后验概率对缺失特征做期望填补，或把无标签数据纳入似然。
  • 作为生成模型的基础组件：VAE 的先验、归一化流的分量、HMM 的发射分布等都以 GMM 为原型。

RLHF 人类反馈强化学习

类别：大模型对齐 | 难度：困难

算法简介

RLHF（Reinforcement Learning from Human Feedback，人类反馈强化学习）是把"人类偏好"转化为可优化奖励信号、再用强化学习调整语言模型的一整套对齐流程。它由三个阶段组成：① SFT（用人工示范数据做监督微调，让模型学会"像人一样回答"）；② 奖励建模（让人类对同一 prompt 的多个回答排序，用 Bradley-Terry 模型训练一个输出标量分数的奖励模型 $ r_\phi $）；③ PPO 强化学习（策略模型 $ \pi_\theta $ 生成回答，奖励模型打分，同时用 KL 惩罚约束策略不要偏离 SFT 参考模型 $ \pi_{\text{ref}} $ 太远，再用 PPO 的截断重要性采样目标稳定更新）。

RLHF 解决的是"损失函数写不出来"的问题：翻译、摘要、对话的"好坏"很难用交叉熵表达，但人类比较两个回答谁更好却很容易。把比较数据蒸馏进奖励模型后，语言生成就变成了一个序列决策问题——每生成一个 token 是一个动作，回答结束拿到奖励。InstructGPT/ChatGPT 的成功让这套流程成为大模型对齐的标准范式；它的代价是训练不稳定、需要同时驻留策略/参考/奖励/价值四个模型、显存约为 DPO 的两倍，因此工程上出现了 DPO、GRPO、RLAIF 等大量简化与变体。

原理示意图

数学公式

1. Bradley-Terry 偏好模型与奖励模型损失

给定 prompt $ x $ 和两个回答 $ y_w $（win，被偏好）、$ y_l $（lose，被拒绝），奖励模型 $ r_\phi $ 给每个回答打一个标量分。Bradley-Terry 模型假设：

$$ P(y_w \succ y_l \mid x) = \sigma\left(r_\phi(x, y_w) - r_\phi(x, y_l)\right) = \frac{1}{1 + \exp\left(-\left(r_\phi(x,y_w) - r_\phi(x,y_l)\right)\right)} $$

最大化该似然等价于最小化负对数似然：

$$ \mathcal{L}_{\text{RM}}(\phi) = -\mathbb{E}_{(x, y_w, y_l) \sim \mathcal{D}} \left[ \log \sigma\left(r_\phi(x,y_w) - r_\phi(x,y_l)\right) \right] $$

变量解释：

  • $ x $：输入的 prompt（问题/指令）
  • $ y_w, y_l $：人类标注的"更好"和"更差"的回答
  • $ r_\phi(x,y) $：奖励模型输出的标量分数，$ \phi $ 为奖励模型参数
  • $ \sigma(z) = 1/(1+e^{-z}) $：Sigmoid 函数，把分数差映射到 $ (0,1) $ 的概率
  • $ \mathcal{D} $：人类偏好数据集
  • 只看分数差，因此奖励的绝对尺度不可识别（可整体平移），训练时通常把输出归一化到零均值

加入 margin $ m $ 的变体（要求 win 至少高出 $ m $ 分）：

$$ \mathcal{L}_{\text{RM}}^{\text{margin}} = -\mathbb{E}\left[\log \sigma\left(r_\phi(x,y_w) - r_\phi(x,y_l) - m\right)\right] $$

变量解释：

  • $ T $：回答的最后一个 token（EOS）
  • $ y_t $：第 $ t $ 步生成的 token
  • $ \pi_\theta(y_t \mid x, y_{
  • $ \pi_{\text{ref}} $：SFT 模型（冻结），作为"不要偏离太远"的锚点
  • $ \beta $：KL 惩罚系数，越大越保守
  • $ r_\phi(x,y) $：回答结束时由奖励模型给出的整体分数

3. PPO 的截断替代目标

$$ \mathcal{L}^{\text{CLIP}}(\theta) = \mathbb{E}_{t}\left[\min\left(r_t(\theta)\,A_t,\; \mathrm{clip}\left(r_t(\theta), 1-\epsilon, 1+\epsilon\right)A_t\right)\right] $$

其中重要性采样比：

$$ r_t(\theta) = \frac{\pi_\theta(a_t \mid s_t)}{\pi_{\theta_{\text{old}}}(a_t \mid s_t)} $$

变量解释：

  • $ s_t $：状态，即 prompt 加已生成的前缀 $ x, y_{
  • $ a_t $：动作，即当前步生成的 token $ y_t $
  • $ \pi_{\theta_{\text{old}}} $：更新前（采样时）的旧策略，训练中固定
  • $ r_t(\theta) $：新旧策略对同一 token 的概率比；$ r_t = 1 $ 表示策略未变
  • $ A_t $：优势函数，表示该动作比平均水平好多少
  • $ \epsilon $：截断范围，典型 $ 0.2 $
  • $ \min(\cdot,\cdot) $：取两者较小值，保证"悲观下界"——优势为正时不允许比率超过 $ 1+\epsilon $，优势为负时不允许低于 $ 1-\epsilon $

为什么需要 clip：重要性采样要求新旧策略接近，否则方差爆炸。clip 把比率限制在 $ [1-\epsilon, 1+\epsilon] $，避免一次更新把策略推得太远；这也是 PPO 相比原始策略梯度的核心改进。

4. GAE（广义优势估计）

$$ \delta_t = R_t + \gamma V_\psi(s_{t+1}) - V_\psi(s_t) $$

$$ A_t = \sum_{l=0}^{T-t} (\gamma\lambda)^{l}\,\delta_{t+l} $$

变量解释：

  • $ \delta_t $：第 $ t $ 步的 TD 误差（实际奖励 + 下一状态价值 − 当前状态价值）
  • $ R_t $：第 $ t $ 步的即时奖励（含 KL 惩罚）
  • $ V_\psi(s_t) $：价值网络对状态 $ s_t $ 的估值
  • $ \gamma $：折扣因子，LLM 中通常取 $ 1.0 $（回合在 EOS 终止，不需要折扣）
  • $ \lambda $：GAE 的偏差-方差折中参数，$ \lambda=0 $ 退化为单步 TD（低方差高偏差），$ \lambda=1 $ 退化为蒙特卡洛回报（高方差低偏差），常用 $ 0.95 $
  • $ T-t $：从当前步到回合结束的剩余步数

5. 价值损失与总损失

$$ \mathcal{L}_V = \mathbb{E}\left[\max\left((V_\psi(s_t) - R_t^{\text{target}})^2,\; (\mathrm{clip}(V_\psi(s_t), V_{\text{old}}-\epsilon_v, V_{\text{old}}+\epsilon_v) - R_t^{\text{target}})^2\right)\right] $$

$$ \mathcal{L} = -\mathcal{L}^{\text{CLIP}} + c_v \mathcal{L}_V - c_e \mathcal{H}(\pi_\theta) $$

变量解释：

  • $ R_t^{\text{target}} = A_t + V_\psi(s_t) $：回报目标（优势 + 当前价值）
  • $ \epsilon_v $：价值截断范围，典型 $ 0.2 $
  • $ c_v $：价值损失权重 vf_coef，典型 $ 0.1 $
  • $ c_e $：熵奖励系数 ent_coef，鼓励探索，典型 $ 0 \sim 0.01 $
  • $ \mathcal{H}(\pi_\theta) $：策略熵，越大表示输出越多样

6. 与 DPO 的对比（理解 RLHF 代价的参照）

DPO 跳过奖励模型与在线采样，直接在偏好对上优化：

$$ \mathcal{L}_{\text{DPO}}(\theta) = -\mathbb{E}_{(x,y_w,y_l)}\left[\log \sigma\left(\beta \log \frac{\pi_\theta(y_w \mid x)}{\pi_{\text{ref}}(y_w \mid x)} - \beta \log \frac{\pi_\theta(y_l \mid x)}{\pi_{\text{ref}}(y_l \mid x)}\right)\right] $$

它把 RLHF 的三阶段压缩成一个分类式损失，显存与训练稳定性都更好，但缺少在线探索，理论上限与奖励模型解耦能力不如 PPO。

核心要点

  • RLHF 的本质是"用比较数据学奖励，再用 RL 优化奖励"：奖励模型是人类的代理，PPO 是在代理奖励上做策略优化。
  • KL 惩罚不可省略：没有 KL，策略会找到奖励模型的漏洞（reward hacking），输出重复、谄媚、超长或乱码文本。
  • 四个模型各司其职：actor 训练、critic 训练、reference 冻结、reward 冻结；reference 与 actor 必须同 tokenizer、同初始权重。
  • PPO 是 on-policy 算法：采样数据只能用于少数几个 epoch（通常 4），不能像 SFT 那样反复训练多轮。
  • 优势归一化很关键：同一 batch 内对 $ A_t $ 做 whitening（减均值除标准差）能显著稳定训练；奖励尺度失配会导致价值网络崩溃。
  • 长度偏置普遍存在：奖励模型常偏好更长的回答，需用长度惩罚、长度归一化或配对长度匹配来缓解。
  • 奖励模型本身会被"刷分"：RM 只在训练分布附近可靠，策略越偏离，RM 的打分越不可信，因此需要 KL 约束与定期人工评估。
  • 显存是最大工程瓶颈：7B 模型四份权重加优化器状态超过 200 GB，必须用 ZeRO-3/FSDP、LoRA、QLoRA 或 vLLM 分离推理。

技术细节与参数详解

参数分为两类：流程级超参数（决定 RLHF 怎么搭）与 PPO 训练超参数（决定优化是否稳定）。默认值以 HuggingFace TRL 的 PPOConfig 经典默认值为参考，不同版本字段名与默认值可能略有差异，落地时以所装版本文档为准。

参数 1：sft_model_path（策略初始化 / SFT 模型）

  • 含义：PPO 训练的起点，通常加载第一阶段 SFT 后的模型权重。
  • 类型：str（模型路径或 Hub ID）。
  • 默认值：TRL 中为 "lvwerra/gpt2-imdb"（示例默认），实际项目必须替换。
  • 取值范围：任意与 tokenizer 匹配的因果语言模型路径。
  • 对结果的影响：SFT 质量决定上限；若 SFT 模型本身不会遵循指令，PPO 很难把它"训会"，只会放大已有能力。
  • 推荐设置：使用与目标任务同分布、经过充分 SFT 的 checkpoint；不要直接从 base model 开始 PPO。

参数 2：reward_model_path（奖励模型）

  • 含义：为生成回答打分的奖励模型路径，通常是 SFT 模型加一个标量 value head 后做偏好学习得到。
  • 类型：str。
  • 默认值：TRL 示例为 "lvwerra/gpt2-imdb-pos-v2"。
  • 取值范围：任意序列分类/回归式奖励模型路径，输出维度为 1。
  • 对结果的影响：奖励模型的质量与偏见直接决定策略行为；RM 偏好长度，策略就会变长；RM 偏好谄媚，策略就会谄媚。
  • 推荐设置：RM 与策略同规模或略小（InstructGPT 用 6B RM 配 175B 策略）；用与 PPO prompt 同分布的数据训练 RM；上线前做人工一致性评估。

参数 3：beta / init_kl_coef（KL 惩罚系数）

  • 含义：控制策略偏离参考模型的惩罚强度。TRL 中通过 init_kl_coef 设定初值，再由自适应控制器动态调整。
  • 类型：float。
  • 默认值：init_kl_coef = 0.2（TRL 经典默认）。
  • 取值范围：$ (0, +\infty) $，常用 $ 0.01 \sim 0.5 $。
  • 对结果的影响：太小 → KL 迅速增大、策略崩坏、reward hacking；太大 → 策略几乎不更新，输出与 SFT 无差别，训练"白跑"。
  • 推荐设置：全参数微调 7B 模型从 $ 0.02 \sim 0.05 $ 起；LoRA 微调可用 $ 0.1 \sim 0.2 $；观察训练中平均 KL 是否稳定在 5～15 nats 区间。

参数 4：target / target_kl（自适应 KL 目标）

  • 含义：自适应控制器希望维持的平均 KL 值；当实际 KL 低于目标时减小 $ \beta $，高于目标时增大 $ \beta $。
  • 类型：float。
  • 默认值：6.0（TRL 经典默认）。
  • 取值范围：$ [0, +\infty) $，常用 $ 4 \sim 10 $。
  • 对结果的影响：目标越大允许策略跑得越远、学习信号越强但风险越高；越小越保守。
  • 推荐设置：先用默认 6.0；若发现输出重复/退化，降到 3～4；若几乎不学习，升到 8～10。

参数 5：horizon（自适应控制的窗口）

  • 含义：自适应 KL 控制器在多少步内衡量平均 KL，用于平滑更新 $ \beta $。
  • 类型：int。
  • 默认值：10000。
  • 取值范围：$ [1, +\infty) $，常用 1000～10000。
  • 对结果的影响：窗口太小 → $ \beta $ 抖动剧烈；太大 → 对 KL 漂移反应迟钝。
  • 推荐设置：数据量在万级以内用 10000；大规模训练可降到 1000～5000 以加快响应。

参数 6：adap_kl_ctrl（是否自适应调整 KL 系数）

  • 含义：开启后 $ \beta $ 不再固定，而是按"实际 KL 与目标 KL 的比值"动态缩放。
  • 类型：bool。
  • 默认值：True。
  • 取值范围：True / False。
  • 对结果的影响：开启可自动平衡学习与稳定，是 RLHF 能跑通的关键；关闭则需手工调 $ \beta $，对超参极敏感。
  • 推荐设置：始终开启；只有在做消融实验或已有充分调参经验时才关闭。

参数 7：cliprange（策略比率截断 ε）

  • 含义：PPO 目标中重要性采样比的截断范围 $ [1-\epsilon, 1+\epsilon] $。
  • 类型：float。
  • 默认值：0.2。
  • 取值范围：$ (0, 1) $，常用 $ 0.1 \sim 0.3 $。
  • 对结果的影响：太小 → 每次更新幅度小、收敛慢、易早停；太大 → 策略更新过猛、训练不稳定甚至崩溃。
  • 推荐设置：默认 0.2；小模型或数据噪声大时降到 0.1；训练稳定但学得慢时可试 0.25。

参数 8：cliprange_value（价值函数截断 ε_v）

  • 含义：价值网络更新的截断范围，防止价值估计一次跳变过大。
  • 类型：float。
  • 默认值：0.2。
  • 取值范围：$ (0, 1) $，常用 $ 0.1 \sim 0.3 $。
  • 对结果的影响：太小 → 价值网络学得慢，优势估计不准；太大 → 价值损失震荡，进而污染优势与策略梯度。
  • 推荐设置：与 cliprange 保持一致（0.2）；若价值损失剧烈震荡，先检查奖励尺度再调小。

参数 9：gamma（折扣因子 γ）

  • 含义：未来奖励的折扣率。
  • 类型：float。
  • 默认值：1.0。
  • 取值范围：$ [0, 1] $，LLM 场景常用 $ 1.0 $。
  • 对结果的影响：小于 1 会让模型偏向短回答（早期 token 的奖励被折扣）；等于 1 表示整条回答的奖励等权回传。
  • 推荐设置：语言生成固定为 1.0；若希望鼓励"尽早给出结论"，可试 0.99，但要同步调整 GAE。

参数 10：lam（GAE 的 λ）

  • 含义：GAE 中平衡偏差与方差的系数。
  • 类型：float。
  • 默认值：0.95。
  • 取值范围：$ [0, 1] $，常用 $ 0.9 \sim 1.0 $。
  • 对结果的影响：越小 → 优势估计方差小但偏差大、学习信号短视；越大 → 更接近蒙特卡洛回报、方差大但更准确。
  • 推荐设置：默认 0.95；长回答（>512 token）且训练不稳时降到 0.9；短回答可升到 0.98。

参数 11：vf_coef（价值损失权重 c_v）

  • 含义：总损失中价值回归项的权重。
  • 类型：float。
  • 默认值：0.1。
  • 取值范围：$ [0, 1] $，常用 $ 0.05 \sim 0.5 $。
  • 对结果的影响：太小 → 价值网络欠拟合，优势估计噪声大；太大 → 价值损失主导，策略学习被削弱。
  • 推荐设置：0.1 起步；若 value_loss 长期居高不下，先做奖励归一化，再考虑升到 0.2。

参数 12：ent_coef（熵奖励系数 c_e，可选）

  • 含义：鼓励策略输出多样性的系数，熵越高探索越强。
  • 类型：float。
  • 默认值：0.0（多数 RLHF 实现默认关闭；TRL 经典 PPOConfig 不含该字段，需要在自定义损失里手动加入）。
  • 取值范围：$ [0, 0.1] $，常用 $ 0 \sim 0.01 $。
  • 对结果的影响：太大会让输出变得随机、偏离奖励目标；太小（0）则可能过早收敛到单一话术。
  • 推荐设置：SFT 后策略已足够多样时保持 0；出现模式坍塌（同一回答反复出现）时可加 $ 0.001 \sim 0.01 $。

参数 13：learning_rate（学习率）

  • 含义：PPO 优化器的学习率，同时作用于策略与价值网络。
  • 类型：float。
  • 默认值：1e-5。
  • 取值范围：$ 10^{-7} \sim 10^{-4} $，常用 $ 10^{-6} \sim 10^{-5} $。
  • 对结果的影响：太大 → KL 飙升、策略崩坏；太小 → 训练极慢、看起来"没效果"。
  • 推荐设置：7B 全参微调 $ 1\times10^{-6} $；LoRA $ 1\times10^{-5} $；先用小学习率跑 50 步观察 KL 曲线。

参数 14：batch_size（rollout 批大小）

  • 含义：每次 PPO 迭代采样的 prompt 数量（全局批大小）。
  • 类型：int。
  • 默认值：256。
  • 取值范围：$ [1, +\infty) $，常用 64～1024，受显存限制。
  • 对结果的影响：太小 → 梯度噪声大、训练不稳；太大 → 显存占用高、单位时间吞吐下降。
  • 推荐设置：单卡 24GB 跑 7B LoRA 时 32～64；多卡 A100 可到 256～512；确保 batch_size 能被 mini_batch_size × 梯度累积 × 卡数 整除。

参数 15：mini_batch_size（小批大小）

  • 含义：一次前向/反向实际处理的样本数，决定梯度累积的切分方式。
  • 类型：int。
  • 默认值：1（TRL 经典默认，按设备计）。
  • 取值范围：$ [1, \text{batch\_size}] $。
  • 对结果的影响：太小 → 梯度噪声大、GPU 利用率低；太大 → 显存不足。
  • 推荐设置：让每个 mini-batch 至少占满显存的 60%～80%；7B 全参微调常用 1～4，LoRA 可用 8～16。

参数 16：gradient_accumulation_steps（梯度累积步数）

  • 含义：累积多少个 mini-batch 的梯度再更新一次参数。
  • 类型：int。
  • 默认值：1。
  • 取值范围：$ [1, +\infty) $，常用 1～32。
  • 对结果的影响：增大等效于增大批大小，可在小显存上模拟大 batch；但会拉长单步耗时。
  • 推荐设置：显存不足时优先加它而不是减小 batch_size；保证 batch_size = mini_batch_size × grad_accum × num_gpus。

参数 17：ppo_epochs（PPO 轮数）

  • 含义：同一批 rollout 数据被重复用于优化的次数。
  • 类型：int。
  • 默认值：4。
  • 取值范围：$ [1, 10] $，常用 2～4。
  • 对结果的影响：越多 → 数据利用率高，但策略偏离旧策略越远，重要性采样比失真、训练不稳；越少 → 稳定但样本效率低。
  • 推荐设置：默认 4；若 ratio 的均值远离 1 或 KL 飙升，降到 2；数据昂贵时可试 6，但必须配合更小的学习率。

参数 18：max_grad_norm（梯度裁剪阈值）

  • 含义：按全局范数裁剪梯度，防止梯度爆炸。
  • 类型：float。
  • 默认值：1.0。
  • 取值范围：$ (0, +\infty) $，常用 0.5～1.0。
  • 对结果的影响：太小 → 梯度被过度压缩、学习变慢；太大 → 失去保护作用。
  • 推荐设置：1.0；RLHF 中梯度爆炸常见，若频繁触发可降到 0.5 并检查奖励尺度。

参数 19：max_new_tokens / response_length（生成长度）

  • 含义：rollout 阶段每条回答允许生成的最大 token 数。
  • 类型：int。
  • 默认值：TRL 示例常用 512（PPOConfig 本身不含此项时由生成配置指定）。
  • 取值范围：$ [16, 4096] $，视任务而定。
  • 对结果的影响：太短 → 回答被截断、奖励模型无法完整评估；太长 → 显存与时间线性增长，且易触发长度偏置。
  • 推荐设置：摘要 256～512；对话 512～1024；代码 1024～2048；与 RM 训练时的 max_length 保持一致。

参数 20：temperature / top_p / top_k（采样参数）

  • 含义：rollout 时的解码策略，控制探索程度。
  • 类型：float / float / int。
  • 默认值：temperature=1.0、top_p=1.0、top_k=0（即纯采样）。
  • 取值范围：temperature $ (0, 2] $；top_p $ (0, 1] $；top_k $ [0, +\infty) $（0 表示关闭）。
  • 对结果的影响：温度高 → 探索多、样本多样但质量下降；温度低 → 接近贪心、多样性不足，PPO 学不到新行为。
  • 推荐设置：temperature=0.7～1.0、top_p=0.9～1.0；不要用 greedy，否则同一 prompt 永远生成同一回答，GAE 优势全为 0。

参数 21：whiten_rewards（奖励白化）

  • 含义：对每个 mini-batch 的奖励做减均值、除标准差（可选再裁剪）。
  • 类型：bool。
  • 默认值：False。
  • 取值范围：True / False。
  • 对结果的影响：开启可让不同 batch 的奖励尺度一致，稳定价值学习；关闭则依赖原始奖励尺度，容易出现价值损失爆炸。
  • 推荐设置：强烈建议开启，尤其是 RM 分数范围未知时；若开启后学习信号过弱，检查是否把有用信号也归一化掉了。

参数 22：score_clip（奖励裁剪）

  • 含义：对奖励模型输出做截断，抑制极端分数。
  • 类型：float 或 None。
  • 默认值：None（不裁剪）。
  • 取值范围：任意正数，常用 5～10。
  • 对结果的影响：能防止个别样本的超高奖励主导训练；裁剪过狠会丢失区分度。
  • 推荐设置：先用 None 观察奖励分布，若出现长尾极端值再设为均值 ± 3σ 左右。

参数 23：missing_eos_penalty（缺失 EOS 惩罚）

  • 含义：当生成因达到 max_new_tokens 仍未输出 EOS 时，追加的负奖励。
  • 类型：float 或 None。
  • 默认值：None。
  • 取值范围：任意负数，常用 $ -1.0 $。
  • 对结果的影响：不加惩罚时，模型可能学会"永远不结束"以拖延奖励；加了能鼓励完整回答。
  • 推荐设置：生成常被截断时设为 $ -1.0 $；同时检查 max_new_tokens 是否过小。

参数 24：奖励模型的 margin 与 loss_type

  • 含义：margin 要求 win 的分数至少比 lose 高出的最小间隔；loss_type 选择 pairwise logistic 或 margin ranking 损失。
  • 类型：float / str。
  • 默认值：margin=0.0，loss_type="pairwise"（常用实现）。
  • 取值范围：margin $ [0, 10] $；loss_type 取 pairwise / margin。
  • 对结果的影响：margin 太大会让模型只关注"明显更好"的样本，忽略细微偏好；太小则对噪声标注不鲁棒。
  • 推荐设置：标注一致性高时用 0；标注噪声大时可加 0.1～0.5 的 margin，或改用 margin ranking loss。

import torch.nn as nn                                     # 神经网络模块
import torch.nn.functional as F                           # 函数式接口（logsigmoid 等）

class RewardModel(nn.Module):                             # 奖励模型：骨干 + 标量头
    def __init__(self, backbone, hidden_size):            # 构造函数
        super().__init__()                                # 初始化父类
        self.backbone = backbone                          # 预训练语言模型（如 Llama/Qwen）
        self.value_head = nn.Linear(hidden_size, 1, bias=False)  # 把隐藏状态映射为 1 个分数

    def forward(self, input_ids, attention_mask):         # 前向传播
        out = self.backbone(                              # 调用骨干模型
            input_ids=input_ids,                          # token id 序列
            attention_mask=attention_mask,                # 注意力掩码，区分 padding
            output_hidden_states=True,                    # 需要最后一层隐藏状态
        )
        last = out.hidden_states[-1]                      # 取最后一层，形状 (B, T, H)
        lengths = attention_mask.sum(dim=1) - 1           # 每条序列最后一个有效 token 的下标
        batch_idx = torch.arange(last.size(0), device=last.device)  # 批内下标 [0..B-1]
        pooled = last[batch_idx, lengths]                 # 取每条序列的最后一个 token 表示
        return self.value_head(pooled).squeeze(-1)        # 输出形状 (B,) 的标量奖励


def reward_loss(r_win, r_lose, margin=0.0):               # Bradley-Terry 成对损失
    diff = r_win - r_lose - margin                        # 偏好分数差（减去可选 margin）
    return -F.logsigmoid(diff).mean()                     # -log σ(diff)，越小越好

示例 2：GAE 优势估计与 PPO 截断损失（从零实现核心逻辑）

import torch                                              # 导入 PyTorch

def compute_gae(rewards, values, mask, gamma=1.0, lam=0.95):   # 计算 GAE 优势
    B, T = rewards.shape                                  # B 为批大小，T 为序列长度
    advantages = torch.zeros_like(rewards)                # 预分配优势矩阵
    last_adv = torch.zeros(B, device=rewards.device)      # 每个样本的"下一步优势"初值
    for t in reversed(range(T)):                          # 从最后一个 token 往回递推
        next_value = values[:, t + 1] if t + 1 < T else torch.zeros(B, device=rewards.device)  # V(s_{t+1})
        delta = rewards[:, t] + gamma * next_value - values[:, t]   # TD 误差 δ_t
        last_adv = delta + gamma * lam * mask[:, t] * last_adv      # A_t = δ_t + γλA_{t+1}
        advantages[:, t] = last_adv                       # 保存第 t 步优势
    returns = advantages + values                         # 回报目标 R_t = A_t + V(s_t)
    return advantages, returns                            # 返回优势与回报


def ppo_loss(logp, logp_old, values, values_old, returns, advantages,
             cliprange=0.2, cliprange_value=0.2, vf_coef=0.1, ent_coef=0.0, entropy=None):   # PPO 总损失
    ratio = torch.exp(logp - logp_old)                    # 重要性采样比 r_t = π_θ / π_old
    adv = (advantages - advantages.mean()) / (advantages.std() + 1e-8)   # 优势白化，稳定训练
    surr1 = ratio * adv                                   # 未截断的替代目标
    surr2 = torch.clamp(ratio, 1.0 - cliprange, 1.0 + cliprange) * adv   # 截断后的替代目标
    policy_loss = -torch.min(surr1, surr2).mean()         # 取较小值再取负（最大化转最小化）

    value_clipped = values_old + torch.clamp(values - values_old, -cliprange_value, cliprange_value)  # 价值截断
    value_loss = torch.max((values - returns) ** 2, (value_clipped - returns) ** 2).mean()  # 悲观价值损失

    loss = policy_loss + vf_coef * value_loss             # 策略损失 + 价值损失
    if entropy is not None:                               # 若提供熵
        loss = loss - ent_coef * entropy.mean()           # 减去熵奖励（鼓励探索）
    return loss, policy_loss.detach(), value_loss.detach()  # 返回总损失与分项，便于日志

复杂度分析

设策略参数量为 $ P $、批大小为 $ B $、序列长度为 $ T $、模型隐藏维度为 $ d $、层数为 $ L $。

1. Rollout（采样）

自回归生成 $ T $ 个 token，每步都要对整条前缀做一次前向。注意力部分为 $ O(T^2 d) $、FFN 部分为 $ O(T d^2) $，合计：

$$ O\left(B \cdot L \cdot (T^2 d + T d^2)\right) $$

使用 KV Cache 后，每步只需计算新 token，总生成代价降为 $ O(B \cdot L \cdot T d^2) $；但训练时的反向传播仍需完整序列，不能省。

2. PPO 更新

每个 PPO epoch 需要：策略前向 + 反向、价值前向 + 反向、参考模型前向（算 KL）、奖励模型前向（算分数）。粗略有：

$$ O\left(B \cdot T \cdot P \times (2 \sim 3)\right) \times \text{ppo\_epochs} $$

参考模型与奖励模型只做前向（约为训练的 $ 1/3 $ 代价），但四个模型都要驻留显存。

3. 总时间

$$ T_{\text{total}} = O\left(\text{steps} \times \left[T_{\text{rollout}} + \text{ppo\_epochs} \times T_{\text{update}}\right]\right) $$

实际中 rollout 常占总时间的 50%～70%，因此工程上会用 vLLM/SGLang 做推理加速，并把生成与训练分离到不同 GPU。

4. 空间复杂度（显存）

以 bf16 存储、Adam 优化器为例，每个可训练参数约需：

  • bf16 权重 2 B + fp32 master 权重 4 B + Adam 一阶/二阶矩 8 B = 14 B；
  • 两个可训练模型（actor + critic）≈ $ 28P $ B；
  • 两个冻结模型（ref + reward）bf16 ≈ $ 4P $ B；
  • 合计约 $ 32P $ B，加上激活值、KV Cache、临时缓冲区。

对 $ P=7\text{B} $：$ 32 \times 7\times10^9 \approx 224 $ GB，单卡 80 GB 远不够，必须用 ZeRO-3/FSDP 切分参数与优化器状态，或用 LoRA 只训练低秩适配器（可训练参数降到 $ P $ 的 1% 以下）。

5. 与 DPO 的对比

DPO 只需策略与参考两个模型（约 $ 16P $ B），且无需在线 rollout，显存约为 PPO 的 $ 1/2 $、训练步数少一个数量级；代价是失去了在线探索与奖励模型的泛化能力。

应用场景

  • 对话助手对齐：InstructGPT/ChatGPT 的核心流程，让模型更有帮助、更诚实、更无害（HHH）。
  • 摘要与写作：用人类偏好优化摘要的忠实度、覆盖度与可读性，典型如 OpenAI 的 summarization 实验。
  • 代码生成：以单元测试通过率或人类评审作为奖励，优化代码正确性与可维护性。
  • 安全与价值观对齐：降低有害、歧视、越狱回答的比例；配合红队数据做拒绝策略。
  • Agent 与工具调用：以任务完成率、工具调用正确性为奖励，训练多步决策能力。
  • RLAIF / Constitutional AI：用 AI 反馈替代部分人工标注，降低标注成本（Anthropic 的 Constitutional AI）。
  • 个性化与风格控制：按用户偏好（简洁/详细、正式/口语）训练奖励模型，做风格对齐。
