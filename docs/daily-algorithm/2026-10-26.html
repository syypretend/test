一致性哈希

类别：分布式算法 | 难度：中等

算法简介

一致性哈希（Consistent Hashing）是 1997 年由 MIT 的 Karger 等人为解决分布式缓存热点问题而提出的特殊哈希技术，现已成为分布式系统的基石算法之一。它要解决的核心矛盾是：传统「hash(key) % N」分片在节点数量 N 变化时，几乎所有数据都要重新映射。举例来说，缓存集群从 3 台扩到 4 台时，取模哈希会导致约 75%（3/4）的缓存键失效，瞬间把全部读压力打回数据库，形成「缓存雪崩」。

一致性哈希的解法非常优雅：把哈希输出空间（如 32 位整数的 [0, 2^32-1]）首尾相接构成一个哈希环，服务器节点和数据键都通过同一个哈希函数映射到环上，数据沿顺时针方向找到的第一个节点就是它的归属节点。这样节点增删时，只有环上紧邻该节点的一段区间内的数据需要迁移，期望迁移量仅为 K/(N+K)。为解决节点在环上分布不均导致的负载倾斜，又引入虚拟节点机制：每个物理节点在环上放置几十到几百个虚拟节点，使节点分布统计均匀，同时天然支持按机器性能设置权重。Memcached 客户端（Ketama 算法）、Amazon DynamoDB、Apache Cassandra 的数据分片都基于这一思想。

数学公式

公式 1：传统取模哈希分片

$$ \text{server}(k) = h(k) \bmod N $$

  • $ k $：数据键（如缓存 key「user:1001」）
  • $ h(\cdot) $：普通哈希函数（任意均匀哈希均可）
  • $ N $：集群节点总数
  • $ \bmod $：取模运算，把哈希值压缩到 $ [0, N-1] $ 的节点编号区间

当节点数从 $ N $ 变为 $ N+1 $ 时，同一个键 $ k $ 的 $ h(k) $ 不变，但 $ N $ 变了，导致约 $ \frac{N}{N+1} $ 的数据需要重新分配——这就是灾难所在。

公式 2：哈希环位置映射

$$ \text{pos}(x) = h(x) \bmod 2^{32} $$

  • $ x $：待映射对象，既可以是节点标识（如 IP「10.0.0.1:11211」），也可以是数据键
  • $ \text{pos}(x) $：对象在哈希环上的位置，取值 $ [0, 2^{32}-1] $
  • $ 2^{32} $：32 位哈希空间的环周长；工程上也可选 $ 2^{64} $ 或 $ 2^{128} $

公式 3：顺时针归属规则（数据定位）

$$ \text{node}(k) = \min\Big\{ s_i \,\Big|\, s_i \geq \text{pos}(k),\ s_i \in S \Big\} $$

  • $ S = \{s_1, s_2, \dots, s_V\} $：所有虚拟节点在环上的位置集合（已排序）
  • $ s_i $：第 $ i $ 个虚拟节点的环上位置
  • $ \min\{\cdot\} $：取大于等于数据位置的最小节点位置，即顺时针方向遇到的第一个节点
  • 若集合为空（数据位置大于环上最大节点位置），则回绕到环起点，取位置最小的节点 $ s_{(1)} $——环是首尾相接的

公式 4：节点变动时的数据迁移比例

$$ \mathbb{E}\left[\frac{\text{迁移数据量}}{\text{总数据量}}\right] = \frac{K}{N+K} $$

  • $ N $：原有节点数；$ K $：新增（或摘除）的节点数
  • 直觉：新增节点只「接管」它在环上所占据的那 $ K $ 段弧长，占整个环的比例即为 $ \frac{K}{N+K} $
  • 对比取模哈希：同样场景下迁移比例约为 $ \frac{N}{N+K} $，高出 $ (N+K)/K $ 倍

公式 5：虚拟节点生成

$$ \text{pos}_{i,j} = h(\text{node}_i \,\|\, j), \quad j = 0, 1, \dots, V_i - 1 $$

  • $ \text{node}_i $：第 $ i $ 个物理节点的标识（IP:端口）
  • $ \| $：字符串拼接符，如 h("10.0.0.1#0")、h("10.0.0.1#1")
  • $ j $：虚拟节点序号
  • $ V_i $：节点 $ i $ 的虚拟节点数，由权重决定：$ V_i = V_{\text{base}} \times w_i $（$ w_i $ 为权重因子）

核心要点

  • 单调性（Monotonicity）：新增节点时，已有数据只可能从旧节点迁移到新节点，绝不在旧节点之间互相搬移
  • 平衡性（Balance）：虚拟节点越多，各节点负载越接近理论均值 $ 1/N $；Ketama 默认 160 个/节点
  • 分散性（Spread）：同一键在不同客户端视角下映射结果尽量一致，减少同一数据的多副本散落
  • 哈希函数选择：要求输出在环上均匀分布，MD5/xxHash/MurmurHash 均可，避免 CRC32 这类线性哈希处理相似输入
  • 回绕处理：环是逻辑闭环，定位查找失败时必须回绕到起点，这是新手实现最常漏掉的 bug

技术细节与参数详解

以业界最经典的 Ketama（Memcached 一致性哈希实现）与通用实现为参照，逐个讲解核心可调参数。

#### 参数 1：virtual_nodes（每个物理节点的虚拟节点数）

  • 含义：每个物理节点在哈希环上放置的虚拟位置数量。每个虚拟节点是「节点标识 + 序号」哈希后落环的独立锚点
  • 类型：整数（int）
  • 默认值：Ketama 算法为 160；常见库还有 100（spymemcached）、150（twemproxy）
  • 取值范围：1 到数百万均可，工程上通常 10 ~ 1000
  • 对结果的影响：
  • 越大 → 节点在环上的弧长占比越接近权重比例，负载越均匀（标准差随 $ \sqrt{V} $ 收敛）
  • 越小 → 节点间负载偏差增大，可能出现某节点分到 30% 请求、另一节点仅 10% 的倾斜
  • 过大 → 建环内存、增删节点的重排成本上升，收益却边际递减
  • 推荐设置：生产缓存集群用 150~200；节点数很少（如 3 台）时建议取 500+ 补偿小样本偏差；一致性要求高的存储系统可用 1000

#### 参数 2：hash_function（哈希函数选择）

  • 含义：把节点标识和数据键映射到环上位置所用的函数
  • 类型：可插拔的哈希算法（字符串 → 整数）
  • 默认值：Ketama 用 MD5（取摘要的 32 位切片）；xxHash/MurmurHash/SipHash 也是主流选择
  • 取值范围：任意输出均匀的哈希函数
  • 对结果的影响：
  • 分布均匀性直接决定负载均衡质量；对相似输入（如同一网段的 IP）敏感的哈希会造成节点扎堆
  • CRC32 这类线性哈希不建议直接使用，对有规律的输入分布差
  • 哈希必须在所有客户端/服务端版本间保持一致，否则同一数据被不同机器定位到不同节点——一致性比性能更重要
  • 推荐设置：优先沿用框架默认（Ketama-MD5 兼容生态最广）；新系统可用 xxHash64（非加密哈希中最快之一，分布质量好）。不要使用会随版本变化的 hash() 内置函数

#### 参数 3：ring_bits（哈希空间位数）

  • 含义：哈希环的总刻度数，决定环的周长 $ 2^{\text{bits}} $
  • 类型：整数（int），以 2 为幂
  • 默认值：32 位（$ 2^{32} \approx 43 $ 亿个位置），64 位实现见于部分存储系统
  • 取值范围：一般 32 / 64 / 128
  • 对结果的影响：位数越大，哈希碰撞概率越低、分布更细腻，但定位计算与存储宽度变大；32 位对绝大多数缓存集群完全够用
  • 推荐设置：默认 32 位即可；与 MD5/xxHash32 对齐实现最简单

#### 参数 4：node_weight（节点权重）

  • 含义：表征节点处理能力差异的比例因子，决定其虚拟节点数量 $ V_i = V_{\text{base}} \times w_i $
  • 类型：浮点数或整数（float/int）
  • 默认值：1.0（所有节点等权）
  • 取值范围：大于 0 的任意正数；如 0.5（半容量小容器）、2.0（双倍配置大机器）
  • 对结果的影响：权重大的节点在环上占据更大弧长，分到更多数据与流量，实现异构集群的按容量分流
  • 推荐设置：按机器内存或 CPU 容量比例设置，如 64GB 机器权重 2、32GB 机器权重 1

#### 参数 5：replica_count（数据副本数）

  • 含义：一份数据在环上沿顺时针方向存储到连续几个不同物理节点（用于数据冗余，缓存场景常为 1，存储场景常为 3）
  • 类型：整数（int）
  • 默认值：缓存系统 1（缓存可丢）；存储系统（DynamoDB 风格）3
  • 取值范围：1 ~ N-1（N 为物理节点数）
  • 对结果的影响：副本越多可靠性越高、可用性越强，但写放大与存储成本线性上升；副本放置须跳过同一物理节点的多个虚拟节点，否则虚节点会骗过副本机制
  • 推荐设置：纯缓存用 1；持久化存储用 3，并确保副本落在不同机架/可用区

#### 参数 6：lookup_mode（环上查找方式）

  • 含义：给定数据位置后，如何在有序的虚拟节点位置数组中定位「顺时针第一个节点」
  • 类型：枚举（线性扫描 / 二分查找 / 跳表）
  • 默认值：成熟实现均为二分查找
  • 取值范围：linear、binary、skiplist
  • 对结果的影响：决定单次请求定位复杂度：线性 $ O(V) $（V 为虚拟节点总数，300 节点×160 虚节点=4.8 万次扫描太慢）；二分 $ O(\log V) $（约 16 次比较）；结果本身无差别，纯性能差异
  • 推荐设置：必须用二分查找（虚拟节点数组保持有序，bisect 即可）

#### 参数 7：ring_rebuild_strategy（增删节点时的环维护策略）

  • 含义：节点变更时如何更新环结构
  • 类型：枚举（全量重建 / 增量插入删除）
  • 默认值：小集群常全量重建，大集群用增量
  • 取值范围：rebuild_all、incremental
  • 对结果的影响：全量重建简单可靠但增删节点时 $ O(V \log V) $；增量插入（insort）为 $ O(V) $ 挪动。注意元数据同步：所有客户端必须尽快看到一致的新环视图，否则出现短暂的「数据找不到/双写」
  • 推荐设置：节点规模 < 100 用全量重建（每次也就毫秒级）；配合配置中心推送新环快照保证视图一致

代码示例

import hashlib                    # 标准库哈希算法集合，Ketama 传统上使用 MD5 保证跨语言一致性
import bisect                     # 二分查找模块，实现 O(log V) 的环上定位
from typing import Dict, List, Optional  # 类型标注，提升代码可读性
from collections import Counter   # 计数器，用于统计键的分布


class ConsistentHashRing:
    """一致性哈希环：支持虚拟节点、节点权重、二分定位与副本查找"""

    def __init__(self, vnodes: int = 160, hash_name: str = "md5"):
        self.vnodes: int = vnodes          # 参数1：每个权重单位对应的虚拟节点数，默认 160（Ketama 默认）
        self.hash_name: str = hash_name    # 参数2：哈希函数名，默认 md5 与 Ketama 生态兼容
        self._ring: List[int] = []         # 升序排列的虚拟节点位置数组，供二分查找（参数6）
        self._sorted_nodes: List[str] = [] # 与 _ring 位置一一对应的物理节点名（下标对齐）
        self._node_map: Dict[str, int] = {}  # 物理节点名 -> 该节点当前拥有的虚拟节点数

    def _hash(self, key: str) -> int:
        """把任意字符串哈希为 [0, 2^32) 的环上位置（公式2）"""
        digest = hashlib.new(self.hash_name, key.encode("utf-8")).digest()  # 计算 MD5 摘要，UTF-8 编码避免中文 key 报错
        return int.from_bytes(digest[:4], "big")  # 取摘要前 4 字节组成 32 位无符号整数，正好覆盖 0 ~ 2^32-1 的环空间

    def _gen_vnode_key(self, node: str, index: int) -> str:
        """生成第 index 个虚拟节点的哈希输入串（公式5：node#j）"""
        return f"{node}#{index}"           # 用 '#' 拼接节点标识与序号，等价于公式中的 ||（拼接）运算

    def add_node(self, node: str, weight: float = 1.0):
        """新增物理节点：按权重放置 vnodes*weight 个虚拟节点（公式5 的 V_i）"""
        count = int(self.vnodes * weight)  # 虚拟节点数 = 基准值 × 权重（参数4），如 160 × 0.5 = 80
        for i in range(count):             # 逐个生成虚拟节点
            pos = self._hash(self._gen_vnode_key(node, i))   # 计算该虚拟节点在环上的位置
            idx = bisect.bisect_left(self._ring, pos)        # 二分找到插入点，保持数组有序
            self._ring.insert(idx, pos)                      # 插入位置（增量策略，参数7）
            self._sorted_nodes.insert(idx, node)             # 同步插入物理节点名，保证两数组下标始终对齐
        self._node_map[node] = self._node_map.get(node, 0) + count  # 登记该节点的虚拟节点总数

    def remove_node(self, node: str):
        """摘除物理节点：删除它名下所有虚拟节点（触发该弧段数据迁移）"""
        if node not in self._node_map:     # 防御：节点不存在时直接返回，避免误删
            return
        keep_pos: List[int] = []           # 暂存保留下来的位置
        keep_name: List[str] = []         # 暂存保留下来的节点名
        for pos, name in zip(self._ring, self._sorted_nodes):  # 遍历整个环
            if name != node:               # 只保留不属于待删节点的虚拟节点
                keep_pos.append(pos)
                keep_name.append(name)
        self._ring, self._sorted_nodes = keep_pos, keep_name  # 一次性替换两个数组
        del self._node_map[node]           # 清理登记表

    def get_node(self, key: str) -> Optional[str]:
        """定位单个 key 的归属节点（公式3：顺时针第一个虚拟节点）"""
        if not self._ring:                 # 空环防御：没有任何节点时返回 None
            return None
        pos = self._hash(key)              # 数据键哈希到环上位置
        idx = bisect.bisect_right(self._ring, pos)  # 找第一个严格大于 pos 的下标（right 保证命中环点时取下一个）
        if idx == len(self._ring):         # 越界说明 pos 在最大节点位置之后
            idx = 0                        # 环形回绕：回到环起点，取位置最小的节点（公式3 的空集分支）
        return self._sorted_nodes[idx]     # 返回该虚拟节点对应的物理节点

    def get_nodes(self, key: str, replica: int = 1) -> List[str]:
        """定位 key 的 replica 个不同物理节点（参数5：数据副本放置）"""
        result: List[str] = []             # 收集结果，去重后最多 replica 个物理节点
        if not self._ring:
            return result                   # 空环返回空列表
        pos = self._hash(key)              # 键位置
        idx = bisect.bisect_right(self._ring, pos)  # 起始下标
        for _ in range(len(self._sorted_nodes)):  # 最多绕环一圈
            if idx >= len(self._ring):     # 越界回绕
                idx = 0
            name = self._sorted_nodes[idx]  # 候选物理节点
            if name not in result:          # 跳过同一物理节点的重复虚拟节点（防止副本落在同一台机器）
                result.append(name)
                if len(result) == replica:  # 凑够副本数立即返回
                    return result
            idx += 1                       # 顺时针步进到下一个虚拟节点
        return result                      # 物理节点总数不足 replica 时返回全部


if __name__ == "__main__":
    ring = ConsistentHashRing(vnodes=160)  # 参数1：每节点 160 个虚拟节点（Ketama 默认）
    for server in ["10.0.0.1:11211", "10.0.0.2:11211", "10.0.0.3:11211"]:  # 模拟 3 台 Memcached 服务器
        ring.add_node(server)              # 等权加入（参数4 weight 默认 1.0）
    keys = [f"user:{uid}" for uid in range(100000)]  # 构造 10 万个键做分布统计
    stat = Counter(ring.get_node(k) for k in keys)   # 统计各节点分到的键数，理想接近 1/3 ≈ 33333
    print("扩容前分布:", dict(stat))       # 观察三个节点各约 33% ± 少量偏差（虚拟节点保证）
    before = {k: ring.get_node(k) for k in keys[:1000]}  # 记录前 1000 个键的旧归属
    ring.add_node("10.0.0.4:11211")        # 新增第 4 台节点，验证迁移量
    moved = sum(1 for k, v in before.items() if ring.get_node(k) != v)  # 统计归属发生变化的键数
    print(f"扩容后 1000 个键中迁移 {moved} 个（理论约 250 = 1/4，取模哈希则约 750）")  # 公式4 的直观验证
    print("user:1001 归属:", ring.get_node("user:1001"))   # 单键定位演示
    print("user:1001 副本:", ring.get_nodes("user:1001", replica=2))  # 双副本放置演示（参数5）

复杂度分析

时间复杂度（设物理节点数 $ N $，每节点虚拟节点数 $ V_0 $，虚拟节点总数 $ V = N \cdot V_0 $）：

  • 建环：$ N $ 个节点共生成 $ V = N \cdot V_0 $ 个虚拟节点位置，逐个有序插入时每次 $ O(V) $ 挪动，总计 $ O(V^2) $；若先批量生成再统一排序，则为 $ O(V \log V) $——推荐后者。以 $ N=300 $、$ V_0=160 $ 计，$ V=48000 $，排序约 48 万次比较，毫秒级完成
  • 单次定位：位置数组上二分查找，每轮比较折半，$ O(\log V) $。$ V=48000 $ 时仅约 16 次比较；对比线性扫描 48000 次，快约 3000 倍
  • 增删一个节点：插入/删除 $ V_0 $ 个虚拟节点位置，每个 $ O(V) $ 数组挪动，总计 $ O(V \cdot V_0) $；同时仅该节点弧段内的数据迁移，迁移量期望为总数据的 $ \frac{1}{N} $（与 $ V_0 $ 无关，公式 4 中 $ K=1 $ 情形）

空间复杂度：$ O(V) $ 存储虚拟节点位置数组与映射表；$ V = 48000 $ 个整数约 400KB，可忽略不计。

推导关键——为什么负载偏差随 $ V_0 $ 收敛？ 节点占环比例 $ \hat{p} $ 近似服从二项分布，$ \text{Var}(\hat{p}) = \frac{p(1-p)}{V_0} $，标准差 $ \propto \frac{1}{\sqrt{V_0}} $。$ V_0 $ 从 10 提到 160 时偏差缩小 $ \sqrt{16} = 4 $ 倍——这就是 Ketama 选 160 的统计学依据。

应用场景

  • 分布式缓存客户端分片：Memcached 客户端（Ketama / spymemcached / twemproxy）在上百台缓存节点间路由键，扩缩容不雪崩
  • 分布式 KV 存储：Amazon DynamoDB、Apache Cassandra 的 token ring 数据分区，即一致性哈希 + 虚拟节点思想
  • CDN 与边缘节点调度：把 URL 哈希到边缘节点，节点上下线时仅局部用户受影响
  • 有状态负载均衡：会话保持场景把会话 ID 绑定到后端服务器，后端弹性伸缩时会话大面积不丢
  • 消息队列分区分配：主题-队列映射、消费者组分区再平衡的底层思想
  • 对比参照：Redis Cluster 采用 16384 个 hash slot 的槽定位方案，可视为一致性哈希的离散化变体——槽显式分配、按槽整体迁移，运维更可控

模型合并 Model Merging

类别：大模型微调 | 难度：中等

算法简介

模型合并（Model Merging）是 2023 年以来兴起的一种零训练成本的大模型能力整合技术：把多个同结构的 LLM 的权重按某种数学规则融合成一个新模型，从而把「一个会写代码的模型 + 一个懂数学的模型 + 一个会聊天的模型」的能力叠加到一个模型里，全程不需要 GPU、不需要梯度更新，一台笔记本几分钟就能完成。它之所以可行，源于一个关键经验发现：大模型微调时改变的参数（Delta 参数）高度冗余——95% 以上的参数变化对性能贡献微乎其微，且不同任务学到的「任务向量」在参数空间中近乎正交、互不干扰。

经典方法按提出时间排序：加权平均（Linear Interpolation）直接对多个模型权重做凸组合；SLERP（球面线性插值）在归一化权重的球面上走大圆弧，保留方向信息；Task Arithmetic（任务算术，ICLR 2023）提出任务向量 $ \tau = \theta_{\text{FT}} - \theta_{\text{pre}} $ 的加减法，通过「预训练权重 + 任务向量之和」注入能力；TIES-Merging（ICLR 2023）解决多模型合并时的参数冲突——先按幅度修剪（Trim）、再按符号投票（Elect）、最后同号求均（Agree）；DARE（2023）发现随机丢弃 90% 甚至 99% 的 Delta 参数再缩放，性能几乎不降，进一步消除冲突。社区工具 MergeKit 已把这些方法封装为 YAML 配置，Open LLM Leaderboard 上曾涌现大量合并模型。但要注意：并非任意合并都有效——2026 年 10 月的研究与报道指出，分别独立训练的模型合并后性能可能大幅下降，合并效果高度依赖「是否共享同一基座」与「任务向量是否正交」。

原理示意图

上图完整呈现合并主线：同一基座模型 $ \theta_{\text{pre}} $ 分别微调出三个专家模型，各自减去基座得到任务向量 $ \tau_A、\tau_B、\tau_C $；多个任务向量直接相加会发生符号冲突（你往东我往西），TIES 用「修剪 → 投票 → 平均」三步消解冲突；最终通过 Task Arithmetic 的加法 $ \theta_{\text{merged}} = \theta_{\text{pre}} + \lambda \tau $ 把合并后的能力注回基座。

数学公式

公式 1：加权平均（Linear / SLMERGE 基线）

$$ \theta_{\text{merged}} = \sum_{i=1}^{m} \lambda_i \,\theta_i, \quad \sum_{i=1}^{m} \lambda_i = 1 $$

  • $ \theta_i $：第 $ i $ 个模型的参数张量（同一层的同名权重矩阵）
  • $ \lambda_i $：第 $ i $ 个模型的混合权重，非负且总和为 1（凸组合保证数值范围不发散）
  • $ m $：参与合并的模型数量
  • 局限：当两个模型在某个参数上一个增一个减时，平均会把两个能力都稀释

公式 2：任务向量与 Task Arithmetic（能力加减法）

$$ \tau_i = \theta_i^{\text{FT}} - \theta_{\text{pre}}, \qquad \theta_{\text{merged}} = \theta_{\text{pre}} + \lambda \sum_{i=1}^{m} \tau_i $$

  • $ \theta_{\text{pre}} $：共享预训练基座参数
  • $ \theta_i^{\text{FT}} $：第 $ i $ 个微调模型参数
  • $ \tau_i $：任务向量（Task Vector），编码「完成第 $ i $ 个任务所需的方向与幅度」
  • $ \lambda $：全局缩放系数（类似学习率，典型 0.3~1.0）
  • 优点：$ \tau_{\text{任务}} $ 可以加（注入能力）也可以减（遗忘/去毒）；不同任务的 $ \tau $ 近似正交时互不干扰

公式 3：SLERP 球面线性插值（保留方向/角度关系）

$$ \theta(t) = \frac{\sin\big((1-t)\,\Omega\big)}{\sin \Omega}\,\theta_0 + \frac{\sin(t\,\Omega)}{\sin \Omega}\,\theta_1, \qquad \cos\Omega = \frac{\theta_0 \cdot \theta_1}{\|\theta_0\|\,\|\theta_1\|} $$

  • $ \theta_0, \theta_1 $：两个模型的（归一化后）权重向量
  • $ t \in [0,1] $：插值参数，$ t=0 $ 完全取模型 0，$ t=1 $ 完全取模型 1
  • $ \Omega $：两权重向量在超球面上的夹角（$ \arccos $ 由点积与范数计算）
  • 与线性插值的区别：SLERP 沿大圆弧移动，恒定角速度，两个端点权重模长更均衡，合并 2 个模型时效果通常优于 linear
  • 只适用两模型；多模型需两两嵌套或退化为 linear

公式 4：TIES-Merging 三步（Trim → Elect → Agree）

$$ \tau_i^{\prime} = \tau_i \cdot \mathbb{1}\big[|\tau_i| \geq \text{top-}k\%\big] \quad (\text{Trim}), \qquad \Delta = \text{sign}\Big(\sum_i \tau_i^{\prime}\Big) \quad (\text{Elect}), \qquad \tau_{\text{merged}} = \Delta \odot \frac{\sum_i \mathbb{1}[\text{sign}(\tau_i^{\prime})=\Delta]\,\tau_i^{\prime}}{\sum_i \mathbb{1}[\text{sign}(\tau_i^{\prime})=\Delta]} \quad (\text{Agree}) $$

  • $ \tau_i $：第 $ i $ 个任务向量（逐元素操作）
  • $ \text{top-}k\% $：幅度修剪阈值（对应 density 参数），只保留绝对值最大的那部分参数，去除微小噪声冗余
  • $ \mathbb{1}[\cdot] $：指示函数，条件成立取 1、否则取 0
  • $ \Delta $：符号投票结果，多数模型认为该参数应「增大」取 +1，多数认为「减小」取 −1——直接消除 $ +x $ 与 $ -y $ 直接相加互相抵消的冲突
  • $ \odot $：逐元素相乘（Hadamard 积）
  • 分子：与投票方向一致的任务向量求和；分母：同方向向量的计数——即只对同号参数求均值

公式 5：DARE（随机丢弃 + 期望不变缩放）

$$ \tau_i^{\text{DARE}} = \frac{\mathbf{m}_i}{1-p} \odot \tau_i, \qquad \mathbf{m}_i \sim \text{Bernoulli}(1-p) $$

  • $ p $：丢弃概率（DARE 论文展示 0.9 甚至 0.99 仍可工作），$ \mathbf{m}_i $ 为 0/1 掩码
  • $ \frac{1}{1-p} $：缩放因子，使 $ \mathbb{E}[\tau_i^{\text{DARE}}] = \tau_i $（期望不变、方差放大）
  • 物理意义：Delta 参数中绝大部分是冗余，随机扔掉后其余参数放大即可近似补偿，同时天然减少多模型间的参数冲突（90% 都被扔了，碰巧同位冲突的概率骤降）

核心要点

  • 零训练成本：不涉及前向/反向传播，只要会加载/保存 safetensors，消费级 CPU 即可完成 7B 模型合并
  • 同基座是前提：所有参与模型必须结构一致且源自同一预训练权重（同一 θ_pre），否则任务向量没有共同坐标系，合并必然崩坏——2026 年研究证实独立训练的模型合并性能会大幅下降
  • 冲突是主要矛盾：多模型合并的核心难题是符号冲突，TIES 投票与 DARE 丢弃是两大主流消解思路
  • 逐层可独立调参：MergeKit 支持按层（layer granularity）设置不同的 density/weight，因为 Transformer 各层对合并的敏感度不同
  • 合并不能注入新知识：只能重组已有能力，无法让模型获得所有源模型都不具备的技能；数学上等价于在参数空间做凸组合/选择，不产生新方向之外的信息
  • 评测不可省：合并结果必须跑 benchmark 验证，存在「合并后低于所有源模型」的风险（能力干涉）

技术细节与参数详解

以社区标准工具 MergeKit（mergekit-yaml）为参照，逐参数讲解。命令行用法：mergekit-yaml config.yaml ./output-model --cuda --lazy-unpickle。

#### 参数 1：merge_method（合并方法）

  • 含义：决定采用哪种数学规则融合权重，是 YAML 中最核心的开关
  • 类型：字符串枚举
  • 默认值：无（必填）
  • 取值范围：linear、slerp、ties、task_arithmetic、dare_ties、dare_linear、model_stock、model_soups、passthrough（仅复制/裁剪层）
  • 对结果的影响：
  • linear：两模型最平滑；slerp：两模型时通常优于 linear；多模型冲突大时 ties/dare_ties 显著更稳；passthrough 用于做层裁剪/深堆叠（如depth up-scaling）
  • 推荐设置：两个模型选 slerp；三个及以上选 dare_ties（社区实测成功率最高的路线之一）

#### 参数 2：weight（各模型混合权重）

  • 含义：每个参与模型在该层合并中的相对贡献
  • 类型：浮点数（float），写在每个 models 条目内
  • 默认值：linear 方法下需保证所有权重的和为 1；ties/dare 系列中作相对倍率（不要求和为 1，会内部归一化）
  • 取值范围：0 ~ 1（linear 约束下）；ties/dare 可为任意非负数如 0.5、1.0、2.0 表示信任度
  • 对结果的影响：权重高的模型能力在合并结果中占比更重；某模型权重过低其能力几乎被忽略；全 1.0 表示平权
  • 推荐设置：想保留某主模型 70% 特性时设 0.7 + 0.3（linear 两模型）；不确定时全部 1.0 平权，再按评测微调

#### 参数 3：density（参数保留密度）

  • 含义：TIES/DARE 系方法中，按幅度保留（或丢弃）任务向量的比例
  • 类型：浮点数（float）
  • 默认值：mergekit 中 ties 常用 0.7；dare_* 的 drop 率常配 0.9（即保留 0.1）
  • 取值范围：0 ~ 1（1 表示不修剪；0 表示全部丢弃——无效）
  • 对结果的影响：密度越低，冲突越少、但信息损失越多；DARE 论文显示低密度下性能依然坚挺（Delta 冗余），而过低（如 0.01）会崩坏
  • 推荐设置：ties 用 0.5~0.7；dare_ties 用 density=0.5~0.75 + drop 率另行控制（版本不同写法有别，以所用 MergeKit 版本文档为准）；每层可不同（0 层 embedding 附近宜高）

#### 参数 4：t（SLERP 插值参数）

  • 含义：球面插值中两模型的混合比例
  • 类型：浮点数（float）
  • 默认值：无默认，必填（仅 slerp 方法使用）
  • 取值范围：0 ~ 1（0=完全取第一模型，1=完全取第二模型，0.5=各半）
  • 对结果的影响：t 越大越偏向第二个模型；与 linear 的 weight 不同，它沿球面弧线而非直线移动，在两模型差异较大时过渡更平滑
  • 推荐设置：0.4 ~ 0.6 起步，按评测在 0.25/0.5/0.75 网格搜索

#### 参数 5：base_model（基座模型）

  • 含义：task_arithmetic / ties / dare 系方法中作为「共同原点」的预训练模型，任务向量以其为参照
  • 类型：字符串（HuggingFace 模型名或本地路径）
  • 默认值：无（这些方法必填）
  • 取值范围：与参与模型同源同构的任意模型
  • 对结果的影响：选错基座（与微调模型不同源）时任务向量无意义，合并产物大概率不可用；基座决定了「回到哪个公共点」
  • 推荐设置：必须填所有参与模型的共同预训练祖先（如都在 mistralai/Mistral-7B-v0.1 上微调，就填它）

#### 参数 6：slices / layer_range（层切片）

  • 含义：把模型按层划分为多个切片，每个切片可独立配置合并参数（哪些层、用哪些模型、什么 weight/density）
  • 类型：列表（YAML 数组），每项含 sources 与逐层参数
  • 默认值：不写 slices 时对全模型统一处理
  • 取值范围：任意连续或离散层区间，如 layer_range: [0, 8]、[8, 16]
  • 对结果的影响：底层（embedding、attention 前几层）与顶层的能力承载不同；逐层调参能显著改善合并质量；也可用于层裁剪/深堆叠（passthrough）
  • 推荐设置：先整体合并，发现部分层不稳再按 1/4~1/3 分段精调；embedding 层（token_embedder）常需单独处理

#### 参数 7：normalize（权重归一化开关）

  • 含义：合并前是否把各模型权重归一化（多用于 ties/linear 变体，避免范数差异干扰）
  • 类型：布尔（bool）
  • 默认值：通常 false
  • 取值范围：true / false
  • 对结果的影响：源模型训练后权重范数差异大时，不归一化会让范数大的模型实际主导合并；归一化后更侧重「方向」而非「幅度」
  • 推荐设置：源模型训练轮数/学习率差异大时开启尝试；相同配方微调出的模型保持 false

#### 参数 8：dtype（输出数值精度）

  • 含义：合并结果保存的浮点精度
  • 类型：字符串枚举
  • 默认值：跟随输入模型（多数为 float16 或 bfloat16）
  • 取值范围：float16、bfloat16、float32
  • 对结果的影响：float16 在数亿参数累加时可能溢出（尤其 linear 大权重和）；float32 最安全但体积翻倍；bfloat16 动态范围大，是大模型首选
  • 推荐设置：默认 bfloat16；若合并中报 inf/nan 则改 float32 排查

#### 参数 9：--cuda 与 --lazy-unpickle、--low-cpu-memory（CLI 资源参数）

  • 含义：--cuda 用 GPU 加速逐元素运算；--lazy-unpickle 惰性加载避免一次性读入整个模型；--low-cpu-memory 分块处理省内存
  • 类型：命令行布尔开关
  • 默认值：均为关闭（纯 CPU 也可完成 7B 合并，只是慢）
  • 取值范围：开/关
  • 对结果的影响：只影响速度与内存占用，不影响合并结果数值（浮点顺序差异极小可忽略）
  • 推荐设置：有 GPU 加 --cuda；内存 <32GB 加 --low-cpu-memory --lazy-unpickle

#### 参数 10：--copy-tokenizer 与 --trust-remote-code（CLI 辅助参数）

  • 含义：--copy-tokenizer 把 tokenizer 文件复制进输出目录（推荐，避免缺文件）；--trust-remote-code 允许加载带自定义代码的模型（某些架构必需）
  • 类型：命令行布尔开关
  • 默认值：均为关闭
  • 取值范围：开/关
  • 对结果的影响：--copy-tokenizer 影响发布可用性；--trust-remote-code 影响能否加载（安全上仅信任可信来源）
  • 推荐设置：--copy-tokenizer 始终开启；自定义架构模型（如某些 MoE）需要 --trust-remote-code 时再开

def task_vector(ft: dict, base: dict, key: str) -> torch.Tensor:
    """计算指定参数名的任务向量 τ = θ_FT − θ_pre（公式2 前半部分）"""
    return ft[key].float() - base[key].float()  # 转 float32 再相减，避免半精度下小差异被吞掉


def ties_merge(taus: list, density: float) -> torch.Tensor:
    """TIES 三步合并多个任务向量（公式4：Trim → Elect → Agree）"""
    stacked = torch.stack(taus)                   # 堆叠成 [m, rows, cols]，m 为模型数，便于一次算全模型
    k = max(1, int(stacked.numel() / stacked.shape[0] * density))  # 每个向量保留的元素总数（按 density 换算）
    flat = stacked.flatten(1)                     # 展平每个向量成 [m, numel]，便于逐向量取 top-k
    thresh = flat.abs().kthvalue(int(flat.shape[1] * (1 - density)), dim=1).values  # 每行找幅度阈值（下取 1-density 分位）
    trimmed = flat * (flat.abs() >= thresh.unsqueeze(1)).float()   # Trim：保留幅度达标元素，其余置零（去掉微小冗余）
    sign_sum = trimmed.sum(dim=0)                 # 对所有模型在同一个参数位置上求和，用于统计符号
    elected = torch.sign(sign_sum)                # Elect：符号投票，多数为正取 +1，多数为负取 −1
    same_sign = (torch.sign(trimmed) == elected.unsqueeze(0)).float()  # 生成掩码：标记与投票方向一致的贡献
    numerator = (trimmed * same_sign).sum(dim=0)  # Agree 分子：只累加「与当选方向同号」的参数值
    denominator = same_sign.sum(dim=0).clamp(min=1)  # Agree 分母：同号贡献的计数（防 0 保护）
    return (numerator / denominator).view_as(stacked[0])  # 求均值并还原原始形状 [rows, cols]


def main():
    base = load_tensor("base_model.safetensors")    # 加载共同基座 θ_pre
    ft_a = load_tensor("model_code.safetensors")    # 加载代码微调模型 θ_A
    ft_b = load_tensor("model_math.safetensors")    # 加载数学微调模型 θ_B
    merged = {}                                     # 存放合并后的全部参数
    for key in base:                                # 逐参数遍历（参数名对齐是合并可行的前提）
        tau_a = task_vector(ft_a, base, key)        # 任务向量 τ_A（公式2）
        tau_b = task_vector(ft_b, base, key)        # 任务向量 τ_B
        tau = ties_merge([tau_a, tau_b], density=0.7)  # TIES 合并（density 保留 70%）
        merged[key] = (base[key].float() + 0.8 * tau).to(torch.bfloat16)  # Task Arithmetic 注回基座（λ=0.8，公式2 后半部分）
    save_file(merged, "merged_model.safetensors")   # 保存合并结果（dtype=bfloat16）


if __name__ == "__main__":
    main()                                          # 全程无 GPU、无训练，纯张量算术完成能力合并

复杂度分析

设参数总量为 $ P $（如 7B 模型 $ P \approx 7 \times 10^9 $），参与合并模型数 $ m $，单个任务向量元素数 $ P $：

  • 任务向量计算：逐元素相减，$ O(m \cdot P) $ 次浮点减法，7B 模型每个约 28GB(float32) 量级的内存带宽操作
  • TIES 的 Trim：逐模型找幅度分位阈值，kthvalue 为 $ O(P) $（选择算法）；naive 排序实现为 $ O(P \log P) $——是全流程中最贵的一步
  • Elect/Agree：符号判断与掩码求和均为 $ O(m \cdot P) $ 逐元素操作
  • DARE：生成 Bernoulli 掩码 + 逐元素乘法，$ O(m \cdot P) $，比 TIES 更便宜
  • 总时间：$ O(m \cdot P \log P) $（TIES）或 $ O(m \cdot P) $（linear/DARE），纯内存带宽受限；7B 模型 CPU 上约几分钟级
  • 空间复杂度：需同时驻留基座 + $ m $ 个模型（或惰性分块加载），$ O((m+1) \cdot P) $；用 --low-cpu-memory 逐层分块后可压到 $ O(2P) $
  • 与训练对比：一次 LoRA 微调至少数 GPU·小时；一次合并在单机 CPU 数分钟——四到五个数量级的成本差，这是该技术火爆的根本原因

应用场景

  • 多能力整合：把代码、数学、对话等多个 LoRA/全参微调模型合并为一个「全能」模型（社区 MergeKit 玩法的主体）
  • 低成本新模型发布：Open LLM Leaderboard 时代大量 SOTA 模型（如早期 blend 类开源模型）由合并产生
  • 知识/能力裁剪：Task Arithmetic 的减法方向 $ \theta_{\text{pre}} - \lambda \tau $ 可用于「遗忘」某能力（模型去后门、去毒性实验）
  • 模型量化/压缩前的能力保全：先用合并补齐能力短板，再做量化推理部署
  • 企业私有化整合：内部多个业务各自微调的模型（客服、工单、网络运维知识），合并为单一部署模型节省算力

交叉熵损失

类别：损失函数 | 难度：入门

算法简介

交叉熵损失（Cross-Entropy Loss）是分类任务（从手写数字识别到大语言模型的下一个 token 预测）中最常用、最核心的损失函数。它衡量的是模型预测的概率分布与真实标签分布之间的差异：预测概率越集中于正确类别，损失越小；越分散（尤其在错误类别上概率高），损失越大。其形式为负对数似然的期望——$ \hat{y} = -\log p_{\text{正确类别}} $，配合 softmax 把模型原始输出（logits，任意实数）变换为合法概率分布（非负、和为 1）。

在 PyTorch 中，nn.CrossEntropyLoss 并不是一个「单一运算」，而是 log_softmax + NLLLoss 的数值稳定封装：先对 logits 计算 LogSoftmax（内部用 log-sum-exp 技巧减去最大值防止指数溢出，且从不显式计算 softmax 再取对数，因为那样会在概率接近 0 时产生数值灾难），再取目标类别对应的负对数概率。它有三个高频工程特性：weight 支持类别不平衡加权，ignore_index 让 padding 位置不参与损失（NLP 序列任务的必需品），label_smoothing 通过给非目标类别留一点概率质量来抑制过度自信、提升泛化。与 nn.NLLLoss 的关系经常被误解——NLLLoss 的输入是已经过 log_softmax 的对数概率，而 CrossEntropyLoss 的输入是原始 logits，后者等价于前两者串联。理解交叉熵与 softmax 的梯度联动（$ \frac{\partial L}{\partial z_i} = p_i - y_i $，预测即误差）是理解整个分类训练动力学的基础。

数学公式

公式 1：Softmax（logits → 概率分布）

$$ p_i = \frac{\exp(z_i)}{\sum_{j=1}^{C} \exp(z_j)}, \quad i = 1, \dots, C $$

  • $ z_i $：模型第 $ i $ 个类别的原始输出（logit），任意实数
  • $ C $：类别总数（词表大小、分类类别数）
  • $ p_i $：第 $ i $ 类的预测概率，$ p_i \in (0,1) $ 且 $ \sum_i p_i = 1 $
  • 分母 $ \sum_j \exp(z_j) $：归一化因子（配分函数），保证输出是合法分布

公式 2：交叉熵损失（多分类一般形式）

$$ L_{\text{CE}} = -\frac{1}{N}\sum_{n=1}^{N}\sum_{i=1}^{C} y_{n,i}\,\log p_{n,i} $$

  • $ N $：批量内样本数
  • $ y_{n,i} \in \{0,1\} $：第 $ n $ 个样本真实标签的 one-hot 编码（真实类别处为 1，其余为 0）
  • $ p_{n,i} $：模型对第 $ n $ 个样本属于第 $ i $ 类的预测概率
  • 内层求和：真实分布与预测分布的交叉熵 $ H(y, p) = -\sum_i y_i \log p_i $（仅真实类别项非零）

公式 3：one-hot 情形的简化（实际计算形式）

$$ L_{\text{CE}} = -\frac{1}{N}\sum_{n=1}^{N} \log p_{n,\,y_n} $$

  • $ y_n $：第 $ n $ 个样本的类别索引（0 ~ C−1 的整数，而非 one-hot 向量）
  • 含义：损失只取决于正确类别的预测概率；$ p_{y_n} \to 1 $ 时损失趋于 0，$ p_{y_n} \to 0 $ 时损失趋于 $ +\infty $——「惩罚错误自信」不对称地严格

公式 4：数值稳定的 LogSoftmax（log-sum-exp 技巧）

$$ \text{log\_softmax}(z_i) = z_i - \underbrace{\max_j z_j}_{\text{平移}} - \log\Big(\sum_{j=1}^{C}\exp(z_j - \max_k z_k)\Big) $$

  • $ \max_j z_j $：先减去所有 logits 的最大值，把指数运算的输入压到 $ \leq 0 $，杜绝 $ \exp(1000) $ 溢出
  • 等价变形：$ \log\frac{e^{z_i}}{\sum_j e^{z_j}} = z_i - \log\sum_j e^{z_j} $，平移后分母各项 $ \exp(z_j - \max) \leq 1 $，和至少为 1，同时杜绝 $ \log(0) $
  • PyTorch 实现即按此式计算，这也是「不要先 softmax 再 log」的根本原因

公式 5：带权重的加权平均（weight 参数生效时）

$$ L = -\frac{\sum_{n=1}^{N} w_{y_n}\,\log p_{n,\,y_n}}{\sum_{n=1}^{N} w_{y_n}} $$

  • $ w_{y_n} $：目标类别 $ y_n $ 的权重（weight 张量在该类别的分量）
  • 分母：权重和而非 $ N $——reduction='mean' 时按权重归一化，保证加权后损失量纲与不加权可比；reduction='sum' 时分母为 1，直接累加
  • 效果：小类别用大权重（如 $ w=10 $），等效于在梯度中把该类样本复制 10 份，缓解类别不平衡

公式 6：标签平滑（label_smoothing 参数）

$$ y^{\text{smooth}}_i = (1-\varepsilon)\,y_i + \frac{\varepsilon}{C}, \qquad L = -\sum_{i=1}^{C} y^{\text{smooth}}_i \log p_i $$

  • $ \varepsilon $：平滑系数（label_smoothing 参数），典型 0.1
  • $ y_i $：原 one-hot 标签；平滑后真实类别为 $ 1-\varepsilon+\frac{\varepsilon}{C} $，其余类别各 $ \frac{\varepsilon}{C} $
  • 效果：最优解从「正确类别概率 1」变为「正确类别 $ 1-\varepsilon $」，抑制过度自信，提升校准与 OOD 泛化；过大会欠拟合

公式 7：梯度联动（softmax + CE 的反向传播）

$$ \frac{\partial L}{\partial z_i} = p_i - y_i $$

  • $ \frac{\partial L}{\partial z_i} $：损失对第 $ i $ 个 logit 的梯度
  • 推导要点：softmax 的雅可比 $ \frac{\partial p_j}{\partial z_i} = p_j(\delta_{ij} - p_i) $（$ \delta_{ij} $ 为 Kronecker 符号）与 $ -\frac{y_i}{p_i} $ 相乘后大量项相消，得到极简结果
  • 含义：误差信号 = 预测概率 − 真实标签。正确类别（$ y_i=1 $）梯度为 $ p_i - 1 \leq 0 $ 继续推高该类概率；错误类别（$ y_i=0 $）梯度为 $ p_i \geq 0 $ 压低其概率。这个简洁性是它取代 MSE 做分类的动力学理由（MSE 梯度含 $ p_i(1-p_i) $ 因子，在饱和区梯度消失）

核心要点

  • 输入是 logits 而非概率：nn.CrossEntropyLoss(input, target) 的 input 必须是未经 softmax 的原始输出；先手动 softmax 再传入等于做了两次归一化，训练必然失败
  • shape 规范：分类任务 (input=(N,C), target=(N,))，target 为整数类别索引；图像分割为 (input=(N,C,H,W), target=(N,H,W))；target 值必须在 $ [0, C-1] $ 或等于 ignore_index，否则报错
  • log_softmax 而非 softmax→log：一步到位的 LogSoftmax 数值稳定，是 PyTorch 内部实现方式
  • 与 NLLLoss 的关系：CrossEntropyLoss == LogSoftmax + NLLLoss；若已手动做 log_softmax，应该用 NLLLoss 而不是 CrossEntropyLoss
  • 类别不平衡三件套：weight 加权、Focal Loss（本系列后续讲）、采样均衡——weight 是其中成本最低的一招
  • 混合精度注意：fp16 下 logits 过大易上溢，配合 GradScaler 或保持 logits 计算在 fp32

技术细节与参数详解

PyTorch 完整签名（依据官方文档）：

torch.nn.CrossEntropyLoss(weight=None, size_average=None, ignore_index=-100,
                          reduce=None, reduction='mean', label_smoothing=0.0)

#### 参数 1：weight（类别权重张量）

  • 含义：为每个类别分配一个损失权重，控制该类样本在梯度中的相对重要性
  • 类型：一维张量（Tensor），长度等于类别数 $ C $
  • 默认值：None（所有类别等权）
  • 取值范围：任意正数张量，如 [0.1, 1.0, 10.0]；长度必须等于 C
  • 对结果的影响：某类权重为 10 时，该类样本的损失与梯度等效放大 10 倍，模型在训练早期优先压低该类误差；类别极度不平衡（正负样本 1:99）时是首选手段
  • 推荐设置：用频率倒数加权 $ w_c = \frac{N_{\max}}{N_c} $ 或有效样本数 $ w_c = \frac{1-\beta^{N_c}}{1-\beta} $（$ \beta=0.999 $）；先小权重后逐步调大，观察验证集各类召回率

#### 参数 2：size_average（已弃用）

  • 含义：PyTorch 0.4 之前的旧参数，决定是否对批量损失取平均（True）或求和（False）
  • 类型：布尔（bool）
  • 默认值：None
  • 取值范围：None / True / False（新代码不要设置）
  • 对结果的影响：仅作为向后兼容保留；设置它会与 reduction 冲突，PyTorch 内部按规则映射到 reduction 后忽略
  • 推荐设置：新代码一律用 reduction 替代，此参数保持默认 None 不动

#### 参数 3：ignore_index（忽略标签索引）

  • 含义：指定一个不参与损失计算的目标值，匹配该值的样本损失记 0 且梯度不回传
  • 类型：整数（int）
  • 默认值：-100
  • 取值范围：任意整数，最常用 -100；注意它可以取 C 到 int 范围内的任意值，因此 -100 不与任何合法类别（0~C−1）冲突
  • 对结果的影响：
  • 不设置时，NLP 任务的 padding 位（如填充的 0）会被当成真实类别 0 参与损失，严重污染梯度
  • 设置后 padding/背景类完全不进入损失统计与 reduction 的分母
  • 推荐设置：把数据集 pad 值统一为 -100（与默认对齐）；语义分割中把背景类或边界类标为 ignore_index；若你的 pad 恰好是 0，务必改数据管线而不是将就

#### 参数 4：reduce（已弃用）

  • 含义：同为 0.4 时代旧参数，旧式「是否聚合损失」开关
  • 类型：布尔（bool）
  • 默认值：None
  • 取值范围：None / True / False（新代码不要设置）
  • 对结果的影响：与 size_average 同理，会被映射并忽略
  • 推荐设置：保持默认 None，用 reduction 表达意图

#### 参数 5：reduction（聚合方式）

  • 含义：决定对批量内逐样本损失如何聚合为最终输出
  • 类型：字符串枚举（str）
  • 默认值：'mean'
  • 取值范围：'none' / 'mean' / 'sum'
  • 对结果的影响：
  • 'none'：返回形状 (N,) 的逐样本损失向量——用于自定义聚合、focal 加权、逐样本分析
  • 'mean'：批量均值，梯度尺度稳定，与学习率默认搭配最常见
  • 'sum'：直接求和，损失随 batch size 线性放大，等效放大学习率，大批量下易震荡
  • 推荐设置：常规训练用默认 'mean'；要按样本加权（如 Focal Loss 手写版）时先 'none' 再手动聚合；'sum' 仅在明确知道梯度尺度后果时使用

#### 参数 6：label_smoothing（标签平滑系数）

  • 含义：把 one-hot 硬标签「软化」为分布（公式 6），给非目标类别分配 $ \varepsilon/C $ 的概率质量
  • 类型：浮点数（float）
  • 默认值：0.0（不平滑）
  • 取值范围：0.0 ~ 1.0；典型 0.05 ~ 0.2
  • 对结果的影响：
  • 抑制 logits 无界增长导致的过度自信，改善 ECE 校准指标
  • 略微增加训练损失下限（最优解不再是 0），但往往提升验证集准确率与鲁棒性
  • 设 1.0 时标签完全均匀，等价于模型学「全随机」，无意义
  • 推荐设置：分类任务 0.1 起步；小数据集/易过拟合场景 0.1~0.2；竞赛级调参时对比 0 / 0.05 / 0.1 / 0.2 的验证曲线

def manual_cross_entropy(logits_in, target_in, reduction='mean'):
    """按公式 4 实现数值稳定的交叉熵（log-sum-exp 技巧）"""
    max_ = logits_in.max(dim=1, keepdim=True).values   # 取每行最大 logit，用于平移防溢出
    shifted = logits_in - max_                          # 平移：使所有指数输入 ≤ 0，杜绝 exp 上溢
    log_sum_exp = torch.log(shifted.exp().sum(dim=1)) + max_.squeeze(1)
    # log(Σexp(z−m)) + m = log(Σexp(z))，恢复真实 log-sum-exp 值且全程数值稳定
    log_p = logits_in - log_sum_exp.unsqueeze(1)        # log_softmax(z)（公式 4：z_i − LSE）
    nll = -log_p.gather(1, target_in.unsqueeze(1)).squeeze(1)  # 取目标类别位置的负对数概率（公式 3）
    if reduction == 'mean':                             # reduction='mean'：对样本维度求均值
        return nll.mean()
    elif reduction == 'sum':                             # reduction='sum'：求和
        return nll.sum()
    return nll                                          # 'none'：原样返回逐样本损失

复杂度分析

设批量样本数 $ N $、类别数 $ C $（大模型场景即词表大小，如 32k~152k）：

  • 前向计算：softmax 归一化需对每样本做一次 $ C $ 元素的求和（$ \sum_j \exp z_j $）与一次 $ C $ 元素的除法，总计 $ O(N \cdot C) $ 浮点操作；对 7B 级 LLM 的 128k 词表，单个 token 的损失计算即 $ 1.28\times10^5 $ 次超越函数运算，这也是训练中 loss 头为何显著占显存与算力的原因之一
  • 反向计算：梯度公式 $ \frac{\partial L}{\partial z_i} = p_i - y_i $ 只需逐元素相减，$ O(N \cdot C) $；求和结构带来的雅可比稠密矩阵乘法被 softmax 的特殊结构消掉了（否则是 $ O(N \cdot C^2) $）——这是 softmax+CE 组合被称为「天作之合」的复杂度依据
  • 空间复杂度：仅需缓存 logits（或 log_softmax 输出）与 target，$ O(N \cdot C) $；相比保存完整 softmax 雅可比矩阵 $ O(N \cdot C^2) $ 的朴素做法节省 $ C $ 倍
  • 大词表工程优化：HuggingFace/Flash 实现的 chunked cross-entropy 把 logits 分块计算损失，避免一次性物化 (N×T, C) 巨型矩阵——这正是 KV Cache 推理加速之外的另一个显存瓶颈点

应用场景

  • 图像分类：CNN/ViT 最后一层全连接输出接 CE（ImageNet 1000 类，ignore_index 处理难例挖掘的丢弃样本）
  • 大语言模型预训练：下一个 token 预测本质是词表大小的分类任务；GPT/BERT/Llama 的损失全部是 CE，ignore_index=-100 掩掉 padding
  • 语义分割：每个像素一个分类问题（U-Net 逐像素 CE + Dice 组合），(N,C,H,W) 五维输入形态
  • 多标签软标签训练：知识蒸馏中教师概率分布作为软标签直接传入（target 为 FloatTensor 的概率分布）
  • 类别不平衡场景：垃圾检测、罕见病筛查、故障告警分类中，weight + label_smoothing 组合常比纯 CE 提升小类别召回
  • 强化学习偏好对齐：DPO/RLHF 的隐式奖励由 policy 与 ref 的对数概率差构造，其底层仍是 CE 的对数概率运算（本系列 RLHF/DPO 篇详述）
