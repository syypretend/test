滑动窗口（Sliding Window）

类别：技巧 | 难度：入门

算法简介

滑动窗口是一种用于处理「连续子数组 / 子串」类问题的经典算法技巧。它把待研究的区间看成一个窗口，窗口始终是原始数组（或字符串）上的一个连续片段 [left, right]。算法维护两个指针：右指针 right 不断向右扩展窗口（把新元素纳入窗口），当窗口内的状态不满足题目要求时，左指针 left 向右收缩窗口（把最左边的元素移出窗口）。这样窗口就像一扇在数组上「滑行」的窗户，只遍历一遍数组就能求出答案，把暴力枚举所有子区间时的 $ O(n^2) $ 时间复杂度降为 $ O(n) $。

滑动窗口的思想与 TCP 协议的滑动窗口机制同源——本质都是「维护一个可伸缩的区间，通过两端指针的移动持续评估区间内状态」。它通常配合哈希表 / 计数数组（统计窗口内元素出现次数）或单调双端队列（快速求窗口内极值）使用，能解决：最长/最短满足条件的子数组、最小覆盖子串、固定大小窗口内最大值、字符串异位词匹配等高频面试题。

原理示意图

数学公式

窗口长度（闭区间）：窗口为闭区间，长度为

$$ \text{window\_size} = right - left + 1 $$

  • $ right $：窗口右端点下标（当前遍历位置）
  • $ left $：窗口左端点下标（可能被向右收缩）
  • $ +1 $：闭区间两侧端点都计入长度

总访问次数推导：滑动窗口保证两个指针都只向右移动，且每个指针最多把每个元素处理一次：

$$ T(n) = \underbrace{\sum_{i=1}^{n}(\text{right 处理 }a_i)}_{=n} + \underbrace{\sum_{i=1}^{n}(\text{left 处理 }a_i)}_{\le n} = O(n) $$

  • $ T(n) $：总操作次数
  • 第一个求和：右指针扩展窗口，每个元素恰好入窗一次，共 $ n $ 次
  • 第二个求和：左指针收缩窗口，每个元素最多出窗一次，最多 $ n $ 次

哈希计数器的状态判定（以覆盖子串类问题为例）：

$$ \text{valid} = \sum_{c \in T} \mathbb{1}[\text{cnt}_{window}(c) \ge \text{cnt}_{T}(c)] = |T| $$

  • $ c $：目标集合 $ T $ 中的某个字符
  • $ \text{cnt}_{window}(c) $：当前窗口内字符 $ c $ 的出现次数
  • $ \text{cnt}_T(c) $：目标串中字符 $ c $ 需要的次数
  • $ \mathbb{1}[\cdot] $：指示函数，条件成立取 1，否则取 0
  • 当满足条件的字符种类数等于 $ |T| $（目标去重字符数）时，窗口即「覆盖」了目标

核心要点

  • 滑动窗口只适用于连续区间问题；若子序列可以不连续，则应改用 DP 等其他方法
  • 窗口的「收缩条件」是算法正确性的关键，必须能准确判定窗口状态是否满足题目要求
  • 用计数表（哈希表/数组）+「未满足的种类数 missing」可把「判断覆盖」从 $ O(k) $ 降到 $ O(1) $
  • 固定窗口求极值：单调双端队列队首即窗口极值，每个元素入队出队各一次
  • 窗口移动时只需增量更新统计：右端 +1、左端 -1，不要重新统计整个窗口

技术细节与参数详解

滑动窗口没有标准库「函数参数」，它的「参数」就是实现中的控制要素，下面逐个讲解。

#### 1. 窗口类型：固定窗口 / 可变窗口

  • 含义：窗口长度固定不变（如「大小为 k 的滑动窗口最大值」）还是随条件动态伸缩（如「最短覆盖子串」）
  • 类型：算法设计决策
  • 默认值：视题目而定
  • 对结果的影响：固定窗口用「长度计数 + 单调队列」；可变窗口用「双指针 + 条件判定」，选错模板会写出错误代码
  • 推荐设置：看到「连续 + 固定长度」优先固定窗口；看到「最长/最短/满足某条件」优先可变窗口

#### 2. left：窗口左边界指针

  • 含义：窗口最左侧元素的下标，闭区间左端点
  • 类型：int
  • 默认值：0
  • 取值范围：$ 0 \le left \le right \le n-1 $，且只增不减
  • 对结果的影响：left 收缩的时机（while 条件）决定窗口是否会「错过更优解」；收缩过慢窗口可能不满足条件，收缩过快会漏解
  • 推荐设置：用 while 循环收缩到「恰好满足条件」为止，保证不漏解

#### 3. right：窗口右边界指针

  • 含义：窗口右边界下标，由外层 for 循环驱动，每轮把新元素纳入窗口
  • 类型：int
  • 默认值：0 起遍历
  • 取值范围：0 到 n-1
  • 对结果的影响：决定扩展速度与窗口覆盖范围；right 的遍历顺序不可跳跃，否则窗口不连续
  • 推荐设置：一律「只向右扩展」，不回溯，保证 $ O(n) $

#### 4. 计数表 need / have（哈希表或数组）

  • 含义：need 记录目标要求，have 记录窗口内现状
  • 类型：dict / list（字符有限时用定长数组更快）
  • 默认值：空容器
  • 取值范围：键为元素，值为非负整数
  • 对结果的影响：数组版（ord(ch) 索引）常数更小；哈希版可处理任意可哈希元素；错用「每次重新统计整个窗口」会使复杂度退化到 $ O(n·k) $
  • 推荐设置：字符类问题用定长数组（如 [0]*128），一般问题用 defaultdict(int)

#### 5. missing：未满足需求的种类数

  • 含义：还有多少种元素尚未达标，missing == 0 表示窗口满足条件
  • 类型：int
  • 默认值：len(need)（一开始全部未满足）
  • 取值范围：0 到 len(need)
  • 对结果的影响：用「种类数」而非「总个数」做判据，可避免窗口内某个元素大量冗余导致的误判；维护错误会漏解或死循环
  • 推荐设置：只有当某元素的计数恰好从不足变为达标（或反向）时才更新 missing

#### 6. 收缩条件：while 循环判定

  • 含义：当窗口满足题意时不断右移 left，寻找更优（更短/更多）解
  • 类型：布尔表达式
  • 对结果的影响：收缩停止的位置即当前 right 下的最优窗口；不收缩或收缩过度都得不到正确答案
  • 推荐设置：条件写成「窗口合法」就收缩；在收缩过程中同步更新统计与答案

#### 7. 双端队列 deque（固定窗口极值场景）

  • 含义：存储窗口内元素下标，队列中对应元素值单调递减（求最大值时）
  • 类型：collections.deque
  • 默认值：空
  • 取值范围：下标范围 [i-k+1, i]
  • 对结果的影响：队首始终是窗口内最大/最小值，取极值为 $ O(1) $；若用暴力重扫则整体变 $ O(nk) $
  • 推荐设置：入队前弹出所有「更小且更旧」的队尾，再检查队首是否过期

代码示例

# 示例 1：LeetCode 76 最小覆盖子串（可变窗口 + 计数表）
def min_window(s: str, t: str) -> str:
    # need 记录目标串 t 中每个字符所需的次数
    need = {}
    for ch in t:
        need[ch] = need.get(ch, 0) + 1
    # have 记录当前窗口内每个字符已有的次数
    have = {}
    # missing 表示还有几种字符尚未满足；初始为 t 的去重种类数
    missing = len(need)
    # left 为窗口左边界，best_start / best_len 记录当前最优窗口
    left = 0
    best_start, best_len = 0, float('inf')
    # right 从 0 开始逐位扩展窗口
    for right in range(len(s)):
        ch = s[right]                      # 取出当前右端字符
        have[ch] = have.get(ch, 0) + 1     # 窗口内该字符计数 +1
        # 若该字符是目标字符且恰好达标，则未满足种类数 -1
        if ch in need and have[ch] == need[ch]:
            missing -= 1
        # 窗口已覆盖 t 的全部字符，尝试收缩左边界以寻找更短解
        while missing == 0:
            cur_len = right - left + 1     # 当前窗口长度
            if cur_len < best_len:         # 比已有最优更短则更新
                best_len = cur_len
                best_start = left
            lch = s[left]                  # 待移出窗口的左边字符
            have[lch] -= 1                 # 窗口内计数 -1
            # 若移出后该字符不再满足需求，未满足种类数 +1
            if lch in need and have[lch] < need[lch]:
                missing += 1
            left += 1                      # 左边界右移，窗口收缩
    # 从未找到解则返回空串，否则截取最优窗口
    return '' if best_len == float('inf') else s[best_start:best_start + best_len]

# 示例 2：LeetCode 239 滑动窗口最大值（固定窗口 + 单调双端队列）
from collections import deque

def max_sliding_window(nums: list, k: int) -> list:
    dq = deque()          # dq 存下标，对应元素从队头到队尾单调递减
    res = []              # 结果列表，每项是当前窗口的最大值
    for i, v in enumerate(nums):   # 逐元素处理
        if dq and dq[0] <= i - k:  # 队首下标已滑出窗口范围，出队
            dq.popleft()
        while dq and nums[dq[-1]] <= v:  # 弹出队尾所有比 v 小的元素
            dq.pop()               # 它们永远不可能成为最大值了
        dq.append(i)               # 当前元素下标入队
        if i >= k - 1:             # 窗口攒满 k 个元素后开始输出
            res.append(nums[dq[0]])  # 队首即当前窗口最大值
    return res

复杂度分析

时间复杂度的推导：

  • 外层 for：right 从 0 走到 n-1，共 n 次迭代；
  • 内层 while：left 只增不减，总移动次数 ≤ n；
  • 计数表的增删均为 O(1)，因此：

$$ T(n) = \underbrace{n}_{\text{right 扩展}} + \underbrace{n}_{\text{left 收缩}} = O(n) $$

若使用单调队列求极值：每个元素入队一次、出队一次，摊还到每个元素仍为 O(1)，总时间同样为 O(n)。

空间复杂度的推导：

  • 计数表最多存 |T| 或窗口内不同元素种数：O(min(n, |Σ|))，字符场景可视为 O(1)；
  • 单调队列最多存 k 个下标：O(k)；
  • 除输入与输出外无额外大数组，总体空间为 O(1) ~ O(k)。

应用场景

  • 计算「过去 1 分钟内呼叫量 / 请求量」等滑动时间窗统计
  • 网络流量监控：连续时间窗内的最大/平均流量
  • 最小覆盖子串、最长无重复字符子串等字符串处理高频面试题
  • 数组中「长度不小于 k 的子数组」的最大平均值、最接近目标和连续子段

多查询注意力（Multi-Query Attention, MQA）

类别：大模型架构 | 难度：困难

算法简介

多查询注意力（MQA）由 Shazeer 于 2019 年在论文《Fast Transformer Decoding: One Write-Head is All You Need》（arXiv:1911.02150）中提出，是多头注意力（MHA）的一种内存优化变体。在标准 MHA 中，每个注意力头都有自己独立的 Key 和 Value 投影矩阵，因此推理时每个头都要缓存一份键值对（KV Cache），内存开销随头数线性增长。MQA 的核心思想是：Query 保持多头，但 Key 和 Value 只保留一个共享头——所有头的注意力计算共用同一份 K 和 V 向量。这样 KV Cache 的体量直接从「头数份」降为「1 份」，解码（生成）阶段的内存占用与内存带宽需求大幅下降，从而显著加速自回归推理。MQA 带来的参数量削减与速度提升几乎不影响模型质量（论文实验显示质量仅略有下降），因此在 Falcon、PaLM、StarCoder 等大模型中广泛采用；后续的 GQA（分组查询注意力）是它在质量与速度之间的折中演进，MLA（多头潜在注意力）则进一步把 KV 压缩进低维潜在向量。

原理示意图

数学公式

标准多头注意力（MHA）：第 $ i $ 个头的输出为

$$ \text{head}_i = \text{softmax}\left( \frac{Q_i K_i^{\top}}{\sqrt{d_k}} \right) V_i, \quad Q_i = XW_i^{Q},\ K_i = XW_i^{K},\ V_i = XW_i^{V} $$

  • $ X \in \mathbb{R}^{L \times d} $：输入序列（长度 $ L $，维度 $ d $，即 d_model）
  • $ W_i^{Q}, W_i^{K}, W_i^{V} \in \mathbb{R}^{d \times d_k} $：第 $ i $ 个头独立的 Q/K/V 投影矩阵
  • $ d_k = d / h $：每个头的维度（head_dim）
  • $ h $：注意力头数（num_heads）
  • $ \sqrt{d_k} $：缩放因子，防止内积过大导致 softmax 梯度消失

多查询注意力（MQA）：只有 Q 保留逐头投影，K/V 共享一份投影：

$$ \text{head}_i = \text{softmax}\left( \frac{Q_i K^{\top}}{\sqrt{d_k}} \right) V, \quad Q_i = XW_i^{Q},\ K = XW^{K},\ V = XW^{V} $$

  • $ W^{K}, W^{V} \in \mathbb{R}^{d \times d_k} $：全局共享的 Key/Value 投影，所有头公用
  • 最终输出：$ \text{Output} = \text{Concat}(\text{head}_1, \dots, \text{head}_h) W^{O} $

KV 缓存占用对比（自回归解码时每生成一个 token 都要把新 K/V 追加进缓存）：

$$ \text{MHA: } h \times L \times d_k \times 2 \qquad \text{MQA: } L \times d_k \times 2 $$

  • $ L $：已生成的序列长度（缓存长度）
  • 节省比例：$ 1 - \frac{1}{h} $，当 $ h=8 $ 时缓存降低 87.5%

核心要点

  • MQA 的本质是「多 Q、单 K/V」，把 KV 缓存的显存占用与带宽需求降低 $ h $ 倍，换取解码速度大幅提升
  • 训练时 MQA 与 MHA 一样可并行；收益集中在自回归推理阶段的缓存与带宽
  • 共享 K/V 使表达能力略降（各头不能再有独立的键值表征），但实践中质量损失很小
  • MQA 是 MHA → GQA（分组共享）→ MLA（低秩潜在压缩）这条优化链的起点，理解 MQA 是读懂 GQA/MLA 的前提
  • 实现上通过矩阵乘法广播（单份 K/V 与所有头相乘）即可完成共享，无需真正复制

技术细节与参数详解

#### 1. num_heads（头数 $ h $）

  • 含义：Query 拆分的注意力头数量
  • 类型：int
  • 默认值：8（经典配置，如 d_model=512, h=8）
  • 取值范围：一般为 1 ~ d_model 的约数，head_dim 必须整除
  • 对结果的影响：头越多，模型可从不同子空间关注不同模式；MQA 的头数不额外增加缓存，所以可以保留较多头
  • 推荐设置：沿用 MHA 的头数（如 8/16/32），只改 K/V 的共享策略

#### 2. head_dim（$ d_k $，每头维度）

  • 含义：每个注意力头的特征维度，即 K/V 向量的长度
  • 类型：int
  • 默认值：d_model // num_heads
  • 取值范围：必须整除 d_model，常用 64 或 128
  • 对结果的影响：决定注意力的缩放因子 $ \sqrt{d_k} $；d_k 过小表达力不足，过大则 softmax 输入方差增大、梯度不稳
  • 推荐设置：保持 64~128 的常见值

#### 3. kv_heads（K/V 共享头数）

  • 含义：Key 与 Value 实际的头数，MQA 中固定为 1
  • 类型：int
  • 默认值：MQA 固定 1（区别于 GQA 的 2~num_heads 及 MHA 的 num_heads）
  • 取值范围：MQA 场景下只取 1；该字段通常由 multiquery=True 标志触发
  • 对结果的影响：直接决定 KV 缓存大小与参数量；=1 时缓存最少、速度最快，但注意力多样性最低
  • 推荐：追求极速用 1（MQA）；质量与速度平衡用 GQA（如 4~8）

#### 4. d_model（embed_dim，模型维度）

  • 含义：隐藏层向量维度，所有投影的输入输出基准
  • 类型：int
  • 默认值：依模型而定，常见 512 / 768 / 1024
  • 取值范围：任意正整数（通常为 64 的倍数）
  • 对结果的影响：与 num_heads 一起决定 head_dim 与总参数量，也是 KV 缓存每步字节数的基础
  • 推荐设置：与所选模型/框架对齐即可，不是 MQA 独有参数

#### 5. softmax_scale（缩放因子）

  • 含义：attn = Q·K^T * scale，默认 1/√d_k
  • 类型：float
  • 默认值：None（自动取 1/√d_k）
  • 取值范围：任意正数，实践中 0.01 ~ 0.2 附近
  • 对结果的影响：控制注意力分布的「尖锐程度」；过大会接近 one-hot 分布、梯度变差，过小则分布太平、几乎不关注
  • 推荐设置：保留默认 1/√d_k，仅在微调阶段按需修改

#### 6. dropout_p（注意力丢弃率）

  • 含义：对注意力权重矩阵做随机丢弃，防止过拟合
  • 类型：float
  • 默认值：训练 0.1，推理 0.0
  • 取值范围：$ 0 \le p \le 1 $
  • 对结果的影响：训练时防止头之间过分耦合；推理时必须置 0，否则随机丢弃会破坏确定性输出
  • 推荐设置：小模型 0.0~0.1，大模型可 0.1~0.2

#### 7. is_causal（因果掩码）

  • 含义：是否让每个位置只能看到「当前及之前」的 token
  • 类型：bool
  • 默认值：False（编码器场景）；解码器应设 True
  • 对结果的影响：设 True 时用上三角掩码把未来位置置 -inf，防止生成时「偷看未来」；设错会导致训练泄露、推理错乱
  • 推荐设置：自回归 LM 的 decoder 一律 True；encoder 与双向模型设为 False

#### 8. key_padding_mask（填充掩码）

  • 含义：标记批次中 padding 位置，避免对填充 token 分配注意力
  • 类型：BoolTensor，shape [B, L]
  • 默认值：None（无 padding）
  • 取值范围：与序列长度一致，True 表示该位置是 padding
  • 对结果的影响：不设会让模型把注意力浪费在无意义 pad 上，损害批次训练质量
  • 推荐：有变长序列与 batch 训练时必传

#### 9. out_proj（输出投影）

  • 含义：把拼接后的多头输出映射回 d_model 维度的线性层
  • 类型：nn.Linear(d_model, d_model)
  • 默认值：存在（MHA/MQA 标配）
  • 对结果的影响：决定最终输出维度与跨头融合能力；其参数不参与 K/V 共享优化
  • 推荐设置：bias 视实现而定，保持与框架默认一致

#### 10. Wqkv 合并投影的参数量

  • 含义：输入到 Q/K/V 三路投影的合并线性层
  • MHA：d → 3d（Q、K、V 各 d 维）
  • MQA：d → d + 2×head_dim（Q 全维，K/V 各只有单头维度）
  • 对结果的影响：投影参数量下降约 2(h-1)/(3h)；同时 KV 缓存按 h 倍缩减，是加速主因
  • 推荐：用 split([d_model, head_dim, head_dim]) 切分 Q/K/V

代码示例

import torch
import torch.nn as nn
import torch.nn.functional as F

class MultiQueryAttention(nn.Module):
    """MQA：Q 保持多头，K / V 只保留单头共享。"""
    def __init__(self, d_model: int, num_heads: int):
        super().__init__()
        self.d_model = d_model                    # 模型隐藏维度
        self.num_heads = num_heads                # 注意力头数（仅 Q 拆头）
        self.head_dim = d_model // num_heads      # 每头维度 d_k
        # 合并投影：Q 占 d_model，K 和 V 各只占 head_dim（共享单头）
        self.Wqkv = nn.Linear(d_model, d_model + 2 * self.head_dim)
        self.out_proj = nn.Linear(d_model, d_model)  # 输出回 d_model

    def forward(self, x, causal: bool = True):
        B, S, D = x.shape                         # batch / 序列长 / 维度
        qkv = self.Wqkv(x)                        # (B, S, D + 2*d_k)
        # 切分：q 全维，k/v 各 head_dim
        q, k, v = qkv.split([self.d_model, self.head_dim, self.head_dim], dim=-1)
        # 把 q 拆成多头形状 (B, H, S, Dk)
        q = q.view(B, S, self.num_heads, self.head_dim).transpose(1, 2)
        # k/v 维持单头，扩展出头维 (B, 1, S, Dk)
        k = k.unsqueeze(1)
        v = v.unsqueeze(1)
        # 点积注意力：scores 形状 (B, H, S, S)
        scores = (q @ k.transpose(-1, -2)) / (self.head_dim ** 0.5)
        if causal:                                # 因果掩码：上三角置 -inf
            mask = torch.triu(torch.ones(S, S, device=x.device), diagonal=1).bool()
            scores = scores.masked_fill(mask, float('-inf'))
        attn = F.softmax(scores, dim=-1)          # 归一化得到注意力权重
        out = attn @ v                            # (B, H, S, Dk)
        out = out.transpose(1, 2).contiguous().view(B, S, -1)  # 拼接多头
        return self.out_proj(out)                 # 输出投影后返回

# 参数对比：d_model=512, h=8 时
# MHA 的 Wqkv 权重形状：(512, 1536)
# MQA 的 Wqkv 权重形状：(512, 512 + 2*64) = (512, 640)
# KV 缓存每 token：MHA = 8×64×2 = 1024 个浮点；MQA = 64×2 = 128 个浮点

复杂度分析

参数量：设输入维度 $ d $、头数 $ h $、每头维度 $ d_k = d/h $：

  • MHA 的 QKV 投影：$ d \times 3d = 3d^2 $
  • MQA 的 QKV 投影：$ d \times (d + 2d_k) = d^2 + 2d d_k = d^2(1 + 2/h) $

参数减少比例：$ 1 - \frac{1 + 2/h}{3} = \frac{2(h-1)}{3h} $（h=8 时约省 58%）。

KV 缓存空间：自回归生成 L 个 token：

$$ \text{MHA: } O(h \cdot L \cdot d_k \times 2) \qquad \text{MQA: } O(L \cdot d_k \times 2) $$

降低 $ h $ 倍 → 显存压力下降 → 可增大 batch，提升吞吐率。

解码带宽：每次生成都要读取全部 KV 缓存参与注意力计算；缓存变小意味着从 DRAM 读取的字节数少，计算单元等待减少，解码速度显著提升（论文与 Falcon 等模型实测）。

应用场景

  • 大模型自回归解码加速（Falcon、PaLM、StarCoder 等采用 MQA 的代表模型）
  • 长上下文生成：KV 缓存体量随 L 线性增长，MQA 直接降低显存压力、支持更长序列
  • 高吞吐在线推理服务（客服机器人、代码补全、文本生成 API）
  • 作为理解 GQA / MLA 的教学基石，掌握「共享 K/V → 分组共享 → 低秩压缩」的演进

LSTM 长短期记忆（Long Short-Term Memory）

类别：深度学习 | 难度：中等

算法简介

LSTM（Long Short-Term Memory）由 Hochreiter 与 Schmidhuber 于 1997 年提出，是一种专门解决长期依赖问题的循环神经网络（RNN）变体。传统 RNN 在每个时间步仅靠一个隐藏状态 $ h_t $ 传递信息，反向传播时梯度沿时间展开连乘，序列一长就会指数级消失或爆炸，导致模型「记不住远距离信息」。LSTM 的改进是引入一条贯穿整个序列的细胞状态（Cell State）$ C_t $——相当于一条「记忆传送带」，配合遗忘门、输入门、输出门三个门控（每个门输出 [0,1] 之间的比例），用逐元素乘法控制：忘掉什么旧记忆、写入什么新记忆、输出多少给上层。因为细胞状态的更新是「旧状态乘以门值再加新信息」的线性累加，梯度沿这条通路可以近似恒等地反向传播，从而大幅缓解梯度消失。LSTM 在语音识别、机器翻译、时序预测、异常检测等领域长期占据主流地位，直到 Transformer 兴起才逐渐让位，但其门控思想至今仍是序列建模的必修基础。

原理示意图

数学公式

设输入 $ x_t $、上一时刻隐藏状态 $ h_{t-1} $、上一时刻细胞状态 $ c_{t-1} $，$ W $ 为输入权重，$ U $ 为循环权重，$ b $ 为偏置。

遗忘门（决定保留多少旧记忆）：

$$ f_t = \sigma(W_f x_t + U_f h_{t-1} + b_f) $$

  • $ f_t $：遗忘门输出（0~1，1 表示完全保留）
  • $ \sigma $：sigmoid 激活函数，$ \sigma(z) = \dfrac{1}{1+e^{-z}} $
  • $ W_f \in \mathbb{R}^{H \times X} $：遗忘门对输入 $ x_t $ 的权重
  • $ U_f \in \mathbb{R}^{H \times H} $：遗忘门对上一隐藏状态的循环权重
  • $ b_f \in \mathbb{R}^{H} $：遗忘门偏置
  • $ H $：隐藏单元数（hidden_size），$ X $：输入特征数（input_size）

输入门 + 候选记忆（决定写入多少新信息）：

$$ i_t = \sigma(W_i x_t + U_i h_{t-1} + b_i), \qquad \tilde{c}_t = \tanh(W_c x_t + U_c h_{t-1} + b_c) $$

  • $ i_t $：输入门输出（0~1），控制「候选记忆写入的强度」
  • $ \tilde{c}_t $：候选记忆（-1~1），由 tanh 产生的新信息
  • $ W_i, U_i, b_i $：输入门的输入/循环权重与偏置
  • $ W_c, U_c, b_c $：候选记忆的输入/循环权重与偏置

细胞状态更新（旧记忆衰减 + 新记忆叠加，关键的「加法」通路）：

$$ c_t = f_t \odot c_{t-1} + i_t \odot \tilde{c}_t $$

  • $ c_t $：当前时刻细胞状态（长期记忆）
  • $ \odot $：逐元素相乘（Hadamard 积）
  • 第一项 $ f_t \odot c_{t-1} $：选择性遗忘旧记忆
  • 第二项 $ i_t \odot \tilde{c}_t $：选择性写入新记忆

输出门 + 隐藏状态：

$$ o_t = \sigma(W_o x_t + U_o h_{t-1} + b_o), \qquad h_t = o_t \odot \tanh(c_t) $$

  • $ o_t $：输出门（0~1），决定从细胞状态中放行多少信息
  • $ h_t $：当前时刻隐藏状态（输出），也是下一时间步的输入之一
  • $ \tanh(c_t) $：把细胞状态压缩到 -1~1 再按比例输出

梯度路径：从时刻 T 反传到 t，细胞状态链上的偏导数为连乘形式：

$$ \frac{\partial c_T}{\partial c_t} = \prod_{k=t+1}^{T} f_k $$

  • 当 $ f_k \approx 1 $ 时连乘接近 1，梯度可以「穿透」长序列；
  • $ f_k < 1 $ 时梯度才衰减——而门是可学习的，网络会学会长期保持 $ f_k \approx 1 $，这正是 LSTM 能记忆长期依赖的根本原因。

核心要点

  • LSTM 的核心是细胞状态 $ c_t $ + 三个门，门输出都是 [0,1] 的「比例」，靠逐元素相乘控制信息流量
  • 「加法」式更新让梯度沿细胞状态链近似恒等传播，缓解传统 RNN 的梯度消失
  • 标准 LSTM 每步有 4 组权重（遗忘/输入/候选/输出），PyTorch 把它们合并为一个 [4H, X+H] 矩阵一次算出再切分
  • 双向 LSTM 拼接正反两个方向的隐藏状态；多层 LSTM 把前一层输出作为下一层输入
  • 门必须用 sigmoid（0~1 的比例），候选与输出用 tanh（-1~1 的表示）

技术细节与参数详解

以下以 PyTorch nn.LSTM 为准，逐个讲解关键参数。

#### 1. input_size

  • 含义：输入序列 $ x_t $ 每个时间步的特征维数
  • 类型：int
  • 默认值：无，必填
  • 取值范围：正整数
  • 对结果的影响：决定输入权重尺寸；太小特征表达不足，太大会显著增加参数
  • 推荐设置：等于你的特征维度/词嵌入维度

#### 2. hidden_size

  • 含义：隐藏单元数量 $ H $，即 $ h_t $ 与 $ c_t $ 的向量长度
  • 类型：int
  • 默认值：无，必填
  • 取值范围：正整数
  • 对结果的影响：LSTM 的表达能力与参数量正比于 $ H^2 $（U 矩阵是 H×H）；H 翻倍参数量约翻 4 倍
  • 推荐设置：小任务 32~128，中大型任务 256~1024，配合验证集调节

#### 3. num_layers

  • 含义：堆叠的 LSTM 层数
  • 类型：int
  • 默认值：1
  • 取值范围：≥1 的整数
  • 对结果的影响：加深提升抽象层次与容量，但参数量线性增加、训练更难；层间可用 dropout 缓解
  • 推荐设置：初学 1~2 层，生产环境 2~4 层

#### 4. bias

  • 含义：是否使用偏置项
  • 类型：bool
  • 默认值：True
  • 取值范围：True / False
  • 对结果的影响：False 时门控计算不含偏置，参数略减但拟合灵活性下降
  • 推荐设置：保持 True

#### 5. batch_first

  • 含义：输入张量第一维是否为 batch
  • 类型：bool
  • 默认值：False（默认形状 [seq, batch, feature]）
  • 取值范围：True / False
  • 对结果的影响：False 时输入为 (seq, batch, feature)；True 后为 (batch, seq, feature)，减少转置错误
  • 推荐设置：配合 DataLoader 习惯设 True

#### 6. dropout

  • 含义：层与层之间的 dropout 丢弃率（注意：不作用于时间步内部）
  • 类型：float
  • 默认值：0.0
  • 取值范围：0 ≤ dropout ≤ 1，且 num_layers > 1 时才有实际效果
  • 对结果的影响：降低层间耦合、缓解过拟合；设 1 会完全置零，训练失效
  • 推荐设置：0.1~0.5，随数据量增大而减小

#### 7. bidirectional

  • 含义：是否为双向 LSTM
  • 类型：bool
  • 默认值：False
  • 取值范围：True / False
  • 对结果的影响：True 时正反向各有一个 LSTM，输出维度变成 2×hidden_size；能同时利用前后文，适合 NER 等标注任务
  • 推荐设置：任务需要「未来信息」时启用，否则保持 False

#### 8. proj_size

  • 含义：对隐藏状态 $ h_t $ 做线性投影后的维度（部分框架支持）
  • 类型：int 或 None
  • 默认值：None（不投影）
  • 取值范围：正整数且 ≤ hidden_size；会额外引入投影矩阵参数
  • 对结果的影响：把 h 维度压缩到 proj_size，降低输出层参数量与显存；c_t 保持 hidden_size
  • 推荐设置：显存紧张或输出维度需求小时使用

#### 9. 输入状态：h_0 / c_0

  • 含义：初始隐藏状态与初始细胞状态；None 时全零
  • 类型：Tensor，形状 [num_layers × directions, batch, hidden_size]
  • 默认值：None
  • 对结果的影响：起始状态影响开头的「记忆起点」；全零是默认，条件生成可注入有意义的初始状态
  • 推荐设置：无特殊需求用全零

#### 10. 序列打包：pack_padded_sequence

  • 含义：对变长序列做 padding 后，用真实长度告诉 LSTM 哪些位置是填充
  • 类型：PackedSequence
  • 对结果的影响：不处理则 LSTM 会「吃掉」padding、污染输出；处理后计算更高效且正确
  • 推荐：批量变长数据必用，返回时用 pad_packed_sequence 还原

#### 11. 权重初始化与学习率

  • 含义：LSTM 门权重初始化方式与学习率
  • 对结果的影响：sigmoid 门初始偏置设为正数（如遗忘门偏置 1~5）可让初始「记得更多」，利于长序列
  • 推荐：循环权重用 orthogonal 初始化，遗忘门偏置初始化为正值

代码示例

import torch
import torch.nn as nn

# ---------- 示例 1：直接用 nn.LSTM ----------
batch = 2
seq_len = 5          # 序列长度（时间步数）
input_size = 3       # 每步特征维
hidden_size = 8      # 隐藏单元数
num_layers = 2       # 两层堆叠

lstm = nn.LSTM(input_size=input_size, hidden_size=hidden_size,
               num_layers=num_layers, batch_first=True, dropout=0.1)
x = torch.randn(batch, seq_len, input_size)     # (2, 5, 3) 批次优先
out, (h_n, c_n) = lstm(x)                        # 前向传播
# out 形状: (batch, seq_len, hidden_size) 每步输出
# h_n 形状: (num_layers, batch, hidden_size) 各层最终隐藏状态
# c_n 形状: (num_layers, batch, hidden_size) 各层最终细胞状态
print(out.shape)      # torch.Size([2, 5, 16])
print(h_n.shape)      # torch.Size([2, 2, 16])

# ---------- 示例 2：手写一个 LSTM 单元（便于理解门控） ----------
class MyLSTMCell(nn.Module):
    """单个时间步的 LSTM 细胞。"""
    def __init__(self, input_size, hidden_size):
        super().__init__()
        self.hidden_size = hidden_size
        # 合并 4 组门的输入变换，输出 4H 维
        self.w_ih = nn.Linear(input_size, 4 * hidden_size)
        # 上一时刻隐藏状态到 4 组门的变换
        self.w_hh = nn.Linear(hidden_size, 4 * hidden_size)

    def forward(self, x, state):
        """x: (batch, input_size)；state: (h_prev, c_prev)"""
        h_prev, c_prev = state
        gates = self.w_ih(x) + self.w_hh(h_prev)   # 一次算完 4 组门线性值
        f, i, g, o = gates.chunk(4, dim=-1)        # 切为 4 段
        f = torch.sigmoid(f)      # 遗忘门 σ → 0~1
        i = torch.sigmoid(i)      # 输入门 σ → 0~1
        g = torch.tanh(g)         # 候选记忆 tanh → -1~1
        o = torch.sigmoid(o)      # 输出门 σ → 0~1
        c = f * c_prev + i * g    # 细胞状态：旧记忆衰减 + 新记忆写入
        h = o * torch.tanh(c)     # 隐藏状态：门控放出细胞信息
        return h, (h, c)          # 返回隐藏状态与新状态对

cell = MyLSTMCell(3, 16)                        # 3 特征 → 16 隐藏
h, c = torch.zeros(2, 16), torch.zeros(2, 16)  # 初始状态全零
for t in range(seq_len):                       # 逐时间步推进
    h, (h, c) = cell(x[:, t, :], (h, c))       # 用第 t 步输入更新
print(h.shape)                                # torch.Size([2, 16])

# ---------- 示例 3：小任务训练流程（序列回归） ----------
import torch.optim as optim

model = nn.LSTM(1, 16, num_layers=1, batch_first=True)  # 1 维输入 → 16 隐
head = nn.Linear(16, 1)            # 输出回归到 1 维
opt = optim.Adam(list(model.parameters()) + list(head.parameters()), lr=0.01)
loss_fn = nn.MSELoss()

for epoch in range(100):
    seq = torch.randn(2, 10, 1)             # 随机序列 (batch=2, len=10, 1)
    target = seq[:, -1, :] + 0.5            # 目标：最后一步 + 0.5
    out, _ = model(seq)                     # 前向
    pred = head(out[:, -1, :])              # 取最后一步输出回归
    loss = loss_fn(pred, target)            # MSE 损失
    opt.zero_grad()                         # 清梯度
    loss.backward()                         # 反向传播
    opt.step()                              # 更新参数
    if epoch % 20 == 0:
        print(f"epoch {epoch}, loss={loss.item():.4f}")

复杂度分析

时间复杂度：每个时间步需计算 4 组门，每组包含一次矩阵乘法：

  • 单时间步：$ 4 \times (X \cdot H + H \cdot H) = O(H(X+H)) $
  • T 个时间步总计：$ O(T \cdot H \cdot (X+H)) $，约 4·T·H·(X+H) 次乘加

空间复杂度：

  • 权重参数：$ O(4H(X+H)) $
  • 前向需保存每一步中间激活用于反向：$ O(T \cdot H) $
  • 双向时时间与空间再乘 2；层数 L 使参数与计算再乘 L

应用场景

  • 语音识别 / 语音合成：逐帧序列建模
  • 自然语言处理：文本分类、机器翻译编码、情感分析、NER
  • 时序预测：股票/流量/电力负荷预测、设备异常检测
  • 生物信号：心电分类、基因序列模式识别
  • 作为 Transformer 的对比基线及低成本序列建模方案
