位运算技巧

类别：技巧 | 难度：入门

算法简介

位运算（Bit Manipulation）是直接对整数的二进制位进行操作的一类运算，核心是六个运算符：按位与 &、按位或 |、按位异或 ^、按位取反 ~、左移 <<、右移 >>。在现代 CPU 上，一次位运算通常只需单个时钟周期，比乘除法快数倍甚至数十倍，且一个 32 位整数能当 32 个布尔开关用（位掩码 bitmask），因此在性能敏感场景、算法竞赛和面试中都是必备基本功。位运算技巧的精髓不在"认识六个运算符"，而在于几个经典位模式：n & (n-1) 可以消去 n 的二进制表示中最右侧的 1（Brian Kernighan 算法，可 O(1) 判断 2 的幂、O(k) 统计 1 的个数）；n & (-n) 可以提取最右侧的 1（lowbit 运算，树状数组的基石）；异或满足自反性 a ^ a = 0，是"只出现一次的数字"系列问题的钥匙；1 << k 构造掩码，把 n 个元素集合的 2^n 个子集压缩进一个整数，支撑状态压缩 DP。本文按"运算符语义 → 原理示意 → 数学推导 → 逐参数 API → 代码模板 → 复杂度 → 应用"的完整脉络讲解。

数学公式

公式 1：补码恒等式

$$ -n = \sim n + 1 $$

变量解释：

  • $ n $：任意正整数
  • $ \sim n $：按位取反，Python 中对无限位宽补码取反
  • 由该式可推出 $ \sim n = -n - 1 $

公式 2：lowbit 运算

$$ \mathrm{lowbit}(n) = n \& (-n) = n \& (\sim n + 1) = 2^{k}, \quad k = \mathrm{ctz}(n) $$

变量解释：

  • $ n $：待操作的非负整数
  • $ \& $：按位与
  • $ k = \mathrm{ctz}(n) $：n 的二进制中末尾连续 0 的个数（count trailing zeros）
  • 证明思路：设 $ n = x10^k $（$ x $ 为任意高位串），则 $ n-1 = x01^k \sim $，取 $ \sim n + 1 $ 的效果等效于把 $ x $ 全部翻转、保留第 $ k $ 位的 1、低位全为 0，故按位与后只剩 $ 2^k $

公式 3：消位运算（Brian Kernighan）

$$ n \& (n-1) = x0^k 0, \quad \text{其中 } n = x10^k $$

变量解释：

  • $ x $：第 $ k $ 位以左的任意位串
  • 该运算把 $ n $ 最右侧的 1 置 0，其余位不变；循环执行直到 $ n=0 $，循环次数恰为 1 的个数 $ \mathrm{popcount}(n) $

公式 4：2 的幂判定

$$ n > 0 \;\wedge\; (n \,\&\, (n-1)) = 0 \iff \exists\, k \geq 0,\; n = 2^k $$

变量解释：

  • $ 2^k $ 的二进制形如 $ 100\cdots0 $，仅含一个 1，消掉它即得 0
  • 注意 $ n=0 $ 时 $ 0 \& (-1) = 0 $ 也会通过前半判断，必须加上 $ n > 0 $ 的边界条件

公式 5：异或恒等式组

$$ a \oplus 0 = a, \quad a \oplus a = 0, \quad a \oplus b = b \oplus a, \quad (a \oplus b) \oplus c = a \oplus (b \oplus c) $$

变量解释：

  • $ a, b, c $：任意整数；$ \oplus $ 即 ^
  • 推论：序列中偶数次出现的元素在全体异或中全部抵消，只留下出现奇数次的元素，这是"只出现一次的数字"系列的核心原理

公式 6：无进位加法递推（不用加减号求和）

$$ a + b = (a \oplus b) + \big((a \& b) \ll 1\big) $$

变量解释：

  • $ a \oplus b $：本位"不进位加法"结果（半加器和）
  • $ (a \& b) \ll 1 $：所有需要进位的位置，整体左移一位
  • 迭代入 $ a' = a \oplus b,\; b' = (a \& b) \ll 1 $，直到进位项为 0，结果收敛于真实和（补码体系下对负数同样成立，最多迭代位宽次）

核心要点

  • 六大运算符：& 与、| 或、^ 异或、~ 取反、<< 左移、>> 右移，均为单周期 CPU 指令
  • n & (n-1) 消最右 1 → 判 2 的幂、数 1 个数、判断是否为 0、求最低位以上的剩余值
  • n & (-n) 提最右 1（lowbit）→ 树状数组、状态机定位、坐标离散化
  • 异或三性质（自反、交换、结合）→ 找落单数、找缺失数、交换变量、加密 XOR 一次性密码本
  • 1 << k 构造掩码：测试位 (n >> k) & 1、置位 n | (1 << k)、清位 n & ~(1 << k)、翻位 n ^ (1 << k)
  • 枚举子集：sub = (sub - 1) & s，从 s 的最大子集递减到 0，比逐个判断快
  • Python 整数无限位宽，>> 是算术右移；C/Java 中 >> 算术右移、>>> 逻辑右移（注意负数）
  • popcount 四连：朴素移位 O(w)、Brian Kernighan O(k)、SWAR 位并行 O(1)（固定 5 步）、硬件指令 int.bit_count()

技术细节与参数详解

#### 运算符 1：按位与 &

  • 含义：两个整数逐二进制位比较，都为 1 才得 1
  • 类型：二元运算符，操作数为 int（Python 为任意精度，C/Java 为固定位宽）
  • 默认值：无（必填两个操作数）
  • 取值范围：任意整数；Python 中负数按无限位宽补码参与运算
  • 对结果的影响：是掩码操作的主力——掩码中为 1 的位被"保留"，为 0 的位被"清零"
  • 推荐设置：与 % 2^k 取模等价时用 & (2^k - 1) 更快，如哈希桶定位 h & (n_buckets - 1) 要求桶数为 2 的幂

#### 运算符 2：按位或 |

  • 含义：逐位比较，任一为 1 即得 1
  • 类型：二元运算符
  • 默认值：无
  • 取值范围：任意整数
  • 对结果的影响：用于"置位"——n | (1 << k) 把第 k 位强行置 1，其余位不变
  • 推荐设置：权限组合场景（读=4、写=2、执行=1，chmod 644 本质就是 110/100/100）

#### 运算符 3：按位异或 ^

  • 含义：逐位比较，不同得 1，相同得 0
  • 类型：二元运算符
  • 默认值：无
  • 取值范围：任意整数
  • 对结果的影响：可逆的"翻转"操作；连续异或同一值两次恢复原值（加密校验基础）
  • 推荐设置：找落单元素、变量交换、备份两数（a ^ b 存差异）

#### 运算符 4：按位取反 ~

  • 含义：一元运算符，0 变 1、1 变 0
  • 类型：一元运算符
  • 默认值：无
  • 取值范围：任意整数
  • 对结果的影响：Python 中恒有 ~n == -n-1（无限位宽补码）；固定位宽语言中等于 $ 2^w - 1 - n $
  • 推荐设置：配合与运算做"清位"：n & ~(1 << k) 清第 k 位，注意括号不可省略（优先级 ~ 高于 &）

#### 运算符 5：左移 <<

  • 含义：二进制位整体左移 k 位，低位补 0
  • 类型：二元运算符，右操作数为移位量 k
  • 默认值：无；k 必须为非负整数
  • 取值范围：k 在 0 到位宽内；Python 的 k 可超过 63（大整数自动扩展），C/Java 中移位量超过位宽是未定义行为/按 31/63 取模
  • 对结果的影响：n << k 等价于 $ n \times 2^k $，比乘法快；Python 中不会溢出，C/Java 的 uint32 会高位截断
  • 推荐设置：乘除 2 的幂一律用移位；构造掩码 1 << k 是位掩码 DP 的固定搭配

#### 运算符 6：右移 >>

  • 含义：二进制位整体右移 k 位；对无符号数高位补 0（逻辑右移），对负数高位补 1（算术右移，Python、Java 的 >> 均如此）
  • 类型：二元运算符，右操作数为移位量 k
  • 默认值：无
  • 取值范围：k 为非负整数；Python 中 -8 >> 1 == -4（向下取整除法）
  • 对结果的影响：n >> k 等价于 $ n / 2^k $ 且向下取整（正数即截断），比除法快
  • 推荐设置：取第 k 位的值固定写法 (n >> k) & 1；正数除 2 写 n >> 1，负数优先用 // 明确语义

#### API 参数 1：bin(x) 的 x

  • 含义：把整数转为带 0b 前缀的二进制字符串
  • 类型：int
  • 默认值：必填
  • 取值范围：任意整数（负数返回如 '-0b1010'）
  • 对结果的影响：仅用于展示/调试，性能低于位运算本身
  • 推荐设置：刷题时打印 bin(n)[2:] 快速检查位型；注意 bin(-5) == '-0b101' 而非补码串

#### API 参数 2：int(s, base) 的 base

  • 含义：把字符串 s 按 base 进制解析为整数
  • 类型：str（或 bytes）与 int
  • 默认值：10（十进制）；取值范围 {0, 2, 8, 10, 16}，0 表示按字符串前缀（0b/0o/0x）自动识别
  • 对结果的影响：int('1100', 2) 得 12；int('0b1100', 0) 同样得 12；base 传 2~36 之外的进制字符串解析会抛 ValueError
  • 推荐设置：字符串掩码转整数用 int(s, 2)；位运算结果可视化配合 bin() 使用

#### API 参数 3：int.bit_length()

  • 含义：返回该整数绝对值的有符号二进制表示所需位数（不含符号与前导 0）
  • 类型：无参数方法
  • 默认值：无
  • 取值范围：0.bit_length() == 0；12.bit_length() == 4
  • 对结果的影响：用于估算位宽、确定最高位位置 $ \lfloor \log_2 n \rfloor + 1 $，是二分/倍增的上界推导依据
  • 推荐设置：需要"最高位是第几位"时用它，代替 len(bin(n)) - 2

#### API 参数 4：int.bit_count()（Python 3.10+，对应 C++ 的 __builtin_popcount / Java 的 Integer.bitCount）

  • 含义：返回二进制中 1 的个数（popcount）
  • 类型：无参数方法
  • 默认值：无
  • 取值范围：非负整数返回值
  • 对结果的影响：底层走 CPU 硬件 POPCNT 指令，单周期完成；3.10 之前的版本用 bin(n).count('1')
  • 推荐设置：Python 3.10+ 直接用；旧版本（如 3.7 环境）写 bin(n).count('1')

#### API 参数 5：int.to_bytes(length, byteorder, *, signed=False) 的 length 与 byteorder

  • 含义：把整数序列化为定长字节数组
  • 类型：length 为 int；byteorder 为 str，取值 'big'（大端，网络字节序）或 'little'（小端，x86 内存序）
  • 默认值：length 必填；byteorder 必填；signed 默认 False
  • 取值范围：length 过小且数值放不下时抛 OverflowError
  • 对结果的影响：字节序决定多字节整数在内存/网络中的排列顺序，通信协议双方必须一致，否则数值解释完全颠倒
  • 推荐设置：网络传输统一 'big'（socket 协议惯例）；本地 numpy/struct 互操作时仔细核对 'little'
  • 配对函数 int.from_bytes(bytes, byteorder, *, signed=False) 用于还原

#### 技巧参数 6：lowbit 与消位边界（操作数 n 的取值语义）

  • 含义：n & (n-1) 与 n & (-n) 对 n 边界值的行为差异
  • 类型：int
  • 默认值：无
  • 取值范围：n = 0 时 n & (-n) == 0（无 1 可提取，树状数组循环终止条件）；n 为负数时 lowbit 在 Python 中返回 2^k 形式的正数，而 C/Java 固定位宽下结果需按补码解读
  • 对结果的影响：忘记 n=0 边界会造成死循环；把 Python 的"无限位宽"结果照搬到 C 会静默出错
  • 推荐设置：刷题模板统一先判 if n == 0: return；跨语言移植时用 ((unsigned)n & (unsigned)(-(unsigned)n)) 显式说明

代码示例

import sys
print(sys.version)  # 打印 Python 版本，确认 bit_count() 等 API 的可用性（3.10+）


# ---------- 模板 1：O(1) 判断 2 的幂 ----------
def is_power_of_two(n: int) -> bool:
    if n <= 0:                       # 边界：0 和负数都不是 2 的幂（避免 0 & -1 == 0 误判）
        return False
    return n & (n - 1) == 0          # 2 的幂二进制只有一个 1，消掉即为 0


# ---------- 模板 2：统计二进制中 1 的个数（三种实现） ----------
def popcount_naive(n: int) -> int:
    cnt = 0                          # 计数器
    while n:                         # n 不为 0 就继续（Python 无负数死循环风险，位宽自动收缩）
        cnt += n & 1                 # 取出最低位（1 则加 1，0 则加 0）
        n >>= 1                      # 右移一位，检查下一位
    return cnt                       # 时间 O(位宽 w)，逐位检查


def popcount_bk(n: int) -> int:
    cnt = 0                          # 计数器
    while n:                         # n 中还有 1
        n &= n - 1                   # 每次消去最右侧的 1（Brian Kernighan 算法）
        cnt += 1                     # 消一次计一次
    return cnt                       # 时间 O(popcount(n))，稀疏 1 时最快


def popcount_swar(n: int) -> int:
    # SWAR：SIMD Within A Register，用乘法并行累加，固定 5 步，对 32 位整数 O(1)
    n = n - ((n >> 1) & 0x55555555)  # 第 1 步：相邻 2 位一组计数 0x55555555=01010101...，先减高位再与，等效每组 2 位内计数
    n = (n & 0x33333333) + ((n >> 2) & 0x33333333)  # 第 2 步：相邻 2 组(4 位)相加，0x33333333=00110011...
    n = (n + (n >> 4)) & 0x0f0f0f0f  # 第 3 步：相邻 4 组(8 位)相加并清高 4 位干扰，0x0f=00001111
    n = ((n * 0x01010101) & 0xFFFFFFFF) >> 24  # 第 4 步：乘 0x01010101 把 4 个字节的计数折叠进最高字节再右移 24 位；Python 大整数必须先 & 0xFFFFFFFF 模拟 32 位截断（C/Java 固定位宽天然截断）
    return n                         # 结果即 1 的总个数（要求输入 n 不超过 32 位）


# ---------- 模板 3：只出现一次的数字 I（其余出现两次） ----------
def single_number_1(nums):
    ans = 0                          # 异或的单位元是 0
    for x in nums:                   # 遍历所有元素
        ans ^= x                     # 出现两次的元素相互抵消（a^a=0），交换律保证顺序无关
    return ans                       # 剩下的就是只出现一次的那个数


# ---------- 模板 4：只出现一次的数字 II（其余出现三次，有限状态自动机） ----------
def single_number_2(nums):
    ones, twos = 0, 0                # ones：当前位上 1 出现 mod 3 == 1 的掩码；twos：mod 3 == 2 的掩码
    for x in nums:                   # 逐个元素输入状态机
        ones = (ones ^ x) & ~twos    # 先异或更新 ones，再排除已进入 twos 的位（该位已出现 2 次，再来一次应清零归 0）
        twos = (twos ^ x) & ~ones    # 同理更新 twos，并排除刚刚进入 ones 的位，保证 11→00 的三态循环
    return ones                      # 3 次抵消后 ones 恰好保存只出现 1 次的元素


# ---------- 模板 5：lowbit 与树状数组（Fenwick Tree）核心操作 ----------
def lowbit(n: int) -> int:
    return n & (-n)                  # 提取最右侧的 1：12(1100) & -12(...0100) = 4


class Fenwick:                       # 树状数组：单点修改 + 前缀查询，均 O(log n)
    def __init__(self, n: int):
        self.n = n                   # 逻辑下标从 1 开始
        self.t = [0] * (n + 1)       # 树状数组存储，索引 0 弃用

    def add(self, i: int, delta: int):
        while i <= self.n:           # 沿父链向上更新：i → i + lowbit(i)
            self.t[i] += delta       # 更新覆盖 i 的每个节点
            i += lowbit(i)           # lowbit 定位下一个父节点位置

    def prefix(self, i: int) -> int:
        s = 0                        # 前缀和累加器
        while i > 0:                 # 沿子链向下求和：i → i - lowbit(i)
            s += self.t[i]           # 累加管辖区间恰好不重叠的节点
            i -= lowbit(i)           # 每步跳过 lowbit(i) 个已统计元素
        return s                     # 返回 nums[1..i] 的和


# ---------- 模板 6：不用加减乘除做加法（进位法） ----------
def plus_without_op(a: int, b: int) -> int:
    MASK = 0xFFFFFFFF                # 32 位掩码，模拟定长补码（Python 无限位宽需手动限位）
    MAX = 0x7FFFFFFF                 # 32 位最大正数，用于把补码结果还原为 Python 负数
    while b != 0:                    # 只要还有进位未处理
        a, b = (a ^ b) & MASK, ((a & b) << 1) & MASK  # a^b 是不进位和；(a&b)<<1 是进位项，均截断到 32 位
    return a if a <= MAX else ~(a ^ MASK)             # 高于 31 位说明是负数补码，~(a ^ 0xFFFFFFFF) 还原


# ---------- 模板 7：枚举 n 元集合的所有子集（状态压缩基础） ----------
def enumerate_subsets(s: int):
    sub = s                          # 从最大子集（全集本身）开始
    while True:                      # 递减遍历 s 的所有子集（含 0 与全集）
        yield sub                    # 产出当前子集掩码
        sub = (sub - 1) & s          # 关键技巧：减 1 再与 s，跳过不属于 s 的位，保证每次都是 s 的子集
        if sub == s:                 # 0 之后再减回到 s，说明遍历结束（0 - 1 = -1，-1 & s == s）
            break


if __name__ == '__main__':           # 本地自测（Python 3.7 兼容）
    assert is_power_of_two(64) is True          # 64 = 2^6
    assert is_power_of_two(12) is False         # 12 = 1100 有两个 1
    assert popcount_naive(0xF0F0) == 8          # 1111 0000 1111 0000 共 8 个 1
    assert popcount_bk(0xF0F0) == 8             # BK 算法结果一致
    assert popcount_swar(0xF0F0) == 8           # SWAR 结果一致
    assert single_number_1([4, 1, 2, 1, 2]) == 4   # 1、2 两次抵消
    assert single_number_2([2, 2, 3, 2]) == 3      # 三个 2 走完三态循环归零
    assert lowbit(12) == 4                      # 1100 & -1100 = 0100
    f = Fenwick(8)                              # 建 8 长度树
    for i in range(1, 9):                       # 位置 1..8 全部 +1
        f.add(i, 1)
    assert f.prefix(8) == 8                     # 前缀和为 8
    assert plus_without_op(13, 29) == 42        # 不用 + 号算出 13+29
    assert len(list(enumerate_subsets(0b1111))) == 16  # 0b1111 有 4 个 1，子集数 2^4=16；有 3 个 1 的 0b1011 则恰为 8 个
    print('All bit manipulation tests passed.') # 全部断言通过

复杂度分析

单次位运算：设机器字长 $ w $（通常 64），单个 &/^/|/~/ 对一个字长的整数时间为 $ \Theta(w/w)=\Theta(1) $（CPU 一次处理整个字）；Python 大整数超过 $ w $ 位时按每 30 位一段处理，时间 $ \Theta(\lceil m/30 \rceil) $，$ m $ 为位长。

统计 1 的个数：

  • 朴素法：循环 $ w $ 次（n 不为 0 就右移），时间 $ O(w) $，空间 $ O(1) $
  • Brian Kernighan：设 $ k = \mathrm{popcount}(n) $，每次消去一个 1，循环恰 $ k $ 次，时间 $ O(k) $，对稀疏位串（1 很少）显著快于朴素的 $ O(w) $
  • SWAR：固定 5 次运算，时间 $ O(1) $（字长固定时），空间 $ O(1) $；硬件 POPCNT 同为单周期
  • 推导要点：BK 的循环不变式是"n 的 1 个数每轮减一"，初始与终止条件合力给出精确步数

枚举子集：集合大小为 $ n $ 时子集共 $ 2^n $ 个，sub = (sub-1) & s 每步 $ O(1) $，总计 $ O(2^n) $ 时间、$ O(1) $ 额外空间——这也是状态压缩 DP 的状态数下界。

位掩码压缩：用 1 个 $ w $ 位整数存 32 个布尔状态，空间从 $ O(n) $ 字节压到 $ O(n/32) $ 字节；配合集合运算整体操作，常数缩小约 32~64 倍。

MLA 多头潜在注意力

类别：大模型架构 | 难度：困难

算法简介

MLA（Multi-head Latent Attention，多头潜在注意力）是 DeepSeek 在 2024 年 5 月发布的 DeepSeek-V2 论文中提出的注意力机制，随后被 DeepSeek-V3、R1 及 Kimi K2 等前沿开源模型沿用，是当前大模型推理成本优化的标志性技术。它要解决的痛点是：自回归解码时每生成一个 token，都要把之前所有 token 的 Key/Value 向量缓存进显存（KV Cache），MHA 架构下每层每 token 需要缓存 $ 2 \times n_h \times d_h $ 个元素；序列越长、批量越大，KV Cache 迅速吞光显存，只能靠重算或换页兜底。已有的 MQA（所有头共享一份 KV）和 GQA（分组共享）通过"共享"省显存，但牺牲了表达能力。MLA 的思路完全不同——"低秩压缩"：用一个下投影矩阵把每个 token 的 KV 联合压缩成一个低维潜在向量 $ c^{KV} $（维度 $ d_c=512 $，远小于 $ 16384=128\times128 $），推理时只缓存这个潜在向量，需要时再经上投影矩阵恢复出各头的 K/V；配合"矩阵吸收"技术，恢复步骤可被数学上等价地融进 Q 的投影和输出投影，不产生额外计算开销。由于 RoPE 位置旋转与低秩压缩的数学形式不兼容（旋转矩阵插在中间无法合并），MLA 又设计了"解耦 RoPE"：把每个头的 Query/Key 拆成"不带位置信息的压缩部分 + 单独的带 RoPE 的小维度部分"，两部分拼接后一起参与注意力打分。据 DeepSeek-V2 论文，其 KV Cache 相比不做压缩的同等头数配置可缩减到约 2% 量级（论文报告中以 LLaMA2-7B 为对照减少 93.3%），生成吞吐最多提升 5.35 倍，且模型质量与全量 MHA 相当甚至更优，真正做到"省显存不降智"。

数学公式

以下记号与 DeepSeek-V2 论文一致：$ d_n $ 为模型隐层维度，$ n_h $ 为注意力头数，$ d_h $ 为每头维度，$ d_c $ 为 KV 联合压缩维度（kv_lora_rank），$ d_c' $ 为查询压缩维度（q_lora_rank），$ d_R $ 为解耦 RoPE 维度（qk_rope_head_dim）。

公式 1：KV 联合低秩压缩

$$ c_t^{KV} = W^{DKV} h_t, \quad W^{DKV} \in \mathbb{R}^{d_c \times d_n} $$

变量解释：

  • $ h_t \in \mathbb{R}^{d_n} $：第 $ t $ 个 token 的隐藏层输出（如 5120 维）
  • $ W^{DKV} $：下投影（压缩）矩阵，把 5120 维压到 $ d_c = 512 $ 维
  • $ c_t^{KV} \in \mathbb{R}^{d_c} $：KV 联合潜在向量，这是推理时唯一需要缓存的主体
  • 压缩成立的前提：KV 矩阵 $ \{K, V\} $ 在训练中学到近低秩结构（loose 自适应低秩），信息集中在前 $ d_c $ 维子空间

公式 2：逐头上投影恢复每头的 K/V

$$ k_{t,i}^{C} = W^{UK}_i\, c_t^{KV}, \quad v_{t,i}^{C} = W^{UV}_i\, c_t^{KV}, \quad W^{UK}_i, W^{UV}_i \in \mathbb{R}^{d_h \times d_c} $$

变量解释：

  • $ W^{UK}_i $、$ W^{UV}_i $：第 $ i $ 个头的上投影矩阵，从共享潜在向量"解压"出该头专属的 K/V
  • $ k_{t,i}^{C}, v_{t,i}^{C} \in \mathbb{R}^{d_h} $：第 $ i $ 头的内容（Content）部分，上标 $ C $ 表示不带位置信息
  • 实现中各头矩阵拼成大矩阵 $ W^{UK}, W^{UV} \in \mathbb{R}^{n_h d_h \times d_c} $，一次矩阵乘全部恢复

公式 3：查询侧低秩压缩

$$ c_t^{Q} = W^{DQ} h_t \in \mathbb{R}^{d_c'}, \quad q_{t}^{C} = W^{UQ} c_t^{Q} \in \mathbb{R}^{n_h \times d_h} $$

变量解释：

  • $ c_t^Q $：查询侧潜在向量（$ d_c' = 1536 $）
  • Q 压缩的意义：多层共享信息冗余时降低激活内存与训练显存；对推理 KV Cache 无直接影响（Q 不缓存）

公式 4：解耦 RoPE（Decoupled RoPE）

$$ q_{t,i} = \big[\, q_{t,i}^{C}\,;\ \ R_{m,i}\, q_{t,i}^{R} \,\big], \quad q_t^{R} = W^{QR} c_t^{Q}; \qquad k_{t,i} = \big[\, k_{t,i}^{C}\,;\ \ R_{m}\, W^{KR} h_t \,\big] $$

变量解释：

  • $ q_{t,i}^R \in \mathbb{R}^{d_R} $：第 $ i $ 头的旋转（RoPE）查询分量，$ d_R = 64 $ 维
  • $ W^{KR} h_t \in \mathbb{R}^{d_R} $：所有头共享的一份带位置信息 key 分量（每 token 只缓存这一个 64 维向量）
  • $ R_{m,i} $、$ R_m $：RoPE 旋转矩阵，作用是给分量注入相对位置信息
  • $ [\cdot\,;\cdot] $：向量拼接，故每头打分用的总维度 $ q_{head\_dim} = qk\_nope + qk\_rope = 128 + 64 = 192 $
  • 为什么必须拆分：若对 $ k = W^{UK} c^{KV} $ 直接乘 RoPE，注意力式中会出现 $ R \cdot W^{UK} $ 交错乘积，矩阵吸收失效，缓存/计算优势尽失；拆出小通道后，压缩分量与旋转分量各走各的，两全其美

公式 5：注意力计算与输出

$$ o_{t,i} = \sum_j \mathrm{softmax}_j\!\left(\frac{q_{t,i}^{\top} k_{j,i}}{\sqrt{q_{head\_dim}}}\right) v_{j,i}^{C}, \quad u_t = W^{O}\big[\, o_{t,1};\cdots;o_{t,n_h} \,\big] $$

变量解释：

  • $ q_{t,i}^{\top} k_{j,i} $：拼接维度 192 上的内积（前面 128 维不旋转 + 后 64 维旋转）
  • $ \sqrt{q_{head\_dim}} $：缩放因子防止点积方差过大
  • $ W^O \in \mathbb{R}^{d_n \times n_h d_h} $：输出投影矩阵

公式 6：矩阵吸收（推理优化核心）

$$ q_{t,i}^{C\top} k_{j,i}^{C} = q_{t,i}^{C\top}\big(W^{UK}_i c_j^{KV}\big) = \big((W^{UK}_i)^{\top} q_{t,i}^{C}\big)^{\top} c_j^{KV} $$

变量解释：

  • 左式：先恢复 key 再打分（每步解码要做 $ O(\text{history}) $ 次 $ d_h \times d_c $ 恢复）
  • 右式：把 $ (W^{UK}_i)^\top $ 预乘进当前步的查询（每步只做一次），打分直接发生在 $ d_c = 512 $ 维潜在空间，历史端零恢复开销
  • V 与输出投影同理：$ W^O $ 吸收 $ W^{UV} $，矩阵乘合并，数学上完全等价

公式 7：KV Cache 显存对比（每 token 每层元素数）

$$ \text{MHA}: 2 n_h d_h = 2 \times 128 \times 128 = 32768; \quad \text{GQA}: 2 n_g d_h; \quad \text{MLA}: d_c + d_R = 512 + 64 = 576 $$

变量解释：

  • $ n_g $：GQA 的 KV 头组数（如 8 组则 2048 元素）
  • MLA 的 576 元素约为 MHA 的 1.75%，压缩约 57 倍；FP16 下每层每 token 仅 1152 字节

核心要点

  • KV Cache 是自回归推理的显存第一杀手，MLA 用"低秩压缩缓存"替代"全量 KV 缓存"，576 元素 vs 32768 元素（DeepSeek-V2 配置）
  • 三件套缺一不可：低秩联合压缩（省显存）、解耦 RoPE（保位置能力 + 保持可吸收性）、矩阵吸收（省去恢复计算）
  • 与 MQA/GQA 的本质区别：MQA/GQA 靠"共享头"砍容量，MLA 靠"低秩投影"压信息，表达能力接近 MHA，论文实测性能优于 MHA 基线
  • Q 侧压缩（q_lora_rank）主要服务训练期激活/显存成本，推理收益主要看 kv_lora_rank
  • DeepSeek-V2 论文报告：KV cache 大幅缩减（论文以 LLaMA2-7B 为参照减少 93.3%）、生成吞吐最多提升 5.35 倍，模型质量与 MHA 相当
  • vLLM/SGLang 等推理引擎已实现 MLA 吸收版前向与专用 kernel；注意 MLA 与 Flash-Decoding、PagedAttention 兼容时走的是"潜在缓存 + 联合矩阵"路径
  • 局限：注意力权重显存仍随序列平方增长（打分本身）、训练时需维护两套投影权重、与部分依赖标准 KV 形状的优化（如某些 KV Cache 量化方案）需要适配

技术细节与参数详解

以下参数以 DeepSeek-V2 236B / DeepSeek-V3 的 HuggingFace config.json 字段为准（两者 MLA 参数一致）。

#### 参数 1：kv_lora_rank（论文记号 $ d_c $）

  • 含义：KV 联合潜在向量的维度，决定每个 token 每层需要缓存的主体大小
  • 类型：int
  • 默认值：DeepSeek-V2/V3 均为 512；DeepSeek-V2-Lite 也为 512
  • 取值范围：64~2048 的 2 的幂常见的经验区间；必须小于 $ n_h d_h = 16384 $ 才有压缩意义
  • 对结果的影响：越大信息保留越充分、模型质量上限越高，但 KV Cache 线性增大、解码吞吐下降；过小（如 64）语义信息丢失明显
  • 推荐设置：512 是 DeepSeek 系列大模型的成熟经验值；推理显存预算极紧时可降到 256 观察 PPL 回退幅度

#### 参数 2：q_lora_rank（论文记号 $ d_c' $）

  • 含义：查询侧联合压缩向量的维度，Q 先压到该维度再上投影到各头
  • 类型：int
  • 默认值：DeepSeek-V2/V3 为 1536
  • 取值范围：128~4096；设为 0 或省略表示不压缩查询（直接 $ W^Q $ 投影）
  • 对结果的影响：主要压缩训练期激活内存与参数量（Q 投影从 $ d_n \times n_h d_h $ 两级联），对推理 KV Cache 无影响；过小会限制查询表达能力
  • 推荐设置：1536（约为 $ d_n $ 的 30%）为官方稳定配置；纯推理服务复现训练权重时必须与 checkpoint 一致

#### 参数 3：qk_nope_head_dim

  • 含义：每个头的注意力打分中"不带位置信息的压缩部分"维度（$ q^C $、$ k^C $ 的维度）
  • 类型：int
  • 默认值：128
  • 取值范围：64/128 居多
  • 对结果的影响：决定语义相关性的容量，与标准 MHA 的 head_dim 角色一致；与 qk_rope_head_dim 相加即每头打分总维度（$ 192 $）
  • 推荐设置：跟随官方 128 对齐 CUDA Tensor Core（128 的倍数 kernel 效率最优）

#### 参数 4：qk_rope_head_dim（论文记号 $ d_R $）

  • 含义：解耦 RoPE 通道的维度，即每头参与旋转位置编码的分量维度
  • 类型：int
  • 默认值：64
  • 取值范围：32/64 常见（必须为偶数，RoPE 两两配对旋转）
  • 对结果的影响：越大位置信息容量越大（长上下文外推越稳），但每 token 缓存的共享 $ k^R $ 与打分维度同时增大；过小可能损伤长程位置分辨率
  • 推荐设置：64 为官方值；做超长上下文（128K+）微调实验时可对比 64/128 两档

#### 参数 5：v_head_dim

  • 含义：每个头输出 value 分量的维度
  • 类型：int
  • 默认值：128（注意：等于 qk_nope_head_dim，但理论上可独立配置）
  • 取值范围：64~256
  • 对结果的影响：决定每头输出信息带宽，直接影响 $ W^{UV} $ 与输出投影的参数量
  • 推荐设置：与 qk_nope_head_dim 保持一致的 128，便于权重布局与吸收实现

#### 参数 6：n_heads（$ n_h $）

  • 含义：注意力头数
  • 类型：int
  • 默认值：DeepSeek-V2/V3 为 128；V2-Lite 为 16
  • 取值范围：典型 8~128；与 kv_lora_rank 无整除约束（潜在向量是全体头共享的，这正是与 GQA 分组共享的差异）
  • 对结果的影响：头数决定子空间多样性与打分矩阵并行度；MLA 中头数增大不增加 KV Cache（只增大非缓存的投影矩阵参数），这是相对 MHA 的结构性优势
  • 推荐设置：复现官方模型严格取 128；自研小模型按 $ n_h \times d_h \approx 2\sim4 \times d_n $ 经验配比

#### 参数 7：hidden_size（$ d_n $，模型 d_model）

  • 含义：残差流的向量宽度，所有下投影的输入、上投影的输出维度
  • 类型：int
  • 默认值：DeepSeek-V2 为 5120，V3 为 7168，V2-Lite 为 2048
  • 取值范围：千级到万级，通常为各头维度和的近似（$ 128 \times 128 = 16384 $ 压缩进 5120/7168）
  • 对结果的影响：决定压缩比（16384/5120 ≈ 0.3 → 512/16384 的两级压缩）；与 MoE 结构、GPU 通信分片策略强相关
  • 推荐设置：与训练目标规模匹配即可，MLA 本身无额外强约束

#### 参数 8：rope_theta 与 RoPE 缩放（长上下文相关）

  • 含义：RoPE 的基频底数 $ \theta $，位置 $ m $ 在维度偶对 $ \{2i, 2i+1\} $ 上的旋转角为 $ m\theta^{-2i/d_R} $；DeepSeek-V3 另用 YaRN 高频外推缩放扩展到 128K
  • 类型：float 与 dict（如 {"type": "yarn", "factor": 40, ...}）
  • 默认值：DeepSeek-V2/V3 均为 10000
  • 取值范围：常见 10000~500000；scale 因子随目标上下文长度增大
  • 对结果的影响：$ \theta $ 越大高频成分衰减越慢，长序列分辨率更好但短程区分度可能下降； MLA 中 RoPE 只作用于 64 维小通道，缩放超参不当会先伤及位置通道
  • 推荐设置：默认 10000 + YaRN 扩展（跟随官方脚本），微调超长上下文时单独调 YaoRN 的 attention_factor

#### 参数 9（推理侧）：KV Cache dtype（vLLM kv_cache_dtype）

  • 含义：缓存潜在向量与共享 $ k^R $ 的数值精度
  • 类型：str 选项
  • 默认值：随模型权重 dtype（bf16/fp16）
  • 取值范围：auto（同权重）、fp8_e4m3（量化缓存）
  • 对结果的影响：576 元素的基础已极省，再上 fp8 可减半至约 576 字节/层/token；量化误差集中在长上下文末端，需用长文档长 needle 任务回归验证
  • 推荐设置：显存充裕用 auto；极限并发场景 fp8_e4m3 并配合引擎的 MLA fp8 kernel

def kv_cache_cost(n_heads=128, head_dim=128, n_layers=60, seq_len=4096,      # MHA 参数
                  gqa_groups=8, kv_lora_rank=512, rope_dim=64,               # GQA/MLA 参数
                  bytes_per_elem=2, batch_size=8):                           # FP16、批量
    """对比 MHA / GQA / MLA 三种注意力在推理时的 KV Cache 显存占用"""
    # ---- 1. 每 token 每层需要缓存的元素数 ----
    mha_elems = 2 * n_heads * head_dim            # MHA：每个头各存一份 K(128 维) + V(128 维)
    gqa_elems = 2 * gqa_groups * head_dim         # GQA：8 组共享，每组一份 K + V
    mla_elems = kv_lora_rank + rope_dim           # MLA：潜在向量 512 + 共享 RoPE key 64
    # ---- 2. 单条序列全层全 token 的缓存字节数 ----
    def total_gb(elems_per_token_layer):
        one_seq = elems_per_token_layer * n_layers * seq_len * bytes_per_elem  # 元素数 × 层数 × 序列长 × 精度
        return one_seq * batch_size / 1024**3                                   # 批量后换算 GB（1024 进制）
    # ---- 3. 打印对比表 ----
    for name, e in [('MHA', mha_elems), ('GQA-8', gqa_elems), ('MLA', mla_elems)]:
        print('%-6s %6d 元素 tok^-1 layer^-1  batch=%d 时共 %7.2f GiB'
              % (name, e, batch_size, total_gb(e)))
    print('MLA 相对 MHA 压缩率: %.1f%%' % (100 * (1 - mla_elems / mha_elems)))
    # 运行输出（DeepSeek-V2 236B 配置 60 层，4096 上下文，batch=8，FP16，1024 进制 GiB）：
    # MHA     32768 元素 tok^-1 layer^-1  batch=8 时共  120.00 GiB
    # GQA-8    2048 元素 tok^-1 layer^-1  batch=8 时共    7.50 GiB
    # MLA       576 元素 tok^-1 layer^-1  batch=8 时共    2.11 GiB
    # MLA 相对 MHA 压缩率: 98.2%

示例 2：MLA 前向的教学级 PyTorch 实现（展示投影矩阵结构，参数按 DeepSeek-V3）：

import torch
import torch.nn as nn


class RMSNorm(nn.Module):
    """RMS 归一化：比 LayerNorm 少去均值一步，现代 LLM 标配（自实现，避免依赖 PyTorch 2.4+ 的 nn.RMSNorm）"""

    def __init__(self, dim, eps=1e-6):
        super().__init__()
        self.weight = nn.Parameter(torch.ones(dim))   # 可学习缩放 γ，初始化全 1
        self.eps = eps                                # 数值稳定项，防除零

    def forward(self, x):
        rms = x.pow(2).mean(-1, keepdim=True)         # 最后一维（特征维）的均方值
        return x * torch.rsqrt(rms + self.eps) * self.weight  # x/RMS(x) 再乘 γ（rsqrt 即 1/√）


class MiniMLA(nn.Module):
    """教学版 MLA：保留全部关键投影路径与吸收式打分，仅省略末尾 softmax 融合（见 forward 内 print）"""

    def __init__(self, d_model=7168, n_heads=128,                          # 隐层维度、头数（DeepSeek-V3 配置）
                 q_lora_rank=1536, kv_lora_rank=512,                       # 压缩维度 d_c' 与 d_c
                 qk_nope_dim=128, qk_rope_dim=64, v_head_dim=128):         # nope/rope/输出三组头维度
        super().__init__()
        self.n_heads, self.dh, self.dR = n_heads, qk_nope_dim, qk_rope_dim   # 存下常量便于切片
        self.dc, self.vd = kv_lora_rank, v_head_dim                          # 压缩维 512、每头 value 输出维 128
        self.q_head_dim = qk_nope_dim + qk_rope_dim                          # 每头打分总维度 = 128 + 64 = 192
        self.wq_a = nn.Linear(d_model, q_lora_rank, bias=False)              # W_DQ: 7168 → 1536 查询压缩
        self.q_norm = RMSNorm(q_lora_rank)                                   # 压缩后归一化（DeepSeek 实现含 q_norm）
        self.wq_b = nn.Linear(q_lora_rank, n_heads * self.q_head_dim, bias=False)  # [W_UQ; W_QR]: 1536 → 128×192
        self.wkv_a = nn.Linear(d_model, kv_lora_rank + qk_rope_dim, bias=False)    # [W_DKV; W_KR]: 7168 → 512+64 一次投影
        self.kv_norm = RMSNorm(kv_lora_rank)                                 # 潜在向量归一化（V3 特有，稳定吸收前数值）
        self.wkv_b = nn.Linear(kv_lora_rank, n_heads * (qk_nope_dim + v_head_dim), bias=False)  # [W_UK; W_UV]: 512 → 128×256
        self.wo = nn.Linear(n_heads * v_head_dim, d_model, bias=False)       # W^O 输出投影

    def forward(self, h, rope_fn, kv_cache=None):
        bsz, seqlen, _ = h.shape                                              # h: (batch, seq, 7168)
        # ---- Q 支路：先压缩再分头双通道 ----
        cq = self.q_norm(self.wq_a(h))                                        # c^Q: (b, s, 1536)
        q = self.wq_b(cq).view(bsz, seqlen, self.n_heads, self.q_head_dim)    # 拼出每头 192 维
        q_nope, q_pe = q[..., :self.dh], q[..., self.dh:]                     # 切分: 128 维内容 + 64 维旋转
        q_pe = rope_fn(q_pe)                                                  # 仅旋转通道施加 RoPE
        # ---- KV 支路：所有历史只需缓存 c_KV(512) 与共享 RoPE key(64) ----
        kv = self.wkv_a(h)                                                    # 单次线性投影出拼接结果: (b, s, 512+64)
        c_kv = self.kv_norm(kv[..., :self.dc])                                # 前 512 维 → KV 联合潜在向量: (b, s, 512)
        k_pe = rope_fn(kv[..., self.dc:])                                     # 后 64 维 → 共享 RoPE key: (b, s, 64)
        if kv_cache is not None:                                              # 解码期：拼接历史缓存
            c_kv = torch.cat([kv_cache[0], c_kv], dim=1)                      # 缓存连续追加（PagedAttention 分页管理）
            k_pe = torch.cat([kv_cache[1], k_pe], dim=1)
        new_cache = (c_kv, k_pe)                                              # ← 需要持久化的只有这两个张量
        # ---- 吸收式注意力：数学上等效于先恢复 K/V 再打分（见示例 3 的数值验证）----
        wkv_b = self.wkv_b.weight.view(self.n_heads, self.dh + self.vd, self.dc)  # 恢复逐头形状: (128 头, 128+128, 512)
        w_uk = wkv_b[:, :self.dh, :]                                          # W^UK_i: (128 头, 每头 128 维输出, 512 维潜在输入)
        q_eff = torch.einsum('bshd,hcd->bshc', q_nope, w_uk)                  # 关键一步：把 W^UK 吸收进 q → (b, s, h, c=512)，打分直接作用于潜在空间
        attn = torch.einsum('bshc,btc->bhst', q_eff, c_kv)                    # 内容打分 (b, 头, 当前步 s, 历史 t)，全程无需恢复历史 K
        attn = attn / (self.q_head_dim ** 0.5)                                # 缩放 √192，防 softmax 饱和
        rope_attn = torch.einsum('bshd,btd->bhst', q_pe, k_pe)                # 旋转通道打分：q 每头独立、k 全头共享 64 维
        print('教学版到打分为止；softmax(attn + rope_attn) 后再做 V 吸收与 W^O 输出投影即为完整前向')  # 完整实现见 DeepSeek 开源 modeling_deepseek.py
        return attn, rope_attn, new_cache                                     # 需要持久化的缓存始终只有 c_kv(512) 与 k_pe(64)

示例 3：矩阵吸收等价性的数值验证（说明"先恢复再打分"与"先吸收再打分"完全等价）：

import torch

torch.manual_seed(0)                                          # 固定随机种子，结果可复现
d_h, d_c = 8, 4                                               # 小维度便于人工检查
q = torch.randn(d_h)                                          # 某头的查询向量（一维，形式最简）
W_uk = torch.randn(d_h, d_c)                                  # 上投影矩阵 W^UK_i (8×4)
c_kv = torch.randn(d_c)                                       # 某历史 token 的 KV 潜在向量 (4,)

score_direct = q @ W_uk @ c_kv                                # 路径 A：先恢复 k = W_uk @ c_kv，再点积 q·k
score_absorbed = (W_uk.T @ q) @ c_kv                          # 路径 B：先吸收得 q~ = W_ukT q，再与潜在向量 c_kv 点积
print(torch.allclose(score_direct, score_absorbed, atol=1e-6))  # 输出 True：两条路径数学上完全等价
# 推理含义：路径 A 每个历史 token 都要恢复一次 k（成本随历史长度增长），
# 路径 B 只对当前 token 的 q 做一次吸收变换，历史端直接用缓存的 c_kv 打分 → 解码加速的根源

复杂度分析

注意力本体：设序列长 $ s $、每头打分维度 $ q_{head\_dim}=192 $，单层注意力计算量 $ O(s^2 \cdot n_h \cdot q_{head\_dim}) $，MLA 与 MHA 同阶（这是无法回避的自注意力平方项）。

推理 KV Cache 空间（每 token 每层元素数）：

  • MHA：$ 2 n_h d_h = 32768 $；GQA：$ 2 n_g d_h = 2048 $（8 组）；MLA：$ d_c + d_R = 576 $
  • 推导：MHA 需为每个头保存独立 K/V 向量；MLA 全部头共享一个 512 维潜在向量，外加一份 64 维共享旋转 key，故仅需 $ 512+64 $；压缩比 $ 32768/576 \approx 56.9 $
  • 60 层、4096 上下文、batch=8、FP16 下：MHA 约 120 GiB、GQA-8 约 7.5 GiB、MLA 仅约 2.1 GiB（见示例 1 实测输出）

解码一步的时间复杂度：

  • 无吸收朴素版：恢复历史 K/V 需 $ O(s \cdot (n_h d_h d_c)) $，与序列长线性相关且随每步重复
  • 吸收版：每步仅对当前 q 与 $ W^{UK} $、$ W^{UV} $ 做两次 $ O(n_h d_h d_c) $ 变换（常数次），打分直接在 512 维潜在空间，历史端零开销——这是长序列解码吞吐提升的关键来源

训练显存：Q 低秩压缩把激活从 $ O(n_h d_h) $（1536 对 16384，约 1/10 激活压缩）降低，配合 FlashAttention 类 kernel 的重算策略，整体训练显存与 MHA 同规模可持平或更低。

应用场景

  • DeepSeek-V2 / V2-Lite / V3 / R1 全系开源权重，是 2024-2026 年长上下文推理成本优化的参考实现
  • 需要超长上下文的场景：128K 合同/代码分析、长文档 RAG、多轮长对话记忆压缩（单条 4096 序列的 KV Cache 从约 15 GiB 降到约 270 MiB，同卡可承载的 batch 数量提升数十倍）
  • 高并发推理服务：显存预算内吞吐近似线性提升（DeepSeek-V2 论文报告生成吞吐最高 5.35 倍），直接摊薄单 token 服务成本

Transformer 架构

类别：深度学习 | 难度：困难

算法简介

Transformer 是 2017 年 Google 论文《Attention Is All You Need》提出的序列建模架构，用自注意力机制（Self-Attention）完全取代了 RNN 的循环结构和 CNN 的局部卷积，让序列中任意两个位置都能一步直达地交换信息（路径长度 O(1)），且整个序列可完全并行训练，彻底解决了 RNN 训练慢、长距离依赖衰减两大痛点。其经典结构为编码器-解码器（Encoder-Decoder）双塔：编码器由 N 层"多头自注意力 + 前馈网络（FFN）"堆叠，每层配残差连接与 LayerNorm；解码器额外多一个"带掩码的自注意力"（下三角掩码防止看到未来）和"交叉注意力"（对编码器输出做 K/V）。三个魔法组件构成核心：Query/Key/Value 三元组的缩放点积注意力负责"按相关性加权取数"；多头机制把 embedding 切到多个子空间并行学习不同的关系模式；位置编码（正弦/可学习/RoPE 等）弥补注意力本身排列不变的缺陷。今天几乎所有大模型都是它的变体：GPT 系列取解码器（decoder-only）、BERT 取编码器（encoder-only）、T5 保留双塔，视觉领域的 ViT、语音领域的 Whisper、蛋白质折叠的 AlphaFold 也全部构建在 Transformer 之上。工程实践中最快上手的方式是 torch.nn.MultiheadAttention，但它有 9 个构造参数和一批易错的 forward 参数（batch_first、attn_mask、key_padding_mask 的方向性），本文逐个讲透。

数学公式

以下记号与《Attention Is All You Need》一致：$ d_{model} $ 为模型维度（embed_dim），$ h $ 为头数（num_heads），$ d_k = d_v = d_{model}/h $ 为每头维度。

公式 1：缩放点积注意力（Scaled Dot-Product Attention）

$$ \mathrm{Attention}(Q, K, V) = \mathrm{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V $$

变量解释：

  • $ Q \in \mathbb{R}^{n \times d_k} $：查询矩阵，n 个位置各自"想找什么"
  • $ K \in \mathbb{R}^{m \times d_k} $：键矩阵，m 个被检索位置各自"是什么"
  • $ V \in \mathbb{R}^{m \times d_v} $：值矩阵，被检出的实际内容
  • $ QK^\top \in \mathbb{R}^{n \times m} $：所有查询与所有键的相似度打分矩阵
  • $ \sqrt{d_k} $：缩放因子。当 $ d_k $ 较大时点积方差约为 $ d_k $（初始化下 $ \mathrm{Var}(q\cdot k) = d_k $），值域过大把 softmax 推入饱和区，梯度接近 0，除以 $ \sqrt{d_k} $ 把方差拉回 1
  • $ \mathrm{softmax} $：按行归一化，使每个查询对全部键的注意力权重和为 1

公式 2：多头注意力（Multi-Head Attention）

$$ \mathrm{MultiHead}(Q,K,V) = \mathrm{Concat}(\text{head}_1, \dots, \text{head}_h)\,W^O, \quad \text{head}_i = \mathrm{Attention}(QW_i^Q,\; KW_i^K,\; VW_i^V) $$

变量解释：

  • $ W_i^Q \in \mathbb{R}^{d_{model} \times d_k} $、$ W_i^K \in \mathbb{R}^{d_{model} \times d_k} $、$ W_i^V \in \mathbb{R}^{d_{model} \times d_v} $：第 i 头的投影矩阵（nn.MultiheadAttention 内部的 in_proj_weight 三段拼接）
  • $ W^O \in \mathbb{R}^{(h d_v) \times d_{model}} $：输出投影（模块的 out_proj）
  • 多头不是"维度变大"，而是把同一输入投到 h 个不同的低维子空间分别交互，最后拼回，总计算量与单头 $ d_{model} $ 维持平

公式 3：前馈网络（Position-wise FFN）

$$ \mathrm{FFN}(x) = \max(0,\; xW_1 + b_1)\,W_2 + b_2 $$

变量解释：

  • $ W_1 \in \mathbb{R}^{d_{model} \times d_{ff}} $、$ W_2 \in \mathbb{R}^{d_{ff} \times d_{model}} $：先升维（通常 $ d_{ff} = 4 d_{model} $）再降回
  • $ \max(0, \cdot) $：ReLU，现代实现多换 GELU/SwiGLU，公式结构不变，为每个位置独立做同一变换（position-wise）
  • $ b_1, b_2 $：偏置，LLaMA 等现代架构常去掉（bias=False）

公式 4：正弦位置编码（Sinusoidal Positional Encoding）

$$ PE_{(pos,\,2i)} = \sin\!\left(\frac{pos}{10000^{2i/d_{model}}}\right), \qquad PE_{(pos,\,2i+1)} = \cos\!\left(\frac{pos}{10000^{2i/d_{model}}}\right) $$

变量解释：

  • $ pos $：token 在序列中的位置（0, 1, 2, ...）
  • $ i $：维度索引对编号，第 $ 2i $ 与 $ 2i+1 $ 维构成一对正交分量，等价于不同频率的旋转（RoPE 的先声）
  • $ 10000 $：基频底数，低维振荡快（局部位置差异敏感）、高维振荡慢（长程相对位置可分）
  • 该编码直接与词向量相加注入位置信息，本身可外推到训练未见长度

公式 5：LayerNorm（层归一化）

$$ \mathrm{LN}(x) = \gamma \odot \frac{x - \mu}{\sqrt{\sigma^2 + \epsilon}} + \beta $$

变量解释：

  • $ \mu, \sigma^2 $：x 最后一维上的均值与方差
  • $ \epsilon $：数值稳定项（PyTorch 默认 $ 10^{-5} $，layer_norm_eps 参数）
  • $ \gamma, \beta $：可学习的缩放与平移（elementwise_affine=True 引入；Pre-LN/ViT 类架构常保留）
  • Post-LN（原论文，Norm 在残差后）与 Pre-LN（Norm 在子层前，GPT-2 起主流，norm_first=True）训练稳定性不同：Pre-LN 梯度更平滑，深模型不热身也能训

公式 6：自注意力复杂度

$$ \text{时间}: O(n^2 \cdot d_{model}), \qquad \text{空间}: O(n^2) + O(n \cdot d_{model}) $$

变量解释：

  • $ n $：序列长度；$ O(n^2 d) $ 来自 $ QK^\top $ 与 softmax 后乘 $ V $（两遍全量乘）
  • $ O(n^2) $：注意力矩阵本身的存储，FlashAttention 通过分块重算降掉、稀疏/线性注意力从建模层面降
  • 对比 RNN 的时间 $ O(n d^2) $：串行不可并行 vs 并行但注意力矩阵平方增长

核心要点

  • 自注意力三步曲：投影出 Q/K/V → 缩放点积打分 → 权重加权求和 V；缩放因子防 softmax 饱和是必答细节
  • 多头 = 同一输入的 h 个低维视角并行交互；约束 embed_dim % num_heads == 0，每头 $ d_k = embed\_dim / num\_heads $
  • 位置信息必须外部注入（注意力排列不变）：绝对正弦/可学习 → 相对 RoPE/ALiBi 演进，长上下文时代已成主流
  • 残差连接保证梯度通路、LayerNorm 控制数值分布；Pre-LN（norm_first=True）是现代深模型稳定性标配
  • 解码器因果掩码（下三角 -inf）保证自回归方向性；交叉注意力里 Q 来自解码器、K/V 来自编码器
  • nn.MultiheadAttention 的 batch_first 默认 False（旧接口遗留！），显式传 True 可避免大量转置 bug
  • attn_mask（形状 L×S，遮位置对）与 key_padding_mask（形状 N×S，遮无效 token）维度方向完全不同，是最高频踩坑点
  • 计算瓶颈长序列注意力：FlashAttention（IO 感知分块）、GQA/MLA（KV 压缩，见昨日/今日姊妹篇）两条优化主线

技术细节与参数详解

以 PyTorch torch.nn.MultiheadAttention(embed_dim, num_heads, dropout, bias, add_bias_kv, add_zero_attn, kdim, vdim, batch_first) 为准逐参数讲解。

#### 参数 1：embed_dim

  • 含义：输入嵌入与注意力输出的总维度 $ d_{model} $，Query/Key/Value 的投影源维度
  • 类型：int（必填）
  • 默认值：无
  • 取值范围：正整数且必须能被 num_heads 整除；常见 128~512（小模型/实验）、768（BERT-base、GPT-2 small）、1024~12288（现代 LLM）
  • 对结果的影响：模型容量与显存占用的第一杠杆；每层参数约 $ 12 d_{model}^2 $（注意力 + FFN，含 4 倍 FFN 约为 $ 12d^2 $），维度翻倍参数近 4 倍
  • 推荐设置：教学/原型从 256 或 512 起；对接预训练权重必须与词表 checkpoint 一致

#### 参数 2：num_heads

  • 含义：注意力头数 h，把 embed_dim 均分为 h 个子空间
  • 类型：int（必填）
  • 默认值：无
  • 取值范围：1 到 embed_dim 之间且整除 embed_dim；经验取 8/12/16/32（对应 $ d_k $ 为 64/64/64/128 的居多）
  • 对结果的影响：固定 embed_dim 时头数与每头维度此消彼长——头太多每头维度过小信息瓶颈，头太少子空间模式不够丰富；总 FLOPs 不随头数改变
  • 推荐设置：保持 $ d_k \geq 64 $ 的前提下取最大头数；如 embed_dim=512 时 8 头（$ d_k=64 $）是安全经典配置

#### 参数 3：dropout

  • 含义：注意力权重 softmax 之后随机置零的比例 P
  • 类型：float
  • 默认值：0.0
  • 取值范围：[0.0, 1.0)
  • 对结果的影响：训练时正则防过拟合（注意力自由度大易记住噪声）；推理自动失效；过大（>0.3）会伤害短序列任务收敛
  • 推荐设置：微调/大 batch 0.1；小数据从头训 0.1~0.3；推理与 model.eval() 下无所谓

#### 参数 4：bias

  • 含义：Q/K/V 输出投影是否使用可学习偏置项
  • 类型：bool
  • 默认值：True
  • 取值范围：True / False
  • 对结果的影响：False 少 3×(embed_dim)+每头参数量，现代 LLM（LLaMA 系）证明去掉偏置不损质量还有微小加速；True 与原论文一致、微调老权重必须开
  • 推荐设置：新模型建议 False；兼容 2017-2022 年间 checkpoint 必须保持 True

#### 参数 5：add_bias_kv

  • 含义：是否在 K、V 末端各追加一个可学习的偏置 key/value（额外一行参与注意力）
  • 类型：bool
  • 默认值：False
  • 取值范围：True / False
  • 对结果的影响：等价给注意力加一个可学习的"全局锚点"，图像/点云领域（如 DETR 的 object queries 思想近亲）偶有使用；开销是每层多两个可学向量
  • 推荐设置：常规 NLP 任务保持 False；复现原文或 DETR 变体时核对论文

#### 参数 6：add_zero_attn

  • 含义：是否在 K、V 末尾追加一个全零 key/value（该位置注意力分数恒为 0，softmax 后仍占一份权重的"无操作"选项）
  • 类型：bool
  • 默认值：False
  • 取值范围：True / False
  • 对结果的影响：给模型一个"什么都可以不关注"的逃生门，DINOv2 等自监督模型用它提升注意力分布灵活性；多数监督任务无感
  • 推荐设置：保持 False，除非复现特定视觉自监督方法

#### 参数 7：kdim

  • 含义：K 输入张量的特征维度（交叉注意力时源序列的维度）
  • 类型：int
  • 默认值：None，即等于 embed_dim
  • 取值范围：任意正整数（如翻译模型里源语言 encoder 输出 1024 维对齐到 decoder 的 512 维）
  • 对结果的影响：决定 $ W^K $ 投影矩阵的输入宽度；None 时与 embed_dim 共享统一形状，自定义值时 $ W^K \in \mathbb{R}^{kdim \times embed\_dim} $
  • 推荐设置：标准 Transformer 双塔维度一致，保持 None；异构桥接时显式指定

#### 参数 8：vdim

  • 含义：V 输入张量的特征维度
  • 类型：int
  • 默认值：None，即等于 embed_dim
  • 取值范围：任意正整数
  • 对结果的影响：同 kdim，决定 $ W^V $ 输入宽度；交叉注意力中 K/V 常同源同维，两个参数要一起设
  • 推荐设置：与 kdim 成对出现成对设置

#### 参数 9：batch_first

  • 含义：输入/输出张量的布局约定
  • 类型：bool
  • 默认值：False（PyTorch 所有小版本，历史遗留）
  • 取值范围：True → (batch, seq, feature) 即 (N, S, E)；False → (seq, batch, feature) 即 (L, N, E)
  • 对结果的影响：不改变数学结果，只改变内存排布；与 nn.Embedding、nn.Linear、nn.TransformerEncoder（默认也 False 但可传）混搭时不一致会直接形状冲突报错或静默换轴；fast path 加速仅在该参数与 batch 维匹配时生效
  • 推荐设置：新代码统一显式传 batch_first=True，与 HuggingFace、numpy 数据流一致，避免 transpose(0,1) 满天飞

#### forward 高频参数 A：query / key / value

  • 含义：三个输入张量；自注意力时三者同源（形状一致），交叉注意力时 query 形状 (L,N,E)、key/value (S,N,E) 可不同长
  • 类型：Tensor
  • 默认值：必填
  • 取值范围：E 必须等于 embed_dim；mask 类参数形状随之联动
  • 对结果的影响：query 是 batch_first=False 时 (L,N,E)、True 时 (N,L,E)
  • 推荐设置：自回归解码缓存场景（nn.TransformerDecoder）传增量 query 长度 1

#### forward 高频参数 B：attn_mask

  • 含义：形状 (L, S) 或 (N·h, L, S) 的掩码，布尔 True/数值 -inf 表示禁止关注
  • 类型：Tensor（bool 或 float）
  • 默认值：None（无约束）
  • 取值范围：二维 (L, S) 广播到所有 batch/head；三维按 (N·num_heads, L, S) 精确控制
  • 对结果的影响：实现“因果掩码”（torch.triu(ones, diagonal=1).bool() 上三角为 True 遮未来/padding）；传 float 时直接加到打分上（连续松弛/位置偏置如 ALiBi 就这么用）；形状错误会静默广播出错误稀疏模式，务必断言形状
  • 推荐设置：生成 torch.nn.Transformer.generate_square_subsequent_mask(sz) 一步出因果掩码

#### forward 高频参数 C：key_padding_mask

  • 含义：形状 (N, S) 的掩码，True 表示该 batch 样本的这个 key 位置是 padding，应被忽略
  • 类型：Tensor (bool)
  • 默认值：None
  • 取值范围：S 必须等于 key 序列长度；注意与 attn_mask 的方向区别——这里遮"源序列侧"的无效 token
  • 对结果的影响：不传时 padding 位置参与 softmax 分权重，短文本被 pad token 噪声污染；与 attn_mask 组合时先相加再 softmax
  • 推荐设置：任何变长 batch 必传（如 tokens == pad_id）；与 FlashAttention fastpath 协同需为 float mask 或规范 dtype

#### forward 高频参数 D：need_weights

  • 含义：是否返回注意力权重矩阵
  • 类型：bool
  • 默认值：True
  • 取值范围：True / False
  • 对结果的影响：True 时返回 (N, L, S) 权重（average_attn_weights 控制是否对头平均），会禁用部分 fused fastpath；False 时 attn_output 更快更省显存，权重返回 None
  • 推荐设置：训练/生产推理一律 need_weights=False；仅可视化分析时 True

#### 配套模块参数：nn.TransformerEncoderLayer(d_model, nhead, dim_feedforward, dropout, activation, layer_norm_eps, batch_first, norm_first)

  • dim_feedforward：FFN 中间维度，默认 2048，典型经验 $ 4 \times d_{model} $（GPT-2 起亦流行 $ 8\sim 14 \times $ SwiGLU 变体）
  • activation：默认 'relu'，可传 'gelu'（BERT/GPT 手感更平滑，负区间非零输出）
  • layer_norm_eps：默认 1e-5，数值稳定项 $ \epsilon $，fp16/bf16 训练建议维持 1e-5 或调 1e-6 并观察 NaN
  • norm_first：默认 False（Post-LN 原论文式），True 为 Pre-LN（GPT-2/LLaMA 式，深模型梯度更稳，可省 warmup）

示例 1：从零手写多头注意力（帮助理解内部投影与掩码，可与官方实现对齐）：

import torch
import torch.nn as nn
import torch.nn.functional as F
import math


def scaled_dot_product_attention(q, k, v, mask=None):
    """单头缩放点积注意力。q: (b, h, L, d_k), k: (b, h, S, d_k), v: (b, h, S, d_v)"""
    d_k = q.size(-1)                                   # 每头维度，用于缩放
    scores = torch.matmul(q, k.transpose(-2, -1))      # Q·K^T → (b, h, L, S) 相似度打分
    scores = scores / math.sqrt(d_k)                   # 缩放：方差归一，防 softmax 饱和
    if mask is not None:                               # 掩码可选
        scores = scores.masked_fill(mask, float('-inf'))  # True 位置置 -inf → softmax 后权重为 0
    attn = F.softmax(scores, dim=-1)                   # 沿 key 维归一化，每行权重和为 1
    return torch.matmul(attn, v), attn                 # 输出 = 权重对 V 加权求和；(也返回权重供观察)


class MultiHeadAttention(nn.Module):
    """手写版多头注意力，接口语义对齐 nn.MultiheadAttention"""

    def __init__(self, embed_dim=512, num_heads=8, dropout=0.0, bias=True):
        super().__init__()
        assert embed_dim % num_heads == 0               # 硬约束：维度必须能整除头数
        self.embed_dim, self.h = embed_dim, num_heads   # 记录总维度与头数
        self.d_k = embed_dim // num_heads               # 每头维度 d_k = 512/8 = 64
        self.wq = nn.Linear(embed_dim, embed_dim, bias=bias)  # W^Q 投影
        self.wk = nn.Linear(embed_dim, embed_dim, bias=bias)  # W^K 投影
        self.wv = nn.Linear(embed_dim, embed_dim, bias=bias)  # W^V 投影
        self.wo = nn.Linear(embed_dim, embed_dim, bias=bias)  # W^O 输出融合投影
        self.dropout = nn.Dropout(dropout)              # 注意力权重 dropout

    def forward(self, x, mask=None):
        bsz, seqlen, _ = x.shape                        # x: (batch, seq, embed_dim)（batch_first 风格）
        q = self.wq(x).view(bsz, seqlen, self.h, self.d_k).transpose(1, 2)  # 投影后拆头：(b, h, L, d_k)
        k = self.wk(x).view(bsz, seqlen, self.h, self.d_k).transpose(1, 2)  # 同上
        v = self.wv(x).view(bsz, seqlen, self.h, self.d_k).transpose(1, 2)  # 同上
        out, attn = scaled_dot_product_attention(q, k, v, mask)               # 核心注意力
        out = self.dropout(out)                                           # 对输出做 dropout（等价权重点上）
        out = out.transpose(1, 2).contiguous().view(bsz, seqlen, self.embed_dim)  # 拼头还原 (b, L, embed)
        return self.wo(out), attn                                         # 最终线性融合; 返回输出与权重


torch.manual_seed(42)                                   # 固定随机种子保证可复现
demo = MultiHeadAttention(embed_dim=512, num_heads=8)   # 实例化 512 维 8 头
x = torch.randn(2, 10, 512)                             # batch=2、序列长 10、512 维
causal = torch.triu(torch.ones(10, 10), diagonal=1).bool()  # 上三角 True → 因果掩码（遮未来）
out, attn = demo(x, causal)                             # 前向
print(out.shape, attn.shape)                            # torch.Size([2, 10, 512]) torch.Size([2, 8, 10, 10])
assert torch.allclose(attn.sum(-1), torch.ones(2, 8, 10), atol=1e-5)  # 每行权重和为 1
assert torch.triu(attn, diagonal=1).abs().max().item() < 1e-6         # 未来位置权重全 0（掩码生效）

示例 2：官方 nn.MultiheadAttention 全参数用法（含两类掩码与 fastpath 注意点）：

import torch
import torch.nn as nn

torch.manual_seed(0)                                   # 可复现
mha = nn.MultiheadAttention(embed_dim=512, num_heads=8, dropout=0.1,   # 总维 512、8 头、权重 dropout
                            bias=True, add_bias_kv=False, add_zero_attn=False,  # 标准 Transformer 配置
                            kdim=None, vdim=None, batch_first=True)    # K/V 同维，(N, S, E) 布局
query = torch.randn(2, 6, 512)                         # (N=2, L=6, E=512)：解码端/目标序列
key = torch.randn(2, 10, 512)                          # (N=2, S=10, E=512)：源序列（可不同长度）
value = key                                            # 自定义场景中 value 常与 key 同源同维

causal_mask = nn.Transformer.generate_square_subsequent_mask(6)      # 下三角 0 / 上三角 -inf 的 (6,6) 矩阵
pad = torch.tensor([[False] * 7 + [True] * 3,                          # batch 内第 1 个样本源序列末 3 位 padding
                    [False] * 10])                                     # 第 2 个样本无 padding → key_padding_mask (2,10)

out, weights = mha(query, key, value,                  # 前向：注意 batch_first=True → (N, L, E)
                   attn_mask=causal_mask,              # attn_mask=(L,S)：约束 query i 只能看 key j ≤ i（因果）
                   key_padding_mask=pad,               # key_padding_mask=(N,S)：跳过源序列 padding 位置
                   need_weights=True,                  # 返回权重（生产推理应传 False 提速）
                   average_attn_weights=True)          # 权重对 8 头平均 → (2, 6, 10)；False 则 (2, 8, 6, 10)
print(out.shape, weights.shape)                        # torch.Size([2, 6, 512]) torch.Size([2, 6, 10])
assert torch.isnan(weights[0, :, 7:]).all()            # padding 位置（源 7~9）权重被 -inf → softmax 后为 nan/0

fast, _none = mha(query, key, value, need_weights=False)  # fastpath：不返回权重，内部可用 fused kernel
print(fast.shape, _none)                               # torch.Size([2, 6, 512]) None

示例 3：正弦位置编码 + 一层编码器组装（可直接跑通的最小 Transformer）：

import math
import torch
import torch.nn as nn


class SinPE(nn.Module):
    """原论文正弦位置编码：常量（不可学习），直接与词向量相加"""
    def __init__(self, d_model=512, max_len=5000):
        super().__init__()
        pe = torch.zeros(max_len, d_model)                        # 预分配 (max_len, d_model) 编码表
        pos = torch.arange(0, max_len).unsqueeze(1).float()       # 位置列向量 (max_len, 1)
        div = torch.exp(torch.arange(0, d_model, 2).float() * (-math.log(10000.0) / d_model))  # 频率 10000^(-2i/d)
        pe[:, 0::2] = torch.sin(pos * div)                        # 偶数维：sin(pos / 10000^(2i/d))
        pe[:, 1::2] = torch.cos(pos * div)                        # 奇数维：cos(...)
        self.register_buffer('pe', pe)                            # 注册为 buffer：随模型保存但不训练

    def forward(self, x):
        return x + self.pe[:x.size(1)].unsqueeze(0)               # 按序列长截取并广播相加（batch_first 布局）


torch.manual_seed(0)
pe = SinPE(512)                                                   # 编码器
enc_layer = nn.TransformerEncoderLayer(d_model=512, nhead=8,      # 注意力：512 维 8 头
                                       dim_feedforward=2048,      # FFN 中间维：4 × d_model 惯例
                                       dropout=0.1, activation='gelu',  # GELU 平滑激活（BERT 风格）
                                       layer_norm_eps=1e-5,       # LN 数值稳定项
                                       batch_first=True, norm_first=True)  # Pre-LN：深模型更稳
encoder = nn.TransformerEncoder(enc_layer, num_layers=6)          # 堆 6 层 = 原论文单塔规模
tok = torch.randint(0, 1000, (2, 12))                             # 两个长度 12 的 token id 序列
emb = nn.Embedding(1000, 512)(tok)                                # 查词表 → (2, 12, 512)
x = pe(emb)                                                       # 加位置编码
h = encoder(x)                                                    # 前向：6 层编码后仍为 (2, 12, 512)
proj = nn.Linear(512, 1000)                                       # 输出投影回词表大小
logits = proj(h)                                                  # (2, 12, 1000) 可接交叉熵训练语言模型
print(logits.shape)                                               # torch.Size([2, 12, 1000])
print('参数量: %.1fM' % (sum(p.numel() for p in encoder.parameters()) / 1e6))  # ≈ 20M（6 层）

复杂度分析

单层自注意力：设序列长 $ n $、模型维 $ d $（把 $ h \times d_k $ 合并记 $ d $）：

  • 打分 $ QK^\top $：两个 $ n \times d $ 与 $ d \times n $ 矩阵乘，$ O(n^2 d) $ 次乘加
  • softmax + 加权求和 $ \mathrm{Attn} \cdot V $：同样是 $ O(n^2 d) $
  • 合计时间 $ O(n^2 d) $；注意力矩阵显存 $ O(n^2) $；Q/K/V/输出激活 $ O(n d) $
  • 相比 RNN 单步 $ O(d^2) $、串行 $ n $ 步共 $ O(n d^2) $ 在数学上渐近更贵（$ n > d $ 时），换来的是完全并行（GPU 上实际训练快几个数量级）与 O(1) 最大路径长度

FFN：逐位置的 $ n $ 个独立 $ d \to 4d \to d $ 两层映射，时间 $ O(8 n d^2) $，与序列长度线性相关；当 $ n < 8d $ 时 FFN 反而是层内计算主体（GPT-3 类模型 FFN 常占约 2/3 FLOPs）

整体参数量（每层，标准配置 $ d_{ff}=4d $）：注意力四投影 $ 4d^2 $ + FFN $ 8d^2 $ + LN 微量 $ \approx 12d^2 $；配合本文姊妹篇 MLA（见同日推送）可将推理侧 KV Cache 从 $ O(n \cdot 2h d_k) $ 降为 $ O(n \cdot (d_c + d_R)) $

显存优化谱系：平方注意力矩阵 $ O(n^2) $ → FlashAttention 分块重算降为 $ O(n) $（激活）；KV Cache → MQA/GQA 共享、MLA 低秩压缩（DeepSeek-V3 每层每 token 576 元素）

应用场景

  • 大语言模型：GPT/Ollama/Llama/Qwen/DeepSeek 全部是 decoder-only 因果掩码变体；训练算力约 $ \text{FLOPs} \approx 6 \times \text{参数量} \times \text{token 数} $（Chinchilla 经验式）
  • 理解类任务：BERT/ERNIE 系 encoder-only，搜索排序、文本分类、命名实体识别的标准底座
  • 机器翻译/摘要：T5、NLLB 完整 encoder-decoder 结构，交叉注意力做条件生成
  • 视觉：ViT 把图像切成 16×16 patch 当 token，检测（DETR）、分割（SETR）、多模态（CLIP）通吃
