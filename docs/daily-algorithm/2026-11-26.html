网络流 Ford-Fulkerson

类别：图算法 | 难度：困难

算法简介

Ford-Fulkerson 方法是求解最大流问题的经典框架，1956 年由 L. R. Ford Jr. 与 D. R. Fulkerson 提出。它把网络抽象成一张有向图：每条边有容量 $ c(u,v) $，表示单位时间最多能通过的流量；源点 $ s $ 不断产出流量，汇点 $ t $ 不断消耗流量，中间节点满足流量守恒。算法的核心是残量网络（residual network）+ 增广路径（augmenting path）：只要残量网络中还存在一条从 $ s $ 到 $ t $、每条边剩余容量都为正的路径，就沿这条路径推入"瓶颈容量"大小的流量，直到再也找不到增广路径为止。

它最精妙的地方是反向边：当我们把流量从 $ u $ 推到 $ v $ 时，同时在残量网络中加入一条 $ v \to u $、容量等于当前流量的反向边。反向边代表"撤销"能力，使算法可以纠正早期贪心的错误选择，这正是它能保证全局最优的关键。Ford-Fulkerson 只规定了"反复找增广路径"这一框架，并未规定找路径的方法：用 DFS 找即为原始 FF，最坏复杂度 $ O(Ef) $（$ f $ 为最大流值）；用 BFS 找最短增广路即为 Edmonds-Karp，复杂度与流量无关，稳定为 $ O(VE^2) $。其正确性由最大流最小割定理保证：最大流的值恒等于最小割的容量。

原理示意图

数学公式

流网络的三条约束：

$$ 0 \le f(u,v) \le c(u,v), \qquad \sum_{v} f(v,u) = \sum_{v} f(u,v)\ \ (u \ne s,t) $$

变量解释：

  • $ f(u,v) $：边 $ (u,v) $ 上的当前流量，取值非负且不超过容量
  • $ c(u,v) $：边 $ (u,v) $ 的容量上限，刻画"管道粗细"
  • 第二式即流量守恒：除源汇点外，流入总量等于流出总量

残量容量与增广操作：

$$ c_f(u,v) = c(u,v) - f(u,v), \qquad \Delta f = \min_{(u,v)\in P} c_f(u,v) $$
$$ f(u,v) \leftarrow f(u,v) + \Delta f,\qquad f(v,u) \leftarrow f(v,u) - \Delta f $$

变量解释：

  • $ c_f(u,v) $：残量容量，即这条边还能再推多少流量
  • $ P $：当前找到的 $ s\to t $ 增广路径
  • $ \Delta f $：瓶颈容量，路径上最小的残量容量
  • 第二行同时更新正向流与反向流（反向边容量随之增加 $ \Delta f $），保证斜对称性 $ f(v,u)=-f(u,v) $

最大流最小割定理：

$$ \max_{f} |f| = \min_{(S,T)} \sum_{u\in S,\ v\in T} c(u,v) $$

变量解释：

  • $ |f| $：整张网络的流值，等于源点净流出量
  • $ (S,T) $：把顶点分成含 $ s $ 的集合 $ S $ 与含 $ t $ 的集合 $ T $ 的割
  • 右式为割容量：所有从 $ S $ 跨到 $ T $ 的边容量之和

核心要点

  • 反复在残量网络中找 $ s\to t $ 增广路径，推入瓶颈容量，直到不存在增广路径
  • 反向边是正确性核心，让算法能"反悔"，避免贪心陷于局部最优
  • 整数容量下每轮至少增流 1，FF 复杂度 $ O(Ef) $；BFS 版 Edmonds-Karp 为 $ O(VE^2) $
  • 无增广路径时当前流即最大流；此时从 $ s $ 在残量网络可达的点集构成最小割的 $ S $ 侧
  • 无理数容量下原始 FF 可能不终止，工程中一律使用 BFS/Dinic 等确定性策略

技术细节与参数详解

参数 1：capacity（容量矩阵 / 残量矩阵）
  • 含义：cap[u][v] 表示边 $ u\to v $ 的当前残量容量，初始化时为原始容量，算法过程中不断被扣减与回补
  • 类型：二维数组（整数或浮点）
  • 默认值：无边处为 0
  • 取值范围：非负；整数容量可保证整数最大流（整数流定理）
  • 对结果的影响：直接决定最大流上限与每轮瓶颈；浮点容量需注意精度，建议整数量化
  • 推荐设置：规模小于 $ 10^3 $ 顶点用矩阵；稀疏图改邻接表 + 边对象，只存有向边和其反向边
参数 2：source / sink（源点与汇点）
  • 含义：流量产出的起点 $ s $ 与流量汇入的终点 $ t $
  • 类型：顶点下标
  • 默认值：无，必须显式指定
  • 取值范围：$ [0, V-1] $，且 $ s \ne t $
  • 对结果的影响：换源汇等价于换一个割问题，最大流值随之改变
  • 推荐设置：多源多汇问题可增设超级源 $ S $、超级汇 $ T $，用无穷容量边连接
参数 3：path_strategy（增广路径查找策略）
  • 含义：决定框架内如何选增广路径，是 FF 与 EK 的唯一区别
  • 类型：枚举（DFS / BFS / 带标号的 Dinic 分层）
  • 默认值：工程实现默认 BFS（即 Edmonds-Karp）
  • 取值范围：dfs、bfs、dinic、capacity_scaling
  • 对结果的影响：DFS 最坏 $ O(Ef) $，在 $ f $ 很大时极慢（如容量 $ 10^9 $ 的"虫洞"图）；BFS 保证 $ O(VE^2) $；Dinic 为 $ O(V^2E) $，实际更快
  • 推荐设置：竞赛与生产一律 BFS 起步，规模大时换 Dinic 或 Push-Relabel
参数 4：INF（无穷大初始流量）
  • 含义：BFS 起点携带的"上游可用流量"初值
  • 类型：整数/浮点
  • 默认值：通常 1 << 30 或 float('inf')
  • 取值范围：必须大于任意可能的瓶颈容量
  • 对结果的影响：取小了会人为截断路径流量，导致结果偏小；取大了无副作用
  • 推荐设置：10**18 或 sum(所有边容量)，避免溢出时用 Python 的 float('inf')
参数 5：max_iter（最大迭代轮数，安全阀）
  • 含义：限制增广次数，防止浮点误差导致死循环
  • 类型：整数
  • 默认值：不限制
  • 取值范围：正整数，建议不小于 $ VE $
  • 对结果的影响：过小会提前终止得到次优流
  • 推荐设置：$ 10^6 $ 或 VE2，仅作兜底

代码示例

from collections import deque  # 引入双端队列，用于 BFS 找最短增广路


class MaxFlow:
    def __init__(self, n):                      # n 为顶点数量
        self.n = n                              # 保存顶点数
        self.graph = [[] for _ in range(n)]     # 邻接表：每个点存边在 edges 中的下标
        self.to = []                            # 边的终点数组
        self.cap = []                           # 边的残量容量数组

    def add_edge(self, u, v, c):                # 添加一条 u->v、容量为 c 的有向边
        self.graph[u].append(len(self.to))      # u 的出边记录正向边下标
        self.to.append(v)                       # 正向边终点为 v
        self.cap.append(c)                      # 正向边残量初始化为 c
        self.graph[v].append(len(self.to))      # v 的出边记录反向边下标
        self.to.append(u)                       # 反向边终点为 u
        self.cap.append(0)                      # 反向边初始残量为 0（只有推流后才可用）

    def bfs(self, s, t):                        # BFS 在残量网络中寻找最短增广路
        self.parent_edge = [-1] * self.n        # 记录每个点由哪条边到达，-1 表示未访问
        self.parent_edge[s] = -2                # 源点标记为已访问（-2 区别于普通边下标）
        q = deque([s])                          # 队列初始只含源点
        while q:                                # 队列非空则继续扩展
            u = q.popleft()                     # 取出队首顶点
            for eid in self.graph[u]:           # 遍历 u 的所有出边（含反向边）
                v = self.to[eid]                # 该边指向的顶点
                if self.parent_edge[v] == -1 and self.cap[eid] > 0:   # 未访问且残量为正
                    self.parent_edge[v] = eid   # 记录到达 v 的边
                    if v == t:                  # 一旦到达汇点即可提前结束（BFS 保证最短）
                        return True             # 找到一条增广路
                    q.append(v)                 # 否则把 v 入队继续扩展
        return False                            # 队列耗尽仍未到汇点，说明无增广路

    def max_flow(self, s, t):                   # 计算 s 到 t 的最大流
        flow = 0                                # 累计流量初始为 0
        INF = 10 ** 18                          # 瓶颈容量的无穷大初值
        while self.bfs(s, t):                   # 只要还能找到增广路就持续增广
            delta = INF                         # 本轮瓶颈容量初始为无穷
            v = t                               # 从汇点倒推路径
            while v != s:                       # 沿 parent_edge 回溯到源点
                eid = self.parent_edge[v]       # 取出到达 v 的边
                delta = min(delta, self.cap[eid])  # 瓶颈取路径上最小残量
                v = self.to[eid ^ 1]            # 边下标异或 1 即其反向边，反向边的终点就是前驱
            v = t                               # 再次从汇点出发更新残量
            while v != s:                       # 逐边扣减正向、回补反向
                eid = self.parent_edge[v]       # 当前边
                self.cap[eid] -= delta          # 正向边残量减少 delta
                self.cap[eid ^ 1] += delta      # 反向边残量增加 delta（实现"可撤销"）
                v = self.to[eid ^ 1]            # 移动到前驱顶点
            flow += delta                       # 网络总流量累加本轮增广量
        return flow                             # 无增广路时返回最大流


if __name__ == "__main__":
    mf = MaxFlow(6)                             # 建 6 个顶点：s,A,D,B,C,t
    mf.add_edge(0, 1, 7)                        # s->A 容量 7
    mf.add_edge(0, 2, 4)                        # s->D 容量 4
    mf.add_edge(1, 3, 5)                        # A->B 容量 5
    mf.add_edge(2, 4, 2)                        # D->C 容量 2
    mf.add_edge(3, 5, 8)                        # B->t 容量 8
    mf.add_edge(4, 5, 5)                        # C->t 容量 5
    mf.add_edge(4, 3, 3)                        # C->B 容量 3（跨层边，制造反向调整需求）
    print(mf.max_flow(0, 5))                    # 输出最大流

复杂度分析

  • 单次 BFS 遍历所有边：$ O(E) $，每条正向边与其反向边各访问常数次
  • 增广轮数（Edmonds-Karp）：每条边最多成为瓶颈边 $ O(V) $ 次（每次饱和后它到 $ s $ 的距离严格增大且不超过 $ V $），共 $ E $ 条边，故至多 $ O(VE) $ 轮
  • 总时间复杂度：$ O(VE)\times O(E)=O(VE^2) $；原始 DFS 版为 $ O(Ef) $，$ f $ 为最大流值，容量巨大时可能退化为指数级轮数
  • 空间复杂度：邻接表存 $ 2E $ 条边为 $ O(V+E) $；若用容量矩阵则为 $ O(V^2) $
  • 对比：Dinic 分层 + 当前弧优化可达 $ O(V^2E) $，单位容量网络 $ O(E\sqrt{E}) $；Push-Relabel 为 $ O(V^3) $ 或 $ O(V^2\sqrt{E}) $

应用场景

  • 运输与物流：路网最大通行量、供应链吞吐上限、带宽分配
  • 二分图最大匹配：Kuhn 算法 / 匈牙利算法本质是单位容量最大流
  • 图像分割：Graph Cut / GrabCut 把像素标号问题转成最小割
  • 项目选择、任务分配、调度排班中的"最多能同时满足多少需求"类问题
  • 网络可靠性：最小割直接给出切断多少条边可使网络不连通

梯度累积

类别：训练技巧 | 难度：入门

算法简介

梯度累积（Gradient Accumulation）是一种用小显存模拟大批量（large batch）训练的工程技巧。深度模型的显存占用主要来自激活值与梯度，二者都与单次前向的样本数（micro-batch）成正比。当目标 batch size 为 256 而显卡只能放下 16 条样本时，梯度累积把 256 拆成 16 个 micro-batch，逐个前向与反向，但不立即更新参数，而是把 16 次算出的梯度在参数缓冲区中累加；累加满 16 次后才执行一次 optimizer.step() 并清零梯度。这样每次参数更新所使用的样本总量等效于 256，显存却只有 16 的峰值。

它的数学本质是期望意义下的梯度等价：若损失按样本均值定义，则"先分别求均值再平均"等于"整体求均值"。因此累积 $ K $ 步得到的梯度与真·大 batch 完全一致（浮点误差除外）。需要注意三点：一是损失必须除以累积步数（或用 loss/K 再 backward），否则梯度会被放大 $ K $ 倍；二是 BatchNorm 的统计量按 micro-batch 计算，与真大 batch 不等价，需换 GroupNorm/LayerNorm；三是学习率通常要按有效 batch 放大后的规则重新标定（线性缩放或平方根缩放），并配合梯度裁剪防止偶发尖峰。

原理示意图

数学公式

等效批量与更新公式：

$$ B_{\text{eff}} = m \times K, \qquad \theta_{t+1} = \theta_t - \eta \cdot \frac{1}{K}\sum_{k=1}^{K} g_k,\quad g_k = \frac{1}{m}\sum_{i\in B_k}\nabla_\theta \ell_i $$

变量解释：

  • $ m $：单个 micro-batch 的样本数，决定显存峰值
  • $ K $：累积步数 gradient_accumulation_steps
  • $ B_{\text{eff}} $：有效 batch size，等于真正大 batch 的样本数
  • $ g_k $：第 $ k $ 个 micro-batch 的平均梯度
  • $ \eta $：学习率；$ \theta $：模型参数

梯度裁剪（按全局 L2 范数）：

$$ \|g\|_2 = \sqrt{\sum_{p}\sum_{i} g_{p,i}^2},\qquad g \leftarrow g \cdot \min\left(1, \frac{\text{max\_norm}}{\|g\|_2 + \epsilon}\right) $$

变量解释：

  • $ g_{p,i} $：参数 $ p $ 的第 $ i $ 个梯度分量
  • $ \|g\|_2 $：所有参数梯度拼成一个长向量后的 L2 范数
  • $ \text{max\_norm} $：允许的最大范数阈值
  • $ \epsilon $：防止除零的小常数（PyTorch 内部为 $ 10^{-6} $）
  • 缩放系数 $ \min(1,\cdot) $：只有超阈值时才等比例缩小，不改变梯度方向

学习率缩放经验式：

$$ \eta_{\text{new}} = \eta_{\text{base}} \times \frac{B_{\text{eff}}}{B_{\text{base}}}\quad\text{（线性）}\qquad \eta_{\text{new}} = \eta_{\text{base}} \times \sqrt{\frac{B_{\text{eff}}}{B_{\text{base}}}}\quad\text{（平方根）} $$

变量解释：$ B_{\text{base}} $ 为原学习率对应的基准批量；线性规则适合小到中等 batch，平方根规则更稳健，适合超大 batch 与自适应优化器。

核心要点

  • 用时间换显存：多个 micro-batch 的梯度累加，等价于一次大 batch 更新
  • loss 必须除以 $ K $（或按样本数加权），否则梯度尺度错误
  • optimizer.step() 每 $ K $ 步一次，zero_grad() 只在其后调用，位置错会白训
  • BatchNorm 与真大 batch 不等价；Dropout 的随机性也会带来细微差异
  • 梯度裁剪应在 step() 之前、累积完成之后执行一次，而非每个 micro-batch 都裁
  • 混合精度下配合 GradScaler，scaler.step() 与 scaler.update() 同样每 $ K $ 步一次

技术细节与参数详解

参数 1：gradient_accumulation_steps（累积步数 $ K $）
  • 含义：多少次 micro-batch 反向后才更新一次参数
  • 类型：整数
  • 默认值：1（即不累积）
  • 取值范围：$ [1, \text{总步数}] $，常用 2/4/8/16/32
  • 对结果的影响：$ K $ 越大有效 batch 越大、更新越平滑、噪声越小；但 $ K $ 过大会减少参数更新次数，收敛变慢，且小数据集上可能欠拟合
  • 推荐设置：令 $ m\times K $ 接近论文/经验最优 batch（如 256/512/1024）；显存紧张时优先减小 $ m $ 而非无限增大 $ K $
参数 2：micro_batch_size（$ m $）
  • 含义：单次前向实际喂入的样本数
  • 类型：整数
  • 默认值：由显存实测决定
  • 取值范围：≥1；受显存、序列长度、模型参数量约束
  • 对结果的影响：决定显存峰值与吞吐；过小会使单步计算效率下降（GPU 利用率低）
  • 推荐设置：取显存占用约 80%–90% 的最大可行值，保持 $ m\times K $ 不变
参数 3：max_norm（裁剪阈值）
  • 含义：clip_grad_norm_ 允许的梯度全局范数上限
  • 类型：浮点
  • 默认值：无（必须显式给出），LLM 常用 1.0
  • 取值范围：$ (0, +\infty) $，常见 0.5 / 1.0 / 5.0
  • 对结果的影响：过小会压制有效梯度导致收敛慢甚至欠拟合；过大则失去防爆炸作用
  • 推荐设置：Transformer 类 1.0；CNN 可 5.0–10.0；先用不裁剪跑几百步统计梯度范数分布再定阈值
参数 4：norm_type（范数类型）
  • 含义：计算梯度范数所用的 $ p $ 范数阶数
  • 类型：浮点
  • 默认值：2.0
  • 取值范围：任意正数；inf 表示最大绝对值范数
  • 对结果的影响：$ p=2 $ 是欧氏长度，最常用；$ p=\infty $ 只压最大分量，更保守
  • 推荐设置：保持 2.0，与主流实现和论文对齐
参数 5：error_if_nonfinite
  • 含义：梯度出现 NaN/Inf 时是否直接抛错而非静默跳过
  • 类型：布尔
  • 默认值：False
  • 取值范围：True / False
  • 对结果的影响：True 可尽早暴露数值不稳定（如 loss 爆炸），便于定位；False 会静默把参数更新变成 NaN
  • 推荐设置：调试阶段 True，长跑训练可 False 并配合监控告警
参数 6：foreach（批量实现开关）
  • 含义：是否用 foreach 的批量张量运算加速裁剪
  • 类型：布尔或 None
  • 默认值：None（由后端自动选择）
  • 取值范围：True / False / None
  • 对结果的影响：通常更快，个别设备/版本存在数值差异或兼容问题
  • 推荐设置：保持 None，遇到性能或精度异常再显式设 False
参数 7：set_to_none（zero_grad 的模式）
  • 含义：清零梯度时是把梯度置为 None 还是填 0
  • 类型：布尔
  • 默认值：True（新版 PyTorch）
  • 取值范围：True / False
  • 对结果的影响：置 None 可省显存并略提速；若代码里手动读写 .grad 需注意空值判断
  • 推荐设置：True；依赖 .grad 累加的自定义逻辑改为 False

代码示例

import torch                                   # 引入 PyTorch 主库
from torch.nn.utils import clip_grad_norm_      # 引入按范数裁剪梯度的工具函数

K = 8                                           # 梯度累积步数，等效 batch 放大 8 倍
micro_bs = 16                                   # 单次前向的样本数（受显存限制）
base_lr = 1e-4                                  # 基准学习率（对应 micro_bs 的有效批量）
lr = base_lr * (K ** 0.5)                       # 按平方根规则随有效批量放大学习率
optimizer = torch.optim.AdamW(model.parameters(), lr=lr)  # 构造优化器
scaler = torch.cuda.amp.GradScaler()            # 混合精度梯度缩放器，防 fp16 下溢

model.train()                                   # 切换到训练模式（启用 Dropout/BN 训练行为）
global_step = 0                                 # 记录已完成的参数更新次数
for epoch in range(num_epochs):                 # 外层按 epoch 迭代
    for step, batch in enumerate(loader):       # 内层按 micro-batch 迭代
        with torch.cuda.amp.autocast():         # 前向在 fp16/bf16 下计算，省显存提速
            loss = model(**batch).loss / K      # 关键：损失除以 K，使累加后梯度尺度正确
        scaler.scale(loss).backward()           # 反向传播；梯度自动累加到各参数的 .grad
        if (step + 1) % K == 0:                 # 攒满 K 个 micro-batch 才更新参数
            scaler.unscale_(optimizer)          # 反缩放梯度，保证裁剪看到真实尺度
            clip_grad_norm_(model.parameters(), max_norm=1.0)  # 全局 L2 范数裁剪，防爆炸
            scaler.step(optimizer)              # 执行一次参数更新（内部跳过 inf/nan）
            scaler.update()                     # 调整下一轮的缩放因子
            optimizer.zero_grad(set_to_none=True)  # 清空梯度缓冲，准备下一轮累积
            global_step += 1                    # 更新计数加一

复杂度分析

  • 时间：每个 micro-batch 的前向/反向计算量与不累积时相同，总 FLOPs 不变；参数更新（step）次数减少为 $ 1/K $，故优化器开销（Adam 的状态更新）降至原来的 $ 1/K $，整体往往略快
  • 显存：激活值与梯度峰值只与 $ m $ 相关，约 $ O(m\cdot d\cdot L) $，与 $ K $ 无关；这是与"直接大 batch"最本质的差别（后者激活显存正比于 $ Km $）
  • 通信（分布式）：梯度 all-reduce 频率降为 $ 1/K $，DDP 下可显著降低通信开销；但需保证所有 rank 的累积步数一致，否则会卡在集合通信
  • 收敛性：梯度无偏但方差更小；等效批量增大后需配合学习率缩放与 warmup，否则前期易震荡

应用场景

  • 单卡/小显存复现大 batch 论文结果（视觉、检测、分割）
  • 大语言模型预训练：micro-batch + 梯度累积 + ZeRO/FSDP 组合成超大全局批量
  • 长序列/高分辨率输入导致单样本就吃满显存，只能 $ m=1 $ 时靠 $ K $ 凑批量
  • 多任务训练中隔离不同任务的梯度累积节奏
  • 联邦学习/边缘设备上以极小批量逼近中心化训练效果

线性注意力 Transformer

类别：前沿架构 | 难度：困难

算法简介

标准 Transformer 的自注意力计算 $ \mathrm{softmax}(QK^\top)V $ 需要显式构造 $ N\times N $ 的注意力矩阵，时间复杂度与显存均为 $ O(N^2) $，序列越长越昂贵。线性注意力（Linear Attention） 的核心洞察是：softmax 里的指数核 $ \exp(q^\top k) $ 无法分解成"只关于 $ q $"与"只关于 $ k $"两个函数的乘积，所以矩阵乘法结合律用不上；但只要换成一个可分解的核 $ \mathrm{sim}(q,k)=\phi(q)^\top\phi(k) $，注意力就能重写为

$$ \frac{\phi(Q)\big(\phi(K)^\top V\big)}{\phi(Q)\big(\phi(K)^\top \mathbf{1}\big)} $$

先算 $ \phi(K)^\top V $（$ d\times d $ 矩阵）再乘 $ \phi(Q) $，复杂度立刻从 $ O(N^2d) $ 降到 $ O(Nd^2) $——当 $ N \gg d $ 时就是线性。Katharopoulos 等人 2020 年的 ICML 论文《Transformers are RNNs》系统提出这一形式，并指出它可写成递归（RNN）形式：维护状态 $ S_t = S_{t-1} + \phi(k_t)v_t^\top $、$ z_t = z_{t-1} + \phi(k_t) $，则 $ o_t = \phi(q_t)^\top S_t / (\phi(q_t)^\top z_t) $。这让自回归解码只需 $ O(1) $ 状态与每步 $ O(d^2) $ 计算，长序列推理可比标准注意力快数千倍。

代价是表达力损失：softmax 的尖锐选择性与"聚焦"能力被平滑核削弱，长程检索与精确复制能力下降，训练稳定性也更敏感。因此工程上衍生出两大流派：一派用随机特征近似 softmax（Performer 的 FAVOR+、RFA），保留 softmax 语义；另一派用 ELU+1、ReLU、1+swish 等正性特征映射做"真线性"注意力（Linear Transformer、cosFormer、FLASH），主打速度。近年 Mamba/线性注意力混合架构又把这一思路推向大模型主流。

原理示意图

数学公式

核化注意力定义：

$$ \mathrm{Attn}(Q,K,V)_i = \frac{\sum_{j=1}^{N}\phi(q_i)^\top\phi(k_j)\,v_j}{\sum_{j=1}^{N}\phi(q_i)^\top\phi(k_j)} = \frac{\phi(q_i)^\top\sum_{j}\phi(k_j)v_j^\top}{\phi(q_i)^\top\sum_{j}\phi(k_j)} $$

变量解释：

  • $ Q\in\mathbb{R}^{N\times d_k} $、$ K\in\mathbb{R}^{N\times d_k} $、$ V\in\mathbb{R}^{N\times d_v} $：查询、键、值矩阵
  • $ q_i,k_j $：第 $ i $ 个查询与第 $ j $ 个键向量
  • $ \phi(\cdot) $：逐元素非负特征映射，ELU+1 时为 $ \phi(x)=\mathrm{ELU}(x)+1 $
  • 分子分母都先对 $ j $ 求和（得到 $ d_k\times d_v $ 矩阵与 $ d_k $ 向量），再与 $ \phi(q_i) $ 相乘

矩阵形式与复杂度：

$$ O = \frac{\phi(Q)\big(\phi(K)^\top V\big)}{\phi(Q)\big(\phi(K)^\top\mathbf{1}\big)},\qquad \text{FLOPs}=O(Nd_kd_v),\ \text{显存}=O(Nd + d_kd_v) $$

变量解释：$ \mathbf{1} $ 为全 1 列向量，用于归一化分母；对比 softmax 注意力的 $ O(N^2d) $，当 $ N\gg d $ 时优势显著。

因果（causal）形式的递归：

$$ S_t = S_{t-1} + \phi(k_t)v_t^\top,\qquad z_t = z_{t-1} + \phi(k_t),\qquad o_t = \frac{\phi(q_t)^\top S_t}{\phi(q_t)^\top z_t + \epsilon} $$

变量解释：

  • $ S_t\in\mathbb{R}^{d_k\times d_v} $：截至第 $ t $ 步的"键值外积和"，即压缩后的历史记忆
  • $ z_t\in\mathbb{R}^{d_k} $：归一化累计项
  • $ \epsilon $：防止分母为零的小常数（如 $ 10^{-6} $）
  • 训练时可用分块并行（chunk）形式，兼顾并行度与 $ O(N) $ 复杂度

Performer 的 softmax 近似（FAVOR+）：

$$ \exp(q^\top k)\approx \mathbb{E}_{\omega}\left[\exp(\omega^\top q - \tfrac{\|q\|^2}{2})\cdot \exp(\omega^\top k - \tfrac{\|k\|^2}{2})\right] $$

变量解释：$ \omega $ 为从各向同性高斯（FAVOR+ 用正交随机特征）采样的随机向量，$ m $ 个样本给出无偏估计，误差随 $ m $ 增大而下降；$ \frac{\|q\|^2}{2} $ 项保证数值稳定。

核心要点

  • 把不可分解的 softmax 核换成可分解核 $ \phi(q)^\top\phi(k) $，再用结合律重排计算顺序
  • 训练复杂度 $ O(Nd^2) $，推理递归形式每步 $ O(d^2) $、状态恒定，适合超长序列与流式生成
  • 特征映射必须非负以保证分母为正，ELU+1 是最常用的默认选择
  • 因果掩码通过累加前缀状态实现，天然支持自回归，无需 $ N\times N $ 掩码矩阵
  • 表达力弱于 softmax：长程精确检索、复制、in-context 学习较弱，混合局部注意力是主流折中
  • Performer/RFA 用随机特征近似 softmax，是"保留语义的线性化"；Linear Transformer 是"换核的线性化"

技术细节与参数详解

参数 1：embed_dim（$ d_{\text{model}} $）
  • 含义：模型隐藏维度，也是注意力输入特征维度
  • 类型：整数
  • 默认值：无，常用 512/768/1024
  • 取值范围：需被 num_heads 整除
  • 对结果的影响：决定状态矩阵 $ S $ 的大小（$ d_k\times d_v $）与表达容量；越大越强但显存与计算按 $ d^2 $ 增长
  • 推荐设置：小模型 256–512，中型 768，大模型 2048+；线性注意力的 $ d^2 $ 状态在超大 $ d $ 时反而成为瓶颈
参数 2：num_heads（$ h $）
  • 含义：多头注意力的头数
  • 类型：整数
  • 默认值：8
  • 取值范围：正整数，且 embed_dim % num_heads == 0
  • 对结果的影响：头数多可捕获多种子空间模式，但每头维度 $ d_k=d/h $ 变小，状态矩阵总量 $ h\cdot d_k d_v $ 不变；头过多会削弱单头表达
  • 推荐设置：与标准 Transformer 对齐（8/12/16）；线性注意力中适度减少头数、增大每头维度往往更好
参数 3：feature_map（$ \phi $）
  • 含义：把 $ q,k $ 映射到非负特征空间的函数
  • 类型：字符串/可调用对象
  • 默认值：elu + 1
  • 取值范围：elu+1、relu、1+swish、softmax（近似）、rfa（随机特征）
  • 对结果的影响：决定表达力与数值稳定性；ReLU 会产生大量零特征（信息丢失），ELU+1 平滑且恒正，softmax 近似最贴近原语义但更慢
  • 推荐设置：默认 elu+1；追求质量用 Performer 的 FAVOR+；追求速度用 1+swish
参数 4：eps（分母稳定项 $ \epsilon $）
  • 含义：归一化分母的平滑常数
  • 类型：浮点
  • 默认值：1e-6
  • 取值范围：$ [10^{-9}, 10^{-3}] $
  • 对结果的影响：过大使输出偏向均匀平均、削弱选择性；过小在长序列初期（分母接近 0）易数值爆炸
  • 推荐设置：1e-6 起步；fp16 训练建议 1e-4 并配合 bf16
参数 5：causal（因果掩码开关）
  • 含义：是否只允许关注当前位置及之前的位置
  • 类型：布尔
  • 默认值：False（双向）/ True（解码器）
  • 取值范围：True / False
  • 对结果的影响：True 时用前缀和/递归实现，$ O(N) $；False 时可全序列并行，但用于生成会信息泄漏
  • 推荐设置：语言模型/自回归生成必须 True；视觉/编码器可 False
参数 6：dropout（注意力输出丢弃率）
  • 含义：对注意力输出做 Dropout 的概率
  • 类型：浮点
  • 默认值：0.0
  • 取值范围：$ [0, 1) $，常用 0–0.1
  • 对结果的影响：抑制过拟合；线性注意力本身正则性较弱，过大 dropout 会拖慢收敛
  • 推荐设置：小数据 0.1，大数据 0.0
参数 7：chunk_size（分块大小，训练用）
  • 含义：因果线性注意力训练时把序列切成多块，块内并行、块间传递状态
  • 类型：整数
  • 默认值：无（全序列并行）
  • 取值范围：64–2048，需能整除或补齐序列长度
  • 对结果的影响：块越大并行度越高但中间激活越多；块越小显存越省但循环开销增加
  • 推荐设置：128/256，兼顾显存与吞吐；超长序列（>32k）必用分块
参数 8：bias（线性层偏置）
  • 含义：Q/K/V/O 投影层是否带偏置
  • 类型：布尔
  • 默认值：True（PyTorch nn.Linear 默认）
  • 取值范围：True / False
  • 对结果的影响：现代 LLM 多去掉偏置以省参数、改善数值稳定性；线性注意力对偏置不敏感
  • 推荐设置：大模型 False，小模型可保留 True

代码示例

import torch                                   # 引入 PyTorch
import torch.nn as nn                          # 引入神经网络模块
import torch.nn.functional as F                # 引入函数式接口


def elu_feature_map(x):                        # 定义非负特征映射 φ(x) = ELU(x) + 1
    return F.elu(x) + 1.0                      # ELU 下界为 -1，加 1 后恒非负，保证分母为正


class LinearAttention(nn.Module):              # 线性注意力模块
    def __init__(self, embed_dim, num_heads, dropout=0.0, eps=1e-6, bias=False):
        super().__init__()                     # 初始化父类
        assert embed_dim % num_heads == 0, "embed_dim 必须能被 num_heads 整除"
        self.h = num_heads                     # 头数
        self.d = embed_dim // num_heads        # 每个头的维度 d_k = d_v = d
        self.eps = eps                         # 分母稳定常数
        self.qkv = nn.Linear(embed_dim, embed_dim * 3, bias=bias)  # 一次投影出 Q/K/V
        self.out = nn.Linear(embed_dim, embed_dim, bias=bias)      # 输出投影
        self.drop = nn.Dropout(dropout)        # 输出 Dropout

    def forward(self, x, causal=True):         # x: (B, N, C)
        B, N, C = x.shape                      # 取出批大小、序列长度、通道数
        qkv = self.qkv(x)                      # (B, N, 3C) 一次算完 QKV，减少 kernel 启动
        q, k, v = qkv.chunk(3, dim=-1)         # 沿最后一维切分成三份
        q = q.view(B, N, self.h, self.d).transpose(1, 2)   # (B, h, N, d) 多头重排
        k = k.view(B, N, self.h, self.d).transpose(1, 2)   # 同上，处理 K
        v = v.view(B, N, self.h, self.d).transpose(1, 2)   # 同上，处理 V
        q, k = elu_feature_map(q), elu_feature_map(k)      # 特征映射，必须非负

        if causal:                             # 因果模式：用前缀和实现逐步注意力
            kv_cum = torch.cumsum(torch.einsum("bhnd,bhne->bhnde", k, v), dim=2)  # 前缀状态 S_t
            k_cum = torch.cumsum(k, dim=2)     # (B,h,N,d) 前缀键和，供分母使用
            num = torch.einsum("bhnd,bhnde->bhne", q, kv_cum)      # 分子 φ(q_t)^T S_t
            den = torch.einsum("bhnd,bhnd->bhn", q, k_cum).unsqueeze(-1) + self.eps  # 分母
            out = num / den                    # 归一化得到输出
            del kv_cum, k_cum                  # 及时释放大张量，降低显存峰值
        else:                                  # 双向模式：先聚合全局 KV 再乘 Q
            kv = torch.einsum("bhnd,bhne->bhde", k, v)          # (B,h,d,d) 全局状态
            k_sum = k.sum(dim=2)               # (B,h,d) 全局键和
            num = torch.einsum("bhnd,bhde->bhne", q, kv)        # 分子
            den = torch.einsum("bhnd,bhd->bhn", q, k_sum).unsqueeze(-1) + self.eps  # 分母
            out = num / den                    # 归一化

        out = out.transpose(1, 2).reshape(B, N, C)   # 合并多头回 (B, N, C)
        return self.drop(self.out(out))         # 输出投影 + Dropout


if __name__ == "__main__":
    x = torch.randn(2, 1024, 256)              # 构造 batch=2、长度 1024、维度 256 的输入
    attn = LinearAttention(256, 8, dropout=0.0)  # 8 头，每头 32 维
    y = attn(x, causal=True)                   # 因果模式前向
    print(y.shape)                             # 期望输出 (2, 1024, 256)

复杂度分析

  • 标准 softmax 注意力：$ QK^\top $ 为 $ O(N^2d) $，乘 $ V $ 为 $ O(N^2d) $，显存需保存 $ N\times N $ 矩阵，合计时间 $ O(N^2d) $、空间 $ O(N^2+Nd) $
  • 线性注意力（双向）：$ \phi(K)^\top V $ 为 $ O(Nd^2) $，$ \phi(Q) $ 乘状态为 $ O(Nd^2) $，合计 $ O(Nd^2) $；空间 $ O(Nd+d^2) $
  • 因果递归/前缀和：训练分块后仍为 $ O(Nd^2) $，块内矩阵运算提升 GPU 利用率；推理每步 $ O(d^2) $、状态 $ O(d^2) $，与序列长度无关
  • 当 $ N > d $ 时线性占优；$ N \ll d $（短序列）时 softmax 注意力反而更快，因为常数因子更小
  • Performer 近似需 $ m $ 个随机特征，复杂度 $ O(Nmd) $，$ m $ 通常取 $ d\log d $ 量级，精度换速度

应用场景

  • 超长文本/文档级建模（8k–1M token），标准注意力显存不可承受
  • 流式语音、实时字幕、长视频理解等需要恒定状态推理的场景
  • 边缘设备/端侧推理，用 RNN 形式把 KV Cache 压缩成固定大小状态
  • 与滑动窗口局部注意力混合（如 Hybrid Linear Attention），兼顾局部精细与全局效率
  • 强化学习长轨迹、基因组序列、时间序列等超长依赖任务
