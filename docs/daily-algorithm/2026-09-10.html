AVL 树

类别：数据结构 | 难度：中等

算法简介

AVL 树是由前苏联数学家 G. M. Adelson-Velsky 和 Evgenii Landis 于 1962 年发明的自平衡二叉搜索树（Self-Balancing Binary Search Tree），也是历史上第一个被发明的自平衡数据结构。它的核心思想是：在二叉搜索树的基础上，要求每个节点的左右子树高度差（平衡因子）绝对值不超过 1。当插入或删除操作破坏了这一平衡条件时，通过四种旋转操作（LL、RR、LR、RL）将树重新调整为平衡状态。

普通二叉搜索树在遇到有序数据插入时会退化为链表，导致查找、插入、删除的时间复杂度从 $ O(\log n) $ 恶化为 $ O(n) $。AVL 树通过严格的高度平衡约束，保证树的高度始终为 $ O(\log n) $，从而使所有基本操作的时间复杂度稳定在 $ O(\log n) $。AVL 树适用于读多写少的场景（如数据库索引、内存中的有序映射），因为它的平衡条件比红黑树更严格，查找效率更高，但插入删除时可能需要更多旋转操作。

原理示意图

数学公式

1. 平衡因子（Balance Factor）

$$ BF(node) = height(node.left) - height(node.right) $$

变量解释：

  • $ BF(node) $：节点 $ node $ 的平衡因子
  • $ height(node.left) $：节点 $ node $ 左子树的高度
  • $ height(node.right) $：节点 $ node $ 右子树的高度
  • 空子树高度定义为 $ 0 $，叶子节点高度定义为 $ 1 $

平衡条件：对所有节点 $ node $，必须满足 $ |BF(node)| \leq 1 $，即 $ BF(node) \in \{-1, 0, 1\} $。

2. AVL 树高度上界

$$ h \leq 1.44 \log_2(n+2) - 0.328 $$

变量解释：

  • $ h $：AVL 树的高度
  • $ n $：树中节点总数
  • 这个公式说明 AVL 树的高度在最坏情况下仍为 $ O(\log n) $

推导过程：设 $ N_h $ 为高度为 $ h $ 的 AVL 树最少节点数，则 $ N_h = N_{h-1} + N_{h-2} + 1 $，$ N_0 = 0, N_1 = 1 $。解此递推关系可得上述上界。

3. 旋转操作时间

$$ T_{rot} = O(1) $$

单次旋转只需修改常数个指针，操作时间为常数级。

核心要点

  • AVL 树是严格高度平衡的 BST，任意节点平衡因子绝对值不超过 1
  • 四种失衡情况：LL（左左）、RR（右右）、LR（左右）、RL（右左），分别对应不同旋转策略
  • LL 和 RR 只需单旋（右旋/左旋），LR 和 RL 需要双旋（先子树旋转再根旋转）
  • 所有基本操作（查找、插入、删除）时间复杂度均为 $ O(\log n) $
  • 插入最多需要 1 次旋转即可恢复平衡；删除最多需要 $ O(\log n) $ 次旋转
  • 相比红黑树，AVL 树平衡更严格，查找更快但插入/删除开销更大

技术细节与参数详解

#### 节点结构参数

#### 参数1：value（节点值）

  • 含义：存储在节点中的数据值，用于 BST 排序
  • 类型：可比较类型（int、float、str 等）
  • 默认值：无（构造时必须指定）
  • 取值范围：任意可比较值
  • 对结果的影响：值的排列顺序决定树的结构
  • 推荐设置：确保类型一致，避免混用不同类型

#### 参数2：left（左子节点指针）

  • 含义：指向当前节点的左子树的根节点
  • 类型：AVLNode 或 None
  • 默认值：None
  • 取值范围：None 或 AVLNode 实例
  • 对结果的影响：左子树所有节点值小于当前节点值
  • 推荐设置：插入时自动维护，无需手动设置

#### 参数3：right（右子节点指针）

  • 含义：指向当前节点的右子树的根节点
  • 类型：AVLNode 或 None
  • 默认值：None
  • 取值范围：None 或 AVLNode 实例
  • 对结果的影响：右子树所有节点值大于当前节点值
  • 推荐设置：插入时自动维护，无需手动设置

#### 参数4：height（节点高度）

  • 含义：以该节点为根的子树高度，用于计算平衡因子
  • 类型：int
  • 默认值：1（叶子节点）
  • 取值范围：$ \geq 1 $，空节点为 0
  • 对结果的影响：高度值直接影响平衡因子的计算，错误的高度会导致误判失衡
  • 推荐设置：每次插入/删除后从底向上更新

#### 旋转操作详解

#### 左旋（rotate_left）

  • 含义：将当前节点的右子节点提升为新根，当前节点变为新根的左子节点
  • 触发条件：RR 型失衡，即 $ BF(node) \leq -2 $ 且 $ BF(node.right) \leq 0 $
  • 操作步骤：

1. 保存当前节点的右子节点 new_root = node.right

2. 将 new_root 的左子树挂到当前节点的右子树 node.right = new_root.left

3. 将当前节点设为 new_root 的左子节点 new_root.left = node

4. 更新 node 和 new_root 的高度

  • 时间复杂度：$ O(1) $

#### 右旋（rotate_right）

  • 含义：将当前节点的左子节点提升为新根，当前节点变为新根的右子节点
  • 触发条件：LL 型失衡，即 $ BF(node) \geq 2 $ 且 $ BF(node.left) \geq 0 $
  • 操作步骤：

1. 保存当前节点的左子节点 new_root = node.left

2. 将 new_root 的右子树挂到当前节点的左子树 node.left = new_root.right

3. 将当前节点设为 new_root 的右子节点 new_root.right = node

4. 更新 node 和 new_root 的高度

  • 时间复杂度：$ O(1) $

#### 左右旋（LR 旋转）

  • 含义：先对左子节点左旋，再对当前节点右旋
  • 触发条件：LR 型失衡，即 $ BF(node) \geq 2 $ 且 $ BF(node.left) < 0 $
  • 操作步骤：

1. 对 node.left 执行左旋 node.left = rotate_left(node.left)

2. 对 node 执行右旋 return rotate_right(node)

  • 时间复杂度：$ O(1) $（两次旋转各 $ O(1) $）

#### 右左旋（RL 旋转）

  • 含义：先对右子节点右旋，再对当前节点左旋
  • 触发条件：RL 型失衡，即 $ BF(node) \leq -2 $ 且 $ BF(node.right) > 0 $
  • 操作步骤：

1. 对 node.right 执行右旋 node.right = rotate_right(node.right)

2. 对 node 执行左旋 return rotate_left(node)

  • 时间复杂度：$ O(1) $（两次旋转各 $ O(1) $）

代码示例

class AVLNode:
    def __init__(self, value):                      # 节点构造函数
        self.value = value                           # 存储节点值
        self.left = None                             # 左子节点初始化为空
        self.right = None                            # 右子节点初始化为空
        self.height = 1                              # 新节点高度为1（叶子节点）

class AVLTree:
    def __init__(self):                              # AVL树构造函数
        self.root = None                             # 根节点初始化为空

    def get_height(self, node):                      # 获取节点高度
        if node is None:                             # 若节点为空
            return 0                                 # 空节点高度为0
        return node.height                           # 返回节点高度

    def get_balance(self, node):                     # 计算平衡因子
        if node is None:                             # 若节点为空
            return 0                                 # 平衡因子为0
        return self.get_height(node.left) - self.get_height(node.right)  # BF = 左子树高 - 右子树高

    def update_height(self, node):                   # 更新节点高度
        node.height = 1 + max(                       # 高度 = 1 + max(左子树高, 右子树高)
            self.get_height(node.left),              # 左子树高度
            self.get_height(node.right)              # 右子树高度
        )

    def rotate_left(self, z):                        # 左旋操作（处理RR型失衡）
        y = z.right                                  # y为z的右子节点（将成为新根）
        T2 = y.left                                  # T2为y的左子树（需要重新挂接）
        y.left = z                                   # z成为y的左子节点
        z.right = T2                                 # T2成为z的右子树
        self.update_height(z)                        # 先更新z的高度（z现在在下面）
        self.update_height(y)                        # 再更新y的高度（y现在在上面）
        return y                                     # 返回新的子树根节点y

    def rotate_right(self, z):                       # 右旋操作（处理LL型失衡）
        y = z.left                                   # y为z的左子节点（将成为新根）
        T3 = y.right                                 # T3为y的右子树（需要重新挂接）
        y.right = z                                  # z成为y的右子节点
        z.left = T3                                  # T3成为z的左子树
        self.update_height(z)                        # 先更新z的高度
        self.update_height(y)                        # 再更新y的高度
        return y                                     # 返回新的子树根节点y

    def insert(self, value):                         # 公共插入接口
        self.root = self._insert(self.root, value)   # 从根节点开始递归插入

    def _insert(self, node, value):                  # 递归插入核心逻辑
        if node is None:                             # 若到达空位置
            return AVLNode(value)                    # 创建并返回新节点

        if value < node.value:                       # 若值小于当前节点
            node.left = self._insert(node.left, value)   # 递归插入左子树
        elif value > node.value:                      # 若值大于当前节点
            node.right = self._insert(node.right, value) # 递归插入右子树
        else:                                        # 若值已存在
            return node                              # 不允许重复值，直接返回

        self.update_height(node)                     # 更新当前节点高度

        balance = self.get_balance(node)             # 计算平衡因子

        # LL型: 左子树偏高，且新节点插入在左子树的左子树
        if balance > 1 and value < node.left.value:  # BF>1 且插入在左子节点左侧
            return self.rotate_right(node)           # 右旋恢复平衡

        # RR型: 右子树偏高，且新节点插入在右子树的右子树
        if balance < -1 and value > node.right.value:  # BF<-1 且插入在右子节点右侧
            return self.rotate_left(node)            # 左旋恢复平衡

        # LR型: 左子树偏高，但新节点插入在左子树的右子树
        if balance > 1 and value > node.left.value:  # BF>1 且插入在左子节点右侧
            node.left = self.rotate_left(node.left)  # 先对左子节点左旋
            return self.rotate_right(node)           # 再对当前节点右旋

        # RL型: 右子树偏高，但新节点插入在右子树的左子树
        if balance < -1 and value < node.right.value:  # BF<-1 且插入在右子节点左侧
            node.right = self.rotate_right(node.right)  # 先对右子节点右旋
            return self.rotate_left(node)            # 再对当前节点左旋

        return node                                  # 未失衡，直接返回当前节点

    def search(self, value):                         # 查找接口
        return self._search(self.root, value)        # 从根节点开始递归查找

    def _search(self, node, value):                  # 递归查找核心逻辑
        if node is None:                             # 若节点为空
            return False                             # 未找到，返回False
        if value == node.value:                      # 找到目标值
            return True                              # 返回True
        elif value < node.value:                     # 若值小于当前节点
            return self._search(node.left, value)    # 在左子树中查找
        else:                                        # 若值大于当前节点
            return self._search(node.right, value)   # 在右子树中查找

    def inorder(self):                               # 中序遍历接口
        result = []                                  # 结果列表
        self._inorder(self.root, result)             # 递归中序遍历
        return result                                # 返回有序结果

    def _inorder(self, node, result):                # 递归中序遍历
        if node:                                     # 若节点不为空
            self._inorder(node.left, result)         # 先遍历左子树
            result.append(node.value)                # 访问当前节点
            self._inorder(node.right, result)        # 再遍历右子树

# 使用示例
avl = AVLTree()                                      # 创建AVL树
values = [10, 20, 30, 40, 50, 25]                    # 待插入的值
for v in values:                                     # 依次插入
    avl.insert(v)                                    # 插入每个值
print("中序遍历:", avl.inorder())                     # 输出有序序列: [10, 20, 25, 30, 40, 50]
print("查找30:", avl.search(30))                     # 输出: True
print("查找99:", avl.search(99))                     # 输出: False

复杂度分析

时间复杂度：

操作时间复杂度推导
查找$ O(\log n) $树高 $ h \leq 1.44 \log_2(n+2) $，查找路径长度 $ \leq h $
插入$ O(\log n) $查找插入位置 $ O(\log n) $ + 回溯调整 $ O(\log n) $ + 最多 1 次旋转 $ O(1) $
删除$ O(\log n) $查找删除节点 $ O(\log n) $ + 回溯调整 $ O(\log n) $ + 最多 $ O(\log n) $ 次旋转

推导：AVL 树高度 $ h = O(\log n) $，所有操作都需要从根遍历到叶子，路径长度为 $ O(\log n) $。插入时回溯路径上最多在一个节点触发旋转（旋转后子树高度恢复，不再向上传播），所以插入的旋转次数为 $ O(1) $。删除时回溯路径上可能多个节点都需要旋转，旋转次数为 $ O(\log n) $。

空间复杂度：

场景空间复杂度说明
存储$ O(n) $每个节点存储值、左右指针、高度，共 $ n $ 个节点
递归栈$ O(\log n) $递归深度等于树高 $ O(\log n) $

应用场景

  • 数据库索引：早期数据库系统使用 AVL 树作为内存索引结构，保证查询效率稳定
  • 内存中的有序映射/集合：C++ STL 中部分实现使用 AVL 树变体管理有序容器
  • 文件系统：部分文件系统使用 AVL 树管理磁盘块分配信息
  • 路由表：网络路由器中使用 AVL 树快速查找路由前缀
  • 编译器符号表：编译过程中使用 AVL 树管理变量名与位置的映射
  • 适合读多写少的场景：AVL 树严格平衡使查找路径更短，但写操作旋转开销比红黑树大

BERT 预训练模型

类别：NLP | 难度：困难

算法简介

BERT（Bidirectional Encoder Representations from Transformers）是 Google 于 2018 年发布的预训练语言模型，基于 Transformer 编码器架构，通过双向自注意力机制捕获文本的深层语义表示。BERT 的核心创新在于使用了掩码语言模型（Masked Language Model, MLM）和下一句预测（Next Sentence Prediction, NSP）两个预训练任务，使模型能够学习上下文相关的双向表示。

BERT 的出现是 NLP 领域的里程碑事件，它在 11 个 NLP 基准测试中刷新了记录，推动了"预训练 + 微调"范式成为 NLP 的标准方法论。BERT 的模型配置包含大量超参数（如 hidden_size、num_hidden_layers、num_attention_heads 等），这些参数直接影响模型的表示能力、计算开销和内存占用。理解每个参数的含义和调优策略，是有效使用和微调 BERT 的关键。

原理示意图

数学公式

1. 自注意力机制（Scaled Dot-Product Attention）

$$ \text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V $$

变量解释：

  • $ Q $：查询矩阵（Query），形状为 $ (N, L, d_k) $，其中 $ N $ 为批次大小，$ L $ 为序列长度，$ d_k $ 为每个注意力头的维度
  • $ K $：键矩阵（Key），形状为 $ (N, L, d_k) $
  • $ V $：值矩阵（Value），形状为 $ (N, L, d_v) $，通常 $ d_k = d_v = d_{\text{model}} / h $
  • $ d_k $：每个注意力头的维度，$ d_k = \text{hidden\_size} / \text{num\_attention\_heads} $
  • $ K^T $：键矩阵的转置，形状为 $ (N, d_k, L) $
  • $ \sqrt{d_k} $：缩放因子，防止点积结果过大导致 softmax 梯度消失
  • $ \text{softmax} $：对最后一维进行归一化，使注意力权重和为 1

2. 多头注意力（Multi-Head Attention）

$$ \text{MultiHead}(Q, K, V) = \text{Concat}(\text{head}_1, \ldots, \text{head}_h) W^O $$

$$ \text{head}_i = \text{Attention}(QW_i^Q, KW_i^K, VW_i^V) $$

变量解释：

  • $ h $：注意力头数（num_attention_heads），默认 12
  • $ \text{head}_i $：第 $ i $ 个注意力头的输出
  • $ W_i^Q \in \mathbb{R}^{d_{\text{model}} \times d_k} $：第 $ i $ 个头的查询投影矩阵
  • $ W_i^K \in \mathbb{R}^{d_{\text{model}} \times d_k} $：第 $ i $ 个头的键投影矩阵
  • $ W_i^V \in \mathbb{R}^{d_{\text{model}} \times d_v} $：第 $ i $ 个头的值投影矩阵
  • $ W^O \in \mathbb{R}^{hd_v \times d_{\text{model}}} $：输出投影矩阵
  • $ \text{Concat} $：将所有头的输出在特征维度上拼接

3. 前馈网络（Feed-Forward Network）

$$ \text{FFN}(x) = \max(0, xW_1 + b_1)W_2 + b_2 $$

变量解释：

  • $ x $：输入向量，维度为 hidden_size（如 768）
  • $ W_1 \in \mathbb{R}^{d_{\text{model}} \times d_{\text{ff}}} $：第一层权重矩阵，将维度从 hidden_size 扩展到 intermediate_size（如 3072）
  • $ b_1 $：第一层偏置
  • $ \max(0, \cdot) $：GELU 激活函数（BERT 中默认使用 GELU 而非 ReLU）
  • $ W_2 \in \mathbb{R}^{d_{\text{ff}} \times d_{\text{model}}} $：第二层权重矩阵，将维度从 intermediate_size 压缩回 hidden_size
  • $ b_2 $：第二层偏置

4. 层归一化（Layer Normalization）

$$ \text{LayerNorm}(x) = \gamma \cdot \frac{x - \mu}{\sqrt{\sigma^2 + \epsilon}} + \beta $$

变量解释：

  • $ x $：输入向量
  • $ \mu $：$ x $ 在隐藏维度上的均值
  • $ \sigma^2 $：$ x $ 在隐藏维度上的方差
  • $ \epsilon $：防止除零的小常数（layer_norm_eps，默认 $ 10^{-12} $）
  • $ \gamma, \beta $：可学习的缩放和平移参数

核心要点

  • BERT 仅使用 Transformer 的编码器部分（不使用解码器），因此是双向的
  • 输入由 Token Embedding + Position Embedding + Segment Embedding 三部分相加而成
  • 预训练任务：MLM（随机遮盖 15% 的 token 并预测）+ NSP（判断两句话是否相邻）
  • [CLS] token 的最终隐藏状态用于句子级分类任务
  • hidden_size 必须能被 num_attention_heads 整除
  • BERT-base 有约 110M 参数，BERT-large 有约 340M 参数

技术细节与参数详解

#### 模型配置参数（BertConfig）

#### 参数1：vocab_size

  • 含义：词表大小，即模型能识别的不同 token 的数量
  • 类型：int
  • 默认值：30522（BERT-base English）
  • 取值范围：$ \geq 1 $，通常为数千到数十万
  • 对结果的影响：决定了 Token Embedding 表的大小（$ vocab\_size \times hidden\_size $），值越大模型能处理的词汇越丰富但参数量增加
  • 推荐设置：英文任务用 30522，中文任务用 21128（bert-base-chinese）

#### 参数2：hidden_size

  • 含义：隐藏层维度，即每个 token 的表示向量维度
  • 类型：int
  • 默认值：768（BERT-base），1024（BERT-large）
  • 取值范围：正整数，必须能被 num_attention_heads 整除
  • 对结果的影响：直接决定模型表示能力，维度越大表示能力越强但计算量和内存增加
  • 推荐设置：base 模型用 768，large 模型用 1024，轻量级模型可设为 256/512

#### 参数3：num_hidden_layers

  • 含义：Transformer 编码器的层数（堆叠的 Encoder Block 数量）
  • 类型：int
  • 默认值：12（BERT-base），24（BERT-large）
  • 取值范围：$ \geq 1 $，通常 4~48
  • 对结果的影响：层数越多模型越深，能学习更抽象的语义表示，但训练更慢、更容易过拟合
  • 推荐设置：base 用 12 层，轻量级用 4~6 层，large 用 24 层

#### 参数4：num_attention_heads

  • 含义：多头注意力机制中的注意力头数
  • 类型：int
  • 默认值：12（BERT-base），16（BERT-large）
  • 取值范围：$ \geq 1 $，必须满足 hidden_size % num_attention_heads == 0
  • 对结果的影响：头数越多，模型能同时关注不同子空间的信息，但每个头的维度 $ d_k = hidden\_size / num\_heads $ 减小，可能降低单头表达能力
  • 推荐设置：通常等于 hidden_size / 64（每头 64 维），如 768/64=12

#### 参数5：intermediate_size

  • 含义：前馈网络（FFN）中间层的维度
  • 类型：int
  • 默认值：3072（BERT-base），4096（BERT-large）
  • 取值范围：正整数，通常为 hidden_size 的 4 倍
  • 对结果的影响：决定 FFN 的表达能力，值越大非线性变换能力越强，但参数量和计算量增加
  • 推荐设置：设为 hidden_size × 4

#### 参数6：hidden_act

  • 含义：FFN 中的激活函数
  • 类型：str 或 Callable
  • 默认值："gelu"
  • 取值范围："gelu"、"relu"、"silu"（"swish"）、"tanh"、"sigmoid"
  • 对结果的影响：不同激活函数有不同的非线性特性，GELU 在 BERT 中效果最佳
  • 推荐设置：保持默认 "gelu"

#### 参数7：hidden_dropout_prob

  • 含义：全连接层和 Embedding 层的 Dropout 概率
  • 类型：float
  • 默认值：0.1
  • 取值范围：$ [0, 1) $
  • 对结果的影响：值越大正则化效果越强但可能欠拟合，值越小越容易过拟合
  • 推荐设置：0.1（标准值），大数据集可降到 0.05，小数据集可升到 0.2

#### 参数8：attention_probs_dropout_prob

  • 含义：注意力权重（softmax 后）的 Dropout 概率
  • 类型：float
  • 默认值：0.1
  • 取值范围：$ [0, 1) $
  • 对结果的影响：随机丢弃部分注意力连接，防止模型过度关注某些 token
  • 推荐设置：0.1，通常与 hidden_dropout_prob 保持一致

#### 参数9：max_position_embeddings

  • 含义：模型能处理的最大序列长度
  • 类型：int
  • 默认值：512
  • 取值范围：$ \geq 1 $，通常 512 或 1024
  • 对结果的影响：直接限制输入文本的最大长度，超过此长度的文本需要截断。增加此值会显著增加 Position Embedding 参数量和内存占用
  • 推荐设置：512（标准），长文本任务可用 Longformer/BigBird 等变体替代

#### 参数10：type_vocab_size

  • 含义：句子类型（Segment）的词表大小，用于区分输入中的不同句子
  • 类型：int
  • 默认值：2
  • 取值范围：$ \geq 1 $
  • 对结果的影响：BERT 的 NSP 任务需要区分句子 A 和 B，因此为 2。单句任务只用 1 种类型
  • 推荐设置：2（标准值，支持双句输入）

#### 参数11：initializer_range

  • 含义：权重矩阵初始化的标准差（截断正态分布）
  • 类型：float
  • 默认值：0.02
  • 取值范围：$ > 0 $
  • 对结果的影响：初始化标准差过大导致训练不稳定，过小导致梯度消失
  • 推荐设置：0.02（Transformer 标准设置）

#### 参数12：layer_norm_eps

  • 含义：LayerNorm 中防止除零的 $ \epsilon $ 常数
  • 类型：float
  • 默认值：1e-12
  • 取值范围：$ > 0 $，通常 $ 10^{-5} $ 到 $ 10^{-12} $
  • 对结果的影响：值越大数据归一化越平滑但可能影响表示精度
  • 推荐设置：1e-12（BERT 默认），1e-5（部分其他模型如 GPT-2）

#### 输入参数

#### 参数13：input_ids

  • 含义：输入文本经 Tokenizer 转换后的 token ID 序列
  • 类型：torch.LongTensor，形状 $ (batch\_size, sequence\_length) $
  • 取值范围：$ [0, vocab\_size - 1] $
  • 对结果的影响：是模型最核心的输入，直接决定模型处理的内容
  • 推荐设置：必须包含 [CLS] 和 [SEP] 特殊 token

#### 参数14：attention_mask

  • 含义：注意力掩码，标记哪些位置是真实 token（1）、哪些是 padding（0）
  • 类型：torch.LongTensor，形状 $ (batch\_size, sequence\_length) $
  • 取值范围：$ \{0, 1\} $，1 表示关注该位置，0 表示忽略
  • 对结果的影响：确保 padding 位置不参与注意力计算，避免无意义的 token 干扰结果
  • 推荐设置：batch 推理时必须提供，单条样本可不提供

#### 参数15：token_type_ids（segment_ids）

  • 含义：标记每个 token 属于哪个句子，用于区分句子 A 和 B
  • 类型：torch.LongTensor，形状 $ (batch\_size, sequence\_length) $
  • 取值范围：$ [0, type\_vocab\_size - 1] $，通常为 0 或 1
  • 对结果的影响：使模型能区分输入中的不同句子，对 NSP 和句对分类任务至关重要
  • 推荐设置：单句任务全 0，句对任务前句为 0 后句为 1

#### 参数16：position_ids

  • 含义：位置编码索引，标记每个 token 在序列中的位置
  • 类型：torch.LongTensor，形状 $ (batch\_size, sequence\_length) $
  • 默认值：自动生成 $ [0, 1, 2, \ldots, L-1] $
  • 取值范围：$ [0, max\_position\_embeddings - 1] $
  • 对结果的影响：为模型提供位置信息，错误的位置编码会导致语义混乱
  • 推荐设置：通常无需手动指定，模型自动生成

代码示例

import torch                                            # 导入 PyTorch 核心库
from transformers import BertTokenizer, BertModel, BertConfig  # 导入 BERT 相关组件

# 1. 加载预训练 Tokenizer 和模型
tokenizer = BertTokenizer.from_pretrained('bert-base-uncased')  # 加载英文 BERT tokenizer
model = BertModel.from_pretrained('bert-base-uncased')          # 加载预训练 BERT 模型权重
config = model.config                                  # 获取模型配置对象

# 2. 查看关键配置参数
print(f"hidden_size: {config.hidden_size}")            # 输出: 768（隐藏层维度）
print(f"num_hidden_layers: {config.num_hidden_layers}")  # 输出: 12（编码器层数）
print(f"num_attention_heads: {config.num_attention_heads}")  # 输出: 12（注意力头数）
print(f"intermediate_size: {config.intermediate_size}")  # 输出: 3072（FFN中间层维度）
print(f"vocab_size: {config.vocab_size}")              # 输出: 30522（词表大小）
print(f"max_position_embeddings: {config.max_position_embeddings}")  # 输出: 512（最大序列长度）

# 3. 准备输入文本
texts = ["Hello, how are you?", "I am fine, thank you."]  # 两个输入句子

# 4. Tokenizer 编码
inputs = tokenizer(                                     # 使用 tokenizer 处理输入文本
    texts,                                             # 待编码的文本列表
    padding=True,                                      # 自动 padding 到批次内最长序列
    truncation=True,                                   # 超过 max_length 自动截断
    max_length=512,                                    # 最大序列长度设为 512
    return_tensors="pt"                                # 返回 PyTorch 张量格式
)

print(f"input_ids shape: {inputs['input_ids'].shape}")  # 输出: (2, 8)
print(f"attention_mask shape: {inputs['attention_mask'].shape}")  # 输出: (2, 8)
print(f"token_type_ids shape: {inputs['token_type_ids'].shape}")  # 输出: (2, 8)

# 5. 模型前向传播
with torch.no_grad():                                  # 关闭梯度计算（推理模式）
    outputs = model(                                   # 调用 BERT 模型
        input_ids=inputs['input_ids'],                 # 传入 token ID 序列
        attention_mask=inputs['attention_mask'],       # 传入注意力掩码
        token_type_ids=inputs['token_type_ids'],       # 传入句子类型 ID
        output_hidden_states=True,                     # 输出所有层的隐藏状态
        output_attentions=True                         # 输出所有层的注意力权重
    )

# 6. 解析模型输出
last_hidden_state = outputs.last_hidden_state          # 最后一层的隐藏状态
# 形状: (batch_size, sequence_length, hidden_size) = (2, 8, 768)
print(f"last_hidden_state: {last_hidden_state.shape}")  # 输出: torch.Size([2, 8, 768])

pooler_output = outputs.pooler_output                  # [CLS] token 的池化输出
# 形状: (batch_size, hidden_size) = (2, 768)
# 经过 tanh 激活的全连接层处理，用于句子级分类
print(f"pooler_output: {pooler_output.shape}")        # 输出: torch.Size([2, 768])

hidden_states = outputs.hidden_states                  # 所有层的隐藏状态（含 Embedding 层）
# 共 num_hidden_layers + 1 = 13 个张量
print(f"hidden_states layers: {len(hidden_states)}")   # 输出: 13

attentions = outputs.attentions                        # 所有层的注意力权重
# 共 num_hidden_layers = 12 个张量
print(f"attentions layers: {len(attentions)}")         # 输出: 12

# 7. 自定义 BERT 配置（轻量级模型）
custom_config = BertConfig(                            # 创建自定义配置
    vocab_size=30522,                                  # 词表大小
    hidden_size=256,                                   # 隐藏层维度（缩小为 256）
    num_hidden_layers=4,                               # 编码器层数（减少为 4 层）
    num_attention_heads=4,                             # 注意力头数（256/4=64 每头）
    intermediate_size=1024,                            # FFN 中间层维度（256×4=1024）
    max_position_embeddings=512,                       # 最大序列长度
    hidden_act="gelu",                                 # 激活函数使用 GELU
    hidden_dropout_prob=0.1,                           # 隐藏层 Dropout 概率
    attention_probs_dropout_prob=0.1,                  # 注意力 Dropout 概率
    layer_norm_eps=1e-12                               # LayerNorm epsilon
)
custom_model = BertModel(custom_config)                # 用自定义配置初始化模型（随机权重）
print(f"Custom model params: {sum(p.numel() for p in custom_model.parameters()) / 1e6:.1f}M")  # 输出参数量（约 15M）

标签平滑

类别：训练技巧 | 难度：入门

算法简介

标签平滑（Label Smoothing）是一种简单而有效的正则化技术，用于分类任务中防止模型过度自信（overconfidence）。在传统的分类训练中，标签采用 one-hot 编码——正确类别概率为 1，其他类别为 0。这种"非黑即白"的硬标签会驱使模型无限增大正确类别的 logit 值，导致过拟合和泛化能力下降。

标签平滑的核心思想是：将 one-hot 标签中的 1 降低为 $ 1 - \epsilon $，将 0 提升为 $ \epsilon / (K-1) $（$ K $ 为类别数），形成"软标签"。例如在 10 类分类中，$ \epsilon = 0.1 $ 时，正确类别的标签从 1.0 变为 0.9，其他类别从 0.0 变为 0.0111。这种小幅度的"不确定性注入"可以有效约束模型的 logit 值，使其不会过于极端，从而提升泛化能力。

标签平滑由 Szegedy 等人在 Inception-v3 论文中首次提出，随后在图像分类、机器翻译（Transformer）、语音识别等领域被广泛采用。PyTorch 从 1.10 版本开始在 CrossEntropyLoss 中内置了 label_smoothing 参数。

原理示意图

数学公式

1. 标签平滑公式

$$ \tilde{y}_i = \begin{cases} 1 - \epsilon + \frac{\epsilon}{K} & \text{if } i = y \\ \frac{\epsilon}{K} & \text{if } i \neq y \end{cases} $$

变量解释：

  • $ \tilde{y}_i $：平滑后第 $ i $ 类的目标概率
  • $ y $：真实类别索引
  • $ K $：总类别数
  • $ \epsilon $：平滑因子（smoothing factor），控制平滑强度

等价表述：将 one-hot 标签与均匀分布 $ u = 1/K $ 混合：

$$ \tilde{y} = (1 - \epsilon) \cdot \text{one\_hot}(y) + \epsilon \cdot \frac{1}{K} \mathbf{1} $$

2. 带标签平滑的交叉熵损失

$$ \mathcal{L}_{\text{smooth}} = -\sum_{i=1}^{K} \tilde{y}_i \log(p_i) = -\sum_{i=1}^{K} \left[(1-\epsilon) \cdot y_i + \frac{\epsilon}{K}\right] \log(p_i) $$

变量解释：

  • $ p_i $：模型对第 $ i $ 类的预测概率（softmax 输出）
  • $ y_i $：one-hot 编码中第 $ i $ 类的值（1 或 0）
  • $ \tilde{y}_i $：平滑后第 $ i $ 类的目标概率
  • $ \epsilon $：平滑因子

展开后可分为两部分：

$$ \mathcal{L}_{\text{smooth}} = (1-\epsilon) \cdot \underbrace{\left(-\log(p_y)\right)}_{\text{标准交叉熵}} + \epsilon \cdot \underbrace{\left(-\frac{1}{K}\sum_{i=1}^{K} \log(p_i)\right)}_{\text{均匀分布交叉熵}} $$

3. Logit 天花板推导

对 softmax 函数 $ p_i = \frac{e^{z_i}}{\sum_j e^{z_j}} $，当模型最优拟合平滑标签时，$ p_y \to 1 - \epsilon + \epsilon/K $。可推导出最优 logit 差：

$$ z_y - z_{\text{other}} \approx \log\left(\frac{(1-\epsilon)(K-1)}{\epsilon(1-1/K)} + 1\right) \approx \log\left(\frac{K-1}{\epsilon} \cdot \frac{1-\epsilon}{K}\right) $$

变量解释：

  • $ z_y $：正确类别的 logit 值
  • $ z_{\text{other}} $：其他类别的 logit 值
  • 这个公式说明标签平滑给 logit 差设置了上界，防止模型过度自信

核心要点

  • 标签平滑将 one-hot 硬标签转换为软标签，注入适度不确定性
  • 平滑因子 $ \epsilon $ 控制平滑强度，通常取 0.1
  • 标签平滑隐式地给 logit 值设置了上界，防止数值过大
  • 在图像分类（ImageNet）中通常提升 0.5%~1% 的 Top-1 准确率
  • 在 Transformer 机器翻译中是标准配置（$ \epsilon = 0.1 $）
  • 与其他正则化（Dropout、Weight Decay）正交，可叠加使用
  • PyTorch 1.10+ 内置支持 CrossEntropyLoss(label_smoothing=0.1)

技术细节与参数详解

#### 核心参数

#### 参数1：label_smoothing（ε，平滑因子）

  • 含义：控制标签平滑的强度，即从正确类别中"借走"多少概率质量分配给其他类别
  • 类型：float
  • 默认值：0.0（不使用标签平滑）
  • 取值范围：$ [0, 1) $
  • 对结果的影响：
  • $ \epsilon = 0 $：退化为标准交叉熵，模型可能过度自信
  • $ \epsilon = 0.05 $：轻度平滑，适合大数据集
  • $ \epsilon = 0.1 $：标准设置，大多数任务的最佳值
  • $ \epsilon = 0.2 $：较强平滑，适合小数据集或噪声标签
  • $ \epsilon \to 1 $：标签趋于均匀分布，模型无法学到任何信息
  • 推荐设置：0.1（图像分类/翻译通用最佳值），0.05~0.15 范围内调优

#### PyTorch CrossEntropyLoss 参数详解

#### 参数2：weight（类别权重）

  • 含义：为每个类别分配不同的权重，用于处理类别不平衡
  • 类型：torch.Tensor，形状 $ (K,) $
  • 默认值：None
  • 取值范围：$ > 0 $ 的正数
  • 对结果的影响：高权重类别的误分类会被更重地惩罚
  • 推荐设置：根据类别频率设置 $ w_i = N / (K \cdot N_i) $

#### 参数3：ignore_index

  • 含义：指定一个类别索引，该索引的样本不参与损失计算（如 padding 位置）
  • 类型：int
  • 默认值：-100
  • 取值范围：$ [-100, K-1] $
  • 对结果的影响：被忽略的样本梯度为 0，不影响模型更新
  • 推荐设置：序列标注任务中用 -100 标记 padding token

#### 参数4：reduction

  • 含义：指定损失值的归约方式
  • 类型：str
  • 默认值："mean"
  • 取值范围："none"（不归约，返回每个样本的损失）、"mean"（取均值）、"sum"（取总和）
  • 对结果的影响："mean" 最常用，"sum" 需要手动除以样本数
  • 推荐设置："mean"

#### 参数5：label_smoothing（PyTorch 内置）

  • 含义：在 torch.nn.CrossEntropyLoss 中直接启用标签平滑，同参数1 的 $ \epsilon $
  • 类型：float
  • 默认值：0.0
  • 取值范围：$ [0, 1) $
  • 对结果的影响：$ \epsilon > 0 $ 时自动将硬标签转为软标签计算损失
  • 推荐设置：0.1

代码示例

import torch                                          # 导入 PyTorch
import torch.nn as nn                                  # 导入神经网络模块
import torch.nn.functional as F                        # 导入函数式接口

# ============================================================
# 方式一：PyTorch 内置标签平滑（推荐，PyTorch >= 1.10）
# ============================================================
# 创建带标签平滑的交叉熵损失函数
criterion = nn.CrossEntropyLoss(                       # 实例化交叉熵损失
    label_smoothing=0.1,                               # 平滑因子 ε=0.1
    reduction='mean'                                   # 损失取平均
)

# 模拟数据
logits = torch.randn(4, 10)                            # 4个样本, 10类 的模型输出
# tensor shape: (batch_size=4, num_classes=10)
targets = torch.tensor([0, 3, 7, 9])                   # 4个样本的真实标签

# 计算损失
loss = criterion(logits, targets)                      # 前向计算损失
print(f"Label smoothing loss: {loss.item():.4f}")      # 输出损失值

# ============================================================
# 方式二：手动实现标签平滑（理解原理）
# ============================================================
def label_smoothing_loss(logits, targets, epsilon=0.1, num_classes=10):
    """                                               # 手动实现标签平滑交叉熵
    logits: (N, K) 模型输出                            # 未经 softmax 的原始输出
    targets: (N,) 真实标签                             # 整数索引
    epsilon: 平滑因子                                  # 默认 0.1
    num_classes: 类别数                                # 默认 10
    """
    N = logits.size(0)                                # 获取批次大小 N
    K = num_classes                                   # 获取类别数 K

    # 步骤1: 将 logit 通过 log_softmax 转为 log 概率
    log_probs = F.log_softmax(logits, dim=-1)         # (N, K) log 概率

    # 步骤2: 构造平滑后的软标签
    # one_hot: (N, K)，正确位置为 1，其余为 0
    one_hot = F.one_hot(targets, num_classes=K).float()  # 转为 one-hot 编码

    # 平滑标签 = (1-ε) * one_hot + ε / K
    smooth_targets = one_hot * (1 - epsilon) + epsilon / K  # 混合 one-hot 和均匀分布

    # 步骤3: 计算交叉熵损失
    # L = -sum(smooth_targets * log_probs) / N
    loss = (-smooth_targets * log_probs).sum(dim=-1).mean()  # 逐元素相乘求和再取平均

    return loss                                       # 返回标量损失

# 测试手动实现
manual_loss = label_smoothing_loss(logits, targets, epsilon=0.1, num_classes=10)
print(f"Manual label smoothing loss: {manual_loss.item():.4f}")  # 应与内置结果接近

# ============================================================
# 方式三：对比有/无标签平滑的效果
# ============================================================
# 不使用标签平滑
criterion_no_smooth = nn.CrossEntropyLoss(label_smoothing=0.0)  # ε=0, 标准交叉熵
loss_no_smooth = criterion_no_smooth(logits, targets)  # 计算标准损失
print(f"Without smoothing: {loss_no_smooth.item():.4f}")  # 输出无平滑损失

# 使用标签平滑
criterion_smooth = nn.CrossEntropyLoss(label_smoothing=0.1)  # ε=0.1
loss_smooth = criterion_smooth(logits, targets)        # 计算平滑损失
print(f"With smoothing: {loss_smooth.item():.4f}")     # 输出平滑损失

# ============================================================
# 实际训练示例：在模型训练中使用标签平滑
# ============================================================
model = nn.Linear(768, 10)                             # 简单的线性分类器 (768维→10类)
optimizer = torch.optim.Adam(model.parameters(), lr=1e-3)  # Adam 优化器
criterion = nn.CrossEntropyLoss(label_smoothing=0.1)  # 带标签平滑的损失函数

# 模拟训练循环
for epoch in range(5):                                 # 训练 5 个 epoch
    dummy_input = torch.randn(16, 768)                 # 模拟输入 (batch=16, dim=768)
    dummy_target = torch.randint(0, 10, (16,))         # 随机生成标签

    optimizer.zero_grad()                              # 清零梯度
    output = model(dummy_input)                        # 前向传播
    loss = criterion(output, dummy_target)             # 计算带标签平滑的损失
    loss.backward()                                    # 反向传播
    optimizer.step()                                   # 更新参数

    print(f"Epoch {epoch+1}, Loss: {loss.item():.4f}")  # 打印每个 epoch 的损失

复杂度分析

时间复杂度：

操作时间复杂度推导
标签平滑转换$ O(N \cdot K) $对 $ N $ 个样本的 $ K $ 个类别标签进行混合运算
损失计算$ O(N \cdot K) $与标准交叉熵相同，额外常数倍开销可忽略
总增量$ O(N \cdot K) $与标准交叉熵相比，时间复杂度完全相同

空间复杂度：

组件空间复杂度说明
标准交叉熵$ O(N \cdot K) $存储 log_softmax 输出
标签平滑$ O(N \cdot K) $额外存储平滑标签矩阵（PyTorch 内置实现无需显式存储）

标签平滑的计算开销几乎为零，不影响训练速度。

应用场景

  • 图像分类：ImageNet 训练中标配，Inception-v3、ResNet 等均使用 $ \epsilon = 0.1 $
  • 机器翻译：Transformer 原论文中使用 $ \epsilon = 0.1 $，是 NMT 的标配
  • 语音识别：ASR 模型中使用标签平滑处理噪声标注
  • 知识蒸馏：软标签天然与知识蒸馏兼容，学生模型同时学习平滑标签和教师输出
  • 噪声标签学习：当训练标签存在标注错误时，标签平滑可减轻噪声影响
  • 对抗防御：标签平滑使模型对对抗样本的 logit 变化更不敏感
