二分图匹配（匈牙利算法 / KM 算法）

类别：图算法 | 难度：中等

算法简介

二分图（Bipartite Graph）是指顶点集合可被划分为两个互不相交的子集 $ L $（左部）与 $ R $（右部），且每条边的两个端点分别落在不同子集中的图。二分图匹配问题，就是在这个图上选出尽可能多（或权和尽可能大）的边，使得任意两条被选中的边不共享端点——这正是"排班""岗位分配""推荐召回""任务调度"等场景的数学抽象。

匹配是一组两两不共端点的边；边数最多的匹配称为最大匹配；若所有顶点都被匹配覆盖，则称为完美匹配。求最大匹配的两大经典算法是：

1. 匈牙利算法（Kuhn–Munkres / Hungarian，无权重版）：对左部每个点尝试找一条增广路，找到就把匹配数 +1。单次增广 DFS 复杂度 $ O(E) $，总计 $ O(VE) $。核心依据是 Berge 增广路定理：匹配 $ M $ 是最大匹配当且仅当不存在 $ M $ 的增广路。

2. KM 算法（Kuhn–Munkres，带权版）：在带权完全二分图上求最大权完美匹配。它把"最大化权和"转化为"顶标可行 + 相等子图上的完美匹配"，通过不断调整顶标扩大相等子图，直到找到完美匹配。复杂度 $ O(n^3) $。

当图较稀疏、点数上万时，可用 Hopcroft–Karp 把复杂度降到 $ O(E\sqrt{V}) $；当图不是二分图（存在奇环）时，则需用带花树（Blossom）算法。

原理示意图

数学公式

（1）匹配与最大匹配

$$ M \subseteq E,\quad \forall e_1,e_2\in M:\ e_1\cap e_2=\varnothing $$
$$ |M^*| = \max_{M\ \text{是匹配}} |M| $$
  • $ E $：图的边集；$ M $：一个匹配（边的子集）
  • $ e_1\cap e_2=\varnothing $：任意两条边不共享端点
  • $ M^* $：最大匹配；$ |M| $：匹配的边数

（2）Berge 增广路定理（算法正确性基石）

$$ M \text{ 是最大匹配} \iff \nexists\ P:\ P \text{ 是 } M\text{-增广路} $$
  • $ P $：一条起点与终点都是未匹配点、且匹配边与非匹配边交替出现的路径
  • $ |P| $ 为奇数，且非匹配边比匹配边多 1，故 $ |M\oplus P| = |M|+1 $

（3）二分图最小点覆盖 = 最大匹配（König 定理）

$$ \min |C| = \max |M|,\qquad C\ \text{为点覆盖} $$
  • $ C $：覆盖所有边所需的最少顶点集合
  • 该定理把"最小点覆盖""最大独立集"问题一并归约到最大匹配：$ \alpha(G)=|V|-\nu(G) $

（4）KM 算法的顶标可行条件与松弛量

$$ \forall (u,v)\in E:\ l_x(u)+l_y(v)\ge w(u,v) $$
$$ \Delta = \min_{u\in S,\ v\notin T}\bigl(l_x(u)+l_y(v)-w(u,v)\bigr) $$
  • $ l_x(u),l_y(v) $：左/右部顶标；$ w(u,v) $：边权
  • 相等子图 $ G_l=\{(u,v)\mid l_x(u)+l_y(v)=w(u,v)\} $
  • $ S,T $：当前交替树中已访问的左/右点集；$ \Delta $：本次顶标整体下调的最小步长
  • 更新：$ l_x(u)\mathrel{-}=\Delta\ (u\in S) $，$ l_y(v)\mathrel{+}=\Delta\ (v\in T) $，相等子图只增不减

（5）复杂度

$$ T_{\text{Hungarian}}=O(V\cdot E)=O(nm),\qquad T_{\text{KM}}=O(n^3),\qquad T_{\text{Hopcroft–Karp}}=O(E\sqrt{V}) $$
  • $ n=|L| $、$ m=|E| $；KM 中每个点最多调整 $ O(n) $ 次顶标，每次更新松弛量 $ O(n) $

核心要点

  • 匈牙利算法 = 对每个左点找增广路；找不到则该点在本轮无法匹配，继续下一个点即可
  • 用 vis 时间戳（stamp）代替每轮 memset，可把常数开销降到接近 0
  • 递归 DFS 在链长上万时易爆栈，生产环境建议改迭代版或调大栈/用 BFS（Hopcroft–Karp）
  • 无权用匈牙利，带权用 KM；最小权匹配把边权取负后跑 KM，或令 $ w'=W_{\max}-w $
  • KM 要求完全二分图：不存在的边补权值 0（最大化场景）或 $ -\infty $（必须匹配场景）
  • 匹配数偏小的常见原因：左右部划分写反、单向加边（无向匹配需双向加边）、忽略重边

技术细节与参数详解

参数 1：n_left / n_right（左右部规模）
  • 含义：左右部顶点数量，决定外层循环次数与数组大小
  • 类型：int
  • 默认值：无（必须由输入给定）
  • 取值范围：$ 1\sim 10^5 $（$ O(VE) $ 算法建议 $ \le 2000 $）
  • 对结果的影响：只影响性能不影响正确性；但若把较小的部分放左侧可减少增广次数
  • 推荐设置：左部取较小的一侧（$ \min(|L|,|R|) $ 放外层循环），稀疏大图改用 Hopcroft–Karp
参数 2：adj（邻接表）
  • 含义：adj[u] 存储左点 u 所有可连的右点编号
  • 类型：List[List[int]]
  • 默认值：空列表
  • 取值范围：元素在 $ [0, n_{right}) $
  • 对结果的影响：决定解空间。漏边会低估匹配数；无向匹配场景忘记双向加边是最高频 Bug
  • 推荐设置：去重（同一条边重复入表会拖慢 DFS）、按度数升序排序可提升命中率
参数 3：match_r（右部匹配数组）
  • 含义：match_r[v] = u 表示右点 v 当前匹配到左点 u，-1 表示未匹配
  • 类型：List[int]，长度 $ n_{right} $
  • 默认值：全部 -1
  • 取值范围：$ -1 $ 或 $ [0,n_{left}) $
  • 对结果的影响：直接承载答案，最终非 -1 的个数即最大匹配数
  • 推荐设置：初始化 -1；若需输出匹配方案，另存 match_l 便于查询
参数 4：vis / stamp（访问标记与时间戳）
  • 含义：本轮增广中右点是否已被访问；用递增时间戳避免每轮清空
  • 类型：List[int] + int
  • 默认值：全 0，stamp=0
  • 取值范围：stamp 单调递增，vis[v]==stamp 表示已访问
  • 对结果的影响：漏标记会导致 DFS 在交替环中死循环；时间戳实现错误会导致跨轮"污染"
  • 推荐设置：每轮 stamp += 1，判断用 vis[v] == stamp，比 memset 快一个数量级
参数 5：lx / ly（KM 顶标）
  • 含义：左右部顶标，需始终满足 $ l_x+l_y\ge w $
  • 类型：List[int]
  • 默认值：$ l_x(u)=\max_v w(u,v) $，$ l_y(v)=0 $
  • 取值范围：非负整数（权值为负时需先平移）
  • 对结果的影响：初始值取"行最大值"可保证可行；取值过小会破坏可行性，等价子图为空则死循环
  • 推荐设置：最大化问题按行最大值初始化；最小化问题先转负再按行最大值初始化
参数 6：slack（KM 松弛量）
  • 含义：$ slack[v]=\min_{u\in S}\{l_x(u)+l_y(v)-w(u,v)\} $，即把 $ v $ 拉进相等子图的最小代价
  • 类型：List[int]，长度 $ n $
  • 默认值：每轮置 INF
  • 取值范围：$ [0,\text{INF}] $
  • 对结果的影响：slack 取错会导致顶标调整量 $ \Delta $ 过大，跳过最优解
  • 推荐设置：INF 取所有权值和的上界（如 $ 10^{18} $ 或 float('inf')），每轮必须重置
参数 7：weight（边权矩阵）
  • 含义：$ w(u,v) $，KM 中要求完全图
  • 类型：List[List[int]] 或 numpy.ndarray
  • 默认值：无
  • 取值范围：任意实数（建议先整体平移为非负）
  • 对结果的影响：负权会导致顶标可行域为空；缺失边按 0 处理等于"允许空匹配"
  • 推荐设置：缺失边填 0（允许不匹配）或 $ -\text{BIG} $（强制匹配）；大规模稀疏图改用费用流/匈牙利 + 权值分解

代码示例

# ============ 1. 匈牙利算法：无权二分图最大匹配 ============
def hungarian(n_left, adj, n_right):
    match_r = [-1] * n_right          # 右部匹配数组，-1 表示尚未匹配
    vis = [0] * n_right               # 访问标记，存"时间戳"而不是布尔值
    stamp = 0                         # 全局递增时间戳，避免每轮清空数组

    def dfs(u):
        # 尝试为左点 u 找一条增广路
        for v in adj[u]:              # 遍历 u 能连的所有右点
            if vis[v] == stamp:       # 本轮已访问过 v，跳过防止死循环
                continue
            vis[v] = stamp            # 标记 v 已在本轮交替树中
            if match_r[v] == -1 or dfs(match_r[v]):
                # 条件1：v 未匹配 → 直接构成增广路终点
                # 条件2：v 的当前搭档能另寻出路 → 让位
                match_r[v] = u        # 把 v 匹配给 u
                return True           # 增广成功
        return False                  # u 在本轮无法匹配

    result = 0                        # 最大匹配边数
    for u in range(n_left):           # 每个左点依次尝试增广
        stamp += 1                    # 新的一轮，时间戳 +1（O(1) 清空 vis）
        if dfs(u):                    # 找到增广路则匹配数 +1
            result += 1
    return result, match_r            # 返回匹配数与匹配方案

# ============ 2. KM 算法：带权二分图最大权完美匹配 O(n^3) ============
def km(weight, n):
    # weight: n x n 权值矩阵（完全图；缺失边请填 0 或 -INF）
    lx = [max(weight[i]) for i in range(n)]   # 左顶标 = 该行最大权，保证可行性
    ly = [0] * n                              # 右顶标初始为 0
    match_r = [-1] * n                        # 右点匹配到的左点
    slack = [0] * n                           # 松弛量缓存
    pre = [-1] * n                            # 记录交替树中 v 的前驱左点
    INF = float('inf')                        # 松弛量初始上界

    def bfs(root):
        nonlocal slack, pre
        slack = [INF] * n                     # 每轮重置松弛量
        vis_l = [False] * n                   # 左点是否在交替树中
        vis_r = [False] * n                   # 右点是否在交替树中
        q = [root]                            # 交替树以 root 为根，BFS 扩展
        vis_l[root] = True                    # 根左点入树
        head = 0                               # 队列头指针（用列表模拟队列）
        while head < len(q):
            u = q[head]; head += 1             # 取出一个左点
            for v in range(n):                 # 枚举其所有右邻居（完全图）
                if vis_r[v]:                   # 已在树中的右点跳过
                    continue
                gap = lx[u] + ly[v] - weight[u][v]   # 当前顶标下的差值
                if gap < slack[v]:             # 更新到达 v 的最小松弛量
                    slack[v] = gap
                    pre[v] = u                 # 记录 v 的前驱，用于回溯增广路
                if slack[v] == 0:              # v 落入相等子图
                    vis_r[v] = True            # 把 v 加入交替树
                    if match_r[v] == -1:       # v 是未匹配点 → 找到增广路
                        cur_v = v              # 从 v 开始回溯翻转
                        while cur_v != -1:     # 沿 pre 指针一直回到根
                            u_prev = pre[cur_v]            # v 的前驱左点
                            v_prev = match_r[u_prev] if u_prev != root else -1
                            match_r[cur_v] = u_prev        # v 改配给 u_prev
                            cur_v = v_prev                 # 继续向前回溯
                        return True
                    else:                      # v 已匹配 → 把它的搭档加入树
                        u_next = match_r[v]
                        vis_l[u_next] = True
                        q.append(u_next)
            # 本层扩展完，若未找到增广路则整体调整顶标
            delta = INF
            for v in range(n):
                if not vis_r[v]:
                    delta = min(delta, slack[v])   # 取最小松弛量作为步长
            if delta == INF:                   # 图不连通时提前退出，避免死循环
                return False
            for i in range(n):
                if vis_l[i]:                   # 树中左点顶标下调
                    lx[i] -= delta
                if vis_r[i]:                   # 树中右点顶标上调
                    ly[i] += delta
                else:                          # 树外右点松弛量同步减小
                    slack[i] -= delta
        return False                           # 理论上不会走到这里

    for u in range(n):                    # 依次为每个左点找增广路
        bfs(u)                            # KM 中每点必能匹配（完全图）
    total = sum(weight[match_r[v]][v] for v in range(n) if match_r[v] != -1)  # 汇总权和
    return total, match_r                 # 返回最大权与匹配方案

# ============ 3. 调用示例 ============
if __name__ == "__main__":
    adj = [[0, 1], [0], [1, 2]]           # 左 0 连右 0,1；左 1 连右 0；左 2 连右 1,2
    cnt, mr = hungarian(3, adj, 3)        # 求最大匹配
    print("最大匹配数:", cnt, "匹配方案:", mr)   # 期望输出 3

    W = [[3, 1, 1],                       # 权值矩阵：3 个任务分给 3 个人
         [1, 4, 2],
         [2, 1, 5]]
    val, m = km(W, 3)                     # 求最大权完美匹配
    print("最大权和:", val, "方案:", m)      # 期望 3+4+5 = 12

复杂度分析

  • 匈牙利（DFS）：单次 dfs 最多访问每条边一次 → $ O(E) $；共 $ |L| $ 次增广 → 总时间 $ O(|L|\cdot|E|)=O(nm) $；空间为邻接表 $ O(n+m) $ + 匹配/标记数组 $ O(n) $
  • Hopcroft–Karp：每阶段 BFS 分层 + DFS 多路增广，阶段数 $ O(\sqrt{V}) $，总时间 $ O(E\sqrt{V}) $，适合 $ 10^5 $ 级稀疏图
  • KM：外层 $ n $ 个点 × 每个点 BFS 中最多调整 $ O(n) $ 次顶标 × 每次扫描 $ O(n) $ 条边 → $ O(n^3) $；空间 $ O(n^2) $ 存权值矩阵
  • KM 的优化：BFS 版（上面代码）比朴素 DFS 版少一个 $ n $，且避免递归爆栈；进一步可用 slack 增量维护把常数压到 1/3 左右

应用场景

  • 排班与岗位分配：护士排班、值班表、监考安排（人 × 岗位）
  • 推荐系统召回配对：用户 × 商品、问题 × 答案、简历 × 岗位的最优一对一匹配
  • 任务调度：CPU 核 × 任务、无人机 × 配送点（带权用 KM，最小化总耗时取负）
  • 网络与通信：基站 × 用户资源块分配、信道与频谱配对
  • 图论推论：由 König 定理求最小点覆盖、最大独立集、DAG 最小路径覆盖
  • 计算机视觉：多目标跟踪中的检测框 × 轨迹关联（匈牙利算法是 SORT/DeepSORT 的核心组件）

交叉熵损失（Cross Entropy Loss）

类别：损失函数 | 难度：入门

算法简介

交叉熵源自信息论，衡量两个概率分布 $ p $（真实）与 $ q $（预测）之间的差异：

$$ H(p,q)=-\sum_{c} p_c\log q_c $$

在分类任务中，真实分布通常是 one-hot（或标签平滑后的软标签），预测分布由 logits 经 softmax 得到。最小化交叉熵等价于最大化正确类别的对数似然，也等价于最小化 $ D_{KL}(p\|q) $（因为 $ H(p) $ 与参数无关）。

PyTorch 的 nn.CrossEntropyLoss 把 LogSoftmax + NLLLoss 融合为一个算子（数值稳定、省一次显存读写），因此输入必须是未归一化的 logits，而不是 softmax 后的概率——这是新手最高频的错误：对已 softmax 的输出再送进 CE，会让梯度被压缩、收敛变慢甚至学不动。

它的三个可调维度是：类别加权（应对类别不平衡）、忽略索引（应对 padding / 无效标签）、标签平滑（缓解过置信与过拟合）。此外 reduction 决定标量聚合方式，直接影响多卡/梯度累积时的损失尺度。

原理示意图

数学公式

（1）Softmax

$$ p_c=\frac{e^{z_c}}{\sum_{j=1}^{C}e^{z_j}},\qquad c=1,\dots,C $$
  • $ z_c $：第 $ c $ 类的原始打分（logit），可为任意实数
  • $ C $：类别数
  • 分母保证 $ \sum_c p_c=1 $；实现上用 $ e^{z_c-\max z} $ 防上溢

（2）单样本交叉熵（one-hot 标签）

$$ \ell = -\log p_{y}= -z_{y}+\log\sum_{j=1}^{C}e^{z_j} $$
  • $ y $：真实类别下标；$ p_y $：模型给正确类的概率
  • 第二步是代数化简——这正是"LogSoftmax + NLL"融合的数值稳定实现

（3）带权重的交叉熵（reduction='mean'）

$$ \ell=\frac{\sum_{n=1}^{N} w_{y_n}\left(-z_{n,y_n}+\log\sum_{c=1}^{C}e^{z_{n,c}}\right)}{\sum_{n=1}^{N} w_{y_n}} $$
  • $ N $：batch 内有效样本数（或像素数，取决于输入维度）
  • $ w_{y_n} $：样本 $ n $ 所属类别的权重（来自 weight 张量）
  • 分母是权重之和而非 $ N $：保证损失尺度不随权重整体放大

（4）标签平滑（label smoothing）

$$ y_c^{\text{LS}}=(1-\varepsilon)\,y_c+\frac{\varepsilon}{C} $$
$$ \ell^{\text{LS}}=-\sum_{c=1}^{C}y_c^{\text{LS}}\log p_c=(1-\varepsilon)\,\ell+\varepsilon\cdot\frac{1}{C}\sum_{c=1}^{C}\left(-\log p_c\right) $$
  • $ \varepsilon $：平滑系数（label_smoothing，$ [0,1] $）
  • 第一项：原交叉熵按 $ 1-\varepsilon $ 缩放；第二项：与均匀分布的交叉熵
  • 效果：目标概率上限被压到 $ 1-\varepsilon+\varepsilon/C $，抑制 logit 无限增大

（5）对 logits 的梯度（反向传播核心）

$$ \frac{\partial \ell}{\partial z_c}=p_c-y_c,\qquad \frac{\partial \ell}{\partial z_c}\Big|_{\text{weighted}}=w_y\,(p_c-y_c) $$
  • 梯度形式极简：预测减真值，因此 CE + softmax 的反传只需一次减法
  • 当 $ p_c\to y_c $ 时梯度趋 0，训练自然收敛

核心要点

  • 输入是 logits，内部自带 softmax；不要再手动 softmax（除非用 NLLLoss）
  • 目标可以是 类别下标（long，shape (N,) 或 (N,d1..dK)）或 概率分布（float，与输入同 shape）
  • weight 影响的是梯度与损失的相对大小，不是采样概率；极端不平衡时建议配合重采样
  • ignore_index 仅在目标为类别下标时生效；reduction='mean' 时分母不含被忽略样本
  • 多卡 DDP + reduction='mean' 会出现"按卡平均"的偏差，梯度累积时应用 'sum' 并手动除以全局有效样本数
  • 语言模型中的 next-token 预测、分割任务中的逐像素预测，本质都是"把 logits 展平成 $ (N,C) $ 后算 CE"

技术细节与参数详解

参数 1：weight（类别权重）
  • 含义：长度为 $ C $ 的一维张量，为每个类别指定损失权重，用于缓解类别不平衡
  • 类型：torch.Tensor（float），shape (C,)，需与输入同 device/dtype
  • 默认值：None（等价于全 1）
  • 取值范围：任意非负实数；常用 $ w_c \propto 1/f_c $ 或 $ 1/\sqrt{f_c} $（$ f_c $ 为类别频率）
  • 对结果的影响：放大稀有类的梯度，改善 macro-F1/召回；过大（如 $ 10^3 $）会导致训练震荡、BN 统计偏移
  • 推荐设置：w_c = N/(C\cdot n_c)（sklearn 的 balanced），或 $ (1/f_c)^{0.5} $ 折中；先小步试 1~5 倍再放大
参数 2：ignore_index
  • 含义：指定一个标签值，该位置的样本不参与损失与梯度
  • 类型：int
  • 默认值：-100
  • 取值范围：任意整数，通常取 -100 或 -1（不要与真实类别 $ [0,C) $ 冲突）
  • 对结果的影响：用于 padding 的 -100、分割中的"忽略区域"；配错会整批样本被忽略、loss 恒为 0 或 NaN
  • 推荐设置：保持默认 -100，并在数据管道里显式用 -100 填充；仅当目标为类别下标时有效
参数 3：reduction
  • 含义：输出的聚合方式
  • 类型：str
  • 默认值：'mean'
  • 取值范围：'none' | 'mean' | 'sum'
  • 对结果的影响：'none' 返回逐样本损失（shape (N,)），'mean' 加权平均（分母为权重和），'sum' 求和（数值随 batch 线性增长）
  • 推荐设置：需要样本级重加权/难例挖掘用 'none'；常规训练 'mean'；梯度累积或自定义归一化用 'sum'
参数 4：label_smoothing
  • 含义：标签平滑系数 $ \varepsilon $，把 one-hot 目标与均匀分布混合
  • 类型：float
  • 默认值：0.0
  • 取值范围：$ [0.0, 1.0] $（实用区间 $ 0.05\sim0.2 $）
  • 对结果的影响：降低过置信、提升校准与泛化，常带来 0.3~1 个点提升；过大（>0.3）会欠拟合、收敛变慢
  • 推荐设置：分类/检测用 0.1；蒸馏、噪声标签场景可到 0.2；需要精确概率输出时慎用
参数 5：size_average / reduce（已弃用）
  • 含义：旧版权重聚合开关，分别对应"是否平均""是否归约"
  • 类型：bool
  • 默认值：None（跟随 reduction）
  • 取值范围：True / False / None
  • 对结果的影响：一旦显式设置会覆盖 reduction，导致行为与预期不符
  • 推荐设置：一律不传，统一使用 reduction
参数 6：input 的形状与语义
  • 含义：未归一化 logits
  • 类型：Tensor
  • 默认值：无
  • 取值范围：shape (C,)、(N,C) 或 (N,C,d1,...,dK)，dtype 为 float32/float16/bfloat16
  • 对结果的影响：第 1 维必须是类别维；若把 (N,d1,d2,C)（channel-last）直接送入会算错类别
  • 推荐设置：分类用 (N,C)；分割用 (N,C,H,W) + target (N,H,W)；混合精度下建议在 autocast 内调用
参数 7：target 的两种模式
  • 含义：真实标签，类别下标或概率分布
  • 类型：LongTensor（下标）或 FloatTensor（分布）
  • 默认值：无
  • 取值范围：下标在 $ [0,C) $（或 ignore_index）；分布每个元素 $ \in[0,1] $ 且按行和为 1
  • 对结果的影响：PyTorch 不校验概率是否合法，传入未归一化/含负值的目标会得到误导性损失与不稳定梯度
  • 推荐设置：软标签务必先 softmax(dim=1) 或确保归一化；蒸馏时用 teacher 概率并乘温度 $ T^2 $

代码示例

# ============ 1. 最基础的用法：多分类 ============
import torch                        # 导入 PyTorch 主库
import torch.nn as nn               # 导入神经网络模块（含损失函数）
import torch.nn.functional as F     # 导入函数式接口，便于手写对照

torch.manual_seed(0)                # 固定随机种子，保证结果可复现
logits = torch.randn(4, 5, requires_grad=True)   # 4 个样本、5 类的原始打分
target = torch.tensor([0, 2, 4, 1])              # 每个样本的真实类别下标（long）

criterion = nn.CrossEntropyLoss()                # 默认 reduction='mean'
loss = criterion(logits, target)                 # 前向：内部自动做 log_softmax + NLL
print("默认 CE:", loss.item())                    # 打印标量损失

# ============ 2. 手工实现，验证与官方一致 ============
logp = F.log_softmax(logits, dim=1)              # 先做 log_softmax（数值稳定）
manual = -logp.gather(1, target.view(-1, 1)).mean()   # 取出正确类的 log 概率再取负平均
print("手工 CE:", manual.item())                  # 应与上面数值完全一致

# ============ 3. 类别不平衡 + 标签平滑 ============
weights = torch.tensor([1.0, 2.0, 5.0, 1.0, 3.0])     # 稀有类给更大权重
crit_w = nn.CrossEntropyLoss(weight=weights,          # 加权交叉熵
                             label_smoothing=0.1,     # 10% 标签平滑
                             reduction='mean')        # 按权重和求平均
print("加权+平滑:", crit_w(logits, target).item())     # 损失尺度仍在合理范围

# ============ 4. 忽略 padding 位置（NLP 常见） ============
seq_logits = torch.randn(2, 6, 10)                       # batch=2, 序列长 6, 词表 10
seq_target = torch.tensor([[3, 5, 7, -100, -100, -100],  # 后 3 个位置是 padding
                           [1, 2, 9, 4, -100, -100]])    # 同样用 -100 标记
crit_ig = nn.CrossEntropyLoss(ignore_index=-100)         # 忽略 -100 的位置
# 需要把 (N,T,C) 转成 (N*T,C)，target 展平，CE 才能逐 token 计算
loss_ig = crit_ig(seq_logits.reshape(-1, 10), seq_target.reshape(-1))
print("忽略 padding:", loss_ig.item())                    # 分母只统计有效 token

# ============ 5. 软标签（蒸馏 / 混合增强） ============
teacher = torch.randn(4, 5).softmax(dim=1)            # 教师概率分布（已归一化！）
hard = F.one_hot(target, num_classes=5).float()       # 学生真值 one-hot
soft_target = 0.7 * teacher + 0.3 * hard              # 混合软标签，行和仍为 1
crit_soft = nn.CrossEntropyLoss()                     # 目标为 float 时按分布计算
print("软标签 CE:", crit_soft(logits, soft_target).item())

# ============ 6. 逐样本损失（难例挖掘 / 自定义加权） ============
crit_none = nn.CrossEntropyLoss(reduction='none')      # 不做归约，返回 (N,)
per_sample = crit_none(logits, target)                 # 每个样本一个损失值
hard_weight = torch.tensor([1.0, 3.0, 1.0, 2.0])       # 人为放大难例权重
print("加权逐样本:", (per_sample * hard_weight).mean().item())  # 手动聚合成标量

复杂度分析

  • 时间复杂度：$ O(N\cdot C) $。softmax 需对每个样本遍历全部类别求指数和（$ O(C) $），−log p_y 为 $ O(1) $，共 $ N $ 个样本/像素
  • 空间复杂度：$ O(N\cdot C) $ 保存概率/中间量；融合实现（fused log_softmax + NLL）只需 $ O(N) $ 额外空间，避免生成完整概率矩阵
  • 与朴素实现对比：先 softmax 再 log 会多一次读写并可能下溢（$ \log 0=-\infty $）；log_softmax 用 log-sum-exp 技巧保证稳定
  • 反向传播：梯度 $ \partial\ell/\partial z_c=p_c-y_c $，复杂度同为 $ O(N\cdot C) $，但无需保存 softmax 中间结果（可重算），显存更省

应用场景

  • 图像分类：ResNet/ViT 的 top-1 训练目标；配 label_smoothing=0.1 是 timm 的默认配方
  • 语义分割：(N,C,H,W) 逐像素 CE，ignore_index 屏蔽未标注区域
  • 语言模型：next-token 预测，配合 ignore_index=-100 屏蔽 prompt 部分，只对回答段计损失
  • 目标检测/蒸馏：软标签 CE 承载教师分布（常乘 $ T^2 $ 补偿温度缩放）
  • 长尾/不平衡分类：weight + 重采样 + focal 变体组合使用
  • 多任务学习：与其他损失加权求和前，用 reduction='none' 做样本级归一化

模型合并 Model Merging

类别：大模型微调 | 难度：中等

算法简介

模型合并（Model Merging）是一条"不训练、不用数据"的捷径：把多个同源微调（共享同一底座初始化）的模型，直接在参数空间里做算术，得到一个同时具备多种能力的新模型。它解决的是落地中的经典困境——客服模型、合同模型、代码模型各自训了一版，效果都不错，但谁也干不了别人的活；再训一个"全能模型"要数据要算力，集成（ensemble）又要 $ N $ 倍推理成本。

核心概念是任务向量（task vector）：

$$ \tau_t=\theta_t-\theta_0 $$

它表示"微调把底座推离了多少"。于是合并就是在底座上叠加若干任务向量。前提是线性模式连通性（linear mode connectivity）：同源微调的权重落在损失面的同一盆地内，线性插值不会掉进"性能悬崖"。

主流方法谱系：

方法核心思想适用场景
Model Soup（加权平均）$ \theta=\sum_t \lambda_t\theta_t $同任务多次超参微调，稳定提点
Task Arithmetic$ \theta=\theta_0+\lambda\sum_t\tau_t $多任务能力叠加、能力增减
TIES-Merging修剪 → 定符号 → 只平均同号分量多模型干扰严重（符号冲突）
DARE随机丢弃大部分 delta 并重缩放delta 高度冗余，压缩后几乎无损
SLERP球面线性插值，保持方向与模长两模型合并，比线性更平滑
MergeKit上述方法的工程化组合（含分层合并）生产落地首选工具

失败的三类根因：符号冲突（同一参数被不同任务推向相反方向，平均后互相抵消）、幅度失衡（少数大 delta 淹没其他任务）、冗余噪声（大量微小 delta 只是噪声，参与平均反而引入干扰）。TIES 与 DARE 正是分别针对前两者与第三者的解药。

原理示意图

数学公式

（1）任务向量与任务算术

$$ \tau_t=\theta_t-\theta_0,\qquad \theta_{\text{merged}}=\theta_0+\lambda\sum_{t=1}^{T}\tau_t $$
  • $ \theta_0 $：底座（base）参数；$ \theta_t $：第 $ t $ 个微调模型参数
  • $ \tau_t $：任务向量，同 shape 于 $ \theta $
  • $ \lambda $：缩放系数；$ T $：参与合并的模型数
  • $ \lambda>1 $ 会强化任务能力但可能破坏通用能力；$ \lambda<0 $ 可用于"遗忘"某能力

（2）加权平均（Model Soup / 线性插值）

$$ \theta_{\text{merged}}=\sum_{t=1}^{T}\lambda_t\theta_t,\qquad \sum_{t=1}^{T}\lambda_t=1 $$
  • $ \lambda_t $：第 $ t $ 个模型的权重（常取均匀 $ 1/T $，或按验证集性能搜索）
  • 约束权重和为 1，保证合并在参数凸包内，最不易掉点

（3）TIES 第一步：Trim（幅值修剪）

$$ \tilde{\tau}_t^{(j)}=\begin{cases}\tau_t^{(j)}, & |\tau_t^{(j)}|\ge \text{TopK}_k\bigl(|\tau_t|\bigr)\\[2pt] 0, & \text{otherwise}\end{cases} $$
  • $ \tilde{\tau}_t^{(j)} $：修剪后第 $ j $ 个参数；$ k $：保留比例 density（如 0.2 表示保留 20%）
  • $ \text{TopK}_k(\cdot) $：按绝对值取前 $ k $ 分位的阈值
  • 作用：剔除噪声级微小 delta，降低后续冲突面

（4）TIES 第二步：Elect Sign（符号选举）

$$ \gamma^{(j)}=\operatorname{sign}\Bigl(\sum_{t=1}^{T}\tilde{\tau}_t^{(j)}\Bigr) $$
  • $ \gamma^{(j)}\in\{-1,0,+1\} $：第 $ j $ 个参数的最终符号
  • 论文原版用幅值加权投票（$ \sum_t |\tilde\tau_t^{(j)}|\cdot \operatorname{sign}(\tilde\tau_t^{(j)}) $），即"票重 = 幅值"
  • 作用：让占主导方向的任务决定该参数的走向

（5）TIES 第三步：Disjoint Merge（不相交平均）

$$ \tau_{\text{merged}}^{(j)}=\frac{\sum_{t=1}^{T}\tilde{\tau}_t^{(j)}\cdot\mathbb{1}\bigl[\operatorname{sign}(\tilde{\tau}_t^{(j)})=\gamma^{(j)}\bigr]}{\sum_{t=1}^{T}\mathbb{1}\bigl[\operatorname{sign}(\tilde{\tau}_t^{(j)})=\gamma^{(j)}\bigr]} $$
  • $ \mathbb{1}[\cdot] $：指示函数，条件成立取 1，否则 0
  • 分母是该参数"同号模型数"，避免被置 0 的项拉低均值
  • 效果：异号分量完全不参与，消除相互抵消

（6）DARE：随机丢弃 + 重缩放

$$ \hat{\tau}^{(j)}=\frac{m^{(j)}\odot\tau^{(j)}}{1-p},\qquad m^{(j)}\sim\text{Bernoulli}(1-p) $$
  • $ p $：丢弃率 drop_rate（典型 0.5~0.9）
  • $ m $：伯努利掩码；$ 1-p $：保留概率
  • 除以 $ 1-p $ 是无偏重缩放，保证 $ \mathbb{E}[\hat\tau]=\tau $，故"丢 90% 也几乎不掉点"

（7）SLERP（球面线性插值，两模型）

$$ \theta(t)=\frac{\sin\bigl((1-t)\Omega\bigr)}{\sin\Omega}\,\theta_1+\frac{\sin(t\Omega)}{\sin\Omega}\,\theta_2,\qquad \cos\Omega=\frac{\langle\theta_1,\theta_2\rangle}{\|\theta_1\|\,\|\theta_2\|} $$
  • $ t\in[0,1] $：插值位置；$ \Omega $：两参数向量的夹角
  • 与线性插值不同，SLERP 保持模长不变、沿球面走"最短弧"，中间态更平滑

核心要点

  • 同源是硬前提：所有模型必须从同一底座微调而来（同一 tokenizer、同一词表、同一初始化）
  • 先做评估基线：合并前记录各单模型在目标任务与通用任务上的分数，否则无法判断涨跌
  • 符号冲突严重（多个强任务互相打架）→ 用 TIES；delta 冗余（微调步数少、学习率小）→ 用 DARE；两者常串联使用（DARE-TIES）
  • density 是 TIES 最敏感的参数，通常从 0.2 开始扫 0.1/0.2/0.3/0.5
  • 分层合并（不同层用不同权重）往往优于全局统一权重，因为底层偏通用、顶层偏任务
  • 合并后必须检查：词表对齐（embedding/lm_head 尺寸一致）、chat template 一致、tokenizer 一致
  • 合并不能凭空创造能力：两个模型都没有的能力，合并后也不会有

技术细节与参数详解

参数 1：weight（模型权重 $ \lambda_t $）
  • 含义：每个模型在合并中的贡献系数
  • 类型：float（每个模型一个）
  • 默认值：均匀权重 $ 1/T $（MergeKit 中为 1.0 后归一化）
  • 取值范围：通常 $ [0,2] $；可为负（表示"减去该能力"）
  • 对结果的影响：线性调节能力配比；某模型权重过大→其能力主导、其他任务退化；总和非 1 时整体 delta 幅度被缩放
  • 推荐设置：先均匀权重跑基线，再在验证集上做网格/贝叶斯搜索；任务重要性差异大时按 2:1 之类比例分配
参数 2：density（TIES 保留比例 $ k $）
  • 含义：每个任务向量保留幅值最大的参数比例
  • 类型：float
  • 默认值：MergeKit 中 1.0（不修剪）；TIES 论文常用 0.2
  • 取值范围：$ (0,1] $
  • 对结果的影响：过小（<0.1）→ 丢失真实任务信号、欠拟合；过大（>0.5）→ 噪声与冲突重新涌入，TIES 退化为普通平均
  • 推荐设置：$ 0.2 $ 起步；参数越多（7B+）可越小（0.1）；小模型建议 0.3~0.5
参数 3：normalize（是否归一化权重）
  • 含义：是否把 weight 归一化为和为 1
  • 类型：bool
  • 默认值：True
  • 取值范围：True / False
  • 对结果的影响：True 时各模型权重被等比缩放，合并结果落在凸组合内、更稳；False 时权重绝对值即真实缩放，可放大总 delta（等效于调节学习率）
  • 推荐设置：保守合并保持 True；想强化整体任务能力时设 False 并小幅上调权重
参数 4：drop_rate（DARE 丢弃率 $ p $）
  • 含义：DARE 中随机丢弃 delta 参数的比例
  • 类型：float
  • 默认值：MergeKit DARE 配置常为 0.9
  • 取值范围：$ [0,1) $，实用 $ 0.5\sim0.95 $
  • 对结果的影响：丢弃率越高压缩越强、冲突越少，但过高（>0.95）会损失任务信息；重缩放因子 $ 1/(1-p) $ 随之放大，需注意数值溢出
  • 推荐设置：$ 0.9 $ 起步；微调步数多（delta 大）时可到 0.95；小数据微调建议降到 0.5~0.7
参数 5：rescale（DARE 重缩放开关）
  • 含义：是否对保留的 delta 乘以 $ 1/(1-p) $ 做无偏补偿
  • 类型：bool
  • 默认值：True
  • 取值范围：True / False
  • 对结果的影响：True 保持期望不变，是 DARE 有效的关键；设为 False 相当于整体缩小 delta，模型会"欠拟合"任务
  • 推荐设置：保持 True；仅在显存/dtype 溢出（fp16 下 $ 1/(1-p) $ 过大）时考虑关闭
参数 6：int8_mask（掩码精度）
  • 含义：是否用 int8 存储伯努利掩码以省显存
  • 类型：bool
  • 默认值：False
  • 取值范围：True / False
  • 对结果的影响：不改变结果，只影响峰值显存；7B 模型合并时开启可显著降低内存占用
  • 推荐设置：参数量 $ \ge $ 7B 或显存紧张时设为 True
参数 7：t（SLERP 插值位置）
  • 含义：两模型之间的插值比例
  • 类型：float
  • 默认值：0.5
  • 取值范围：$ [0,1] $
  • 对结果的影响：$ t=0 $ 完全取模型 A，$ t=1 $ 完全取 B；中间值在球面上平滑过渡，但仅在两个模型之间有效，不能直接扩展到多模型
  • 推荐设置：0.3~0.7 之间细扫（步长 0.1）；多模型场景改用 TIES/DARE
参数 8：base_model（底座 $ \theta_0 $）
  • 含义：计算任务向量时的参照模型
  • 类型：模型标识/路径
  • 默认值：无（必须显式指定）
  • 取值范围：与所有微调模型完全同源的底座
  • 对结果的影响：底座选错（例如用官方原版去减 LoRA 合并后的模型）会导致 $ \tau $ 含大量无关偏移，合并直接崩坏
  • 推荐设置：与训练脚本中 --model_name_or_path 完全一致；记录 commit hash 以防上游更新

# ============ 1. 任务算术 + 加权平均（最朴素的合并） ============
import torch                                        # 导入 PyTorch

def task_arithmetic(base, finetuned_list, lambdas):  # base: 底座 state_dict
    merged = {}                                      # 存放合并结果
    for k, v in base.items():                        # 遍历底座的每个张量
        if not torch.is_floating_point(v):           # 整型张量（如位置编码 buffer）跳过
            merged[k] = v.clone()                    # 直接沿用底座的值
            continue                                 # 进入下一个参数
        delta = torch.zeros_like(v)                  # 累积的任务向量，初始为 0
        for ft, lam in zip(finetuned_list, lambdas):  # 遍历所有微调模型及其权重
            delta += lam * (ft[k].float() - v.float())   # 累加 λ·(θ_t − θ_0)
        merged[k] = (v.float() + delta).to(v.dtype)  # 底座 + 总任务向量，转回原精度
    return merged                                    # 返回合并后的 state_dict

# ============ 2. TIES 合并（trim → elect sign → disjoint merge） ============
def ties_merge(base, finetuned_list, density=0.2, weights=None):
    if weights is None:                              # 未指定权重时用均匀权重
        weights = [1.0 / len(finetuned_list)] * len(finetuned_list)
    merged = {}                                      # 结果字典
    for k, v in base.items():                        # 逐参数处理
        if not torch.is_floating_point(v):           # 非浮点参数不参与合并
            merged[k] = v.clone()                    # 原样保留
            continue
        taus = []                                    # 存放各模型的（修剪后）任务向量
        for ft, w in zip(finetuned_list, weights):    # 遍历模型
            tau = (ft[k].float() - v.float()) * w    # 任务向量，先乘权重
            if density < 1.0:                        # 需要修剪时
                flat = tau.abs().flatten()           # 展平后取绝对值，便于求分位
                kth = int(flat.numel() * (1 - density))   # 保留前 density 比例的阈值下标
                thresh = torch.kthvalue(flat, max(kth, 1)).values   # 取得幅值阈值
                tau = torch.where(tau.abs() >= thresh, tau, torch.zeros_like(tau))  # 小于阈值置 0
            taus.append(tau)                         # 收集修剪结果
        stack = torch.stack(taus, dim=0)             # shape: (T, ...)，便于沿模型维聚合
        # 符号选举：按幅值加权投票（幅值 × 符号 再求和，取 sign）
        sign_sum = (stack.abs() * stack.sign()).sum(dim=0)   # 每个参数的加权票
        gamma = sign_sum.sign()                      # 得到最终符号 γ ∈ {-1,0,1}
        same = (stack.sign() == gamma.unsqueeze(0))   # 布尔掩码：哪些模型与该符号一致
        same = same & (stack != 0)                   # 被修剪为 0 的项不算同号
        num = (stack * same).sum(dim=0)              # 同号分量求和
        den = same.sum(dim=0).clamp(min=1)           # 同号模型数（防 0 除）
        merged[k] = (v.float() + num / den).to(v.dtype)   # 底座 + 不相交平均
    return merged                                    # 返回 TIES 合并结果

# ============ 3. DARE：随机丢弃 + 无偏重缩放 ============
def dare_apply(tau, drop_rate=0.9, rescale=True):     # tau: 单个任务向量
    mask = (torch.rand_like(tau) > drop_rate).to(tau.dtype)   # 以 1−p 概率保留
    out = tau * mask                                  # 丢弃部分置 0
    if rescale:                                       # 无偏重缩放
        out = out / (1.0 - drop_rate)                 # 期望保持 E[tau_hat] = tau
    return out                                        # 返回稀疏化后的 delta

# ============ 4. 落盘与加载 ============
def save_merged(state, path):                         # 保存为可直接 from_pretrained 的权重
    from safetensors.torch import save_file           # 用 safetensors，避免 pickle 风险
    save_file({k: v.contiguous() for k, v in state.items()}, path)  # 连续内存便于 mmap 加载
    print("已保存:", path)                             # 提示保存路径

复杂度分析

  • 时间复杂度：$ O(T\cdot P) $，$ T $ 为模型数、$ P $ 为参数量。TIES 额外包含排序：每个参数张量做一次 kthvalue（近似 $ O(P\log P) $ 或 $ O(P) $ 的选择算法），总开销仍为 $ O(TP) $ 量级；7B 模型双模型合并，单卡 CPU 约数分钟
  • 空间复杂度：$ O(P) $（流式逐张量处理时）到 $ O(TP) $（一次性载入全部模型）。MergeKit 用 lazy tensor + 分片加载把峰值压到约 $ O(2P) $
  • 无训练成本：不涉及前向/反向，不需要数据，这是相对继续微调最大的优势
  • 评估成本才是瓶颈：每次参数搜索都要跑完整评测集，实践中应先用小样本（数百题）粗筛，再全量验证

应用场景

  • 多能力合体：客服 + 合同 + 代码 + 风控四个垂类模型合成一个"全能"模型，替代 $ N $ 倍成本的集成
  • 垂类增强而不丢通用：在通用底座上叠加领域 delta，同时保留通用对话能力
  • 能力遗忘 / 去毒性：用负权重 $ \lambda<0 $ 减去有害能力向量（task negation）
  • 少量数据冷启动：没有足够数据重训时，把多个小数据微调模型合并以提升鲁棒性
  • 多超参模型融合：同一任务不同学习率/种子的 checkpoint 做 Model Soup，稳定涨点
  • LoRA 合并：把多个 LoRA 适配器合并进底座，或合并多个 LoRA（需注意秩与缩放）
