1. 美团 LongCat-2.5：1.6 万亿参数、全程国产算力，把"长程 Agent"做成了原生能力

11 月 2 日，美团 LongCat 团队发布 LongCat-2.5——总参数 1.6 万亿、每 token 激活约 480 亿的原生多模态模型，定位不是"更会聊天"，而是长程智能体任务。更值得记录的是它的一条硬约束：训练全程由国产算力完成。这是继 6 月 LongCat-2.0（首个在国产算力上跑通万亿参数全流程训练与推理）之后，"国芯国模"路线第一次把规模推到 1.6 万亿量级。

技术要点：

  • 视觉与文本统一为离散 Token：沿用 LongCat-Next 的路线，先用语义对齐编码器（SAE）生成原生分辨率特征，再用残差向量量化（RVQ）压成多层级词表 Token，以缓解视觉离散化的信息损失。视觉 Token 走离线预处理——固定 tokenizer 提前生成并缓存 TokenID，主干模型直接读预处理序列，这既简化了长序列打包/切分，也改善了分布式训练中不同任务的负载均衡。
  • 视觉码本与主干联合学习：团队在平均激活约 30 亿参数的较小 MoE 上验证，视觉与文本 Embedding 在 t-SNE 上已呈交织分布，说明两类信号开始共享语义空间，而不是"外挂一个视觉编码器"。
  • Agentic RL 的数据闭环：从 GitHub 公开仓库与内部真实场景取代码任务，针对筛选后的 PR 与关联 issue 自动生成可交互环境与可验证测试用例，用 fail-to-pass / pass-to-pass 校验任务有效性；再把实时 rollout 轨迹与通过率反过来做二次标注与筛选，并基于假阴性/假阳性分析持续修正 F2P 用例。
  • 长程训练的三个工程细节：① partial rollout 异步——每步保持过采样率，批次凑齐后暂停未完成轨迹、下一轮恢复，并按通过率动态调过采样率、过滤全对/全错的零梯度组；② 样本陈旧性——同一条轨迹的 Token 可能来自不同历史 checkpoint，于是裁剪采样阶段与训练阶段的 Logprob 差异、按历史累计差异调整每个 Token 的梯度贡献；③ 奖励防作弊——训练时断网、清 git 历史与文件缓存，另加 LLM judge 监督整条轨迹，对重复思考/重复调工具施加惩罚。
  • 专家组机制（MOPD）：延续 LongCat-2.0 的"专家组"设计，分别优化 Agent、推理、交互三类能力。为降低教师轨迹与学生采样的分布偏移，把教师每轮回复按固定长度切成 per-cut prefix，把学生自采样长度限制在对应范围；同一教师轨迹的多个 Prefix 分组送入同一推理引擎，共享 Prefill 与 KV Cache，再用 Tree Attention 一次前反向完成同组 OPD 训练。
  • 围绕超节点重排并行：国产加速器单卡显存不足 80GB，这是所有设计的前提。FSDP 与 EP 的并行度对齐单超节点卡数、CP 不超过该卡数，让参数 AllGather、专家 Token AlltoAll、KV AllGather 尽量留在超节点内高带宽域；混合词表并行对 Embedding、LMHead、N-gram 分片；MoonEP 上做阈值触发的动态专家复制，只在负载不均衡超阈值时启用；双重分片 FSDP 把 FP32 主权重与优化器状态再跨 FSDP 域分片。官方称该配置在长序列 SFT 上单卡吞吐较 DDP 基线提升 86%。

实验结果： 在美团自建的 AutomationBench、LongCatClawBench 上，LongCat-2.5 领先 Claude-Opus-5、GPT-5.6-Sol；在第三方终端操作基准 Terminal Bench v4.0 上得分 38.5，超过 GPT-5.6-Sol 但仍落后 Claude-Opus-5。需要提醒：前两个是厂商自建基准，第三方复现前不宜直接与公开榜单横比。

实测观感： 智东西的体验显示它生成速度快、前端视觉效果较好、PPT 图表丰富，但画面细节（如角色围巾位置）、空间与图层关系、PPT 排版仍有明显提升空间。这基本符合"1.6 万亿但激活 480 亿"的定位——广度够、精细度不足。

影响分析： 对国内团队，这条路线最有参考价值的不是参数，而是"80GB 单卡 + 超节点"这一约束下的整套并行与显存方案，它把"国产卡训万亿模型"从口号变成了可复述的工程配方。对电信这类有私有化需求的行业客户，LongCat-2.5 的意义在于：一条不依赖境外算力、可本地部署、原生支持视觉编程与办公任务的万亿级选项，第一次具备可比性。

2. Gemini 4 Carbon 登顶 AA v5.0：59 分、漏洞检测 88.2%，但先发给"防守方"

10 月 28 日，距 Gemini 4 Argon 亮相仅两周，Google DeepMind 发布新一代前沿模型 Gemini 4 Carbon。在更新到 v5.0 的 Artificial Analysis 智能指数上，Carbon 以 59 分排名第一，主打两件事：网络安全与长周期任务。发布由高级副总裁 Koray Kavukcuoglu 主导——他在 Demis Hassabis 卸任后接管了 Google DeepMind。

技术要点：

  • 长时程工程执行：官方称它能在复杂工程问题上连续运行数天。这句话的分量比跑分更重：它意味着模型侧的重点从"单轮答对"转向"多轮不跑偏、状态不丢、目标不漂移"，背后必然是长上下文、工具调用稳定性与错误恢复三者一起优化。
  • 网安能力的具体口径：漏洞检测得分 88.2%，安全代码生成成功率为前代 Argon 的两倍多。这是可量化的进步，但要注意"检测率"与"误报率"必须成对看——只公布前者，无法判断它在真实代码库里的可用性。
  • 节奏即治理：Carbon 最初只对网络安全防御者与安全项目合作伙伴开放，之后才扩大范围。这与 Argon 的审慎策略一致：把最强的攻防能力先交给"守方"，是当前前沿实验室对"能力扩散"的一种默认回应。
  • 定价维持：首发 API 价格每百万输入 Token 2 美元、输出 10 美元；优惠结束后价格翻倍，与 Argon 标准价持平。也就是说，能力提升被"首发折扣"包装，长期成本并未下降。

需要冷静的地方： 多家媒体指出 Carbon 的事实幻觉率高于前代，且访问受限导致第三方独立评测样本不足。一个"智能指数第一 + 幻觉更多"的组合并不矛盾——指数测的是难题通过率，不是事实可靠性。企业在把它接进生产流程前，检索增强与事实校验链路不能省。

影响分析： 这轮发布的信号是"能力分层发售"成为惯例：先给防御方、再给企业、最后给大众。对安全团队，Carbon 把"AI 辅助漏洞挖掘"的门槛又压低了一档；对普通开发者，短期内更现实的变化是价格与配额，而不是能力。另需注意，Google 同期还把 Genie 4（见第 6 条）推向市场，说明它的战略是"前沿模型 + 世界模型"双线押注。

3. Kimi K3.1 Pro：3T 参数、100 万上下文，开源权重把"准前沿"压到 11 月 4 日

10 月下旬上线的 Kimi K3.1 Pro，是月之暗面迄今最强的 3 万亿级参数模型，支持 100 万 Token 上下文，官方把优势场景明确定在长程编程、3D 创作、金融研究——这三个场景的共同点，是天然会触发长上下文与多 Agent 调用。

技术要点：

  • 规模与稀疏：3T 总参数延续"超大总参 + 小激活"的稀疏 MoE 范式。在单卡显存装不下全量权重的前提下，这已是万亿级模型的唯一现实解；真正的差异在路由质量与专家负载均衡，而不在参数数字。
  • 上下文工程：100 万 Token 不是"能塞进去"，而是"塞进去还能用"。长上下文模型的实际能力取决于三件事——位置外推是否稳定、KV 缓存的内存与带宽预算、以及长序列下的注意力召回精度。K3.1 Pro 把这三点押在"长程编程"上做验证，是聪明的选择：代码库天然有结构，便于检验"是否真的读到了远处的那一行"。
  • 能力位次：Artificial Analysis 智能指数 55 分，全球第四、开源模型第一，比 K3 提升 11 分；超过 Claude Fable 5.1、GPT-6 Astra、Gemini 4 Argon（三者均 53），仅次于 Claude Opus 5.5 的 58。这是首个"即将开源"且得分如此贴近前沿的模型。
  • 价格：输入 2 美元 / 输出 10 美元每百万 Token。媒体对"相当于闭源旗舰几成"的口径并不统一（有按 Opus 5.5 计为约一半的说法，也有按 GPT-6 Astra 计为 20% 的说法），差异来自对标型号与是否计入缓存/批处理折扣——采购比价时应统一按"同一任务总成本"折算。
  • 权重时间表：完整权重计划 11 月 4 日放出。这一点比跑分更关键：它把"开源能否追上闭源"从讨论变成了可复现实验。

争议与风险： 有外媒报道其推广过程中存在付费 influencer 相关争议，同时"技术至上但全球化受阻"的讨论也在升温。对一个准备开放权重的模型，这类非技术因素会直接影响海外企业的合规评估。

影响分析： K3.1 Pro 的真正意义在于把"开源 = 落后一代"的默认假设打破了一半。如果 11 月 4 日权重如期放出且社区能在消费级多卡上跑起来，"准前沿能力 + 可自托管"会成为 2027 年企业选型的默认选项之一。反之，若权重延期或量化后掉点严重，这轮叙事会迅速降温。建议 11 月 4 日后先用自有业务样本做一次小规模复现，再决定是否纳入技术选型。

4. DeepSeek 开源 Super-agent：Router/Worker 双层，让 AI 在没人 @ 的时候自己找活干

10 月 31 日晚，DeepSeek Harness 团队发布技术文章《Super-agent 设计探索：迈向更自主的 Agent 系统》，同步以 MIT 协议开源原型 dsh-superagent-prototype。它没有发布更大的模型，也没有刷新的推理基准，而是试图重设计"Agent 与人类如何分工"。

技术要点：

  • 双层架构：常驻 Router 层统一接收并分派交互——群聊消息、issue、PR 评论都从这里进入；Worker 层在独立会话与独立目录中隔离执行，彼此不共享工作区，从而支持并行多任务。Router 常驻意味着"AI 不再依赖某个聊天窗口存活"。
  • 主动发现问题：内部实例的实际案例是——没有 @、没有新建会话、没有人把群聊消息搬运到 GitHub，它自己在群聊里识别到一条软件问题线索，在独立目录复现问题、生成修复方案，然后回到原对话交付一条可评审的 Pull Request。人的角色从"派活"上移到"验收"。
  • 当前边界：公开原型只面向单个 GitHub 仓库，可选接入飞书，部分设计尚未实现。也就是说，这是架构探索而非成品。
  • 与 Claude Duet、A5 的差别：后者是"个人助理型主动 Agent"，重在理解项目、离开时继续工作、敏感操作前请求批准；Super-agent 更像"工程组织里的一个同事"，重在工作流入口（群聊/仓库）与交付物（PR）。前者优化体验，后者优化协作协议。

必须直视的风险： 有开发者在实测后指出两个问题——Token 账单涨到 3.8 倍，以及它能够读取整个家目录。后者不是 bug 而是设计后果：一个"主动找活"的常驻 Agent，天然需要更宽的读权限；而读权限一旦放宽，提示注入、误删、数据外泄的攻击面就同步放大。开源原型阶段可以接受，生产部署必须先做权限收口与审计日志。

影响分析： 这是今年 Agent 叙事的一次关键转向：从"更强的执行器"转向"更合理的工作流位置"。它带来的问题比答案更多——如何定义 Agent 的职责边界、如何评审它提交的 PR、如何限制它的读权限、如何计价它的自主行为。对正在做企业内 Agent 平台的团队，Super-agent 的 Router/Worker 分层与"独立目录隔离"是可直接借鉴的两条设计约束。

5. PixelUMM：不要 VAE、不要 ViT，NVIDIA 在像素空间把"看懂"和"画出来"合成一条路

统一多模态模型（UMM）长期采用"双通道"：ViT 提语义特征负责理解，VAE 提重建特征负责生成。代价是同一张图要占两份 Token，上下文迅速膨胀；更麻烦的是这套双流接口与主流 VLM 的单视觉流不兼容，想接进现有预训练管线就得大改数据与训练配方。NVIDIA 与滑铁卢大学的 PixelUMM 提出另一条路：彻底去掉预训练视觉编码器与 VAE，直接在像素上做理解与生成。

技术要点：

  • 像素接口：图像切成 16×16 patch，视频切成"4 帧 × 16 × 16"的 tubelet；每个 patch/tubelet 只过一层线性层就进入 Transformer，输出端一层 RMSNorm 加一层线性层还原像素。中间没有编码器、没有 VAE、没有离散视觉词表。
  • MoT 双专家：理解与生成各用一套投影（干净视觉走理解投影，加噪目标走生成投影），并用 Mixture-of-Transformers 让每层拥有两套归一化、注意力投影与前馈网络，但所有 Token 仍在同一个自注意力里互相可见。共享"看世界"的部分，分开"打包"和"摆盘"的部分。
  • 不做时间步嵌入：模型不显式告诉自己去噪到第几步，而是从带噪像素本身推断噪声强度。
  • 视频帧率对齐：≥4FPS 用 dense_mode（按 4FPS 采样、4 帧打包成 tubelet）；<4FPS 用 sparse_mode（按 1FPS 采样、单帧走图像投影），避免硬凑帧数造成浪费。
  • 统一对话格式：图像理解、视频理解、文生图、文生视频四类任务都塞进 ChatML；视频片段前标时间戳（如 <0.0 seconds>），生成任务则由助手"输出"一串带噪视觉 patch，在被去噪的过程中逐步成为真实图像/视频。

实验结果：

几个反直觉的发现（论文专门列了一节"没被采用的实验"）：

  • patch 越小越好，且加数据补不回来：16×16 的训练损失始终低于 32×32；即便 32×32 在同样序列预算下多见了 4 倍图片，也没追上。说明某些压缩造成的信息损失，不是靠堆数据能填的。

  • 压缩越轻越好，但最终没选最优：视频时空 patch 里"32×32×1 帧"（几乎不压时间）损失最低，可最终仍选 16×16×4 帧——因为它与 Wan2.2 等主流视频 VAE 的压缩比一致，便于对齐生态。最优方案与可用方案经常不是同一个。

  • 像素输出会留"棋盘纹"：高 CFG 下天空、墙面等平滑区会出现沿 patch 边界的网格痕迹。卷积风格输出头压得最干净但训练损失卡在 0.05 以上、画面更糊；PixelShuffle 方案平衡最好。不过发布模型与全部评测仍用最朴素的线性头。

  • 算力对不同任务不等价：8B 用约 1/3 步数达到 1.7B 同等损失；GPU 从 8 张加到 128 张，文本交叉熵收敛提速约 9 倍，而图像 MSE 只有约 1.3 倍。

影响分析： PixelUMM 不是一个"更强的模型"，而是一份架构取舍的对照实验报告——它把"如果换个设计会怎样"逐条跑完并公开，包括那些没被采用的分支。对做多模态工程的团队，最有价值的三条结论是：视觉 Token 的粒度选择比模型规模更影响收敛；生态兼容性会压倒纸面最优；以及"统一"的代价往往体现在某些子任务掉点上（SEED-I 掉了 5.41 分，而 BLINK 涨了 2.37 分）。

6. Genie 4：首个"实时"世界模型，画面、环境音与人物对话一次生成

10 月 27 日，Google DeepMind 以"面向受信任测试者的有限研究预览"形式发布 Genie 4。官方定位很明确：公司首个实时世界模型，且在生成模拟世界的同时原生生成音频——环境音、音乐与角色对话与画面在同一次生成中产出，而不是事后叠加。

技术要点：

  • 实时逐帧构建：系统实时生成可交互世界，用户可用键盘操控角色或镜头，用自然语言改变天气、移动镜头、添加角色或放置新物体，模型在执行每条指令的同时保持世界继续运行。
  • Gemini 3.8 Flash 在回路中当"导演"：这个引导代理负责把请求拆解成步骤、监控生成的帧，并在结果偏离意图时调整计划。这是"模型调度模型"的一个务实用法——把"想清楚要什么"与"画出来"解耦。
