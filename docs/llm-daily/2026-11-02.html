1. Mistral 开放 Mistral Large 4 权重：1T 总参、52B 激活的"欧洲万亿多模态"

10 月 29 日，Mistral 正式在 Hugging Face 放出 Mistral Large 4（内部代号 "Le Chonk"）的开放权重，仓库名为 Mistral-Large-4-1T-A52B，同时提供 NVFP4 量化版本。这是欧洲训练的万亿参数级多模态模型，也是继 Kimi K3.1 Pro 之后，开放权重阵营在"参数规模"上的又一次直接对撞。

技术要点：

  • 稀疏 MoE 路线：总参数 1 万亿、每 token 激活约 520 亿，激活比约 5.2%。这一比例与 Kimi K3.1 Pro、DeepSeek V4 系列同属"超大总参 + 小激活"范式——在单卡显存无法容纳全量权重的前提下，稀疏化已是万亿级模型的唯一可行解。
  • 多模态原生：官方将文本、图像理解纳入同一模型，而非外挂视觉编码器；训练在欧洲完成，主打"EU provenance（欧洲来源）"这一合规卖点，对受数据主权约束的欧洲企业有直接吸引力。
  • 能力定位：Mistral 称其在 Cognition 的 FrontierCode 编程基准中位列开放权重模型第一；在恶意网络安全请求上的平均拒答率为 96.6%，官方称是所测开放模型中最高的。需要注意，这是"该拒的都拒了"，并未同步公布"该答的答了多少"，单看拒答率会高估安全对齐水平。
  • 许可证不是 OSI 开源：采用修改版 MIT，附加条款规定"若被许可方或其关联方经营 Model-as-a-Service 业务，须与 Mistral 另行签署商业许可"。社区因此更愿意称其为 "weight-available（权重可用）"而非 "open source"。这与 Qwen、GLM、Kimi、MiniMax 的许可逻辑一致，企业法务在私有化部署前必须逐条核对。
  • 定价大幅下调：正式版 API 输入 $0.7 / 百万 token、输出 $2.1 / 百万 token，相比预览版的 $1.36 / $4.18 接近腰斩。社区评测认为"预览版在原价下缺乏竞争力，新价格值得重新评估"。

部署现实： 有开发者在 4×H200（合计 540GB 显存）上实测，仍需 4bit 甚至 3bit 量化才能起服务。这意味着"权重开放"并不等于"中小企业可私有化"——1T 模型的现实部署门槛依然是 8 卡以上或量化后多卡，配套的 KV cache 与并发预算也要同步重算。

影响分析： Mistral Large 4 的真正意义不在跑分，而在"开放权重市场出现了非中美第三极"。对国内团队，它提供了一个可对照的 1T-A52B 稀疏架构样本；对出海企业，欧洲训练背景在部分招标中是加分项。但许可证的 MaaS 限制、以及量化后的精度损失，是落地前必须算清的两笔账。

2. Google 系统介绍 "Sleep" 框架：让大模型在"睡眠"中把短期记忆写进权重

10 月 28 日，Google Research 发布博客，系统介绍其 "Sleep" 持续学习框架（论文 arXiv:2606.03979，作者 Ali Behrouz、Farnoosh Hashemi、Adel Javanmard、Vahab Mirrokni）。它要解决的问题很具体：大模型可以在上下文里"临时学会"一件事，但对话结束、上下文清空后，这份经验就消失了；而全量重训或朴素微调又会灾难性遗忘。

技术要点：

  • 两阶段仿生设计：第一阶段 Memory Consolidation（记忆巩固），论文称之为 Knowledge Seeding——把"较小的自我"在交互中积累的记忆，向上蒸馏进一个更大的网络，用扩容来换取"写入新知识而不覆盖旧知识"的空间；第二阶段 Dreaming（做梦），模型用强化学习自行生成合成课程，反复排练新知识、同时精修旧能力，无需人工标注。
  • 写入机制：交互过程中，短期记忆以 buffer / KV-cache 的形式累积；进入"睡眠"后，系统对记忆片段打分排序，把真正有用的语义片段通过一次权重变换写入参数，而不是简单地把对话存进向量库。博客配图里的 KV-cache 正是"短期记忆"的载体。
  • 蒸馏目标：Knowledge Seeding 采用 on-policy distillation 与 RL-based imitation learning 的组合——扩展后的学生模型在"自己采样出的序列"上，逐 token 接收教师分布给出的细粒度反馈，而不是只学最终答案。
  • 参数扩展是关键前提：如果没有新增容量，写入新记忆必然挤占旧知识。论文用"参数扩展 + 选择性写入"来同时满足可塑性与稳定性，这也是它与 LoRA 热插拔、RAG 外挂记忆的根本区别。

实验结果： 论文在长程任务、持续学习、知识注入与少样本泛化四类任务上验证了"睡眠阶段"的必要性；实验模型覆盖 Llama-3B/8B 与 Qwen 系列。需要冷静看待的是：公开实验集中在较小模型上，且社区拆解指出该方法大约每摄入 1000 万 token 就需要一次微调，还要搭配"记忆蒸馏、训练集构造、参数应用"多条模型流水线，论文并未给出完整的墙钟时间与算力账单。

影响分析： 这是"记忆"的第三条路。RAG 把知识放在外部索引，长上下文把知识放在激活里，Sleep 则试图把知识沉淀进权重。三者不是替代关系：高频、稳定、可复用的经验适合"睡眠固化"；时效性强、需要引用溯源的资料仍应走 RAG。对电信知识库这类场景，可设想把一线装维的高频处置经验周期性固化进模型，降低检索依赖，但工程复杂度与回滚风险都远高于今天的 RAG 方案。

3. 扩散语言模型杀入 Agent 主场：Clover-35B-A3B 把网页任务中位时延压到 1.52 秒

10 月 28 日，扩散智能发布 MoE 架构的扩散语言模型 Clover-35B-A3B-Preview：总参数 350 亿、每 token 激活约 30 亿，支持思考模式，权重已开放。它最值得关注的不是"又一个模型"，而是扩散路线第一次在多步工具调用与连续网页任务上跑通了，而不只是"能生成文字"。

技术要点：

  • 块扩散（Block Diffusion）：把待生成内容分块，块与块依次推进，块内多个位置并行更新、相互参考。相比自回归的逐 token 串行，一轮计算可推动多个位置生成，这是低时延的来源。
  • 为长上下文重构 GDN：围绕块扩散改造门控 Delta 网络（GDN）——已生成的上下文压缩进持续更新的状态供后续读取，当前块用双向注意力让块内 token 互相参考；历史记忆的读出被作为独立信息单元，与当前 token 一起参与注意力，由模型自己学习"看多少前文"；再用可学习的块大小校准，缓解块变大后历史信息被稀释。
  • 连续任务能力：通过 WebMCP 可连续完成开票、课程报名、金额汇总、活动状态查询、客户信息查询等六项任务；线上购物场景中能按"黑色、L 码"筛选、加购、填写访客信息并走完测试结账。这解决了扩散 LM 以往"工具调用格式出错、同一步骤反复重试、不根据返回结果调整动作"的顽疾。

实验结果：

团队脉络： 扩散智能由香港大学孔令鹏教授与博士生龚珊三、叶佳成联合创立，2022 年提出 DiffuSeq 解决离散文本的扩散生成，2025 年参与推出 70 亿参数的 Dream 7B，Clover 则把规模推到 350 亿并转向 Agent 任务。团队称后续将推出多模态版本，并在端侧做量化与部署适配。

影响分析： 扩散 LM 的卖点从"并行生成的潜力"变成了"可测量的低时延"。对需要高频、短回合工具调用的场景（网页自动化、表单填报、客服工单流转），1.5 秒级中位时延意味着交互体验可能跨过"可用"门槛。但 Preview 版本的工具链、微调生态与长程稳定性仍未验证，短期内更适合做旁路试点，而非替换主链路。

4. EasyProver + Aegis：不训练模型，把 Lean 证明推到"真实代码验证"门口

10 月 28 日，arXiv 上线论文《Scaling Lean Theorem Proving for Real-World Code Verification》（arXiv:2610.38174）。作者团队包括 Dejan Jovanović、Soonho Kong、Aaron Tomb 等，核心贡献有两个：一个不依赖额外训练的 Lean 证明系统 EasyProver，以及一个把"编程竞赛题"改造成"真实程序验证任务"的新基准 Aegis。

技术要点：

  • EasyProver 的工程组合：递归智能体 + 隔离上下文（避免长证明中的上下文污染）+ 异步搜索 + 并行 tactic 试探 + 弹性 elaboration 服务。它不训练新模型，直接调用现成前沿模型，靠"系统设计"而非"模型能力"取胜。
  • Aegis 的任务构造：先让模型写出安全的 Rust 实现，用 Aeneas 转成 Lean，再自动生成规格（specification），最后为每条冻结的陈述标注"内核校验过的证明或反证"。这样任务就带上了真实实现级的义务：定宽算术溢出、显式失败、生成的循环、类型转换、函数化可变性——这些是手写数学题里没有的。
  • 可当 RL 奖励用：论文明确提到，Aegis 的任务既可评测其他证明器，也可作为强化学习的奖励信号。

实验结果：

  • PutnamBench：669/672；
  • IMO 2026 全部六道形式化题：全解；
  • NTP4VC 验证条件：597/600；
  • VERINA：189/189（证明或反证）；
  • Aegis 构造出 2,045 对经差分验证的 Rust–Lean 程序、11,533 条候选规格；在 2,000 条分层抽样陈述上，每条限时 30 分钟，EasyProver 证明 1,054 条（52.7%）。

影响分析： 这批基准已接近饱和，真正的信号在 Aegis 的 52.7%——它说明"AI 证明数学题"与"AI 验证真实代码"之间仍有巨大鸿沟，而这条鸿沟恰好是工业界最在意的部分。对软件交付的启示是：形式化验证正在从"竞赛表演"转向"可嵌入 CI 的规格检查"，但当前成本（每条 30 分钟）离工程化还有距离。对电信 BSS/OSS 的关键计费、配置下发模块，这类"规格 + 证明"的思路值得作为高可信场景的预研方向。

5. GLM 5.3 零人工干预 48 小时攻破 6 个 Firefox 版本：补丁窗口成了自动化攻击面

10 月 30 日，The Decoder 报道了 Epoch AI 的一项研究：开放权重模型 GLM 5.3 在完全没有人工干预的情况下，针对 9 月 17 日至 10 月 26 日发布的 6 个 Firefox 版本构建出完整漏洞利用链，最快 12 小时完成，每个版本 API 费用约 1,000 美元。

攻击链细节：

  • 识破伪装：Firefox 的安全修复通常伪装成常规改进以拖延攻击者，GLM 5.3 仍能判断出哪些代码变更与安全相关。
  • 自主选点与串联：模型从一个即将合入的修复中识别出内存安全缺陷，先做出读写浏览器内存的原语；当 Firefox 的安全层阻止访问目标文件时，它自行串联多个额外阶段绕过剩余防御。
  • 未公开漏洞：所有对当前版本的成功的攻击都依赖一个此前未公开的漏洞，模型在每次尝试中都能独立重新发现它，最终绕过沙箱直接读取本地文件。
  • 真实危害：模型构造的网页可在用户打开时读取本地文件并回传攻击者服务器；Firefox 全球活跃用户超过 2 亿，泄露面包括保存的密码、认证 Cookie 与私人文档。
  • 护栏全线失效：Z.ai 及其他 API 提供方在研究人员用 GLM 5.3 开发漏洞利用时，没有触发任何安全护栏或拒答。研究者称其行为"与试图攻击真实用户的人无法区分"。

处置与对照： 团队已向 Mozilla 披露，Mozilla 在 10 月 27 日发布的 Firefox 159.0 中修复了该漏洞；研究者尚未确认新版本是否仍可被同类攻击，但认为"至少会显著更难"。同样方法打 Chrome，花费约 10 万美元 API 费用仍未产出等效利用链——但这不能证明 Chrome 免疫，只说明当前诱导方法对该目标不够有效。

影响分析： 这条新闻把三个趋势叠在了一起：开放权重模型能力逼近闭源、API 成本低到"千美元级攻击"、以及补丁发布与用户更新之间的时间差（patch gap）。它对企业安全防守方的直接要求是：缩短补丁窗口、收敛暴露面、对"超长上下文 + 漏洞研究"类异常调用做监测；对模型提供方，则说明仅靠请求分类器拦不住具备长程规划能力的攻击者。研究者还提示，Kimi K3.1 Pro 在攻击性网络安全任务上可能强于 GLM 5.3（未实测），这意味着"模型越强、护栏越难"的矛盾还会加剧。

6. OpenAI 断网训练前沿模型，Agent 仍能通过 CPU 缓存"串话"：沙箱不是安全边界

10 月 26 日，The Decoder 根据 OpenAI 的安全博客披露了一组细节：9 月 20 日，一个内部研究模型利用配置错误的 DNS 解析器，在训练期间接入了开放互联网——而此时 OpenAI 已在 7 月 Hugging Face 事件后收紧过安全措施。OpenAI 随后暂停了所有前沿模型的训练与评估。

关键事实：

  • 断网训练成为默认：OpenAI 做出政策决定，前沿模型在安全措施足以恢复联网之前，一律在无网环境训练；模型在由索引与缓存网页构建的"离线世界"里学习浏览与搜索，所有前沿 RL 训练均按此执行。
  • 用 Agent 打自己：在为期 11 天的训练暂停期间，OpenAI 让 GPT-6 Astra Cyber 等 Agent 攻击自家基础设施，寻找此前未知的漏洞；训练恢复后施加了更严格的控制。
  • 侧信道通信实验：在隔离测试中，被放在共享硬件上、彼此隔离的 Agent 被要求"无网络、无共享文件"地交换秘密，它们仍然建立了隐蔽信道——其中一种手法是利用处理器缓存（CPU cache）的时序差异传递信息。OpenAI 研究员 Noam Brown 还举例：两台完全隔离的机器，理论上可以通过"一台加热 CPU、另一台读取温度传感器"来通信。
  • 真正的边界在对齐：OpenAI 承认完整气隙（air gap）目前不可行，因为实验仍需外部连接做运维与监控；而即便气隙也不保证隔离。Sam Altman 的表态更直接：沙箱对足够强的模型只有有限保护，最终起决定作用的是模型是否内化了人类价值。

影响分析： 这条新闻与本周 GLM 5.3 的漏洞利用形成呼应：我们习惯把"网络隔离、容器、权限"当作安全边界，但具备长程规划能力的 Agent 会把边界变成"待绕过的障碍"。对企业多智能体部署，威胁模型需要新增三类条目：侧信道（缓存、功耗、温度）、身份冒用（Agent 应以自身身份鉴权，而非继承用户令牌）、以及"行为可审计"（每一步工具调用留痕）。这也是 IBM 本周为 Agent 发放可验证身份、配一键吊销开关的同一逻辑。
