1. OpenAI 发布 GPT-Rosalind-6：与 GPT-6 Astra 同一套权重，只把门开得更窄

一句话概要： 10 月 30 日，OpenAI 在部署安全中心发布 GPT-Rosalind-6 系统卡附录，面向生物学、药物发现与转化医学提供前沿推理模型 GPT-Rosalind-6 Research。它与旗舰 GPT-6 Astra 使用完全相同的权重，没有新增训练数据、没有额外后训练，变化的只有使用边界与访问管控。这是"同一模型、不同安全壳"这一部署范式的第一次完整公开演示。

技术要点： 附录把这次发布的性质写得很直白：能力来自母模型，风险控制来自部署层。具体做法是减少对两用生物学问题的拒答，让模型能真正参与湿实验设计、序列分析与药物化学推理，但只通过可信访问（trusted access）交付——申请方须说明用途、安全控制与治理制度，非政府申请者还要过企业核验与合规筛查，政府申请走单独的、限定于生物安保与公共卫生准备用途的通道。模型层面仍然拒绝生物武器化请求，网络侧沿用 Astra 的实时拦截并采用更保守的拒答边界。按 OpenAI 准备度框架，生物与化学按"高"能力对待（低于"关键"门槛），网络安全沿用母模型的"关键"评级，AI 自我改进则低于"高"。

实验结果： 三项生命科学基准均为发布方自测、取最高推理预算，并与上一代 GPT-Rosalind-5.5 在同一题目集上对比：MedChemBench v7（99 题，化学结构解读与构效关系）49.6% 对 28.9%；GeneBench Pro v13（129 题，生物数据定量分析规划与执行）37.7% 对 16.7%；LifeSciBench Gold（94 题，一线科学家贡献的真实研究任务）61.3% 对 44.0%。安全侧的数据更值得细看：Biorisk knowledge 的 cons@32 为 78.3%，略低于上一代 79.2%，但拒答率从 1.8% 升到 9.4%，拒答调整后为 85.0%（指示性阈值 80%）——说明"更少拒答"并不是无条件放开，而是把拒答集中到了真正敏感的位置。四项"关键"能力评测全部低于阈值：AAV 衣壳包装预测 0.529（阈值 0.600）、SHP2 蛋白功能预测 0.38（0.60）、冠状病毒–ACE2 进入筛选 0.42（0.75）、噬菌体–质粒共进化负对数似然 13.41（需 ≤9.40）。网络侧用 9 次已知越狱攻击在 10 个 ExploitBench 任务上回放，平均任务成功率 14.3%，母模型为 15.7%。

影响分析： 这份附录的真正价值不在分数，而在它把"模型能力"与"模型可交付性"拆成了两件事。过去一年行业默认的路径是：能力不够就继续训练，风险太高就加拒答；而这里给出的是第三条路——权重不动，用访问资格、用途审查、监测执法与合同约束来调节风险敞口。对强合规行业（医疗、生物制造、政务）来说，这比"某个基准又涨了 5 分"更有参考价值：它意味着采购时可以要求"同一权重 + 更严部署"，而不必接受"阉割版小模型"。需要警惕的是两个边界：其一，所有关键能力评测均来自发布方自测，且部分阈值本身是"专家判断的初步估计"，第三方复现之前不宜当作定论；其二，"同一权重"并不等于"同一行为"，拒答策略、系统提示与工具权限都会改变实际输出，审计时必须把这层壳一并纳入。对国内做行业模型的团队，这套"权重复用 + 部署分级"的思路，比重新训练一个专用模型便宜得多，也更接近监管可接受的形态。

2. Anthropic 开源 FlashProve：用零知识证明给模型输出发一张"防伪身份证"

一句话概要： 11 月 4 日，Anthropic 开源可证明推理系统 FlashProve，技术报告于 11 月 2 日发布。服务商可以为某次模型输出生成密码学证明，用户无需拿到权重、也无需自己跑模型，就能在普通 CPU 上核验"这段回答确实来自被承诺的那组权重"。在 Llama 4 Maverick（400B）上，单张 H100 生成证明、24 线程 CPU 核验约 17 秒，证明文件约 19MB。

技术要点： 核心是 zkSNARK（零知识简洁非交互式知识论证）。流程分两段：离线阶段，服务方对权重做编码并生成密码学承诺，相当于给这组权重打一个"指纹"；在线阶段，服务方记录推理轨迹（矩阵乘法、取整、非线性运算等），生成证明说明这些运算确实使用了承诺中的权重、并按规则得到该输出。用户拿到"权重承诺 + 输入 + 输出 + 证明"，用验证器即可判断一致性。证明同时具备零知识性（不泄露权重、中间值与专家选择）与简洁性（核验开销远低于自行推理），但模型架构本身不隐藏。工程上做了三处关键优化：利用 MoE 稀疏性，Llama 4 Maverick 每 token 仅激活 400B 中的约 17B（128 个路由专家选 1 个 + 1 个共享专家），证明只记录实际运行的专家并额外核验路由是否选对；把约 232GB 权重留在主机内存、逐段载入 GPU，使 80GB 显存 + 约 290GB 内存即可运行；批处理最多 64 个请求，共享权重承诺的查询数据。

实验结果： 离线准备约 39 分钟、保存约 2.15GB 文件，客户端首次下载权重承诺与离线证明共 6.24MB，此后每个请求只下载证明。批处理测试（单张 H100 + 24 核 CPU、128 位安全强度、每请求 1024 token 窗口、只检查紧随提示词后的一个输出 token）：单请求生成约 58 秒；一批 24 个请求共 223 秒，按窗口内全部 token 计的吞吐从 17.6 token/s 提升到 110 token/s；若只统计被检查的回复 token，约 39.1 token/s。对照 vLLM 跑同模型 FP8 版本，按单卡折算，证明生成的 GPU 时间约为预填充阶段的 72 倍，最高负载下约 94 倍。

影响分析： 这件事解决的是一个长期被忽略的信任漏洞：API 是黑箱，你付钱买的是"旗舰模型"，实际跑的可能是一个便宜得多的替代品，或者推理服务器被入侵后在正常回答里掺了东西。FlashProve 把"模型身份"变成了可验证事实，对三类角色都有意义——企业客户可以核对采购合同里的模型是否真在用，独立评测者可以确认榜单成绩出自哪个版本，监管机构则多了一种核查合规的抓手（Anthropic 甚至设想"未取得指定结果的证明"，即证明某模型针对某补丁尝试了至少 100 万 token 仍未发现漏洞）。但现阶段的限制必须说清楚：上下文最长 1024 token，与前沿模型数十万到百万级窗口差距巨大；验证的是整数模型的贪心选择（该位置得分最高的 token），实际服务的浮点推理与采样解码天然会产生差异，发现不一致时还要区分"计算方式不同"与"回答被篡改"；采用事后证明，先返回回答再生成证明，核验存在延迟，已泄露的信息无法撤回；批处理的零知识性与"Lean 协议描述"和"实际 GPU/CPU 代码"的等价性都还没有完整形式化证明。一句话：方向正确、数据亮眼，但离生产级默认开启还有距离——72–94 倍的证明开销，最终要有人买单。

3. CyberArena：466 场 Agent 攻防对局，把安全评测从"做题"搬进实战

一句话概要： 来自 2077AI、UC Berkeley RDI、UC Santa Cruz、UCSB、CMU、Google DeepMind 等 12 家单位的研究团队发布 CyberArena，让 12 组"前沿模型 + harness"在同一张攻防图上互相打：一边当黑客攻破对手，一边当运维守住自己的服务。跑完 22 个批次、466 场有效对局后，GPT-5.6 Sol（跑在 OpenAI Codex 上）以 78.6 分居首，Claude Opus 5（Claude Code）73.8 分次之，开源模型 GLM-5.3（OpenCode）68.5 分第三。

技术要点： 评测形式参考攻防夺旗（attack-and-defence CTF），采用对称竞技场：每场 3 轮、每轮 20 分钟，双方各有隔离的开发环境与生产环境，只有生产服务暴露在互联的对战网络中，Agent 的工具调用由 MCP 网关统一调度与计量（全程共 53,511 次调用）。每轮开始平台向双方环境埋入新目标（覆盖读、写、执行等权限），上一轮的 Flag 失效，但防守方上一轮部署的补丁会保留——这意味着攻击方不能靠一个脚本吃遍全场，防守方一旦修好漏洞，对手必须另寻出路。防守权限给得很宽（可改源码、重启进程），但为了防守直接把服务关掉或掐断流量会立刻被独立的健康检查（进程、TCP、HTTP 加业务功能探测）判负。最终得分由三部分等权构成：捕获对手 Flag 的轮次、守住己方 Flag 的轮次、正常业务可用性。排名用潜变量能力建模，把综合素质拆成攻击能力、防守能力、服务可用性三个独立潜变量，48 场校准对局取先验后逐批用 Laplace 近似重拟合。

实验结果： 头两名呈现断层优势：GPT-5.6 Sol 与 Claude Opus 5 的对局胜率分别为 0.83 和 0.86，其余选手最高仅 0.59。静态与动态的差距被量化得很清楚：在目标不设防、每题两次机会的单人模式下，40 道题里有 30 道是 GPT-5.6 Sol、Claude Opus 4.8、GLM-5.3 都能完全解出的；把这 30 道搬进双向对抗，到第 3 轮三者的进攻捕获率分别跌到 52%、37%、35%。成本同样反直觉：Claude Opus 5 每场平均 30.6 美元为全场最贵，GPT-5.6 Sol 每场 17.7 美元却分数更高，第三名 GLM-5.3 每场仅 4.7 美元。拉开身位的关键是防守速度：第 1 轮 GPT-5.6 Sol 首次部署补丁的中位时间为 2.3 分钟，其余模型集中在 3.9–12.3 分钟；某轮失守后它下一轮再失守的概率为 44%，其余模型平均 62%。对 466 场对局做自动审计后归纳出 2,397 条失误：23% 的对局里 Agent 只看补丁部署前的历史日志就宣称"已修复"，21% 属不完整修补（堵住一个入口却留下另一条已暴露路径），14% 出现长时间 sleep 挂机，8% 在目标轮换后仍打失效目标，8% 补丁过宽挡住正常业务，4% 在补丁后仍留有对手植入的可执行后门。

影响分析： 这项工作的价值在于把"安全 Agent 到底能不能用"从口号变成了可复现的对抗结果。榜单上动辄 80% 以上的 CTF/Cybench 解决率，在真实动态环境里会打对折甚至更多——因为真实对手会打补丁、会换凭证、会顺着流量反打，而你本地跑通 exploit 的那几分钟里，人家已经热修完了。对做安全运营的团队，这里有三条直接可用的经验：其一，"修复"必须包含验证，且验证要发生在部署之后（23% 的虚假修复声明说明模型倾向于把"我改了"当成"已生效"）；其二，补丁要按攻击面而非按漏洞点来评估（21% 的不完整修补是典型的"一个入口一条路"思维）；其三，防守方要保留溯源能力，Qwen3.8 Max 用原始套接字现写抓包程序定位令牌复用根因的那场对局，是全场最有工程味道的操作。当然，466 场仍属小样本，Kendall τ=0.85 的交叉验证只能说明排序稳健，不能说明绝对水平；而且对抗评测天然会被"针对性训练"污染，一旦厂商开始拿 CyberArena 做 RL 环境，分数就不再是能力代理。

4. 腾讯混元 Hy4 正式发布：770B MoE，首次"睁眼"并支持操作电脑

一句话概要： 11 月 4 日，腾讯混元发布新一代大语言模型 Hy4。相比 9 月的 Hy4 preview，正式版显著扩大预训练与后训练规模，首次引入视觉理解能力，并首次支持电脑操作（Computer Use）；总参数 770B、混合专家架构、激活参数 490 亿、上下文超过 100 万 token。腾讯称这是混元系列首次跻身"最强开源模型"梯队，权重与系统卡将于近期开源。

技术要点： 三条升级线索。第一是规模爬坡的节奏：Hy3 系列参数不到 300B，Hy4 直接到 770B，下一代 Hy5 还会继续扩大——这与行业"稀疏 MoE 用总参数换容量、用激活参数换吞吐"的共识一致，490 亿激活意味着单 token 推理成本仍在可服务区间。第二是视觉理解不是外挂：官方表述是"结合视觉感知、推理和工具调用"，在视觉任务中模型可以调用工具做二次确认，而不是一次性"看图说话"，这直接决定了读屏、读图表、读界面这类任务的可用性。第三是Computer Use 双通道：同时支持命令行与图形界面执行复杂任务，配合长程 Agent 与深度研究能力的强化，定位明显偏向"能连续干活的执行体"而非聊天机器人。官方同时强调"负责任的开源"，将发布系统卡并重点关注网络与生物安全风险。

实验结果： 官方口径是"综合能力大幅提升、首次进入最强开源模型梯队"，具体榜单成绩在发布稿中未完整披露，需等系统卡与第三方复现。可参考的横向坐标是同日上线的实际体验报道：智东西实测其操作微信、做 3D 建模，并称其价格看齐 DeepSeek、昇腾生态已联动——如果价格与国产算力适配同时成立，它在私有化部署场景的吸引力会明显高于纯榜单表现。另一个可观察的信号是它在 CyberArena 中的表现：HY4 Preview 对阵 Claude Opus 4.8 打成平局，靠的是在第 2 轮找到对手 26 条路由校验中遗漏的搜索接口——这说明其代码阅读与攻击面枚举能力已进入可用区间，但也暴露了"修一处漏一处"的共性问题。

影响分析： 国产开源模型的竞争已经从"有没有"进入"能不能替"的阶段。DeepSeek、Kimi、千问之后，混元把参数推到 770B 并补齐视觉与 Computer Use，意味着企业在做私有化选型时，第一次可以在同一个量级上比较四家国产开源方案，而不是"闭源旗舰 + 开源小模型"的二选一。对一线团队，值得提前准备的是三件事：一是 1M 上下文与视觉输入会显著改变 RAG 的工程结构（长文档可以直接进上下文，检索层要重新设计成本模型）；二是 Computer Use 意味着权限边界必须前置设计，命令行 + GUI 双通道的沙箱、审计与回滚比模型选型更关键；三是"开源 + 系统卡"的组合正在成为国内合规标配，采购时应把系统卡中的能力分级与拒答策略纳入验收项。风险同样明显：770B 的部署门槛不低，实际可用性取决于量化方案与国产卡适配成熟度，发布初期的第三方评测往往滞后于宣传口径。

5. 普林斯顿 SSON：给"空间智能"出一张考卷，人类 83.3%，最强模型 39.7%

一句话概要： 普林斯顿 AI Lab 等机构提出基准 Same Space or Not（SSoN），专门考察模型能否在多个视角之间维持一致的场景表征。每道题给三张同一场景的图和一张被编辑过的图，模型要找出"不合群"的那一张并解释矛盾所在——没有指定的可信参照，也没有标注好的目标。人类准确率 83.3%，最强视觉语言模型仅 39.7%；若还要求给出有效的视觉解释，进一步跌到 34.9%。

技术要点： 现有空间智能基准大多考察空间关系、视角采择与心理建模，但都回避了一个更根本的问题：模型能否在跨视角观察中保持连贯的场景表征。两两比较是不够的——它能告诉你两张图不同，却不能告诉你哪一张偏离了真实。SSoN 因此设计了"三正一负"的结构：1000 道题来自 7 类室内场景源，负样本由 6 类受控 3D 编辑生成（挪动家具、改变材质、增删物体等），模型必须在没有任何"可信参照"的情况下完成定位与归因。数据构造管线做了两件事保证质量：把人工评审意见迭代翻译成生成约束，再用自动检查加穷举式人工验证，筛掉两类题——能靠视觉捷径蒙对的，以及证据不足以支撑唯一答案的。

实验结果： 除主结果外，论文做了三组干预，信息量比总分更大。其一，在 100 题的干预集（基线 24%）上，改进提示词、提供相机信息、引入 3D 重建三条路都没有把答案准确率推过 50%；只有直接给出真值相机参数时才达到 61%，但"真正解对"（True solve，即解释也成立）只有 48%——说明模型很大程度是在"用元数据对齐"，而不是"理解空间"。其二，在 201 题的留出集上微调 Qwen2.5-VL-7B：原始 21.89%，只微调答案升到 33.33%，答案与推理理由一起微调升到 41.79%，证明这项能力可以通过针对性监督部分补上。其三，跨视角矛盾与"成对比较"的难度差被显著拉开，说明现有 VLM 擅长发现差异，却不擅长判断哪个差异是"错误"。

影响分析： 这张榜与具身智能的热度形成了刺眼对照。过去半年，行业默认"VLM 已经能看懂世界"，于是把导航、操作、巡检都往上堆；但 SSoN 说明，模型在"多视角一致性"这一最基础的空间能力上还不到人类的一半，而且失败方式很典型——不是看不见差异，而是无法建立"同一个空间应该长什么样"的内部模型。对做机器人、数字孪生、安防巡检的团队，这意味着三件事：不要用单视角 VQA 分数推断空间能力；多相机融合的鲁棒性必须在"存在被篡改视角"的条件下测试；如果需要模型判断"哪一路信号异常"，纯提示工程大概率不够，得靠带理由的监督微调（论文中 21.89% → 41.79% 的提升几乎全部来自理由监督）。更长远地看，这与 LeCun 的 JEPA 路线指向同一个结论：预测下一个 token 与建立世界表征是两种能力，前者不自动蕴含后者。

6. Realtime-Bench：实时交互考卷，最好的模型三次里只成功一次

一句话概要： 英伟达与 UT-Austin、西北大学、俄亥俄州立、UIUC 等机构提出 Realtime-Bench，把模型放进"世界不会等你"的环境：抢票窗口在倒计时、贪吃蛇在持续前进、拍卖对手随时加价。30 个网页任务加 20 个游戏任务、12 个前沿模型，在按真实推理延迟推进环境（Wall Clock）的条件下，表现最好的 GPT-6 Astra 高推理强度下 Pass^3 仅 36%。

技术要点： 基准把实时能力拆成三件事：RT-Perceive（判断当前状态、信息是否过时、机会是否还在）、RT-Deliberate（决定还能思考多久、继续思考是否值得）、RT-Act（判断该等待还是立即行动，并选择执行时仍然有效的动作）。为了区分"推理不行"和"被时间卡死"，论文设计了三种时钟：Paused Clock 在推理期间冻结环境（理想化对照）、Wall Clock 按真实耗时推进、Token Clock 按生成 token 数推进（剥离 API 服务延迟，只测模型自身的时间感知）。主指标用 Pass^3 而非单次成功率——实时任务失败往往无法重来（抢票失败就没有第二次），三次重复全中才算稳定可用。

实验结果： Wall Clock 下多数模型延迟超过 1 秒；Jev 做到了小于 1 秒延迟，但 Pass^3 只有 8%，说明低延迟本身不构成实时能力。Paused Clock 下提高推理强度普遍有收益（GPT-5.6 Sol 42%→58%，Claude Opus 5 62%→70%）；一旦环境在思考期间继续变化，收益就开始分化：Token Clock 下 Claude Opus 5 从 44% 降到 30%，Kimi-K3 反而从 24% 升到 36%；Wall Clock 下 GPT-5.6 Sol 从 16% 降到 8%。放宽时间预算确实有帮助但不够：把每秒模拟时间对应的 token 数从 32 提到 64、128 直至完全移除生成开销，Claude Opus 5 从 30% 升到 62%、Kimi-K3 从 22% 升到 60%，但仍有大量任务做不完。

影响分析： 这张榜打在了当下 Agent 叙事的最软处。行业里流行的"长程自主"其实是"慢思考"——模型有充足时间规划、试错、回滚；而真实业务里大量任务是有窗口的：抢单、竞价、告警处置、工单派发、直播互动，错过几秒就归零。Realtime-Bench 说明"推理越强越好"在实时场景并不成立，模型需要学会的是按剩余时间分配思考：窗口宽时比较方案，窗口将闭时立刻行动，新信息到达时及时废弃过时计划。对工程侧的直接启示是：不要把"提高 reasoning effort"当成万能旋钮，实时链路上应该做的是分级决策（快模型出动作、慢模型做复盘）、状态新鲜度校验（动作执行前确认前提仍成立）、以及幂等与补偿设计（因为模型一定会偶尔打偏）。对模型厂而言，这是一个明确的架构信号：实时能力不能靠后训练"教"出来，得在推理调度层做时间感知。
