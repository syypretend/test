1. Claude Fable 5.2 / Mythos 5.2 发布：1000 个 Agent 连跑 8 天造出操作系统，30 小时完成费马大定理形式化

一句话概要： 当地时间 11 月 9 日，Anthropic 发布新一代旗舰模型 Claude Fable 5.2 与 Claude Mythos 5.2，二者共用同一底层模型，区别在安全限制与访问权限；官方给出的成绩单不再是单项跑分，而是三个"长周期任务"：1000 多个 Agent 协作 8 天从零写出可在笔记本上开机的操作系统、30 小时完成费马大定理的形式化证明、解决两个黑洞物理难题。

技术要点： 这次升级的重点在"agentic 长程执行的稳定性"，而非单纯的知识量。官方披露的改进方向包括复杂编程、科研推理、图表理解与机器人控制，输出速度最高提升 30%，标准输入与输出价格均下调 20%。Fable 面向更广泛用户，Mythos 走更严格的安全限制与准入（可理解为"高风险能力沙盒版"）。值得注意的是，Anthropic 明确表示在训练阶段主动锁死了新模型的 RSI（递归自我改进）能力——即不让模型自己改写训练流程/自身权重更新链路，把"能力提升"和"自我进化"在工程上解耦。

实验结果： 三项长周期任务的具体口径：其一，"8 天造 OS"是从一个空文件夹开始，由 1000+ Agent 昼夜不停分工完成内核、磁盘与网卡驱动、文件系统、窗口界面乃至安装程序，最终在笔记本上跑通开机，过程中没有人类写代码；其二，费马大定理形式化由多个 Agent 协作在 30 小时内完成（形式化证明可机器验证，因此这一项的信噪比高于普通 benchmark）；其三，官方称模型在智能编码、科学研究、网络安全、计算机使用等维度"基本全面超过 Opus 5.5"。

影响分析： 对一线团队最实用的信号不是"又强了 30%"，而是评测与交付的颗粒度正在换代。当模型能连续工作 8 天，评价标准必须从"单轮准确率"转向"任务完成率 × 人工介入次数 × 每小时成本"，否则无法回答"这套 Agent 值不值得上线"。其次是 RSI 被主动锁死这件事本身：它说明头部实验室已经把"模型自主改进自身"当成需要管控的风险项，而不是纯能力项——这与国内做 Agent 平台时"是否允许 Agent 修改自身提示词/工具清单"的治理问题同构，建议在平台侧默认关闭自改权限、只开放人工审批后的版本升级。第三，价格下调 20% 叠加 30% 提速，意味着同等预算下的"有效 token 吞吐"提升约一倍，长程任务的成本模型需要重算。

来源： 凤凰网科技：Fable 5.2 登顶世界第一 ｜ 八天搓出操作系统、价格降 20% ｜ Anthropic 冲刺 IPO 时间点解读

2. OpenAI GPT-6 Cyber：10 天 120 万美元，在 Linux 内核复现 948 个提权漏洞并自动出补丁

一句话概要： 11 月 5 日，OpenAI 发布网络安全专用模型 GPT-6 Cyber，同时公开代号"少一千条通往 root 的路"的自动化审计研究：一个由该模型驱动的六阶段流水线，用 10 天扫描了 27% 的 Linux 内核（5034 个审计目标、280 万行代码），在 2308 个候选问题中动态复现 1724 个漏洞，最终形成 948 个可运行的本地提权利用，并向维护者提交了 304 项关键补丁建议。

技术要点： 流水线拆成六个阶段：SCOUT（侦察定位可疑代码）→ ANALYST（人工/模型混合分析成因）→ TRIAGE（去重与优先级）→ SCREEN（可触发性筛选）→ EXPLOITDEV（编写并验证利用代码）→ PATCH（生成补丁）。模型本身在 OpenAI《能力准备度框架》中被评为最高档 Critical，仅通过背景审核的 Daybreak Red 项目客户可调用，并已接入 Codex。研究侧的关键设计是**"利用代码即验证器"**：漏洞是否真实存在，不由模型自述决定，而由"能否在测试环境里把低权限用户提升到 root"来判定，这让整条流水线的误报率可以被工程化地压住。

实验结果： 官方与媒体交叉披露的数据：ExploitGym 基准上 GPT-6 Cyber 得分 48.5%，上一代 GPT-5.6 Cyber 为 32.1%（相对提升约 51%）；Firefox 中发现 81 个此前未知的高危漏洞；同一套工具用 GPT-5.6 Sol 时只能做出 166 个有效利用，本次为 948 个；系统共创建 1169 个有效 root shell，按 Pwn2Own 定价口径，这批利用的价值区间为 1890 万–6630 万美元，而 API 成本约 120 万美元。人类安全专家一年在 Linux 内核只能发现约 20 个本地提权漏洞，即单周产出相当于"数十年人力"。

影响分析： 这是本周最值得企业安全团队认真对待的一条，因为它同时改写了攻防两侧的成本曲线。防守侧：把"AI 审计"纳入 SDL/上线前流程已经具备经济性——按上述口径，120 万美元能覆盖 280 万行代码的系统性审计，对小团队则以"关键子模块 + 可复现验证"的方式降级使用；同时必须配套"利用代码不外流"的流程（沙箱、离网、人工复核）。进攻侧：能力被 Critical 级管控本身就说明门槛在降低，攻击者用开源权重 + 自建流水线复现只是时间问题，因此**"补丁时效"比"漏洞数量"更值得投入**。对我们的实际启示是：变更与上线评审应增加"AI 可挖掘面"检查项（提权路径、默认凭据、越权接口），并把"自动化验证"而非"人工阅读代码"作为准入判据。

来源： 钛媒体：Firefox 81 个高危 + Linux 948 条提权路径 ｜ 网易：10 天 120 万美元的流水线账本 ｜ IT之家：2308 候选 / 1724 复现 / 948 利用

3. Kimi K3.1 Pro 完整权重开放：2.8 万亿总参、1040 亿激活、百万上下文，登顶开放权重榜首

一句话概要： 11 月 5 日，月之暗面按 10 月 24 日发布时的承诺，在 Hugging Face 开放 Kimi K3.1 Pro 完整权重，总参数约 2.8 万亿、单次推理激活约 1040 亿、支持约 100 万 token 上下文，成为当前参数规模最大的开源 MoE 模型。

技术要点： 架构上是稀疏 MoE + 稀疏注意力，原生多模态，权重采用 MXFP4/MXFP8 量化方案，总体积约 1.56 TB、分 96 个分片——这组数字直接决定了部署门槛：单机放不下，必须多机 + 高带宽互联（官方推荐 vLLM、SGLang）。许可证主体接近 MIT，但对"年营收超过一定规模的托管/API 服务商"设有限制条款，属于"开放权重 + 商业护栏"的折中路线，与 DeepSeek 的纯 MIT 形成对照。阿里云灵骏真武 M890 超节点已完成 Day0 适配并在 vLLM/SGLang 双框架完成全链路验证，说明国产超节点在"超大 MoE 权重加载 + 长上下文推理"上已能跟上首发节奏。

实验结果： 第三方口径：Artificial Analysis 智能指数 55，位列全球第 4、开放权重模型第 1（早前发布时为 46.5 分，刷新当时开源纪录）；Arena 运营的 Agent Arena 中位列开放权重模型第一、全部参评模型第 13，净改进率 +5.1%（较前代提升 4.2 个百分点），Bash 可靠性、用户表扬率与可控性为长项；Office QA Pro v2 等办公类基准表现突出。

影响分析： 2.8T 开源意味着"旗舰能力不再靠 API 独享"，但不等于"人人可自托管"：1.56 TB 权重 + 千亿级激活，实际落地形态会是"区域云 + 超节点 + 少量大客户私有化"，而不是单机部署。对国内团队的现实价值有两点：一是它给了"数据不出域"场景一个真正可用的旗舰选项（前提是算力与运维能力匹配）；二是许可证的营收门槛提醒我们，选开源模型时要同时评估"许可证合规成本"，尤其是做对外 SaaS 时。运维层面，MXFP4 量化是这轮超大 MoE 的关键工程手段——它把权重压到能在有限显存/带宽下加载，代价是精度需要在下游任务上单独验证，别默认"量化无损"。

来源： 网易：2.8 万亿参数、激活 1040 亿、MXFP4/MXFP8 ｜ IT之家：Agent Arena 开放权重第一 ｜ 阿里云灵骏 Day0 适配

4. 美团 LongCat-2.5 正式开源：1.6 万亿参数、全程国产算力训练、MIT 协议可商用

一句话概要： 11 月 9 日，美团宣布 LongCat-2.5 正式开源，采用 MIT 协议、允许商用推理部署与二次训练且无需额外授权；模型总参数 1.6 万亿、每 token 激活约 480 亿、支持 100 万 token 上下文，定位是"面向长程智能体任务的原生多模态模型"，训练全程基于国产算力完成，是当前国产算力上规模最大的训练任务之一。

技术要点： 与"拼接式多模态"不同，LongCat-2.5 采取原生多模态路线：把视觉信号转成离散 token 与文本统一建模，从而在同一套自回归目标下学习图文联合分布，这也是它能直接在"Visual Coding"（看设计稿写前端）这类任务上发力的原因。工程侧针对国产芯片显存与带宽受限的特点，在架构、算子与部署三个层面做了适配，并在复杂代码库开发、完整项目构建、专业办公等场景做了定向强化。相比上一代 LongCat-2.0（2026 年 6 月，同为 1.6T，首次在国产算力上完成万亿参数全流程训练），这一代补的是"视觉理解 + 智能体编程"两块短板。

实验结果： 官方口径称其在复杂代码库开发、完整项目构建、Visual Coding 与专业办公场景达到"端到端可用"水平（未给出与海外旗舰的逐项横评分数，需谨慎看待）。更硬的指标是训练侧：万亿级参数 + 百万上下文，全程跑在国产算力上——这验证的不只是模型，而是"国芯 + 国模 + 国产框架"整条链路的可行性。

影响分析： 这条的意义超过模型本身。对电信、金融这类强合规行业，"全程国产算力训练 + MIT 协议 + 可私有化部署"三件套，基本解决了"能不能用"的前置问题：不再依赖境外 API，也不受许可证营收条款约束。但同时要清醒：1.6T 的权重下载与推理仍需可观资源，省级节点落地至少是"多机集群"级别；MIT 协议虽宽松，模型卡中的使用限制与国产芯片算子成熟度仍需逐一核验。实践建议是先做"小场景试点"（如工单摘要、看设计稿生成页面、内部知识问答），用真实业务集测"有效准确率 + 单次成本"，再决定是否进入生产。

5. NVIDIA CPU-ARC：把"推理过程"缓存成可执行的 CPU 程序，调用成本降到 1/16–1/291

一句话概要： NVIDIA 研究团队 11 月 6 日在 arXiv 公开技术报告《CPU-ARC: Agentic Reasoning Caching for on-CPU Reasoning Reuse》（28 页、9 图、11 表）。核心主张是：大模型总在"重新发明轮子"，把"解题"与"执行解法"混在一起，导致每个问题都从头推一遍；而一旦某类任务已经被推通过，把解法应用到新实例上其实可以几乎不依赖模型——他们把这套东西做成"可执行在 CPU 上的推理缓存"（ARC）。

技术要点： 方法链路可以概括为三步：其一，从 LLM 的推理轨迹（reasoning trace）里抽取可复用的步骤序列，而不是缓存最终答案；其二，把步骤序列编译成可在 CPU 上执行的 agentic 程序（含分支、校验与兜底），使"确定性部分"脱离 GPU 推理；其三，对确实需要语义判断的输入片段，调用小模型处理，从而把大模型从"每次都跑"变成"只在建缓存时跑一次"。论文强调 ARC 的四个属性：完全可解释（每一步都能读出）、可持续训练（可随新轨迹增量更新）、对输入扰动鲁棒、以及与源模型相比调用成本低 16–291 倍。作者：Peter Belcak、Greg Heinrich、Saurav Muralidharan、Shizhe Diao、Pavlo Molchanov（均为 NVIDIA 研究）。

实验结果： 论文摘要明确给出"在一系列困难数学与科学任务上，ARC 与前沿 LLM 表现相当（on-par）"。成本侧，按论文的 API 费率估算，8 项测试中原模型单次调用费用约为缓存的 16–291 倍；把"建缓存"的一次性开销计入后，回本所需的复用次数为：AIME 约 13 次、GSM8K 约 90 次。这两个数字很关键——它说明"缓存推理"并非万能：题目类型分散、复用率低的场景，建缓存反而亏。

影响分析： 这是本周技术上最"可迁移"的一条。我们平时做客服、装维、稽核这类业务，本质上都是同一类问题被反复问（同款故障、同类工单、同一套校验规则），天然具备高复用率——正是 AIME 那种"13 次回本"的甜点区。落地思路可以很具体：把 Agent 在历史工单上跑出的成功轨迹沉淀为"步骤模板 + 校验脚本"，高频问题走 CPU 执行的确定性路径（快、可解释、成本近乎为零），低频/新问题再回落到大模型；同时保留"模板失效检测"，一旦命中率下降就触发重训。风险点也很清楚：缓存的是"某类问题的解法"，一旦业务规则变化（资费、口径、系统界面），旧缓存会静默给出错误结果，因此必须给每条 ARC 绑定版本号与生效时间，并做定期回放验证。
