1. 中国电信开源 Xing4.1-Preview：2850 亿参数 MoE，全程 8192 张昇腾 910C 训练，Apache 2.0

一句话概要： 11 月 23 日，中国电信星辰 AGI Lab 开放 Xing4.1-Preview 权重，285B 总参数、约 17B 激活的 MoE 架构、原生 100 万 Token 上下文，Apache 2.0 可商用；比参数更关键的是它从预训练到后训练全程跑在 8192 张华为昇腾 910C + MindSpore 上，训练栈里没有英伟达硬件，也没有 CUDA 代码。

技术要点：

  • 模型形状是为国产卡"重新画的"。 主干 45 层，共 256 个路由专家，每个 Token 激活其中 8 个，再加 1 个共享专家。技术报告直言昇腾显存带宽相对偏弱，因此没有照搬主流开源模型的层数与专家配比，而是把"每 Token 读取多少权重"作为第一约束反推模型形状。这是一次典型的"硬件约束驱动架构设计"，而不是先定架构再优化 kernel。
  • 权重与精度组合面向部署现实。 BF16 版本约 521 GiB、共 261 个分片，同时提供 FP8 与 NVFP4 量化版本，覆盖从单机多卡到小规模推理集群的不同预算。对想私有化部署但又买不到高端卡的团队，这是一条可算成本的路径。
  • 系统层优化给出了可复现的数字。 相比纯 MLA 基线，预填充吞吐最高提升 4.68 倍；DSpark 投机解码带来 2.67—3.77 倍解码加速；取消流水线并行后吞吐再提升 16.1%。这三项分别对应长上下文读入、解码延迟、跨机通信三个实际瓶颈。
  • 训练栈的组织方式也公开了。 8192 卡规模下，主机侧任意一个慢线程都会让所有卡等它，团队把关键训练线程绑定到指定 CPU 核、并把后台任务移开，两项措施叠加后 512 卡集群吞吐明显提升。这类"卡越多越难"的工程细节，此前很少有厂商愿意写进报告。
  • 能力定位在长程 Agent。 支持 Thinking 开关、Function Calling 与结构化输出，可接入 Claude 风格的工具调用协议，面向代码 Agent、复杂任务规划与长程工作流；天翼 AI 平台提供 OpenAI 兼容 API，单次请求支持 896K 输入与 128K 输出。

结果与边界：

技术报告（arXiv 2611.22115，11 月 17 日发布，138 位作者，星辰 AGI Lab 联合华为、哈工大深圳等）给出的是系统层面数字，而非榜单成绩。模型卡明确写了一条边界：完整基准成绩要等正式技术报告发布，发布前不引用任何第三方跑分。也就是说，眼下它是一套权重加一个 API，而不是排行榜上的一个位置。

影响分析：

对国内做私有化、可审计部署的团队，这是目前少见的"权重完整 + 协议宽松 + 国产算力闭环"三者兼备的选项。对做 AI 应用的一线团队，真正可复用的是三层经验：一是按显存带宽反推专家数与层数的建模方法；二是 8192 卡规模下的线程绑核与后台任务隔离；三是把投机解码、去流水线并行这类"系统级增益"单独量化，而不是混在端到端里。局限也很直接：BF16 全量 521 GiB 的部署门槛不低，能力成色尚未有公开基准交叉验证，实际选型前建议先用自有业务集做小样本对比。

2. 智谱发布 GLM-5.4：旗舰首次采用 Loop Transformer，用"层深复用"换参数宽度

一句话概要： 11 月 24 日，智谱发布旗舰 GLM-5.4，距上代旗舰约三个月，首次在旗舰产品采用 Loop Transformer——同一组共享权重层循环执行两次，以计算深度替代参数宽度，官方称智能水平达到 2T—3T 参数级模型水平，新增视觉理解与更长的思考模式。

技术要点：

  • 核心取舍：不堆参数，堆"想的时间"。 传统做法是加宽隐层或加深层数来提升容量，代价是权重显存与单 Token 读取带宽同步上涨。GLM-5.4 选择让 28 层网络循环执行两遍：参数存储量按 28 层计，但有效计算深度按 56 层计。对显存受限、又要提升推理深度的场景，这是一条与 MoE 正交的新路径。
  • 与 MoE 的区别要说清。 MoE 是"每次只激活一部分专家"，节省的是计算量；循环层是"同一批参数用两次"，节省的是存储量与权重加载带宽。两者解决的不是同一个瓶颈：前者降 FLOPs，后者降 HBM 占用与权重读取压力。理论上可以叠加，但循环会放大激活值驻留时间，对 kernel 融合与调度提出新要求。
  • 配套能力同步升级。 新增视觉输入与更长的思考模式（thinking budget 更宽），主打"泛化编程"与原生多模态；官方披露已建成超 10 万张国产芯片的推理集群，说明这次发布是"模型 + 算力"一起交卷。
  • 风险点。 循环结构在训练时容易出现梯度尺度随循环次数放大、深层等效退化的问题，通常需要层间归一化与循环次数随机化（stochastic depth 思路）配合；官方未公开训练细节，实际长程任务稳定性仍需实测。

影响分析：

如果 Loop Transformer 的基准成绩能被第三方复现，最直接的产业影响是推理成本结构变化：同样显存能装下更大有效深度的模型，长上下文与长思考场景的单位成本下降。对做端侧或单机私有化部署的团队，这比"再发一个更大的 MoE"更有价值——因为 MoE 的专家并行在中小规模部署里往往退化严重，而循环层不增加分片数量。反过来，循环结构也让 KV Cache 与并行策略的调优空间变复杂，推理框架需要新的调度支持，短期内生态适配会是瓶颈。

来源：AI 技术进展早报（11/24） ｜ AI 热点日报（11/25）

3. 百度文心 5.5 Flash Preview 提前开源：2800 亿 MoE、140 亿激活、百万上下文、Apache 2.0

一句话概要： 11 月 24 日，百度比承诺提前一天开源 ERNIE 5.5 Flash Preview，稀疏 MoE 总参 2800 亿、每 Token 激活约 140 亿，支持 100 万 Token 上下文，Apache 2.0 协议，权重上架 Hugging Face 与 ModelScope，并直接支持 vLLM / SGLang 部署。

技术要点：

  • 稀疏度约 5%。 2800 亿总参只激活 140 亿，与 Xing4.1（2850 亿 / 170 亿）、Hy4 flash（2240 亿 / 120 亿）基本处于同一稀疏区间。这说明国内头部厂商在"总参撑容量、激活控成本"上的工程共识已经形成，竞争点转向专家路由质量与训练数据配比，而不是单纯堆参数。
  • 百万上下文 + 主流推理框架原生支持。 开箱可用 vLLM / SGLang，意味着不需要自研 kernel 就能跑起来，这对中小团队的实际意义大于参数规模。此前的开源模型常见问题是"权重放了但没人能高效跑"。
  • 协议与合规取向。 Apache 2.0 去掉商用门槛，可本地部署与微调；同期百度 Q3 财报显示 AI 业务收入 132 亿元、占一般性业务收入 53%，连续三季过半，GPU 云收入同比 +191%。开源 Flash 系列本质是用小模型换生态入口，把高价值推理留在云上。

影响分析：

这是本周"发布即开源"节奏里最直接可用的一条：协议宽松、框架原生支持、上下文足够长，适合做企业知识库问答、长文档处理、代码补全这类需要私有化又买不起高端卡的场景。需要提醒的是 Preview 版本的稳定性与长上下文实际有效长度（很多模型的 1M 上下文在中段检索上衰减明显），上线前应做 needle-in-a-haystack 与多跳检索的自测。

4. NeurIPS 2026｜反事实语义显著性：VLM 并不"看人"，而是被"大、居中、醒目"带偏

一句话概要： 加州大学圣塔芭芭拉分校团队提出反事实语义显著性（Counterfactual Semantic Saliency, CSS）——用"移走一个物体看描述变多少"的黑盒因果干预方法，量化 19 个主流开源与闭源 VLM 对场景元素重要性的判断，并与 227 名人类被试的 16603 条描述做对比。结论是所有模型都显著偏离人类：模型过度依赖物体大小、居中程度与低级显著性，而对"场景里有没有人"异常迟钝。

技术要点：

  • 为什么必须用黑盒方法。 主流 VLM 参数巨大且大量闭源，注意力图、梯度热力图这类白盒可解释性手段要么用不了，要么难以揭示真正起因果作用的特征。CSS 的做法是对每个物体做因果干预——把它从图中移除，重新让模型描述，用描述变化幅度定义该物体的"语义显著性"。
  • 数据集与人类基线做得扎实。 基于 OSIE 数据集构建 307 张原始场景 + 1306 张反事实场景（每张原图对应 3—6 个移除版本）；通过 Prolific 招募 227 名被试，采用被试间设计避免记忆效应，共收集 16665 次试次、清洗后保留 16603 条描述，每张图约 10 条独立描述。
  • 四个假设逐一验证。 大小敏感性（分割掩码面积）、中心敏感性（物体中心到画面中心距离的负值）、低级显著性（GBVS 峰值）、人类敏感性（是否为人）。结果显示模型在三个低级属性上的敏感度都显著高于人类，而对"人"的敏感度显著低于人类。
  • 定位到主因：大小。 研究者计算每个模型"属性敏感度与人类的差值 Δr"和"Top-1 准确率与人类的差值 ΔAcc"，在 19 个模型间看相关性——只有大小敏感性显著相关，其余三项均不显著。也就是说，越依赖物体大小的模型，越容易找错场景里的关键物体。
  • 白盒热力图基本无效。 在 Qwen3-VL-4B-Instruct 上对比原始注意力图、Grad-CAM、AGCAM 三种方法与 CSS 的物体重要性排序，结果这些热力图要么杂乱要么过于稀疏，与 CSS 甚至呈负相关。这直接挑战了"看注意力图就能知道模型在意什么"的工程习惯。
  • 评估覆盖范围。 19 个模型涵盖 Qwen3-VL、InternVL3、Gemma 4、GPT-5.4、Claude 4.x、Gemini 3.x 等系列，无一达到人类之间的一致性水平。

影响分析：

对做多模态应用的团队，这条结论有直接的工程含义：如果你的场景里"人"是关键语义（客服视频质检、安防、直播内容审核、无障碍描述），模型的默认注意力分布与业务目标是不一致的，不能假设它"自然会看人"。可行的对策有三条：一是在标注与微调数据里显式强化人物区域；二是在推理侧引入区域提示或先做人/物检测再喂给 VLM；三是用 CSS 这类因果方法做上线前的显著性对齐检查，而不是只看注意力热力图。更宏观地看，在合成数据大规模回流训练的当下，"模型是否像人一样看世界"是一个值得与准确率并列监控的指标。

来源：论文 arXiv:2605.13047 ｜ 项目代码 ｜ 机器之心解读

5. 智能体记忆的两条新路线：SAG-Mem 保原文做词法扩展，Leto 用回答结果反向校准"记忆有没有用"

一句话概要： 同日两篇 arXiv 论文从相反方向改写 Agent 记忆系统的设计前提。SAG-Mem 主张"不总结、不建关系图，完整保留对话原文"，靠查询时词法扩展补足相似度低的中间证据，在 LoCoMo 与 LongMemEval 上分别取得 83.08 与 80.20，均为所比较方法中最高；Leto 则指出"记忆忠实于过去"不等于"对回答有用"，把记忆选择建模为对未来的预测问题，用回答结果反向校准，个性化场景准确率领先最强基线 16.3 个百分点。

技术要点：

  • SAG-Mem 的极简主义。 记忆构建阶段完全不做模型推理：把对话消息按不重叠的块完整保留，只建词法索引，不做 LLM 抽取、摘要或语义关系构建。这消除了现有系统最大的隐性成本——构建期的大量 LLM 调用，也避免了摘要过程丢失源细节。
  • 查询时两轮检索是关键。 第一轮 BM25 召回候选块；证据评估器判断哪些块真正有用；第二轮用被选中证据里的词法线索（人名、时间、专有名词）再检索一次，把与原始问题相似度很低但必需的"中间证据"捞回来。这一步正是多会话长程记忆的痛点：答案往往不在与问题最像的那段对话里。
  • 时间表达单独处理。 检索到的对话会附加相对时间表达式（"上周三""下个月"）的日历解释，但保留原始措辞与时间粒度，避免把"大概那阵子"硬解析成精确日期。
  • SAG-Mem-Lite 是成本版。 用 embedding 打分替代证据评估器，运维成本低于 Full Context 与所有记忆基线，查询延迟也低；代价是 LoCoMo / LongMemEval 掉到 77.09 / 77.20。
  • Leto 换了评价坐标。 现有记忆系统把记忆当作"过去的记录"，用对对话的保真度评估；但记忆的价值在于是否改善回答，而"记什么、取什么"发生在回答存在之前，保真度检查对这两个决策都不适用。Leto 因此保留对对话细节的索引访问（不丢源），在请求到来时做"记忆重放"，主动预判请求未明说的上下文需求，并用回答结果构成效用回路，持续修正未来的记忆选择。
  • Leto 的实验结果。 对比六个记忆系统、五个基准、三种场景：个性化场景 PrefEval 准确率领先最强基线 16.3 个百分点，PERMA 任务完成率领先 3.1 个百分点；长程任务在 MemoryArena 五个环境平均最优，且增益随链深度增加而扩大；长上下文理解上与"直接检索原始历史"持平，但服务的上下文 Token 更少。

影响分析：

这两篇合起来给出了一个清晰判断：不要急着把对话"加工"成摘要或知识图谱。SAG-Mem 证明了原文 + 好的检索策略就能超过复杂的结构化记忆，构建期零 LLM 调用意味着成本可控、可增量、可回滚；Leto 则指出下一步优化目标应该从"记忆是否准确"换成"记忆是否让回答更好"，这要求系统具备闭环评估能力（记录某段记忆被取用后回答是否变好）。对做客服陪练、知识助手这类多轮长会话产品的团队，可落地的顺序是：先把原文分块 + BM25 + 二轮扩展做扎实，再考虑引入效用反馈；一开始就上摘要与关系图，往往是成本最高、丢信息最多的一条路。
